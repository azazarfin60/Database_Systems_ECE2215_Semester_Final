# T04.5: Domain Relational Calculus and Relational Division

> **Topic:** T04 — Relational Algebra & Calculus | **Priority:** 🟢 | **Exam Frequency:** 1/7 finals (3 marks)
> **Sources:** Silberschatz 7e Ch. 2 (§2.6 p. 61 Practice Ex 2.9, Online Ch. 27) · Lecture Deck 02 (Slide 9) · Classnote by Raidah (Pages 13–14)

## Why This Topic Matters

While relational algebra gives the database a step-by-step recipe for *how* to build an answer, relational calculus simply states *what* properties the answer rows must satisfy. That declarative mindset is the mathematical foundation behind SQL. In RUET exams, 2020 Q.4(b) (3 marks) directly asked students to translate relational algebra projection, union, and intersection into Domain Relational Calculus (DRC). In addition, the course syllabus (Unit 3) lists Relational Division ($\div$), which is the go-to algebraic operator for "for all" queries (such as finding students who took *every* course in a department).

---

## 📝 Key Definitions

> **Domain Relational Calculus (DRC):** "Domain relational calculus uses domain variables that take on values from an attribute's domain, rather than values for an entire tuple. A query in the domain relational calculus has the form: $\{\, \langle x_1, x_2, \dots, x_n \rangle \mid P(x_1, x_2, \dots, x_n) \,\}$ where $x_1, x_2, \dots, x_n$ represent domain variables and $P$ represents a formula composed of conditions." — *(Course definition & Silberschatz online Ch. 27 §27.2)*

> **Relational Division Operator ($\div$):** "The division operator of relational algebra, '$\div$', is defined as follows. Let $r(R)$ and $s(S)$ be relations, and let $S \subseteq R$; that is, every attribute of schema $S$ is also in schema $R$.... Then $r \div s$ is a relation on schema $R - S$ (that is, on the schema containing all attributes of schema $R$ that are not in schema $S$). A tuple $t$ is in $r \div s$ if and only if both of two conditions hold: $t$ is in $\Pi_{R - S}(r)$, [and] for every tuple $t_s$ in $s$, there is a tuple $t_r$ in $r$ satisfying both: $t_r[S] = t_s[S]$ and $t_r[R - S] = t$." — Silberschatz, Korth & Sudarshan, *Database System Concepts* (7th Ed.), Chapter 2 Practice Exercises, Ex. 2.9 (p. 61)

> **Safety of Expressions:** "An expression in the domain relational calculus is safe if all values that appear in the result are values from the domain of the formula, which means they appear in the relations or constants of the query." — *(Course definition & Silberschatz online Ch. 27 §27.2.3)*

> **Tuple Relational Calculus (TRC):** "The tuple relational calculus is a nonprocedural query language. A query in the tuple relational calculus is expressed as: $\{\, t \mid P(t) \,\}$. That is, it is the set of all tuples $t$ such that predicate $P$ is true for $t$." — *(Course definition & Silberschatz online Ch. 27 §27.1)*

## The Three Pure Relational Languages

### Intuitive Analogy: Following a Recipe vs. Placing an Order

Why do database theorists study three different "pure" languages (Lecture Deck 02, Slide 9)?

- **Relational Algebra is like a kitchen recipe:** You tell the database the exact sequence of steps: "First filter table $A$, then join it with table $B$, then slice off column $C$."
- **Tuple Relational Calculus (TRC) is like ordering by row:** You say, "Give me every row $t$ where $t$'s department is ECE." Here a single variable $t$ stands for an entire row object.
- **Domain Relational Calculus (DRC) is like filling in blanks on a form:** Instead of using one variable for a whole row, you create a separate variable for each individual column value, written inside angle brackets like $\langle \text{id}, \text{name}, \text{dept} \rangle$. Then you state the rules those column values must obey.

By Codd's Theorem, all three languages have the exact same expressive power (when calculus expressions are restricted to safe queries).

### Comparison of Query Paradigms

| Property | Relational Algebra | Tuple Relational Calculus (TRC) | Domain Relational Calculus (DRC) |
| :--- | :--- | :--- | :--- |
| **Paradigm** | Procedural / Step-by-step | Declarative (non-procedural) | Declarative (non-procedural) |
| **Basic Variable** | Whole relations | Row variable $t$ | Column value variables $\langle a, b, c \rangle$ |
| **Expression Form** | $\Pi_L(\sigma_P(r \bowtie s))$ | $\{\, t \mid P(t) \,\}$ | $\{\, \langle x_1, \dots, x_n \rangle \mid P(x_1, \dots, x_n) \,\}$ |
| **Attribute Access** | Named in operator subscripts | Dot or bracket notation: $t.\text{name}$ or $t[\text{salary}]$ | Positional variable inside $\langle x_1, \dots, x_n \rangle$ |
| **Theoretical Power** | Equivalent (Codd's Theorem) | Equivalent (Codd's Theorem) | Equivalent (Codd's Theorem) |

## Domain Relational Calculus (DRC) Step by Step

### How to Read DRC Notation

Every DRC query looks like standard set-builder notation from discrete math:

$$
\{\, \langle x_1, x_2, \dots, x_n \rangle \mid P(x_1, x_2, \dots, x_n) \,\}
$$

Read the vertical bar $\mid$ as **"such that"**:
- **Left of the bar ($\langle x_1, x_2, \dots, x_n \rangle$):** Lists the exact column variables that will appear in your output table. If your final answer only has 1 column, you write just 1 variable $\langle a \rangle$ on the left!
- **Right of the bar ($P(x_1, x_2, \dots, x_n)$):** States the logical condition that those variables must satisfy. You build $P$ from four simple building blocks:
  - **Table membership:** $\langle a, b, c \rangle \in r_1$ means "the row $(a, b, c)$ exists in table $r_1$."
  - **Comparisons:** $a = 10$ or $x_i > x_j$.
  - **Logical connectives:** $\land$ (AND), $\lor$ (OR), and $\neg$ (NOT).
  - **Quantifiers for hidden columns:** If a table has 3 columns $(A, B, C)$ but you only want to output $\langle a \rangle$ on the left of the bar, what happens to $b$ and $c$? You cannot leave them floating unbound, so you introduce them with the existential quantifier $\exists b, c$ ("there exist some values $b$ and $c$ in the row"). Similarly, $\forall x$ means "for all values of $x$".

### Translating Fundamental Relational Algebra Operations to DRC

Suppose we have a 3-column schema $R = (A, B, C)$ and two tables $r_1$ and $r_2$ on that schema. Let $a, b, c$ be the domain variables for columns $A, B, C$.

#### 1. Selection ($\sigma$)

- **Algebra:** $\sigma_{A = 10}(r_1)$
- **DRC:**

$$
\{\, \langle a, b, c \rangle \mid \langle a, b, c \rangle \in r_1 \land a = 10 \,\}
$$

Because selection keeps all 3 columns of $r_1$, all three variables $\langle a, b, c \rangle$ stay on the left of the bar, and we add $\land\, a = 10$ on the right.

#### 2. Projection ($\Pi$)

- **Algebra:** $\Pi_A(r_1)$
- **DRC:**

$$
\{\, \langle a \rangle \mid \exists b, c \; (\langle a, b, c \rangle \in r_1) \,\}
$$

Because projection keeps only column $A$, only $\langle a \rangle$ appears on the left of the bar. Columns $B$ and $C$ still exist inside $r_1$, so we bind them with $\exists b, c$ on the right.

#### 3. Union ($\cup$)

- **Algebra:** $r_1 \cup r_2$
- **DRC:**

$$
\{\, \langle a, b, c \rangle \mid \langle a, b, c \rangle \in r_1 \lor \langle a, b, c \rangle \in r_2 \,\}
$$

A row is in the union if it is in $r_1$ **OR** ($\lor$) in $r_2$ (or both).

#### 4. Intersection ($\cap$)

- **Algebra:** $r_1 \cap r_2$
- **DRC:**

$$
\{\, \langle a, b, c \rangle \mid \langle a, b, c \rangle \in r_1 \land \langle a, b, c \rangle \in r_2 \,\}
$$

A row is in the intersection if it is in $r_1$ **AND** ($\land$) in $r_2$ at the same time.

#### 5. Set Difference ($-$)

- **Algebra:** $r_1 - r_2$
- **DRC:**

$$
\{\, \langle a, b, c \rangle \mid \langle a, b, c \rangle \in r_1 \land \neg(\langle a, b, c \rangle \in r_2) \,\}
$$

A row is in $r_1 - r_2$ if it is in $r_1$ **AND NOT** ($\land\,\neg$) in $r_2$.

#### 6. Cartesian Product ($\times$)

If $r_1(A, B)$ and $r_2(C, D)$ have 2 columns each, their Cartesian product $r_1 \times r_2$ has 4 columns:

$$
\{\, \langle a, b, c, d \rangle \mid \langle a, b \rangle \in r_1 \land \langle c, d \rangle \in r_2 \,\}
$$

## Safety of Relational Calculus Expressions

### Why "Unsafe" Queries Break a Database

What happens if someone writes a DRC query asking for everything that is **not** in table $r_1$?

$$
\{\, \langle a, b, c \rangle \mid \neg(\langle a, b, c \rangle \in r_1) \,\}
$$

If column $A$ holds integers, there are infinitely many integers in the universe that are not stored in $r_1$! A computer can never finish printing an infinite table.

To prevent infinite answers, relational calculus requires every valid query to be **safe**:
1. Every variable in the output tuple must draw its values from the **domain of the formula** ($\text{dom}(P)$), which consists only of constants written in $P$ or values actually stored in the database tables mentioned in $P$.
2. Every quantified variable ($\exists x$ or $\forall x$) must also be restricted to values appearing in a database relation.

## Relational Division ($\div$)

### Intuitive Analogy: Why Division Uses the "Double-Negative" Trick

Relational division ($r \div s$) answers **"for all"** questions, such as: *"Find the students who have completed **every** required lab."*

When students first see the formula for $r \div s$ using basic operators ($\Pi, \times, -$), the double subtraction looks intimidating. Here is the simple intuition behind why it works:

Suppose a professor wants to know which students completed **all** required labs, using only basic roster sheets:
1. **List all candidates ($\Pi_{R-S}(r)$):** Write down the ID of every student who did at least one lab.
2. **Create the "dream sheet" ($\Pi_{R-S}(r) \times s$):** Pair every student with every required lab. This table shows what the records *would* look like if every student completed 100% of the labs.
3. **Subtract actual work to expose missing labs ($(\Pi_{R-S}(r) \times s) - r$):** Cross off the labs students actually completed. Whatever pairs remain on the dream sheet are **missing labs** that a student skipped!
4. **Make the "disqualified list" ($\Pi_{R-S}(\text{Missing})$):** Read off the student IDs who have at least one missing lab.
5. **Subtract the disqualified list from all candidates:** Take your full student list from Step 1 and remove anyone on the disqualified list. Whoever survives has zero missing labs, which means they completed **every** required lab!

### When to Use Division on Exams

Reach for $r \div s$ whenever a query asks for entities matched with **all** or **every** item in another set:
- Find students who have taken **all** courses offered by the CSE department.
- Find customers who hold an account at **every** branch in Rajshahi.
- Find suppliers who supply **all** parts needed for Project X.

### Formal Definition and Fundamental Algebra Formula

Let $r(R)$ and $s(S)$ be two relations where the attributes of $S$ are a subset of the attributes of $R$ ($S \subset R$):
- Schema of dividend $r$: $R = (A_1, \dots, A_m, B_1, \dots, B_n)$
- Schema of divisor $s$: $S = (B_1, \dots, B_n)$
- Schema of quotient $r \div s$: $R - S = (A_1, \dots, A_m)$

A tuple $t$ is in $r \div s$ if and only if for every tuple $u \in s$, the combined pair $\langle t, u \rangle$ appears in $r$.

Expressed using only fundamental relational algebra operators ($\Pi, \times, -$), division is:

$$
r \div s = \Pi_{R - S}(r) - \Pi_{R - S}\left(\left(\Pi_{R - S}(r) \times s\right) - r\right)
$$

1. **Step 1 (All Candidates):**

$$
\text{Candidates} = \Pi_{R - S}(r)
$$

2. **Step 2 (All Ideal Pairings):**

$$
\text{Ideal} = \Pi_{R - S}(r) \times s
$$

3. **Step 3 (Missing Requirements):**

$$
\text{Missing} = (\Pi_{R - S}(r) \times s) - r
$$

4. **Step 4 (Disqualified Candidates):**

$$
\text{Disqualified} = \Pi_{R - S}(\text{Missing})
$$

5. **Step 5 (Surviving Winners):**

$$
r \div s = \text{Candidates} - \text{Disqualified}
$$

## Division Worked Example with Concrete Tables

Let us trace those exact 5 steps on a small dataset where $r(\text{student\_id}, \text{lab\_id})$ tracks completed labs and $s(\text{lab\_id})$ lists the required labs.

### Completed Labs: $r(\text{student\_id}, \text{lab\_id})$
| student_id | lab_id |
| :--- | :--- |
| S101 | L1 |
| S101 | L2 |
| S101 | L3 |
| S102 | L1 |
| S102 | L2 |
| S103 | L1 |

### Required Labs: $s(\text{lab\_id})$
| lab_id |
| :--- |
| L1 |
| L2 |

### Step-by-Step Trace

1. **All Candidates:** $\Pi_{\text{student\_id}}(r) = \{\text{S101}, \text{S102}, \text{S103}\}$
2. **Ideal Pairings ($\Pi_{\text{student\_id}}(r) \times s$):**
   - $\langle \text{S101}, \text{L1} \rangle$, $\langle \text{S101}, \text{L2} \rangle$
   - $\langle \text{S102}, \text{L1} \rangle$, $\langle \text{S102}, \text{L2} \rangle$
   - $\langle \text{S103}, \text{L1} \rangle$, $\langle \text{S103}, \text{L2} \rangle$
3. **Missing Pairings ($\text{Ideal} - r$):**
   - Only $\langle \text{S103}, \text{L2} \rangle$ remains, because S103 never completed L2. (Note that S101's extra lab L3 in $r$ is harmlessly ignored when subtracting $r$ from $\text{Ideal}$.)
4. **Disqualified Students ($\Pi_{\text{student\_id}}(\text{Missing})$):** $\{\text{S103}\}$
5. **Final Division Result ($r \div s$):**

$$
\{\text{S101}, \text{S102}, \text{S103}\} - \{\text{S103}\} = \{\text{S101}, \text{S102}\}
$$

Both S101 and S102 completed L1 and L2, so both appear in the answer, while S103 is filtered out.

## DRC Worked Mini-Example

Before looking at the 2020 final exam question below, let us write a DRC query on a concrete table `instructor(ID, name, dept_name, salary)` to **find the names of all instructors in the `'ECE'` department whose salary is greater than 70,000**:

1. **Identify output columns:** We only want the instructor's name, so only $\langle n \rangle$ goes on the left of the bar.
2. **Quantify the remaining columns:** The table has 4 columns (`ID`, `name`, `dept_name`, `salary`), represented by variables $\langle i, n, d, s \rangle$. Since $i, d, s$ do not appear on the left, we bind them with $\exists i, d, s$.
3. **Write the conditions:** The row $\langle i, n, d, s \rangle$ must belong to `instructor`, with $d = \text{"ECE"}$ and $s > 70000$:

$$
\{\, \langle n \rangle \mid \exists i, d, s \; (\langle i, n, d, s \rangle \in \text{instructor} \land d = \text{"ECE"} \land s > 70000) \,\}
$$

## 🏆 Golden Questions (Past Exam Archive)

### 🎯 GQ1 · 2020 Q.4(b) · Domain Relational Calculus Equivalents

> **Appeared:** 2020 Q.4(b) — (03 Marks | Sec A)

> **Question:**
>
> Let that, $R=(A, B, C)$ and $r_1$, $r_2$ both be relations on the schema R. Give an expression in the domain relational calculus that is equivalent to each of the followings.  
> (i) $\pi_A(r_1)$  
> (ii) $r_1 \cup r_2$  
> (iii) $r_1 \cap r_2$

**Full Answer:**

Let domain variables $a, b, c$ range over the domains of attributes $A, B, C$ respectively so that any tuple in schema $R$ is represented by $\langle a, b, c \rangle$.

**(i) Domain Relational Calculus expression for $\pi_A(r_1)$:**

The projection on attribute $A$ outputs 1-tuples $\langle a \rangle$. Because attributes $B$ and $C$ are not part of the final output, we bind them using existential quantifiers ($\exists b, c$):

$$
\{\, \langle a \rangle \mid \exists b, c \; (\langle a, b, c \rangle \in r_1) \,\}
$$

*Explanation:* Collects all attribute values $a$ for which there exist some values $b$ and $c$ such that the tuple $\langle a, b, c \rangle$ is in relation $r_1$.

**(ii) Domain Relational Calculus expression for $r_1 \cup r_2$:**

The union outputs 3-tuples $\langle a, b, c \rangle$ that appear in $r_1$, in $r_2$, or in both, using logical OR ($\lor$):

$$
\{\, \langle a, b, c \rangle \mid \langle a, b, c \rangle \in r_1 \lor \langle a, b, c \rangle \in r_2 \,\}
$$

*Explanation:* A tuple is included in the result if it belongs to $r_1$, belongs to $r_2$, or belongs to both relations.

**(iii) Domain Relational Calculus expression for $r_1 \cap r_2$:**

The intersection outputs 3-tuples $\langle a, b, c \rangle$ that appear in both relations at the same time, using logical AND ($\land$):

$$
\{\, \langle a, b, c \rangle \mid \langle a, b, c \rangle \in r_1 \land \langle a, b, c \rangle \in r_2 \,\}
$$

*Explanation:* A tuple is included in the result if and only if it belongs to both $r_1$ and $r_2$ simultaneously.

### 🎯 GQ2 · Likely Exam Question · Universal Query with Relational Division

> **Appeared:** Likely Question (Silberschatz 7e Ch. 2 Ex. 2.9 & Syllabus Unit 3) — (04 Marks)

> **Question:**
>
> Consider the relations $\text{takes}(\text{ID}, \text{course\_id})$ and $\text{cs\_courses}(\text{course\_id})$.  
> (a) Write a relational algebra expression using the division operator ($\div$) to find the IDs of all students who have taken all Computer Science courses.  
> (b) Rewrite the query using only fundamental relational algebra operators ($\Pi, \times, -$).

**Full Answer:**

**(a) Expression using the division operator ($\div$):**

$$
\Pi_{\text{ID}, \text{course\_id}}(\text{takes}) \div \text{cs\_courses}
$$

*Explanation:* Dividing $(\text{ID}, \text{course\_id})$ by $(\text{course\_id})$ drops the divisor attribute $\text{course\_id}$ and outputs $\text{ID}$ values that are paired with every single course in $\text{cs\_courses}$.

**(b) Expression using fundamental relational algebra operators:**

Here $R = (\text{ID}, \text{course\_id})$, $S = (\text{course\_id})$, and $R - S = (\text{ID})$:

$$
\Pi_{\text{ID}}(\text{takes}) - \Pi_{\text{ID}}\left(\left(\Pi_{\text{ID}}(\text{takes}) \times \text{cs\_courses}\right) - \Pi_{\text{ID}, \text{course\_id}}(\text{takes})\right)
$$

*Step-by-step breakdown:*
1. $\Pi_{\text{ID}}(\text{takes})$ gets all candidate student IDs who have taken at least one course.
2. $\Pi_{\text{ID}}(\text{takes}) \times \text{cs\_courses}$ generates all ideal `(student ID, CS course ID)` pairs.
3. Subtracting actual enrollments $\Pi_{\text{ID}, \text{course\_id}}(\text{takes})$ leaves only the missing `(student ID, CS course ID)` pairs that a student failed to take.
4. Applying $\Pi_{\text{ID}}$ to those missing pairs lists all disqualified students who missed at least one CS course.
5. Subtracting those disqualified students from $\Pi_{\text{ID}}(\text{takes})$ leaves only the students who took every CS course.

## ⚡ Exam Tips & Common Mistakes

1. **Match the number of variables on the left of the bar:** In DRC, the tuple vector $\langle x_1, \dots, x_k \rangle$ on the left of $\mid$ must match the exact number of columns in the output. For $\pi_A(r_1)$, write $\langle a \rangle$, not $\langle a, b, c \rangle$.
2. **Never leave projected-out columns unquantified:** Writing $\{\, \langle a \rangle \mid \langle a, b, c \rangle \in r_1 \,\}$ without $\exists b, c$ is a classic syntax mistake because $b$ and $c$ are left unbound. Always write $\exists b, c \; (\langle a, b, c \rangle \in r_1)$.
3. **Do not mix up TRC and DRC notation:**
   - TRC uses one row variable: $\{\, t \mid t \in r_1 \land t[A] = 10 \,\}$
   - DRC uses individual column variables: $\{\, \langle a, b, c \rangle \mid \langle a, b, c \rangle \in r_1 \land a = 10 \,\}$
4. **Watch the subtraction order in division:** In the expansion of $r \div s$, always subtract $\text{Candidates} - \text{Disqualified}$, and inside the parentheses always subtract $\text{Ideal} - r$.
5. **Use both braces and angle brackets in DRC:** Wrap the outer set in curly braces $\{\,\dots\,\}$ and the tuple of domain variables in angle brackets $\langle\dots\rangle$.
