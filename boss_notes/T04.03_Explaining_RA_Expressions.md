# T04.3: Explaining Relational Algebra Expressions in Words

> **Topic:** T04 — Relational Algebra & Calculus | **Priority:** 🟢 | **Exam Frequency:** 1/7 finals (+ CT-01) (4 marks final + 4 marks CT)
> **Sources:** Silberschatz 7e Ch. 2 (§2.6) · Lecture Deck 02 (Slides 15–24) · Classnote by Raidah (Pages 13–14)

## Why This Topic Matters

Most relational algebra problems give you an English question and ask you to write the formula, whereas this subtopic tests the reverse skill: reading a mathematical expression and explaining what it does in plain English. This appeared in both 2021 Q.2(c) and CT-01 Q.05. Examiners award full marks when you break down the inner filters, point out the join keys, and state the real-world meaning of the final result instead of just reading the Greek letters out loud.

---

## 📝 Key Definitions

> **Relational Algebra:** "The relational algebra consists of a set of operations that take one or two relations as input and produce a new relation as their result." — Silberschatz, Korth & Sudarshan, *Database System Concepts* (7th Ed.), §2.6 (p. 48)

> **Select Operation:** "The select operation selects tuples that satisfy a given predicate. We use the lowercase Greek letter sigma ($\sigma$) to denote selection. The predicate appears as a subscript to $\sigma$." — Silberschatz, Korth & Sudarshan, *Database System Concepts* (7th Ed.), §2.6.1 (p. 49)

> **Project Operation:** "The project operation is a unary operation that returns its argument relation, with certain attributes left out. Since a relation is a set, any duplicate rows are eliminated. Projection is denoted by the uppercase Greek letter pi ($\Pi$)." — Silberschatz, Korth & Sudarshan, *Database System Concepts* (7th Ed.), §2.6.2 (p. 49)

> **Natural Join:** "The *natural join* operation replaces the predicate $\theta$ in $\bowtie_\theta$ with an implicit predicate that requires equality over those attributes that appear in the schemas of both the left and right relations." — Silberschatz, Korth & Sudarshan, *Database System Concepts* (7th Ed.), §2.6.8 (Note 2.1, p. 57)

> **Set-Difference Operation:** "The set-difference operation, denoted by $-$, allows us to find tuples that are in one relation but are not in another. The expression $r - s$ produces a relation containing those tuples in $r$ but not in $s$." — Silberschatz, Korth & Sudarshan, *Database System Concepts* (7th Ed.), §2.6.6 (p. 55)

## The Three-Step Translation Method

### Intuitive Analogy: Why We Read from the Inside Out

Think of a relational algebra expression like nested parentheses in high-school algebra, such as $f(g(x))$. You cannot evaluate the outer function $f$ until you know what the inner function $g(x)$ produces. In the same way, every relational algebra formula is a pipeline of tables: the innermost parentheses filter or combine raw tables first, and the outermost operator shapes the final columns you see on screen.

When an exam question gives you a formula and asks you to "explain in words what the expression does", follow this three-step blueprint:

1. **Step 1: Start from the innermost parentheses.** Identify the base tables and any immediate row filters ($\sigma$) or column projections ($\Pi$) applied to them, then state the exact filter condition.
2. **Step 2: Explain how the tables are combined.** Describe whether the intermediate tables are connected by a Cartesian product ($\times$), a theta join ($\bowtie_\theta$), a natural join ($\bowtie$), or a set operation ($\cup, \cap, -$). For any join, name the exact linking attribute.
3. **Step 3: State the final columns and real-world meaning.** Name the attributes kept by the outermost projection ($\Pi$), mention that duplicate rows are automatically removed, and summarize the whole query in one natural English sentence.

### Operator Translation Vocabulary

| Operator | Mathematical Symbol | Exact Mechanical Action | English Translation Pattern |
| :--- | :---: | :--- | :--- |
| **Selection** | $\sigma_P(r)$ | Filters rows that satisfy predicate $P$. | "Selects rows from $r$ where condition $P$ holds." |
| **Projection** | $\Pi_L(r)$ | Keeps only the columns in list $L$ and removes duplicates. | "Lists unique values of columns $L$ for the matching records." |
| **Natural Join** | $r \bowtie s$ | Matches rows that share identical values on common column names. | "Pairs each record in $r$ with its matching record in $s$." |
| **Theta Join** | $r \bowtie_\theta s$ | Pairs rows from $r$ and $s$ that satisfy condition $\theta$. | "Combines records from $r$ and $s$ where condition $\theta$ is met." |
| **Set Difference** | $r - s$ | Keeps tuples present in $r$ but absent from $s$. | "Finds items in $r$ that do not appear in $s$." |
| **Union** | $r \cup s$ | Combines rows from two compatible tables without duplicates. | "Finds items that appear in $r$, in $s$, or in both." |
| **Intersection** | $r \cap s$ | Keeps only rows that appear in both tables at the same time. | "Finds items that appear in both $r$ and $s$." |

## Walkthrough of Core Exam Patterns

Let us see how the three-step method works on four common algebraic patterns using university and banking relations.

### Pattern A: Inner Selection Followed by Natural Join

Suppose we have `instructor(ID, name, dept_name, salary)` and `teaches(ID, course_id, sec_id, semester, year)`, and we want to explain:

$$
\sigma_{\text{salary} > 80000}(\text{instructor}) \bowtie \text{teaches}
$$

1. **Inner Selection:** The inner part $\sigma_{\text{salary} > 80000}(\text{instructor})$ scans the `instructor` table and keeps only rows where `salary` is strictly greater than 80,000.
2. **Natural Join:** Next, the $\bowtie$ operator matches each high-earning instructor with their teaching records in `teaches` using the common attribute `ID` (`instructor.ID = teaches.ID`).
3. **Output Relation:** Because there is no outer $\Pi$ operator, the result keeps all columns from both tables (`ID`, `name`, `dept_name`, `salary`, `course_id`, `sec_id`, `semester`, `year`).
4. **Plain English Meaning:** "Finds the full personal profile and course-teaching records of all instructors who earn more than \$80,000."

### Pattern B: Natural Join Followed by Outer Projection

Now consider what happens when we wrap a join inside a projection:

$$
\Pi_{\text{name}, \text{course\_id}}(\text{instructor} \bowtie \text{teaches})
$$

1. **Natural Join:** First, $\text{instructor} \bowtie \text{teaches}$ pairs every instructor with the course sections they have taught by matching on `ID`.
2. **Outer Projection:** Then, $\Pi_{\text{name}, \text{course\_id}}$ keeps only the instructor's `name` and the `course_id`, dropping all other columns like salary, department, semester, and year.
3. **Duplicate Removal:** Because relational algebra treats every table as a mathematical set, any duplicate `(name, course_id)` pairs are automatically removed if an instructor taught the same course in multiple semesters.
4. **Plain English Meaning:** "Lists each instructor's name alongside the unique course IDs they have taught."

### Pattern C: Theta Join with Selection and Projection

When two tables do not share the same column name (or when we want to make the join condition explicit), we use a theta join ($\bowtie_\theta$):

$$
\Pi_{\text{dept\_name}} \left(\sigma_{\text{budget} > 100000} \left(\text{department} \bowtie_{\text{department.dept\_name} = \text{course.dept\_name}} \text{course}\right)\right)
$$

1. **Theta Join:** The inner join links each department record in `department` with its offered courses in `course` wherever `dept_name` matches.
2. **Selection:** The filter $\sigma_{\text{budget} > 100000}$ keeps only rows belonging to departments whose budget exceeds 100,000.
3. **Projection:** Finally, $\Pi_{\text{dept\_name}}$ extracts just the unique department names.
4. **Plain English Meaning:** "Finds the names of all departments with a budget over \$100,000 that offer at least one course."

### Pattern D: Set Difference Between Two Projections

A very common slide and class-test pattern subtracts one projected set from another (Lecture Deck 02, Slide 24):

$$
\Pi_{\text{course\_id}} \left(\sigma_{\text{semester} = \text{"Fall"} \land \text{year} = 2017} (\text{section})\right) - \Pi_{\text{course\_id}} \left(\sigma_{\text{semester} = \text{"Spring"} \land \text{year} = 2018} (\text{section})\right)
$$

1. **First Set ($S_1$):** Selects all sections offered in Fall 2017 and projects their unique `course_id` values.
2. **Second Set ($S_2$):** Selects all sections offered in Spring 2018 and projects their unique `course_id` values.
3. **Set Difference ($-$):** Computes $S_1 - S_2$, which keeps every `course_id` present in Fall 2017 but removes any course that was also taught in Spring 2018.
4. **Plain English Meaning:** "Finds all courses offered in the Fall 2017 semester that were not offered in the Spring 2018 semester."

The sample tables from Lecture Deck 02 (Slide 21) show how this subtraction works on actual rows:

#### Fall 2017 Courses ($S_1$)
| course_id |
| :--- |
| CS-101 |
| CS-347 |
| PHY-101 |

#### Spring 2018 Courses ($S_2$)
| course_id |
| :--- |
| CS-101 |
| CS-315 |
| CS-319 |
| FIN-201 |
| HIS-351 |
| MU-199 |

#### Difference ($S_1 - S_2$)
| course_id |
| :--- |
| CS-347 |
| PHY-101 |

Notice that `CS-101` appears in both semesters, so the set difference removes it from the final output.

## Worked Mini-Example

Before tackling the past exam questions below, try tracing this banking expression on `depositor(customer_name, account_number)` and `account(account_number, branch_name, balance)`:

$$
\Pi_{\text{customer\_name}}\left(\sigma_{\text{branch\_name} = \text{"Motijheel"} \land \text{balance} > 50000}(\text{account}) \bowtie \text{depositor}\right)
$$

- **Step 1 (Inner Filter):** $\sigma_{\text{branch\_name} = \text{"Motijheel"} \land \text{balance} > 50000}(\text{account})$ filters the `account` table to keep only accounts at the Motijheel branch with a balance above 50,000.
- **Step 2 (Join):** The natural join ($\bowtie$) matches those filtered accounts with `depositor` on the shared attribute `account_number`.
- **Step 3 (Outer Projection & Summary):** $\Pi_{\text{customer\_name}}$ keeps only the unique customer names. In plain English, the expression **finds the names of all customers who hold an account with a balance over 50,000 at the Motijheel branch**.

## 🏆 Golden Questions (Past Exam Archive)

### 🎯 GQ1 · 2021 Q.2(c) · Explaining Takes and Student Expressions

> **Appeared:** 2021 Q.2(c) — (04 Marks | Sec A | CLO2)

> **Question:**
>
> For each expression, explain in words what the expression does.  
> Where takes(<u>id</u>, <u>course</u>, <u>sec_id</u>, sem, year, grade)  
> (i) $\sigma_{year \ge 2009}(\text{takes}) \bowtie \text{student}$  
> (ii) $\Pi_{id, name, course\_id}(\text{student} \bowtie \text{takes})$

**Full Answer:**

**(i) Expression:** $\sigma_{year \ge 2009}(\text{takes}) \bowtie \text{student}$

1. **Selection:** The inner expression $\sigma_{year \ge 2009}(\text{takes})$ filters the `takes` relation and keeps only tuples where the `year` attribute is 2009 or later.
2. **Natural Join:** Next, the $\bowtie$ operator combines those filtered `takes` tuples with matching tuples in the `student` relation on their shared attribute `id` (`takes.id = student.id`).
3. **Result Attributes:** Because no projection is applied at the end, the resulting relation keeps all attributes from both schemas: `id`, `name`, `dept_name`, `tot_cred`, `course` (or `course_id`), `sec_id`, `sem`, `year`, and `grade`.
4. **Summary in Words:** Retrieves the complete personal and course-enrollment records of all students who took at least one course in the year 2009 or later.

**(ii) Expression:** $\Pi_{id, name, course\_id}(\text{student} \bowtie \text{takes})$

1. **Natural Join:** The inner expression $\text{student} \bowtie \text{takes}$ pairs each student tuple with their course enrollment tuples by matching equal `id` values.
2. **Projection:** The outer operator $\Pi_{id, name, course\_id}$ extracts only three columns: the student ID (`id`), student name (`name`), and course identifier (`course_id` / `course`), discarding all other columns such as department, credits, section, semester, year, and grade.
3. **Duplicate Elimination:** Because projection produces a mathematical set, any duplicate `(id, name, course_id)` rows are automatically removed.
4. **Summary in Words:** Produces a list of student IDs, names, and the courses they have taken, showing each unique student-course enrollment pair once.

### 🎯 GQ2 · CT-01 Q.05(iii–iv) · Explaining Theta-Join and Set Difference Expressions

> **Appeared:** CT-01 Q.05(iii–iv) — (04 Marks | CO1)

> **Question:**
>
> Describe the following relational algebra expression:  
> **(iii)** $\Pi_{\text{Name}} \left(\sigma_{\text{Marks} < 50} \left(\text{STUDENT} \bowtie_{\text{STUDENT.Student\_ID} = \text{COURSE.Student\_ID}} \text{COURSE}\right)\right)$  
> **(iv)** $\Pi_{\text{course\_id}} \left(\sigma_{\text{semester} = \text{"Fall"} \land \text{year} = 2017} (\text{section})\right) - \Pi_{\text{course\_id}} \left(\sigma_{\text{semester} = \text{"Spring"} \land \text{year} = 2018} (\text{section})\right)$  
> *(Note: Sub-parts are numbered iii, iv on the original question script; part iv is Deck 02 Slide 24 verbatim).*

**Full Answer:**

**(iii) Expression:** $\Pi_{\text{Name}} \left(\sigma_{\text{Marks} < 50} \left(\text{STUDENT} \bowtie_{\text{STUDENT.Student\_ID} = \text{COURSE.Student\_ID}} \text{COURSE}\right)\right)$

1. **Theta Join:** The inner expression $\text{STUDENT} \bowtie_{\text{STUDENT.Student\_ID} = \text{COURSE.Student\_ID}} \text{COURSE}$ links tuples from `STUDENT` and `COURSE` wherever `Student_ID` matches, pairing each student with their enrolled courses and marks.
2. **Selection:** Next, $\sigma_{\text{Marks} < 50}$ filters the joined table so that only rows where the student scored strictly below 50 marks remain.
3. **Projection:** The outermost operator $\Pi_{\text{Name}}$ keeps only the `Name` column, drops all other columns, and removes any duplicate names.
4. **Summary in Words:** Finds the names of all students who scored less than 50 marks in at least one course.

**(iv) Expression:** $\Pi_{\text{course\_id}} \left(\sigma_{\text{semester} = \text{"Fall"} \land \text{year} = 2017} (\text{section})\right) - \Pi_{\text{course\_id}} \left(\sigma_{\text{semester} = \text{"Spring"} \land \text{year} = 2018} (\text{section})\right)$

1. **First Term:** The left expression $\Pi_{\text{course\_id}} \left(\sigma_{\text{semester} = \text{"Fall"} \land \text{year} = 2017} (\text{section})\right)$ selects all sections offered in Fall 2017 and extracts their unique `course_id` values.
2. **Second Term:** The right expression $\Pi_{\text{course\_id}} \left(\sigma_{\text{semester} = \text{"Spring"} \land \text{year} = 2018} (\text{section})\right)$ selects all sections offered in Spring 2018 and extracts their unique `course_id` values.
3. **Set Difference ($-$):** The minus operator removes any course ID present in the second set from the first set.
4. **Summary in Words:** Finds all courses taught in the Fall 2017 semester that were not taught in the Spring 2018 semester.

## ⚡ Exam Tips & Common Mistakes

1. **Never call set difference arithmetic subtraction:** The $-$ symbol in relational algebra is set difference, not numeric subtraction. Instead of writing "subtracts course numbers", write "finds records in the first set that do not appear in the second set".
2. **Always mention duplicate removal on $\Pi$:** Projection ($\Pi$) returns a mathematical set, which means duplicate rows are automatically eliminated. Mentioning this explicitly shows the examiner you understand set semantics.
3. **Name the implicit join attribute:** Whenever you explain a natural join ($\bowtie$), explicitly name the shared attribute that links the two tables (such as `id` or `Student_ID`).
4. **Keep rows and columns straight:** Remember that $\sigma$ filters horizontal rows based on a condition, while $\Pi$ keeps vertical columns.
5. **Use a clean 3-bullet structure on exam scripts:**
   - What the inner operation filters.
   - How the join or set operator combines the tables.
   - A one-sentence plain-English summary of the final output.
