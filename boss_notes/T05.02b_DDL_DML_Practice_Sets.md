# T05.2b: SQL DDL & DML Practice Sets

> **Topic:** T05 — SQL (DDL, DML, Aggregates, Subqueries) | **Priority:** 🔴 | **Exam Frequency:** 6/7 finals (Part b: 2019 Q5c, 2021 Q3a, 2023 Q3a — 16 marks total)

## Why This Topic Matters

Beyond student-grade tables, RUET finals love giving you real-world business schemas: a Covid-19 hospital registry (2019 Q.5(c)), an e-commerce store (2021 Q.3(a)), and a corporate employee directory (2023 Q.3(a)). Together, these three questions are worth 16 marks. They test whether you know what order to create multi-table schemas in, how to handle printing typos or missing columns on an exam script, and how to write updates, deletions, computed columns, and correlated subqueries.

## 📝 Key Definitions

> **Update Statement:** "In certain situations, we may wish to change a value in a tuple without changing all values in the tuple. For this purpose, the update statement can be used. As we could for insert and delete, we can choose the tuples to be updated by using a query." — Silberschatz, Korth & Sudarshan, *Database System Concepts* (7th Ed.), §3.9.3 (p. 111)

> **Delete Statement:** "A delete request is expressed in much the same way as a query. We can delete only whole tuples; we cannot delete values on only particular attributes... The delete statement first finds all tuples $t$ in $r$ for which $P(t)$ is true, and then deletes them from $r$." — Silberschatz, Korth & Sudarshan, *Database System Concepts* (7th Ed.), §3.9.1 (p. 108)

> **Alter Table Statement:** "We use the alter table command to add attributes to an existing relation. All tuples in the relation are assigned null as the value for the new attribute... We can drop attributes from a relation by the command alter table $r$ drop $A$." — Silberschatz, Korth & Sudarshan, *Database System Concepts* (7th Ed.), §3.2.2 (p. 71)

> **Correlated Subquery:** "A subquery that uses a correlation name from an outer query is called a correlated subquery." — Silberschatz, Korth & Sudarshan, *Database System Concepts* (7th Ed.), §3.8.3 (p. 101)

## Multi-Table Schema Design Rules

When an exam question gives you three related tables and asks you to write `CREATE TABLE` statements for all of them, keep three practical rules in mind:

### 1. Create Parent Tables Before Child Tables
A child table with a `FOREIGN KEY` cannot point to a parent table that does not exist yet! Always create your independent master table first:
1. First, create the parent table (such as `Patient` with `Patient_ID PRIMARY KEY`).
2. Next, create the dependent tables (such as `History` and `Report`) that reference `Patient(Patient_ID)`.

### 2. Spot Event-History Tables That Need a Composite Primary Key
In a hospital or banking database, distinguish between a **master profile table** and an **event log table**:
- A master table like `Patient(Patient_ID, Patient_name, Mobile)` stores one row per person, so `Patient_ID` alone is the primary key.
- An event table like `History(Patient_ID, Symptom, Date)` records multiple symptoms for the same patient across different days. If you made `Patient_ID` the sole primary key of `History`, a patient could only ever record one symptom in their entire life! Instead, make `(Patient_ID, Symptom, Date)` a **composite primary key**, while still declaring `Patient_ID` as a foreign key pointing back to `Patient`.

### 3. How to Handle Exam Question Typos and Missing Columns
Past RUET exam papers occasionally contain small printing slips: for example, 2019 Q.5(c) prints `Parient_ID` instead of `Patient_ID`, and 2023 Q.3(a) asks for a salary comparison in part (iii) after omitting `Salary` from the column list in part (i). Whenever you spot a typo or missing column on an exam paper, write a one-line **Assumption** note above your SQL code:
> *Assumption: "Parient_ID" is a printing typo for "Patient_ID" and references `Patient(Patient_ID)`.*

Writing a clear assumption protects your marks no matter which way the grader's rubric leans.

## Four Essential Maintenance Patterns

Before solving the full 8-mark e-commerce problem in the Golden Questions below, let us review the four core table-maintenance patterns on a mini `book_store` table:

### Pattern 1: Targeted Row Update (`UPDATE ... SET ... WHERE`)
To change a column value for one specific record, filter by its primary key in the `WHERE` clause:

```sql
UPDATE book_store
SET branch_city = 'Rajshahi'
WHERE store_id = 'S105';
```

Never forget the `WHERE` clause! Leaving it off updates every row in the table.

### Pattern 2: Deleting Rows by Condition (`DELETE FROM ... WHERE`)
To remove all rows that match a condition while leaving the rest of the table untouched:

```sql
DELETE FROM staff
WHERE monthly_wage = 25000;
```

### Pattern 3: Adding a Fixed-Length Numeric Column (`ALTER TABLE ... ADD`)
When a question asks for a `numeric` column of a specific size (such as an 11-digit phone number), pass the digit count inside `NUMERIC(n)`:

```sql
ALTER TABLE customer
ADD phone_no NUMERIC(11);
```

### Pattern 4: Computed Columns with `AS` Aliasing
You can perform arithmetic directly inside the `SELECT` list and give the calculated column a clean header name using `AS`:

```sql
SELECT item_id,
       title,
       unit_price,
       unit_price * 1.15 AS taxed_price
FROM inventory
WHERE unit_price > 200;
```

## How Correlated Subqueries Work (2023 Q.3(a)(iii))

### Intuition: Why a Plain Subquery Fails for "Own Department" Comparisons

Suppose a question asks: *"Find employees whose salary is greater than the average salary of **their own** department."*

If you write a plain (uncorrelated) subquery:

```sql
-- WRONG: Compares everyone against the single company-wide average!
SELECT *
FROM Employee
WHERE Salary > (SELECT AVG(Salary) FROM Employee);
```

The inner `SELECT AVG(Salary)` runs just once and computes one global average across the entire company. That means a well-paid HR employee might get excluded just because IT salaries are higher overall!

Instead, we need the inner query to recalculate the average **specifically for the department of whichever employee the outer query is currently checking**. We do that with a **correlated subquery**, giving the outer table an alias (`e1`), the inner table an alias (`e2`), and linking them with `WHERE e2.Department = e1.Department`:

```sql
SELECT *
FROM Employee e1
WHERE e1.Salary > (
    SELECT AVG(e2.Salary)
    FROM Employee e2
    WHERE e2.Department = e1.Department
);
```

### Step-by-Step Row Trace

Watch how the database evaluates that correlated query row by row on a 4-employee table:

| EmpID | Name | Department | Salary |
| :---: | :--- | :--- | :---: |
| 1 | Nafisa | HR | 45,000 |
| 2 | Tariq | HR | 35,000 |
| 3 | Sifat | IT | 60,000 |
| 4 | Anika | IT | 70,000 |

1. **Row 1 (`e1` = Nafisa, `Department = 'HR'`, `Salary = 45,000`):**
   - The inner query plugs in `e1.Department = 'HR'` and calculates the HR average: $\frac{45,000 + 35,000}{2} = 40,000$.
   - Outer check: Is $45,000 > 40,000$? **TRUE** -> **Nafisa is kept.**
2. **Row 2 (`e1` = Tariq, `Department = 'HR'`, `Salary = 35,000`):**
   - The HR average is $40,000$.
   - Outer check: Is $35,000 > 40,000$? **FALSE** -> Tariq is skipped.
3. **Row 3 (`e1` = Sifat, `Department = 'IT'`, `Salary = 60,000`):**
   - Now `e1.Department` is `'IT'`, so the inner query calculates the IT average: $\frac{60,000 + 70,000}{2} = 65,000$.
   - Outer check: Is $60,000 > 65,000$? **FALSE** -> Sifat is skipped (even though 60,000 is above the company-wide average of 52,500!).
4. **Row 4 (`e1` = Anika, `Department = 'IT'`, `Salary = 70,000`):**
   - The IT average is $65,000$.
   - Outer check: Is $70,000 > 65,000$? **TRUE** -> **Anika is kept.**

## 🏆 Golden Questions (Past Exam Archive)

### 🎯 GQ1 · 2019 Q.5(c) · Covid Registry Table Creation

> **Appeared:** 2019 Q.5(c) — (02 marks)

> **Question:**
>
> Write down the SQL queries to create the following tables.  
> `Patient (Patient_ID, Patient_name, Mobile)`  
> `History (Patient_ID, Symptom, Date)`  
> `Report (Parient_ID, Corona_center, Test_result)`
>
> *(Note: Printed as "SQI." and "Parient_ID" in original question paper)*

**Full Answer:**

#### Schema Analysis and Assumptions
1. `Patient` is the master parent table, so we create it first with `Patient_ID` as its primary key.
2. Because a patient can log multiple symptoms across different dates in `History`, we use `(Patient_ID, Symptom, Date)` as a composite primary key.
3. *Assumption:* `Parient_ID` in `Report` is a printing misprint for `Patient_ID` and references `Patient(Patient_ID)`.

#### SQL DDL Statements

```sql
-- 1. Master Patient Table
CREATE TABLE Patient (
    Patient_ID INT PRIMARY KEY,
    Patient_name VARCHAR(50),
    Mobile VARCHAR(15)
);

-- 2. History Table with Composite Key and Foreign Key
CREATE TABLE History (
    Patient_ID INT,
    Symptom VARCHAR(50),
    Date DATE,
    PRIMARY KEY (Patient_ID, Symptom, Date),
    FOREIGN KEY (Patient_ID) REFERENCES Patient(Patient_ID)
);

-- 3. Report Table
CREATE TABLE Report (
    Patient_ID INT PRIMARY KEY,
    Corona_center VARCHAR(50),
    Test_result VARCHAR(20),
    FOREIGN KEY (Patient_ID) REFERENCES Patient(Patient_ID)
);
```

### 🎯 GQ2 · 2021 Q.3(a) · E-Commerce Database Maintenance Drills

> **Appeared:** 2021 Q.3(a) — (08 marks)

> **Question:**
>
> Consider the following E-comerce database:  
>   client (<u>c_no</u>, name, city, state, baldue)  
>   product (<u>p_no</u>, description, profit_percent, quantity, sell_price, cost_price)  
>   salesman (<u>s_no</u>, name, city, state, sal_amount, target, sold_yearly, remarks)
>
> Now write the appropriate MySql code to execute the following query:  
> (i) Change the city of client no "C0005" to "Barishal".  
> (ii) Delete all salesmen whose salaries are equal to 35000 Tk.  
> (iii) Add a column called "Telephone" of datatype numeric and size = '11' to the client table.  
> (iv) Find products whose selling price is more than 500. Calculate a new selling price as original price*15. Rename the new column in the output as new_price.
>
> *(Note: "E-comerce" and "MySql" printed verbatim from original question paper)*
>
> *(Sorting Note: Part iv uses `AS` column rename, cross-ref T05.3)*

**Full Answer:**

#### (i) Change the city of client no "C0005" to "Barishal"

Update the `city` column for the row matching primary key `c_no = 'C0005'`:

```sql
UPDATE client
SET city = 'Barishal'
WHERE c_no = 'C0005';
```

#### (ii) Delete all salesmen whose salaries are equal to 35000 Tk

In the given `salesman` schema, the salary column is named `sal_amount`:

```sql
DELETE FROM salesman
WHERE sal_amount = 35000;
```

#### (iii) Add column "Telephone" of datatype numeric and size 11 to client table

Use `ALTER TABLE ... ADD` with `NUMERIC(11)`:

```sql
ALTER TABLE client
ADD Telephone NUMERIC(11);
```

#### (iv) Find products with sell_price > 500, calculate price * 15, and rename as new_price

Filter rows with `WHERE sell_price > 500`, compute `sell_price * 15`, and alias the column as `new_price`:

```sql
SELECT p_no,
       description,
       sell_price,
       sell_price * 15 AS new_price
FROM product
WHERE sell_price > 500;
```

### 🎯 GQ3 · 2023 Q.3(a) · Employee DDL, Insertion, and Correlated Subquery

> **Appeared:** 2023 Q.3(a) — (06 marks)

> **Question:**
>
> Write SQL queries for the following:  
> (i) Create a table "Employee" with attributes: EmpID (primary key), Name, Age and Department.  
> (ii) Insert a record into this table: EmpID=1, Name='Nafisa', Age=21, department='HR'.  
> (iii) Find employees whose salary is greater than the average salary of their department.
>
> *(Sorting Note: Part iii is a correlated subquery, cross-ref T05.6)*

**Full Answer:**

#### (i) Create table Employee

```sql
CREATE TABLE Employee (
    EmpID INT PRIMARY KEY,
    Name VARCHAR(50),
    Age INT,
    Department VARCHAR(30)
);
```

#### (ii) Insert record into Employee

```sql
INSERT INTO Employee (EmpID, Name, Age, Department)
VALUES (1, 'Nafisa', 21, 'HR');
```

#### (iii) Find employees earning more than their departmental average

*Assumption:* Part (iii) queries an employee's salary, which was omitted from the attribute list in part (i). We assume `Employee` includes a column `Salary DECIMAL(10, 2)`.

We use a correlated subquery so each employee `e1` is compared against the average salary of their own department (`e2.Department = e1.Department`):

```sql
SELECT *
FROM Employee e1
WHERE e1.Salary > (
    SELECT AVG(e2.Salary)
    FROM Employee e2
    WHERE e2.Department = e1.Department
);
```

## ⚡ Exam Tips & Common Mistakes

1. **Always create parent tables first:** Write `CREATE TABLE Patient` before `History` or `Report` so the foreign keys point to a table that already exists.
2. **State a 1-line assumption if a column is missing:** In questions like 2023 Q.3(a)(iii), never leave a sub-question blank because `Salary` was left out of part (i). Write a brief assumption and provide the query.
3. **Use two aliases (`e1` and `e2`) in correlated subqueries:** Linking `WHERE e2.Department = e1.Department` is what makes the inner average recalculate per department instead of across the whole company.
4. **Match exact column names from the prompt:** In 2021 Q.3(a)(ii), the schema calls the column `sal_amount`, not `salary`. Always double-check the printed schema before writing `WHERE` conditions.
5. **Never write `DELETE * FROM`:** Always write `DELETE FROM salesman WHERE ...`.
