# T08.5: Canonical Cover of Functional Dependencies

> **Topic:** T08 — Normalization & Functional Dependencies | **Priority:** 🟢 | **Exam Frequency:** 1/7 finals (8 marks total: 2021 Q6a [3m] + 2021 Q6b [5m])
> **Sources:** Silberschatz 7e Ch. 7 (§7.4.3, pp. 324–328) · Lecture Deck 06 (Slide 4, Slide 14)

## Why This Topic Matters

Whenever a row is inserted or updated, the database engine has to check that no functional dependencies are broken. If your list of functional dependencies contains redundant rules or extra attributes, the database wastes time checking the same things over and over. A **canonical cover** ($F_c$) cleans up a functional dependency set into its smallest, simplest equivalent version without losing any rules. It is also the required first step for the 3NF synthesis algorithm, and RUET tested it for a full 8 marks on the 2021 semester final.

---

## 📝 Key Definitions

> **Functional Dependency:** A functional dependency $\alpha \rightarrow \beta$ on relation schema $R$ is a constraint stating that any two rows with the same value for $\alpha$ must also have the same value for $\beta$ ($t_1[\alpha] = t_2[\alpha] \implies t_1[\beta] = t_2[\beta]$).

> **Extraneous Attribute:** An attribute in a functional dependency $\alpha \rightarrow \beta$ is extraneous if we can remove it without changing the closure $F^+$ of the dependency set. On the left side, $A \in \alpha$ is extraneous if $(\alpha - \{A\}) \rightarrow \beta$ already holds in $F$. On the right side, $A \in \beta$ is extraneous if $\alpha \rightarrow A$ still holds after removing $A$ from $\beta$.

> **Canonical Cover ($F_c$):** A canonical cover $F_c$ is a minimal, simplified set of functional dependencies that is logically equivalent to $F$ ($F_c^+ = F^+$). It satisfies two strict rules:
> - No functional dependency in $F_c$ contains an extraneous attribute on either side.
> - Each left-hand side of a functional dependency in $F_c$ is unique.

---

## Extraneous Attributes and How to Test Them

An attribute inside a functional dependency is called **extraneous** if you can cross it out without changing the overall closure $F^+$ of the rule set. Because crossing out an attribute on the left side does the opposite of crossing out an attribute on the right side, we test them in two slightly different ways.

### 1. Removing an Attribute from the Left-Hand Side (LHS)

**Why the LHS rule works:** Think about what happens when you drop $B$ from $AB \rightarrow C$ to get $A \rightarrow C$. The new rule $A \rightarrow C$ is actually a *stronger* statement (it says $A$ alone is enough to determine $C$, without needing $B$'s help). Because $A \rightarrow C$ automatically implies the old $AB \rightarrow C$ by augmentation, the only thing we have to check is whether the rest of our rules already imply the stronger statement $A \rightarrow C$ (or whether $A$ alone already determines $B$).

**Formal Test for LHS:**  
Suppose $A \in \alpha$ in the dependency $\alpha \rightarrow \beta$. To test if $A$ is extraneous on the left:
1. Let $\gamma = \alpha - \{A\}$ be the left side without $A$.
2. Check if $\gamma \rightarrow \beta$ already holds under the **current set** $F_c$.
3. Do this by computing the attribute closure $\gamma^+$ using the current $F_c$.
4. If $\beta \subseteq \gamma^+$, then $A$ was dead weight (extraneous) in $\alpha$, so we replace $\alpha \rightarrow \beta$ with $(\alpha - \{A\}) \rightarrow \beta$.

### 2. Removing an Attribute from the Right-Hand Side (RHS)

**Why the RHS rule works:** Now think about dropping $C$ from the right side of $AB \rightarrow CD$ to leave $AB \rightarrow D$. That makes the rule *weaker*, because we are throwing away the claim that $AB \rightarrow C$. To make sure we haven't lost $AB \rightarrow C$ forever, we temporarily hide $C$ from that rule and check whether the *remaining* dependencies in our set can still derive $AB \rightarrow C$ on their own.

**Formal Test for RHS:**  
Suppose $A \in \beta$ in the dependency $\alpha \rightarrow \beta$. To test if $A$ is extraneous on the right:
1. Create a temporary modified set $F'$ by removing $A$ from the right side of that rule: $F' = (F_c - \{\alpha \rightarrow \beta\}) \cup \{\alpha \rightarrow (\beta - \{A\})\}$.
2. Check if $\alpha \rightarrow A$ can still be inferred from $F'$.
3. Do this by computing the closure $\alpha^+$ under the **reduced set** $F'$.
4. If $A \in \alpha^+$, then $A$ is extraneous on the right, so we permanently shrink the rule to $\alpha \rightarrow (\beta - \{A\})$.

## The Canonical Cover Algorithm ($F_c$)

```text
Fc := F;
repeat
    Use the union rule to replace any dependencies in Fc 
    of the form alpha1 -> beta1 and alpha1 -> beta2 with alpha1 -> beta1 beta2;
    
    Find a functional dependency alpha -> beta in Fc with an extraneous 
    attribute either in alpha or in beta;
    /* Note: the test for extraneous attributes is done using Fc, not F */
    
    if an extraneous attribute is found then
        delete it from alpha -> beta in Fc;
until (Fc does not change);
```

### Important Properties of Canonical Covers

1. **Equivalence:** $F_c^+ = F^+$. Any database satisfying $F_c$ also satisfies $F$, and vice versa.
2. **Left-hand side uniqueness:** Dependencies with identical left-hand sides are combined using the union rule.
3. **Empty RHS removal:** If removing an extraneous attribute leaves an empty right-hand side ($\alpha \rightarrow \emptyset$), delete the entire dependency.
4. **Multiple Canonical Covers:** A given set $F$ can have more than one valid canonical cover depending on the order of attribute tests. Any valid canonical cover is acceptable.

---

## Canonical Cover vs. Normalization

A common exam question asks to differentiate between normalization and canonical cover. The two concepts operate at different stages of database design:

| Feature / Parameter | Normalization | Canonical Cover ($F_c$) |
| :--- | :--- | :--- |
| **Core Definition** | The process of decomposing relation schemas to eliminate redundancy and update anomalies. | A minimal, non-redundant set of functional dependencies logically equivalent to the original set. |
| **Primary Goal** | Design high-integrity tables free of insertion, deletion, and update anomalies. | Simplify integrity constraints so that updates can be checked with minimal computational overhead. |
| **Input Data** | A relation schema $R$ along with its functional dependency set $F$. | A functional dependency set $F$. |
| **Output Data** | A set of decomposed relation schemas $\{R_1, R_2, \dots, R_k\}$ meeting a target normal form (3NF, BCNF). | A simplified functional dependency set $F_c$ with unique LHS and zero extraneous attributes. |
| **Level of Operation** | Schema design level (modifying table structures, columns, and foreign keys). | Mathematical constraint level (optimizing logical implications between attributes). |
| **Relationship** | Uses canonical cover as an intermediate step (e.g., in the 3NF synthesis algorithm). | Acts as a preparatory optimization step before schema synthesis and decomposition. |

## Worked Example: Step-by-Step Textbook Trace

Let $R(A, B, C)$ with the functional dependency set:
$$
F = \{A \rightarrow BC, \; B \rightarrow C, \; A \rightarrow B, \; AB \rightarrow C\}
$$

### Step 1: Apply the Union Rule on Identical LHS

Dependencies $A \rightarrow BC$ and $A \rightarrow B$ have the same left-hand side ($A$). Combine them using the union rule:
$$
F_c = \{A \rightarrow BC, \; B \rightarrow C, \; AB \rightarrow C\}
$$

### Step 2: Test for Extraneous Attributes on LHS

Consider dependency $AB \rightarrow C$. The LHS contains two attributes: $A$ and $B$.
- **Test attribute $A$ on LHS:**  
  Remove $A$, leaving $B \rightarrow C$. Compute $B^+$ under $F_c$:
  $$
  B^+ = \{B, C\}
  $$
  Because $C \in B^+$, attribute $A$ is extraneous in $AB \rightarrow C$.
  Deleting $A$ converts $AB \rightarrow C$ into $B \rightarrow C$.
- The set is now:
  $$
  F_c = \{A \rightarrow BC, \; B \rightarrow C, \; B \rightarrow C\}
  $$
- Remove the duplicate dependency $B \rightarrow C$:
  $$
  F_c = \{A \rightarrow BC, \; B \rightarrow C\}
  $$

### Step 3: Test for Extraneous Attributes on RHS

Consider dependency $A \rightarrow BC$. The RHS contains two attributes: $B$ and $C$.
- **Test attribute $C$ on RHS:**  
  Form the test set $F' = \{A \rightarrow B, \; B \rightarrow C\}$. Compute $A^+$ under $F'$:
  - Start: $\{A\}$
  - Apply $A \rightarrow B$: $\{A, B\}$
  - Apply $B \rightarrow C$: $\{A, B, C\}$
  - $A^+ = \{A, B, C\}$
  Because $C \in A^+$, attribute $C$ is extraneous in $A \rightarrow BC$.
  Deleting $C$ leaves $A \rightarrow B$.

### Step 4: Final Canonical Cover

The resulting set has unique left-hand sides and no extraneous attributes:
$$
F_c = \{A \rightarrow B, \; B \rightarrow C\}
$$

## 🏆 Golden Questions (Past Exam Archive)

### 🎯 GQ1 · 2021 Q.6(a) · Normalization vs. Canonical Cover

> **Appeared:** 2021 Q.6(a) — (03 Marks, Section B, CLO1)

**Question:**

Differentiate between normalization and canonical cover in DBMS.

**Full Answer:**

#### Comparison Table

| Parameter | Normalization | Canonical Cover ($F_c$) |
| :--- | :--- | :--- |
| **Definition** | The systematic decomposition of a relation schema into smaller schemas to eliminate anomalies and reduce data redundancy. | A minimal, non-redundant set of functional dependencies logically equivalent to the original functional dependency set. |
| **Primary Goal** | To design well-structured tables free of insertion, deletion, and update anomalies. | To simplify database integrity constraints so that runtime modification checks execute with minimal overhead. |
| **Input** | A relation schema $R$ and a functional dependency set $F$. | A functional dependency set $F$. |
| **Output** | A collection of decomposed relations $\{R_1, R_2, \dots, R_k\}$ in a desired normal form (such as 3NF or BCNF). | A simplified functional dependency set $F_c$ with unique left-hand sides and zero extraneous attributes. |
| **Operational Level** | Operates at the relational schema design level (table structure, attributes, keys). | Operates purely at the mathematical constraint level (simplifying functional dependencies). |

#### Complementary Nature

Canonical cover is not a substitute for normalization. Instead, database designers compute a canonical cover as an initial step. Algorithms like the 3NF synthesis algorithm require a canonical cover as input to synthesize minimal, dependency-preserving relations.

### 🎯 GQ2 · 2021 Q.6(b) · Functional Dependency Definition & Canonical Form

> **Appeared:** 2021 Q.6(b) — (05 Marks, Section B, CLO1)

**Question:**

Define Functional dependency. Consider the following functional dependency set:

  $\text{FD} = \{$  
    $A \to BC,$  
    $CD \to E,$  
    $B \to D,$  
    $E \to A$  
  $\}$

Find the canonical form of the FD set.

**Full Answer:**

#### 1. Definition of Functional Dependency

A **functional dependency** is a formal constraint between two sets of attributes in a relational database.

Let relation schema $R$ have attribute subsets $\alpha \subseteq R$ and $\beta \subseteq R$. The functional dependency:
$$
\alpha \rightarrow \beta
$$
holds on $R$ if, in every legal relation instance $r(R)$, whenever any two tuples $t_1$ and $t_2$ agree on all attributes of $\alpha$, they must also agree on all attributes of $\beta$:
$$
t_1[\alpha] = t_2[\alpha] \implies t_1[\beta] = t_2[\beta]
$$

We state that $\alpha$ functionally determines $\beta$, or that $\beta$ is functionally dependent on $\alpha$. The left-hand side $\alpha$ is called the **determinant**, and the right-hand side $\beta$ is called the **dependent**.

#### 2. Derivation of the Canonical Cover ($F_c$)

A canonical cover $F_c$ must satisfy two conditions:
1. No functional dependency contains an extraneous attribute (on the LHS or RHS).
2. Each left-hand side of a functional dependency in $F_c$ is unique.

The given set is:
$$
F = \{A \rightarrow BC, \; CD \rightarrow E, \; B \rightarrow D, \; E \rightarrow A\}
$$

**Step 1: Combine dependencies with identical left-hand sides**  
The left-hand sides of the dependencies are $A, CD, B,$ and $E$. All left-hand sides are distinct. The union rule does not apply.

**Step 2: Test for extraneous attributes**

1. **Examine $A \rightarrow BC$:**
   - **Test attribute $B$ (on RHS):**  
     Remove $B$ to form $F' = \{A \rightarrow C, \; CD \rightarrow E, \; B \rightarrow D, \; E \rightarrow A\}$.  
     Compute $A^+$ under $F'$:  
     Start with $\{A\}$. Using $A \rightarrow C$, we get $\{A, C\}$. No other dependency can be applied.  
     $A^+ = \{A, C\}$.  
     Because $B \notin A^+$, attribute $B$ is **not extraneous**.
   - **Test attribute $C$ (on RHS):**  
     Remove $C$ to form $F' = \{A \rightarrow B, \; CD \rightarrow E, \; B \rightarrow D, \; E \rightarrow A\}$.  
     Compute $A^+$ under $F'$:  
     Start with $\{A\}$. Using $A \rightarrow B$, we get $\{A, B\}$. Using $B \rightarrow D$, we get $\{A, B, D\}$. We cannot apply $CD \rightarrow E$ because $C$ is missing.  
     $A^+ = \{A, B, D\}$.  
     Because $C \notin A^+$, attribute $C$ is **not extraneous**.

2. **Examine $CD \rightarrow E$:**
   - **Test attribute $C$ (on LHS):**  
     Check if $D \rightarrow E$ holds under the current set $F$.  
     Compute $D^+$ under $F$: $D^+ = \{D\}$.  
     Because $E \notin D^+$, attribute $C$ is **not extraneous**.
   - **Test attribute $D$ (on LHS):**  
     Check if $C \rightarrow E$ holds under the current set $F$.  
     Compute $C^+$ under $F$: $C^+ = \{C\}$.  
     Because $E \notin C^+$, attribute $D$ is **not extraneous**.

3. **Examine $B \rightarrow D$:**  
   Both the LHS and RHS contain single attributes. Neither attribute can be removed without dropping the entire dependency. Attribute $D$ cannot be derived from $B$ without using $B \rightarrow D$. Thus, neither attribute is extraneous.

4. **Examine $E \rightarrow A$:**  
   Both the LHS and RHS contain single attributes. Neither attribute is extraneous.

**Step 3: Final Canonical Cover**  
Because no extraneous attributes exist and all left-hand sides are unique, the canonical cover is identical to the given set:

$$
\boxed{F_c = \{A \rightarrow BC, \; CD \rightarrow E, \; B \rightarrow D, \; E \rightarrow A\}}
$$

*(Note: In minimal cover form with singleton right-hand sides, the equivalent set is $\{A \rightarrow B, A \rightarrow C, CD \rightarrow E, B \rightarrow D, E \rightarrow A\}$. In the standard textbook definition of canonical cover, dependencies with the same left-hand side remain combined.)*

### 🎯 HYE-01 · Exercise 7.14 · Non-Uniqueness of Canonical Covers

> **Source:** Silberschatz 7e · Chapter 7 (Exercise 7.14)  
> **Exam Relevance:** Prime Overdue Exam Drill (Theory & Calculation)  
> **Key Tested Concept:** Demonstrating that a set of functional dependencies can produce multiple distinct canonical covers.

**Problem Statement:**
> Show that a set of functional dependencies can have **more than one canonical cover** by finding two distinct canonical covers for the following set of dependencies on relation schema $R = (A, B, C)$:
> $$
> F = \{A \rightarrow BC, \; B \rightarrow AC, \; C \rightarrow AB\}
> $$

**Model Exam-Style Solution:**
1. **Decompose Right-Hand Sides to Singleton Form:**
   $$
   F_{\text{single}} = \{A \rightarrow B, \; A \rightarrow C, \; B \rightarrow A, \; B \rightarrow C, \; C \rightarrow A, \; C \rightarrow B\}
   $$
   Notice that all three attributes are mutually functionally equivalent: $A \leftrightarrow B \leftrightarrow C$.

2. **Finding Canonical Cover 1 ($F_{c1}$):**
   - Let us establish a directed cycle through the attributes: $A \rightarrow B \rightarrow C \rightarrow A$.
   - **Test extraneousness of $A \rightarrow C$:**
     - Using $\{A \rightarrow B, B \rightarrow C\}$, we compute $A^+ = \{A, B, C\}$.
     - Since $C \in A^+$ without $A \rightarrow C$, **$C$ is extraneous in $A \rightarrow BC$**.
   - **Test extraneousness of $B \rightarrow A$:**
     - Using $\{B \rightarrow C, C \rightarrow A\}$, we compute $B^+ = \{A, B, C\}$.
     - Since $A \in B^+$ without $B \rightarrow A$, **$A$ is extraneous in $B \rightarrow AC$**.
   - **Test extraneousness of $C \rightarrow B$:**
     - Using $\{C \rightarrow A, A \rightarrow B\}$, we compute $C^+ = \{A, B, C\}$.
     - Since $B \in C^+$ without $C \rightarrow B$, **$B$ is extraneous in $C \rightarrow AB$**.
   - **Resulting Set 1:**
     $$
     F_{c1} = \{A \rightarrow B, \; B \rightarrow C, \; C \rightarrow A\}
     $$
   - None of these three FDs is redundant (removing any breaks the cycle). Thus, $F_{c1}$ is a canonical cover.

3. **Finding Canonical Cover 2 ($F_{c2}$):**
   - Reverse the cycle direction: $A \rightarrow C \rightarrow B \rightarrow A$.
   - In this case, test and eliminate $A \rightarrow B$, $B \rightarrow C$, and $C \rightarrow A$:
     - $A \rightarrow B$ is implied by $A \rightarrow C$ and $C \rightarrow B$.
     - $C \rightarrow A$ is implied by $C \rightarrow B$ and $B \rightarrow A$.
     - $B \rightarrow C$ is implied by $B \rightarrow A$ and $A \rightarrow C$.
   - **Resulting Set 2:**
     $$
     F_{c2} = \{A \rightarrow C, \; C \rightarrow B, \; B \rightarrow A\}
     $$
   - Both $F_{c1}$ and $F_{c2}$ have the same closure ($F_{c1}^+ = F_{c2}^+ = F^+$) and contain no extraneous attributes, but $F_{c1} \neq F_{c2}$.

4. **Conclusion:**
   A set of functional dependencies does **not** necessarily have a unique canonical cover. $\blacksquare$

**💡 RUET Exam Takeaway:**
Whenever full mutual equivalence exists ($A \leftrightarrow B \leftrightarrow C$), alternating the cycle elimination order proves the non-uniqueness of canonical covers in 4 lines.

## ⚡ Exam Tips & Common Mistakes

1. **LHS test vs. RHS test direction:**  
   - For an attribute $A$ on the LHS of $\alpha \rightarrow \beta$, compute the closure of $(\alpha - \{A\})$ using the **current set** $F_c$.
   - For an attribute $A$ on the RHS of $\alpha \rightarrow \beta$, compute the closure of $\alpha$ using the **reduced set** $F' = (F_c - \{\alpha \rightarrow \beta\}) \cup \{\alpha \rightarrow (\beta - \{A\})\}$.
2. **Do not remove both mutually extraneous attributes:** If testing shows that attribute $B$ is extraneous when keeping $C$, and attribute $C$ is extraneous when keeping $B$, you must pick one and delete it. Never delete both.
3. **Merge identical left-hand sides:** Silberschatz defines canonical covers with combined right-hand sides for identical determinants (e.g., $A \rightarrow BC$ rather than $A \rightarrow B$ and $A \rightarrow C$). Keep them merged in your final answer.
4. **Show test closures explicitly:** Even if no attribute is extraneous (as in 2021 Q.6(b)), showing each closure calculation proves complete algorithmic mastery to the examiner.
