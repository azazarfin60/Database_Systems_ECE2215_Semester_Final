# T05.7b: Multi-Table SQL Query Sets — Insurance and E-Commerce

> **Topic:** T05 — SQL (DDL, DML, Aggregates, Subqueries) | **Priority:** 🔴 | **Exam Frequency:** 5/7 finals (26 marks in this half, Rank #1 Subtopic)  
> **Sources:** Silberschatz 7e Ch. 3 (§3.4, §3.9; Exercises 3.4 & 3.14) · Lecture Deck 03 (Slides 12–61) · Fahim Notes (p. 58)

## Why This Topic Matters

This note covers two classic multi-table database schemas that appear again and again on RUET finals. First, the Silberschatz Insurance database showed up in 2020 Q.7(b) for 8 marks and returned word-for-word in 2024 Q.5(b) for 6 marks. Second, the 2021 Q.4(a) exam featured a 12-mark, 5-table E-commerce database. Together, these problems test whether you can trace foreign-key paths across multiple tables, update records through joins, find missing items using anti-joins, and avoid MySQL reserved-keyword traps.

## 📝 Key Definitions

> **Relational Database Management System (RDBMS):** "An **RDBMS (Relational Database Management System)** is a database management software based on the relational model of data. It stores information in tables (relations) of rows and columns, enforces data integrity using keys and constraints, and provides a structured declarative query language (SQL) for retrieval and manipulation." — *(Course definition / Silberschatz 7e §1.3)*

> **SQL UPDATE Statement:** "In certain situations, we may wish to change a value in a tuple without changing all values in the tuple. For this purpose, the **update** statement can be used." — Silberschatz, Korth & Sudarshan, *Database System Concepts* (7th Ed.), §3.9.3 (p. 111)

> **SQL INSERT Statement:** "To insert data into a relation, we either specify a tuple to be inserted or write a query whose result is a set of tuples to be inserted." — Silberschatz, Korth & Sudarshan, *Database System Concepts* (7th Ed.), §3.9.2 (p. 110)

> **Anti-Join (Set Difference in SQL):** A query pattern that returns rows from one table that have no matching rows in a second table. In SQL, you write an anti-join using `NOT IN`, `NOT EXISTS`, or a `LEFT JOIN` paired with an `IS NULL` filter.

## Architectural Mechanics: The Insurance Database Schema

The Insurance schema comes directly from Silberschatz Exercises 3.4 and 3.14:

```text
Person (driver_id, name, address)
Car (license, model, year)
Accident (report_no, date, location)
Owner (driver_id, license)
Participated (driver_id, report_no, car, damage_amount)
```

### The Driver vs. Owner Relationship Trap

In real life, the person driving a car during an accident is not always the person who owns the car. For example, a friend might borrow your car and get into a fender-bender. Because of this, the schema has two completely different join paths connecting a `Person` to `Participated`:

```text
Path 1 (Ownership — whose car was in the crash?):
[Person] ──(driver_id = driver_id)── [Owner] ──(license = car)── [Participated]

Path 2 (Driving — who was behind the wheel?):
[Person] ──(driver_id = driver_id)── [Participated]
```

When an exam question asks for "accidents in which the cars **belonging to** a person were involved," you must follow **Path 1 (Ownership)**:
- If you join `Person.driver_id = Participated.driver_id`, you only find accidents where that person was driving. If someone else was driving their car, you miss the accident completely!
- Instead, link `Person` to `Owner` (`Person.driver_id = Owner.driver_id`), and then link the car's license plate to the accident participation record (`Owner.license = Participated.car`).
- Wrap `p.report_no` inside `COUNT(DISTINCT p.report_no)` so that if two of the owner's cars were involved in the same crash, you count that accident only once.

```sql
/* Mini-Example: Count distinct accidents involving cars owned by 'Rahim' */
SELECT COUNT(DISTINCT p.report_no) AS accident_count
FROM Participated p
JOIN Owner o ON p.car = o.license
JOIN Person per ON o.driver_id = per.driver_id
WHERE per.name = 'Rahim';
```

## Data Modification Patterns: INSERT and Multi-Table UPDATE

### 1. Adding a New Row (`INSERT`)

To insert a single record into a table like `Accident(report_no, date, location)`, list the target columns and supply matching values in the `VALUES` clause:

```sql
INSERT INTO Accident (report_no, date, location)
VALUES ('AR-105', '2024-05-20', 'Kazla Gate');
```

### 2. Updating Records Across Joined Tables

Sometimes you need to update a table (`Car`), but the filter condition lives in another table (`Person.name`). Also, if an exam prompt says something vague like *"Update the car 'Mazda' belonging to 'John'"* without saying *which* column to change, always write a brief assumption on your answer script (such as updating the car's `year` or `model`) before writing the SQL query.

You can write a multi-table update in two ways:

#### Approach A: MySQL Multi-Table UPDATE Syntax
MySQL lets you write `JOIN` clauses directly inside the `UPDATE` statement before the `SET` clause:

```sql
/* Mini-Example: Update the model year of Karim's Honda to 2023 */
UPDATE Car c
JOIN Owner o ON c.license = o.license
JOIN Person p ON o.driver_id = p.driver_id
SET c.year = 2023
WHERE p.name = 'Karim'
  AND c.model = 'Honda';
```

#### Approach B: Standard SQL Subquery Syntax
In standard SQL (which works across all database engines), you keep `UPDATE Car` simple and filter `license` using an `IN` subquery:

```sql
UPDATE Car
SET year = 2023
WHERE model = 'Honda'
  AND license IN (
      SELECT o.license
      FROM Owner o
      JOIN Person p ON o.driver_id = p.driver_id
      WHERE p.name = 'Karim'
  );
```

### 3. Updating with Composite Keys

In `Participated(driver_id, report_no, car, damage_amount)`, a car can appear in multiple accidents, and a single accident can involve multiple cars. Because of this, updating a specific damage amount requires filtering on **both** the `car` license number and the `report_no` in your `WHERE` clause:

```sql
UPDATE Participated
SET damage_amount = 5000
WHERE car = 'DHK-400'
  AND report_no = 'AR-105';
```

## Architectural Mechanics: The E-Commerce Database Schema

The 2021 Q.4(a) exam paper introduces a 5-table commercial sales database:

```text
client (c_no, name, city, state, Baldue)
product (p_no, description, profit_percent, quantity, sell_price, cost_price)
salesman (s_no, name, city, state, sal_amount, target, sold_yearly, remarks)
order (order_no, client_no, order_date, delivery_address, salesman_no, del_type, del_date, order_status)
order_details (order_no, product_no, quantity_ordered, product_rate)
```

### The MySQL Reserved Keyword Collision: `order`

In SQL, `ORDER` is a built-in keyword used for sorting (`ORDER BY`). Because of this, writing `FROM order` confuses the SQL parser and triggers a syntax error in MySQL. Whenever a table is named `order`, wrap the name in backticks like `` `order` `` so MySQL knows it is a table name and not a sorting clause.

### Sales Revenue Aggregation Pattern

Notice how line-item sales are stored in `order_details(order_no, product_no, quantity_ordered, product_rate)`. A single row only gives the quantity and rate for *one* order. To calculate the total revenue brought in by each product across *all* orders:
1. Multiply the quantity by the unit price for each line item: `od.quantity_ordered * od.product_rate`.
2. Wrap that expression inside `SUM(...)` and group the rows by product (`GROUP BY od.product_no, p.description`).

## Anti-Join Mechanics: Identifying Unsold Products

Suppose you have a master catalog of all products in `product`, and a record of every sale in `order_details`. How do you find products that have **never** been sold?

Intuitively, this is simple set subtraction ($\text{All Products} - \text{Sold Products}$). An `INNER JOIN` between `product` and `order_details` will fail completely here, because an inner join only keeps products that match at least one row in `order_details`. Unsold products have zero rows in `order_details`, so an inner join throws them away!

Instead, use one of these three anti-join patterns:

### Method 1: The `NOT IN` Subquery
First, run a subquery to get the list of all `product_no` values that appear in `order_details`. Then, tell the outer query to pick products whose `p_no` is **not** on that list:

```sql
SELECT p_no, description
FROM product
WHERE p_no NOT IN (
    SELECT DISTINCT product_no
    FROM order_details
);
```

### Method 2: The `NOT EXISTS` Correlated Subquery
For each row in `product`, check whether `order_details` has any matching row for that product. Keep the product only if no match exists:

```sql
SELECT p.p_no, p.description
FROM product p
WHERE NOT EXISTS (
    SELECT 1
    FROM order_details od
    WHERE od.product_no = p.p_no
);
```

### Method 3: `LEFT JOIN` with an `IS NULL` Filter
A `LEFT JOIN` keeps every product from the `product` table, filling in `NULL` for the `order_details` columns whenever a product has never been ordered. Filtering with `WHERE od.product_no IS NULL` isolates those exact unsold products:

```sql
SELECT p.p_no, p.description
FROM product p
LEFT JOIN order_details od ON p.p_no = od.product_no
WHERE od.product_no IS NULL;
```

## Worked Example: Anti-Join Evaluation Trace

Let's trace Method 1 (`NOT IN`) step by step on a small 3-product catalog:

### Given `product` Table:

| p_no | description |
| :--- | :--- |
| P101 | Laptop |
| P102 | Wireless Mouse |
| P103 | Mechanical Keyboard |

### Given `order_details` Table:

| order_no | product_no | quantity_ordered |
| :--- | :--- | :---: |
| ORD-01 | P101 | 2 |
| ORD-02 | P101 | 1 |
| ORD-03 | P103 | 5 |

### Evaluation Steps:
1. **Run the inner subquery first:**  
   `SELECT DISTINCT product_no FROM order_details` scans the sales records and returns the set of sold items: $\{\text{'P101'}, \text{'P103'}\}$.
2. **Filter the outer `product` table using `WHERE p_no NOT IN ('P101', 'P103')`:**
   - **Row 1 (`P101`):** Is `'P101'` not in `('P101', 'P103')`? **FALSE**, so `P101` is dropped.
   - **Row 2 (`P102`):** Is `'P102'` not in `('P101', 'P103')`? **TRUE**, so `P102` is kept!
   - **Row 3 (`P103`):** Is `'P103'` not in `('P101', 'P103')`? **FALSE**, so `P103` is dropped.
3. **Final Output:** Only the unsold product `(P102, 'Wireless Mouse')` is returned.

### 🎯 GQ1 · 2020 Q.7(b) · Insurance Database and RDMS Definition

> **Appeared:** 2020 Q.7(b) — (8 marks) · Directly based on Silberschatz 7e Exercise 3.4 & 3.14

**Question:**

Define RDMS. Consider the following insurance database where the primary keys are underlined.  
  Person(<u>driver_id</u>, name, address)  
  Car(<u>license</u>, model, year)  
  Accident(<u>report_no</u>, date, location)  
  Owner(driver_id, license)  
  Participated(driver_id, report_no, car, damage_amount)  
Write MySQL for the following queries-  
(i) Find the number of accidents in which the cars belonging to "John Smith" were involved.  
(ii) Add a new accident to the database, assuming any values for required attributes.  
(iii) Update the car "Mazda" belonging to "John".  
(iv) Update the damage amounts \$3000 for the car with license number "YJK-100" in the accident with report number "APR2197".  
*(Note: Printed as "RDMS" in original question paper; refers to "RDBMS")*

**Full Answer:**

#### 1. Definition of RDBMS (2020 Paper):
An **RDBMS (Relational Database Management System)** is a database management system based on the relational data model introduced by E.F. Codd. It organizes data into two-dimensional tables (relations) consisting of rows (tuples) and columns (attributes), enforces data integrity through constraints (primary keys, foreign keys, domain checks), and provides a declarative query language (SQL) for data definition, manipulation, and transaction control.

#### 2. Query Solutions (2020 Paper):

**(i) Number of accidents involving cars owned by "John Smith":**
```sql
SELECT COUNT(DISTINCT p.report_no) AS accident_count
FROM Participated p
JOIN Owner o ON p.car = o.license
JOIN Person per ON o.driver_id = per.driver_id
WHERE per.name = 'John Smith';
```

**(ii) Add a new accident with sample values:**
```sql
INSERT INTO Accident (report_no, date, location)
VALUES ('AR-2024-01', '2024-10-15', 'Dhaka-Rajshahi Highway');
```

**(iii) Update the car "Mazda" belonging to "John":**  
*Assumption: The query updates the manufacturing year of John's Mazda to 2022.*

```sql
UPDATE Car c
JOIN Owner o ON c.license = o.license
JOIN Person p ON o.driver_id = p.driver_id
SET c.year = 2022
WHERE p.name = 'John'
  AND c.model = 'Mazda';
```

*(Alternative standard SQL subquery syntax:*
```sql
UPDATE Car
SET year = 2022
WHERE model = 'Mazda'
  AND license IN (
      SELECT o.license
      FROM Owner o
      JOIN Person p ON o.driver_id = p.driver_id
      WHERE p.name = 'John'
  );
```
*)*

**(iv) Update damage amount to \$3,000 for car "YJK-100" in accident "APR2197":**
```sql
UPDATE Participated
SET damage_amount = 3000
WHERE car = 'YJK-100'
  AND report_no = 'APR2197';
```

### 🎯 GQ3 · 2021 Q.4(a) · E-Commerce Database Schema Queries

> **Appeared:** 2021 Q.4(a) — (12 marks)

**Question:**

Consider the following E-comerce database:  
  client (<u>c_no</u>, name, city, state, Baldue)  
  product (<u>p_no</u>, description, profit_percent, quantity, sell_price, cost_price)  
  salesman (<u>s_no</u>, name, city, state, sal_amount, target, sold_yearly, remarks)  
  order (<u>order_no</u>, client_no, order_date, delivery_address, salesman_no, del_type, del_date, order_status)  
  order_details (<u>order_no</u>, product_no, quantity_ordered, product_rate)

(i) Find the total value of each product sold.  
(ii) Find the products and their quantities for the orders placed by client no "C0001" and "C0002".  
(iii) Find the product no and description of the products not being sold.  
(iv) Find if the product "Lyera Top" has been ordered by any client and print the client_no, name to whom it was sold.

*(Note: "E-comerce" and "Lyera Top" printed verbatim from original question paper)*

**Full Answer:**

#### (i) Total value of each product sold:
```sql
SELECT od.product_no,
       p.description,
       SUM(od.quantity_ordered * od.product_rate) AS total_value
FROM order_details od
JOIN product p ON od.product_no = p.p_no
GROUP BY od.product_no, p.description;
```

#### (ii) Products and quantities ordered by client "C0001" and "C0002":
```sql
SELECT o.client_no,
       od.product_no,
       p.description,
       od.quantity_ordered
FROM `order` o
JOIN order_details od ON o.order_no = od.order_no
JOIN product p ON od.product_no = p.p_no
WHERE o.client_no IN ('C0001', 'C0002');
```
*(Note: The table name `` `order` `` is enclosed in backticks because `ORDER` is a reserved keyword in MySQL).*

#### (iii) Product number and description of products not being sold:
```sql
SELECT p_no, description
FROM product
WHERE p_no NOT IN (
    SELECT DISTINCT product_no
    FROM order_details
);
```

*(Alternative using `NOT EXISTS`:*
```sql
SELECT p.p_no, p.description
FROM product p
WHERE NOT EXISTS (
    SELECT 1
    FROM order_details od
    WHERE od.product_no = p.p_no
);
```
*)*

#### (iv) Check if "Lyera Top" was ordered and display client number and name:
```sql
SELECT DISTINCT c.c_no, c.name
FROM client c
JOIN `order` o ON c.c_no = o.client_no
JOIN order_details od ON o.order_no = od.order_no
JOIN product p ON od.product_no = p.p_no
WHERE p.description = 'Lyera Top';
```

## ⚡ Exam Tips & Common Mistakes

1. **Escape Reserved Keyword `order`:** In MySQL, writing `FROM order` causes a fatal syntax error. Always write ``FROM `order` `` using backticks.
2. **Driver vs. Owner Join Path:** In the Insurance schema, do not join `Participated.driver_id = Person.driver_id` when the question asks for cars *belonging* to a person. Join through `Owner.license = Participated.car`.
3. **Always Supply an Assumption for Ambiguous UPDATEs:** In 2020 Q.7(b)(iii), the prompt does not name the attribute to update. Write an explicit note (e.g., `SET c.year = 2022`) to ensure full marks.
4. **Anti-Joins Require Subqueries or Outer Joins:** Never use an `INNER JOIN` to find unsold products. An inner join discards unsold records. Use `NOT IN` or `NOT EXISTS`.
5. **Preserve Exact String Literals:** The 2021 question paper prints "Lyera Top". Keep this exact spelling in your `WHERE` condition.
