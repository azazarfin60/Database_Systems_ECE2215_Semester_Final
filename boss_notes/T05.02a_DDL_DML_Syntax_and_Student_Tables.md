# T05.2a: SQL DDL & DML Syntax and Student Table Drills

> **Topic:** T05 — SQL (DDL, DML, Aggregates, Subqueries) | **Priority:** 🔴 | **Exam Frequency:** 6/7 finals (+ CT-02) (33 marks total for T05.2)
> **Sources:** Silberschatz 7e Ch. 3 (§3.2, §3.9) · Lecture Deck 03 (Slides 5–11, 53–61) · Raidah Notes (pp. 5–7) · Fahim Notes (pp. 33–39, 45–50)

## Why This Topic Matters

Writing `CREATE TABLE`, `ALTER TABLE`, `INSERT`, `UPDATE`, `DELETE`, and basic `SELECT` queries is the bread and butter of SQL exams. In RUET semester finals, subtopic T05.2 appears in 6 out of 7 papers for a total of 33 marks. Examiners love testing student-record schemas where you have to spot a composite primary key from underlined attributes, add a new column with `ALTER TABLE`, filter students by department or roll number, and compute weighted CGPA.

---

## 📝 Key Definitions

> **Data-Definition Language (DDL):** DDL is the part of SQL that defines and modifies database schemas using commands like `CREATE TABLE`, `ALTER TABLE`, and `DROP TABLE`. For each table, DDL specifies column names, data types, integrity constraints, indexes, and storage structure.

> **Primary Key:** A primary key is a column or set of columns that uniquely identifies every row in a table. Primary key columns must be unique and cannot contain `NULL` values. A table can have at most one primary key.

> **Foreign Key:** A foreign key is a column or set of columns in a child table whose values must match the primary key values of a parent table. It links the two tables together and enforces referential integrity across the database.

> **Data-Manipulation Language (DML):** DML is the part of SQL used to retrieve and modify rows inside existing tables. It uses `SELECT` to query rows, `INSERT` to add new rows, `UPDATE` to change existing values, and `DELETE` to remove rows.

## Complete MySQL 8 DDL Guide

Data Definition Language (DDL) statements build, change, and remove the tables themselves rather than individual rows.

### 1. Choosing the Right Data Type

When an exam gives you a list of column names without types (like `student(roll, name, dept)`), you have to pick sensible SQL data types for each column:

| SQL Data Type | Storage & Meaning | Best Exam Use Case |
| :--- | :--- | :--- |
| `INT` / `INTEGER` | 4-byte whole number ($-2^{31}$ to $2^{31}-1$). | Student roll numbers, employee IDs, counts. |
| `SMALLINT` | 2-byte whole number ($-32,768$ to $32,767$). | Semesters, ages, small counters. |
| `BIGINT` | 8-byte whole number. | Large serial numbers or transaction IDs. |
| `DECIMAL(p, d)` / `NUMERIC(p, d)` | Exact decimal with $p$ total digits and $d$ digits after the dot. | GPAs and CGPAs (`DECIMAL(3, 2)`), credit hours, salaries. |
| `FLOAT` / `DOUBLE` | Approximate floating-point number. | Scientific measurements. |
| `CHAR(n)` | Fixed-length text of exactly $n$ characters. | Fixed-length codes or short abbreviations (`CHAR(3)`). |
| `VARCHAR(n)` | Variable-length text up to $n$ characters. | Names, departments, emails, course codes. |
| `DATE` | Calendar date (`YYYY-MM-DD`). | Birth dates, admission dates, exam dates. |
| `TIME` | Clock time (`HH:MM:SS`). | Class start times. |

### 2. Creating Tables (`CREATE TABLE`)

The general template for `CREATE TABLE` lists each column and its type, followed by any table-level key constraints:

```sql
CREATE TABLE relation_name (
    attribute1 datatype [column_constraint],
    attribute2 datatype [column_constraint],
    ...,
    [table_level_constraints]
);
```

#### Inline vs. Composite Primary Keys

If a table's primary key is just **one column**, you can write `PRIMARY KEY` right next to that column's data type. However, if **two or more columns are underlined** in the exam question (such as `(roll, sub_code)` or `(roll, Dept)`), they form a **composite primary key**. In SQL, you cannot write `PRIMARY KEY` inline on two separate columns, because the database will reject the second `PRIMARY KEY` keyword as an error! Instead, always declare a composite primary key on its own line at the bottom of `CREATE TABLE`:

```sql
-- Single-column primary key (inline is fine):
CREATE TABLE Department (
    dept_name VARCHAR(20) PRIMARY KEY,
    building VARCHAR(30)
);

-- Composite primary key (MUST be declared at table level):
CREATE TABLE Enrollment (
    roll INT,
    course_id VARCHAR(10),
    grade VARCHAR(2),
    PRIMARY KEY (roll, course_id)
);
```

#### Foreign Keys and Referential Actions

A foreign key ensures that a value in a child table (like `roll` in `MARKS`) must already exist in the parent table (`INFO`):

```sql
CREATE TABLE MARKS (
    roll INT,
    sub_code VARCHAR(20),
    gpa DECIMAL(3, 2),
    PRIMARY KEY (roll, sub_code),
    FOREIGN KEY (roll) REFERENCES INFO(roll)
        ON DELETE CASCADE
        ON UPDATE CASCADE,
    FOREIGN KEY (sub_code) REFERENCES CREDIT(sub_code)
);
```

What happens if someone deletes or updates a row in the parent table? You can control that behavior with three optional clauses:
- `ON DELETE CASCADE`: Deleting the parent row automatically deletes all matching child rows.
- `ON DELETE SET NULL`: Deleting the parent row sets the child's foreign key column to `NULL`.
- `ON DELETE RESTRICT` (the default): Blocks the parent deletion if any child rows still point to it.

#### Useful Column Constraints

- `NOT NULL`: Forbids leaving the column blank (`NULL`).
- `UNIQUE`: Ensures no two rows have the same value in this column.
- `DEFAULT <value>`: Fills in a fallback value automatically if an `INSERT` omits this column.
- `CHECK (<condition>)`: Rejects any row where the condition is false (for example, keeping `cgpa` between `0.00` and `4.00`).

```sql
CREATE TABLE Student (
    roll INT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    dept VARCHAR(20) DEFAULT 'ECE',
    cgpa DECIMAL(3, 2) CHECK (cgpa >= 0.00 AND cgpa <= 4.00)
);
```

### 3. Modifying Existing Tables (`ALTER TABLE`)

When an exam asks you to "Modify the `student` table to add `session`", you must use `ALTER TABLE` so you update the schema without wiping out the data already inside the table:

```sql
-- 1. Add a brand-new column (most common exam question!):
ALTER TABLE student
ADD session VARCHAR(10);

-- 2. Remove an existing column:
ALTER TABLE student
DROP COLUMN session;

-- 3. Change an existing column's data type or constraints:
ALTER TABLE student
MODIFY name VARCHAR(100) NOT NULL;

-- 4. Rename an existing column (MySQL 8):
ALTER TABLE student
RENAME COLUMN dept TO department;

-- 5. Rename the table itself:
ALTER TABLE student
RENAME TO ruet_student;
```

When you add a new column with `ALTER TABLE ... ADD`, any rows that were already in the table automatically get `NULL` in that new column (unless you also specify a `DEFAULT` value).

### 4. Removing Tables vs. Removing Rows: `DROP`, `TRUNCATE`, and `DELETE`

Make sure you never mix up these three removal commands on an exam:

```sql
-- DROP (DDL): Completely destroys the table structure AND all its data
DROP TABLE student;

-- TRUNCATE (DDL): Empties all rows instantly by resetting storage pages, but keeps the empty table structure
TRUNCATE TABLE student;

-- DELETE (DML): Deletes rows one by one (optionally filtered by WHERE) and can be undone with ROLLBACK
DELETE FROM student;
```

## Complete MySQL 8 DML Guide

Once your tables are created, Data Manipulation Language (DML) commands let you insert, update, delete, and query the rows inside them.

### 1. Inserting Rows (`INSERT INTO`)

You can insert a row either by supplying values for every column in order, or by naming the columns explicitly:

```sql
-- Positional insert (values must match the exact column order of the table):
INSERT INTO student
VALUES (1810001, 'Rahim', 'ECE');

-- Explicit column list (safer and clearer on exams):
INSERT INTO student (roll, name, dept)
VALUES (1810001, 'Rahim', 'ECE');

-- Inserting multiple rows in one command:
INSERT INTO student (roll, name, dept)
VALUES
    (1810002, 'Karim', 'ECE'),
    (1810003, 'Tanvir', 'CSE');

-- Inserting rows copied from a SELECT query:
INSERT INTO ece_honors (roll, name)
SELECT roll, name
FROM student
WHERE dept = 'ECE';
```

### 2. Updating Rows (`UPDATE`)

Use `UPDATE ... SET ... WHERE` to change column values in existing rows:

```sql
UPDATE student
SET dept = 'ECE'
WHERE roll = 1810001;
```

> [!NOTE]
> In MySQL Workbench labs, `Safe Updates` mode is turned on by default and blocks any `UPDATE` or `DELETE` that does not filter by a primary key in its `WHERE` clause. If you ever need to turn that check off during a lab, run `SET SQL_SAFE_UPDATES = 0;`.

### 3. Deleting Rows (`DELETE FROM`)

Use `DELETE FROM` with a `WHERE` clause to remove specific rows, or without a `WHERE` clause to empty the table row by row:

```sql
-- Delete only Civil department students:
DELETE FROM student
WHERE dept = 'Civil';

-- Delete all rows while keeping the table schema intact:
DELETE FROM student;
```

Watch out for a classic syntax trap: **never write `DELETE * FROM student`**. Unlike `SELECT *`, `DELETE` deletes whole rows and never takes an asterisk (`*`).

### 4. Selecting Rows (`SELECT`)

The basic query block projects columns in `SELECT`, names the table in `FROM`, and filters rows in `WHERE`:

```sql
SELECT roll, name
FROM student
WHERE dept = 'ECE';
```

## Intuition: Why Weighted CGPA Needs a Join and `SUM`, Not `AVG`

Before looking at 2017 Q.4(a) in the Golden Questions below, let us see why you cannot compute a student's CGPA using `AVG(gpa)`. Suppose a student takes a 3.00-credit theory course (`CSE 2101`) and a 1.50-credit lab course (`CSE 2102`):

| student_id | course_code | gpa | credit |
| :---: | :--- | :---: | :---: |
| 101 | CSE 2101 | 4.00 | 3.00 |
| 101 | CSE 2102 | 3.00 | 1.50 |

- A simple unweighted average gives $\frac{4.00 + 3.00}{2} = 3.50$, which treats a 1.50-credit lab as if it had the exact same weight as a 3.00-credit theory course!
- Instead, university CGPA multiplies each course's GPA by its credit weight first, adds those weighted points up, and divides by the total credits:

$$
\text{CGPA} = \frac{\sum (\text{gpa} \times \text{credit})}{\sum \text{credit}} = \frac{(4.00 \times 3.00) + (3.00 \times 1.50)}{3.00 + 1.50} = \frac{16.50}{4.50} = 3.67
$$

In SQL, that formula translates directly into `SUM(m.gpa * c.credit) / SUM(c.credit)` after joining the marks table with the course-credit table and grouping by student!

### 🎯 GQ1 · 2017 Q.4(a) · University Student Marks and CGPA Calculation

> **Appeared:** 2017 Q.4(a) — (09 marks)

> **Question:**
>
> Considering following tables (INFO, MARKS, CREDIT) answer (i),(ii) & (iii).
>
> <table style="border: none; border-collapse: collapse;"><tr style="border: none; vertical-align: top;"><td style="border: none; padding-right: 15px;"><b>INFO</b><br><table border="1" style="border-collapse: collapse;"><thead><tr><th>roll</th><th>name</th></tr></thead><tbody><tr><td>1710001</td><td>Amelia</td></tr><tr><td>1710002</td><td>Oliver</td></tr><tr><td>1710003</td><td>James</td></tr><tr><td>1710004</td><td>Sansa</td></tr></tbody></table></td><td style="border: none; padding-right: 15px;"><b>MARKS</b><br><table border="1" style="border-collapse: collapse;"><thead><tr><th>roll</th><th>sub_code</th><th>gpa</th></tr></thead><tbody><tr><td>1710001</td><td>ECE 2205</td><td>3.50</td></tr><tr><td>1710001</td><td>ECE 2215</td><td>3.75</td></tr><tr><td>1710002</td><td>ECE 2205</td><td>3.75</td></tr><tr><td>1710002</td><td>ECE 2215</td><td>3.25</td></tr><tr><td>1710003</td><td>ECE 2205</td><td>4.00</td></tr><tr><td>1710003</td><td>ECE 2215</td><td>3.75</td></tr><tr><td>1710004</td><td>ECE 2205</td><td>3.50</td></tr><tr><td>1710004</td><td>ECE 2215</td><td>4.00</td></tr></tbody></table></td><td style="border: none; vertical-align: top;"><b>CREDIT</b><br><table border="1" style="border-collapse: collapse;"><thead><tr><th>sub_code</th><th>credit</th></tr></thead><tbody><tr><td>ECE 2205</td><td>3.00</td></tr><tr><td>ECE 2215</td><td>3.00</td></tr></tbody></table></td></tr></table>
>
> (i) Write down the SQL query to create the table MARKS.  
> (ii) Write down the SQL query to find out subject code and corresponding gpa of the student whose class serial 02.  
> (iii) Write the the SQL query to calculate the cgpa of each student using the formula, $cgpa = \frac{\Sigma gpa \cdot credit}{\Sigma credit}$
>
> *(Note: In the original printed question paper, Q.4 contains only sub-question (a) with 09 marks indicated in the margin, leaving a 3-mark deficit from the standard 12 marks).*
>
> *(Sorting Note: Part iii calculates CGPA, cross-ref T05.5)*

**Full Answer:**

#### (i) SQL query to create table MARKS

In the `MARKS` table, each student (`roll`) takes multiple subjects (`sub_code`), and each subject has multiple students. Because neither column is unique on its own, `(roll, sub_code)` forms a **composite primary key**. In addition, `roll` references `INFO(roll)` and `sub_code` references `CREDIT(sub_code)`:

```sql
CREATE TABLE MARKS (
    roll INT,
    sub_code VARCHAR(20),
    gpa DECIMAL(3, 2),
    PRIMARY KEY (roll, sub_code),
    FOREIGN KEY (roll) REFERENCES INFO(roll),
    FOREIGN KEY (sub_code) REFERENCES CREDIT(sub_code)
);
```

#### (ii) SQL query for student with class serial 02

In RUET roll numbers (such as `1710002`), the first two digits (`17`) are the series, the middle digits (`10`) are the department code, and the last three digits (`002`) are the student's class serial. Thus, class serial 02 corresponds to roll `1710002` (Oliver):

```sql
SELECT sub_code, gpa
FROM MARKS
WHERE roll = 1710002;
```

*(Alternative dynamic check using modulo if the series prefix is unknown:)*

```sql
SELECT sub_code, gpa
FROM MARKS
WHERE roll % 100 = 2;
```

#### (iii) SQL query to calculate CGPA of each student

We join `MARKS` and `CREDIT` on `sub_code`, group by `m.roll`, and divide the sum of `gpa * credit` by the sum of `credit`:

```sql
SELECT m.roll,
       SUM(m.gpa * c.credit) / SUM(c.credit) AS cgpa
FROM MARKS m
JOIN CREDIT c ON m.sub_code = c.sub_code
GROUP BY m.roll;
```

**Verification on the given table (for Oliver, `roll = 1710002`):**
- `ECE 2205`: $\text{gpa} = 3.75, \text{credit} = 3.00 \implies 3.75 \times 3.00 = 11.25$
- `ECE 2215`: $\text{gpa} = 3.25, \text{credit} = 3.00 \implies 3.25 \times 3.00 = 9.75$
- $\text{CGPA} = \frac{11.25 + 9.75}{3.00 + 3.00} = \frac{21.00}{6.00} = 3.50$

### 🎯 GQ2 · 2018 Q.7(a) = 2024 Q.4(b) · Student Table DDL, Insert, Alter, and Selection

> **Question (2018 Q.7(a)):**
>
> Write down the SQL queries for following operations.  
> (i) Create table for student (<u>roll</u>, Name, <u>Dept</u>)  
> (ii) Insert one example entry for student table  
> (iii) Modify the student table to student(<u>roll</u>, Name, dept, session)  
> (iv) Show the roll and name of the students of ECE department only.
>
> **Question (2024 Q.4(b)):**
>
> Write down the SQL queries for following operations:  
> i) Create table for student (<u>roll</u>, name, dept)  
> ii) Insert one example entry for student tbale  
> iii) Modify the student table to student (roll, name, dept, session)  
> iv) Show the roll and name of the students of ECE dept only.  
> *(Note: "tbale" printed verbatim in original paper; refers to table)*

**Full Answer:**

#### (i) Create student table

In 2018 Q.7(a), both `roll` and `Dept` are underlined, so we declare `(roll, dept)` as a composite primary key (in 2024 Q.4(b), only `roll` is underlined, so `roll INT PRIMARY KEY` is also accepted):

```sql
CREATE TABLE student (
    roll INT,
    name VARCHAR(50),
    dept VARCHAR(20),
    PRIMARY KEY (roll, dept)
);
```

#### (ii) Insert one example entry

```sql
INSERT INTO student (roll, name, dept)
VALUES (1810001, 'Rahim', 'ECE');
```

#### (iii) Modify student table to add session

Use `ALTER TABLE ... ADD` to append the new `session` column:

```sql
ALTER TABLE student
ADD session VARCHAR(10);
```

#### (iv) Show roll and name of ECE students only

```sql
SELECT roll, name
FROM student
WHERE dept = 'ECE';
```

## ⚡ Exam Tips & Common Mistakes

1. **Check for multiple underlined columns:** Whenever two or more columns are underlined (like `(roll, Dept)` or `(roll, sub_code)`), put `PRIMARY KEY (col1, col2)` at the bottom of `CREATE TABLE` instead of writing `PRIMARY KEY` beside individual columns.
2. **Use `ADD` (not `MODIFY`) to add a new column:** To add `session` to `student`, write `ALTER TABLE student ADD session VARCHAR(10);`. Only use `MODIFY` when changing the type of a column that already exists.
3. **Never write `DELETE * FROM`:** Always write `DELETE FROM table_name WHERE ...` without an asterisk.
4. **Never use `AVG(gpa)` for weighted CGPA:** Always multiply `SUM(gpa * credit) / SUM(credit)`.
5. **Wrap text strings in single quotes:** Write `'ECE'`, not `ECE`. Without single quotes, SQL thinks `ECE` is the name of a column!
