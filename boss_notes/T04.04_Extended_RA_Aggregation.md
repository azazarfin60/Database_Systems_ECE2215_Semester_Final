# T04.4: Extended Relational Algebra and Aggregation

> **Topic:** T04 — Relational Algebra & Calculus | **Priority:** 🟡 | **Exam Frequency:** 0/7 standalone finals (+ 5 query sub-questions across 2017, 2018, 2019, 2024, CT-01)
> **Sources:** Silberschatz 7e Ch. 3 (Note 3.2, pp. 97–98), Ch. 16 (§16.1–16.2, pp. 744–751) · Lecture Deck 02 (Slides 27–29) · Raidah Class Notes (T04, p. 14R)

## Why This Topic Matters

Basic relational algebra works purely on sets of rows, so it has no way to count tuples, add up salaries, or calculate averages. Extended relational algebra bridges this gap by introducing the aggregate operator ($\gamma$), which brings SQL-style `GROUP BY` and aggregate math into algebra. While RUET finals have never asked a standalone definition question on $\gamma$, five past exam queries (in 2017, 2018, 2019, 2024, and CT-01) require you to count rows or find a group maximum. If you know how $\gamma$ works, those multi-mark query parts become straightforward.

---

## 📝 Key Definitions

> **Aggregate Operation ($\gamma$):** The aggregate operation ($\gamma$ or $\mathcal{G}$) is an extended relational algebra operator that groups tuples and applies aggregate functions. Written as ${}_{G_1, G_2, \dots, G_n}\gamma_{F_1(A_1), \dots, F_m(A_m)}(E)$, it partitions the rows of expression $E$ by the grouping attributes $G_1, \dots, G_n$ and outputs one summary tuple per group containing the grouping attributes and the computed aggregate values $F_i(A_i)$. If the left subscript is omitted, the entire relation is treated as a single group.

> **Aggregate Functions:** Aggregate functions take a multiset (a collection that preserves duplicates) of values from a column and return a single summary value. The five standard aggregate functions are `avg` (average), `min` (minimum), `max` (maximum), `sum` (total sum), and `count` (number of values). Appending `-distinct` (such as `count-distinct`) removes duplicate values before computing the result.

---

## Intuition and Syntax of the Aggregate Operator ($\gamma$)

### Intuitive Analogy: A Two-Sided Bucket Machine

Why does the $\gamma$ operator have subscripts on both its left and right sides? Think of $\gamma$ as a two-step bucket machine:

- **Left subscript (the buckets):** The attributes written on the **left** of $\gamma$ tell the database how to sort rows into groups, working just like SQL's `GROUP BY` clause. If you leave the left side blank, all rows go into one big bucket.
- **Right subscript (the math):** The functions written on the **right** of $\gamma$ tell the database what summary number (`count`, `sum`, `avg`, `min`, or `max`) to calculate inside each bucket, just like the aggregate functions in SQL's `SELECT` list.

Also notice why aggregate functions work on a **multiset** (a bag that keeps duplicates) rather than a strict mathematical set: if two instructors in the same department both earn \$70,000, we must keep both \$70,000 values when summing or averaging their salaries!

### General Notation

We write the aggregate operator using the lowercase Greek letter gamma ($\gamma$) or script $\mathcal{G}$:

$$
{}_{G_1, G_2, \dots, G_n}\gamma_{F_1(A_1) \text{ as } B_1, \dots, F_m(A_m) \text{ as } B_m}(E)
$$

Here is what each piece means:
- $E$ is any relational algebra expression or table name.
- $G_1, G_2, \dots, G_n$ is an optional list of **grouping attributes** placed in the left subscript.
- $F_i$ is an **aggregate function** (`avg`, `min`, `max`, `sum`, `count`).
- $A_i$ is the column from $E$ being aggregated.
- $B_i$ is an optional alias name given to the new calculated column so outer operators can refer to it easily.

### 1. Global Aggregation (No Grouping)

When you leave the left subscript empty, the entire table is treated as a single group and the operation returns just one summary row.

- **Example 1: Average salary across all instructors:**

$$
\gamma_{\text{avg}(\text{salary})}(\text{instructor})
$$

- **Example 2: Total number of course sections taught in 2018:**

$$
\gamma_{\text{count}(\text{course\_id})}(\sigma_{\text{year} = 2018}(\text{section}))
$$

### 2. Grouped Aggregation (With Grouping Attributes)

When you list grouping attributes $G_1, \dots, G_n$ in the left subscript, $\gamma$ splits the rows into groups that share the same values on $G_1, \dots, G_n$ and computes the aggregate functions separately for each group.

- **Result Schema:** The output table contains the grouping columns followed by the newly computed aggregate columns:

$$
\text{Schema} = (G_1, G_2, \dots, G_n, B_1, B_2, \dots, B_m)
$$

- **Example: Average salary in each department:**

$$
{}_{\text{dept\_name}}\gamma_{\text{avg}(\text{salary}) \text{ as } \text{avg\_salary}}(\text{instructor})
$$

| dept_name | avg_salary |
| :--- | :--- |
| Biology | 72000 |
| Comp. Sci. | 77333 |
| Elec. Eng. | 80000 |
| Finance | 85000 |
| History | 61000 |
| Music | 40000 |
| Physics | 91000 |

### 3. Emulating SQL's `HAVING` Clause

In SQL, `HAVING` filters groups after aggregation. In relational algebra, you get the exact same effect by wrapping a selection operator ($\sigma$) around the outside of your $\gamma$ expression.

- **Example:** Find departments where the average instructor salary is above \$75,000:

$$
\sigma_{\text{avg\_salary} > 75000}\left({}_{\text{dept\_name}}\gamma_{\text{avg}(\text{salary}) \text{ as } \text{avg\_salary}}(\text{instructor})\right)
$$

### 4. The 3-Step Recipe for "Entity with the Maximum Count"

A classic RUET exam question asks you to find the item that achieves the highest count, such as the company with the most employees (2017 Q.2(a)(iv)) or the date with the most patients (2019 Q.2(b)(ii)). Because you cannot nest $\text{max}(\text{count}(\dots))$ inside a single $\gamma$ while still keeping the company name attached, we solve it in three clean steps:

1. **Step 1 (Group and Count):** Group by the entity and count rows into a temporary table $C$.
2. **Step 2 (Find the Peak Number):** Apply an ungrouped $\gamma_{\text{max}}$ on $C$ to find the highest count across all groups, saving that single number in $M$.
3. **Step 3 (Match the Winner):** Pair $C \times M$, use $\sigma$ to keep rows where `count = max_count`, and project the winning entity's name.

Below are complete step-by-step solutions for every RUET final and class-test question that uses $\gamma$.

---

### Drill 1 · 2017 Q.2(a)(iv) · Company with the Most Employees

**Exam Context:** 2017 Q.2(a) (08 marks total, 2 marks for part iv).  
**Schema Given:**  
- `employee(person_name, street, city)`  
- `works(person_name, company_name, salary)`  
- `company(company_name, city)`  
- `manages(person_name, manager_name)`  

**Question:**  
*(iv) Find the company with most employees.*

**Solution:**

1. **Count employees per company:** Group `works` by `company_name` and count how many employees work in each company:

$$
C \leftarrow {}_{\text{company\_name}}\gamma_{\text{count}(\text{person\_name}) \text{ as } \text{emp\_count}}(\text{works})
$$

2. **Find the highest employee count:** Take the maximum of `emp_count` across all companies:

$$
M \leftarrow \gamma_{\text{max}(\text{emp\_count}) \text{ as } \text{max\_count}}(C)
$$

3. **Keep the company (or companies) that hit that maximum:**

$$
\Pi_{\text{company\_name}}(\sigma_{\text{emp\_count} = \text{max\_count}}(C \times M))
$$

### Drill 2 · 2018 Q.3(a)(i–ii) · Insurance Accidents and Car Owners

**Exam Context:** 2018 Q.3(a) (06 marks total, 2 marks each for parts i and ii).  
**Schema Given:**  
- `person(driver_id, name, address)`  
- `car(license, model, year)`  
- `accident(report_number, date, location)`  
- `owns(driver_id, license)`  
- `participated(driver_id, car, report_number, damage_amount)`  

**Question (i):**  
*(i) Find the total number of people who owned cars that were involved in accidents in 1989.*

**Solution (i):**

1. **Filter accidents from 1989:**

$$
A_{1989} \leftarrow \sigma_{\text{date} \ge \text{'1989-01-01'} \land \text{date} \le \text{'1989-12-31'}}(\text{accident})
$$

*(Or using a year check: $\sigma_{\text{year}(\text{date}) = 1989}(\text{accident})$)*

2. **Find participation records for those 1989 accidents:**

$$
P_{1989} \leftarrow \text{participated} \bowtie A_{1989}
$$

3. **Link the damaged cars to their legal owners in `owns`:** Because `participated` calls the license column `car` while `owns` calls it `license`, we join them with a theta condition:

$$
O_{1989} \leftarrow \text{owns} \bowtie_{\text{owns.license} = P_{1989}.\text{car}} P_{1989}
$$

4. **Deduplicate owners and count them:** An owner might have had two cars in 1989 accidents, so we project `driver_id` first to remove duplicates before counting:

$$
\text{DistinctDrivers} \leftarrow \Pi_{\text{driver\_id}}(O_{1989})
$$

$$
\gamma_{\text{count}(\text{driver\_id}) \text{ as } \text{total\_people}}(\text{DistinctDrivers})
$$

**Question (ii):**  
*(ii) Find the number of accidents in which the cars belonging to "John Smith" were involved.*

**Solution (ii):**

1. **Find John Smith's record in `person`:**

$$
\text{Smith} \leftarrow \sigma_{\text{name} = \text{"John Smith"}}(\text{person})
$$

2. **Find all cars owned by John Smith:**

$$
\text{SmithCars} \leftarrow \text{owns} \bowtie \text{Smith}
$$

3. **Match those cars with accident participation records:**

$$
\text{SmithAccidents} \leftarrow \text{participated} \bowtie_{\text{participated.car} = \text{SmithCars.license}} \text{SmithCars}
$$

4. **Count distinct accident reports:** Project unique `report_number` values first (in case two of John Smith's cars were in the same accident) and then count:

$$
\gamma_{\text{count}(\text{report\_number}) \text{ as } \text{accident\_count}}(\Pi_{\text{report\_number}}(\text{SmithAccidents}))
$$

### Drill 3 · 2019 Q.2(b)(ii) · Maximum Suspected Patients on a Date

**Exam Context:** 2019 Q.2(b) (08 marks total, 2 marks for part ii).  
**Schema Given:**  
- `Patient (Patient_ID, Patient_name, Mobile)`  
- `History (Patient_ID, Symptom, Date)`  
- `Report (Patient_ID, Corona_center, Test_result)`  

**Question:**  
*(ii) Consider that if any patient has high-fever symptom he/she will be suspected as corona patient. Find out such maximum number of patients in a date.*

**Solution:**

1. **Select history records with the high-fever symptom:**

$$
\text{Suspected} \leftarrow \sigma_{\text{Symptom} = \text{"high-fever"}}(\text{History})
$$

2. **Count suspected patients on each date:**

$$
\text{PatientsPerDate} \leftarrow {}_{\text{Date}}\gamma_{\text{count}(\text{Patient\_ID}) \text{ as } \text{patient\_count}}(\text{Suspected})
$$

3. **Find the maximum daily patient count:**

$$
\gamma_{\text{max}(\text{patient\_count}) \text{ as } \text{max\_suspected}}(\text{PatientsPerDate})
$$

*(If you also want to display the date that achieved that maximum count, add the matching step:)*

$$
\text{MaxCount} \leftarrow \gamma_{\text{max}(\text{patient\_count}) \text{ as } \text{peak}}(\text{PatientsPerDate})
$$

$$
\Pi_{\text{Date}, \text{patient\_count}}(\sigma_{\text{patient\_count} = \text{peak}}(\text{PatientsPerDate} \times \text{MaxCount}))
$$

### Drill 4 · 2024 Q.2(b) · Employees Working on Multiple Projects

**Exam Context:** 2024 Q.2(b) (04 marks).  
**Schema Given:**  
- `EMPLOYEE (EID, Name, Department, Salary)`  
- `PROJECT (PID, Name, Budget)`  
- `WORKS_ON (EID, PID, Hours)`  

**Question:**  
*Suppose a company wants to find employees working on multiple projects. Write the relational algebra expression for it.*

**Solution:**

1. **Count how many projects each employee works on:**

$$
\text{ProjectCounts} \leftarrow {}_{\text{EID}}\gamma_{\text{count}(\text{PID}) \text{ as } \text{num\_proj}}(\text{WORKS\_ON})
$$

2. **Keep only employees with more than 1 project:**

$$
\text{MultiProjectEIDs} \leftarrow \sigma_{\text{num\_proj} > 1}(\text{ProjectCounts})
$$

3. **Join back with `EMPLOYEE` to get their names and details:**

$$
\Pi_{\text{EID}, \text{Name}, \text{Department}}(\text{EMPLOYEE} \bowtie \text{MultiProjectEIDs})
$$

*(Alternative using self-join without $\gamma$):*

$$
\Pi_{\text{EMPLOYEE.EID}, \text{Name}}\left(\text{EMPLOYEE} \bowtie \Pi_{\text{W1.EID}}\left(\sigma_{\text{W1.EID} = \text{W2.EID} \land \text{W1.PID} \neq \text{W2.PID}}(\rho_{\text{W1}}(\text{WORKS\_ON}) \times \rho_{\text{W2}}(\text{WORKS\_ON}))\right)\right)
$$

Writing both or leading with the $\gamma$ version makes your answer super clear and easy for the examiner to grade.

### Drill 5 · CT-01 Q.04(viii) · Students in Each Department

**Exam Context:** CT-01 Q.04(viii) (01 mark).  
**Schema Given:**  
- $\text{STUDENT}(\text{Student\_ID}, \text{Name}, \text{Dept\_Name}, \text{CGPA})$  
- $\text{COURSE}(\text{Course\_ID}, \text{Course\_Name}, \text{Student\_ID}, \text{Semester}, \text{Marks})$  
- $\text{ALUMNI}(\text{Student\_ID}, \text{Name}, \text{Dept\_Name})$  

**Question:**  
*(viii) Determine the number of students in each department.*

**Solution:**

Group `STUDENT` by `Dept_Name` on the left of $\gamma$ and count `Student_ID` on the right:

$$
{}_{\text{Dept\_Name}}\gamma_{\text{count}(\text{Student\_ID}) \text{ as } \text{Student\_Count}}(\text{STUDENT})
$$

## 🔮 Likely Questions

### 🎯 LQ1 · Highest Average Department Salary

> **Question:**
>
> Given the relation $\text{instructor}(\text{ID}, \text{name}, \text{dept\_name}, \text{salary})$, write a relational algebra expression to find the department name with the highest average salary.

**Full Answer:**

1. **Calculate the average salary for each department:**

$$
\text{DeptAvg} \leftarrow {}_{\text{dept\_name}}\gamma_{\text{avg}(\text{salary}) \text{ as } \text{avg\_sal}}(\text{instructor})
$$

2. **Find the peak average salary across all departments:**

$$
\text{MaxSal} \leftarrow \gamma_{\text{max}(\text{avg\_sal}) \text{ as } \text{peak}}(\text{DeptAvg})
$$

3. **Match and project the winning department name:**

$$
\Pi_{\text{dept\_name}}(\sigma_{\text{avg\_sal} = \text{peak}}(\text{DeptAvg} \times \text{MaxSal}))
$$

### 🎯 LQ2 · Finding Maximum Without $\gamma$ (Classical Relational Algebra)

> **Question:**
>
> Can you find the maximum value of an attribute without using extended relational algebra ($\gamma$)? Explain how this is done using Cartesian product and set difference.

**Full Answer:**

Yes. Classical relational algebra finds the maximum value of attribute $A$ in relation $r$ by first finding all values that are **not** the maximum (because they are smaller than at least one other value in the table) and then subtracting those smaller values from the full set:

1. **Find all values that are strictly smaller than some other value in $r$:** Rename a copy of $r$ to $d$, pair $r \times \rho_d(r)$, and select rows where $r.A < d.A$:

$$
\text{NotMax} \leftarrow \Pi_{r.A}(\sigma_{r.A < d.A}(r \times \rho_{d}(r)))
$$

2. **Subtract those non-maximum values from all values of $A$:**

$$
\text{MaxVal} \leftarrow \Pi_{A}(r) - \text{NotMax}
$$

*Why we still need $\gamma$:* While this clever set-difference trick can find a simple maximum or minimum of an existing column, it cannot count rows, sum values, or compute averages. For any arithmetic aggregation, $\gamma$ is essential.

## ⚡ Exam Tips & Common Mistakes

1. **Left Subscript vs. Right Subscript:** Always put grouping attributes in the **left subscript** and aggregate functions in the **right subscript** (${}_{\text{grouping}}\gamma_{\text{aggregates}}(E)$). Reversing them is a common exam mistake.
2. **Leave the Left Side Blank for Whole-Table Totals:** When calculating a single total or maximum across the whole table, leave the left subscript empty ($\gamma_{\text{count}(A)}(E)$) instead of inventing a dummy grouping attribute.
3. **Always Alias Your Aggregate Columns:** Use `as` (${}_{G}\gamma_{\text{count}(A) \text{ as } C}(E)$) so that outer $\sigma$ or $\Pi$ operators have a clean column name to reference.
4. **Project Before Counting When You Need Distinct Items:** Because $\gamma$ operates on multisets (duplicates included), if you need to count distinct drivers or distinct accident reports, apply $\Pi_{\text{driver\_id}}(E)$ first to strip duplicates before running $\gamma_{\text{count}(\text{driver\_id})}$.
