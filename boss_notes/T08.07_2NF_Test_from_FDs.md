# T08.7: Testing 2NF from a Functional Dependency Set

> **Topic:** T08 — Normalization & Functional Dependencies | **Priority:** 🟢 | **Exam Frequency:** 1/7 finals (4 marks)
> **Sources:** Silberschatz 7e Ch. 7 (§7.3.4, Practice Ex. 7.19, pp. 356–357) · Lecture Deck 06 (Slides 31–36) · Classnote by Raidah (pp. 20, 22)

## Why This Topic Matters

Second Normal Form (2NF) removes partial functional dependencies from database tables so that every non-prime attribute depends on the entire candidate key rather than just a piece of it. RUET exams test 2NF directly by giving you an abstract relation $R$ and a set of functional dependencies $FD$. To score full marks, you need a clean, repeatable workflow to find the candidate keys, classify prime vs. non-prime attributes, spot any partial dependencies, and split the table into 2NF relations without losing data.

---

## 📝 Key Definitions

> **Second Normal Form (2NF):** "A relation schema $R$ is in second normal form (2NF) if each attribute $A$ in $R$ meets one of the following criteria:
> - It appears in a candidate key.
> - It is not partially dependent on a candidate key." — Silberschatz, Korth & Sudarshan, *Database System Concepts* (7th Ed.), Practice Exercise 7.19 (pp. 356–357)

> **Partial Dependency:** "A functional dependency $\alpha \rightarrow \beta$ is called a partial dependency if there is a proper subset $\gamma$ of $\alpha$ such that $\gamma \rightarrow \beta$; we say that $\beta$ is partially dependent on $\alpha$." — Silberschatz, Korth & Sudarshan, *Database System Concepts* (7th Ed.), Practice Exercise 7.19 (p. 356)

> **Second Normal Form (Course Rule):** "A relation is in 2NF if: 1. It is already in 1NF. 2. It has no partial functional dependency." — Lecture Deck 06, Slide 31

> **Prime vs. Non-Prime Attributes:** "A Prime Attribute is an attribute that is a member of at least one Candidate Key of a relation. An attribute that does not belong to any Candidate Key is called a Non-Prime Attribute." — Lecture Deck 06, Slide 16

---

## Testing 2NF: Conditions and Mechanics

### The Core Principle of 2NF

Intuitively, a 2NF violation only happens when part of a composite key tries to act like a key on its own for some non-key attribute. Formally, a 1NF relation violates 2NF if and only if **both** of the following happen at the same time:
1. The relation has a **composite candidate key** (a candidate key made of two or more attributes).
2. A **proper subset** (just a piece) of that composite candidate key functionally determines a **non-prime attribute**.

```text
               +----------------------------------+
               | Composite Candidate Key: (X, Y)  |
               +-----------------+----------------+
                                 |
           (Proper Subset) X     |
                   |             | (Full Key)
                   v             v
            Non-Prime: A   Non-Prime: B
                   |             |
           [PARTIAL DEPENDENCY]  [FULL DEPENDENCY]
             Violates 2NF!         Satisfies 2NF
```

### When is 2NF Automatically Satisfied?

You can immediately conclude that a 1NF relation is **guaranteed to be in 2NF** if either of these shortcuts applies:
- **Every candidate key is a single attribute:** If no candidate key has two or more attributes, no candidate key can have a non-empty proper subset, so partial dependencies are impossible.
- **All attributes are prime:** If every attribute in the table belongs to at least one candidate key, there are zero non-prime attributes that could be partially dependent.

## Step-by-Step Testing Procedure

Use this 4-step recipe on every 2NF exam problem:

### Step 1: Find All Candidate Keys

Use the L/R/M/N classification and attribute closure ($X^+$) under $F$ to find every minimal superkey of $R$.

### Step 2: Classify Attributes into Prime and Non-Prime

- **Prime Attributes:** Any attribute that appears in at least one candidate key.
- **Non-Prime Attributes:** Every remaining attribute in $R$ that never appears in a candidate key.

### Step 3: Inspect Every Functional Dependency

Look at each dependency $X \rightarrow Y$ in $F$ (splitting composite right-hand sides into single attributes if helpful):
- If $Y$ is a **prime attribute**, it cannot cause a 2NF violation.
- If $X$ is a **full candidate key** (or superkey), it is a full dependency and satisfies 2NF.
- If $X$ consists only of non-prime attributes, that is a transitive (3NF) issue, **not** a 2NF violation.
- If $X$ is a **proper subset of a candidate key** AND $Y$ is a **non-prime attribute**, you have caught a **partial functional dependency**, and the table fails 2NF.

### Step 4: Decompose into 2NF Sub-Relations

Why does splitting out the partial dependency fix the table without losing data? Because pulling the partial determinant $X$ and its dependent $Y$ into a new table $R_1(X, Y)$ makes $X$ the full primary key of $R_1$, while leaving $X$ behind in the main table $R_2$ as a foreign key so the two tables can be joined back losslessly:
1. Create a new relation $R_1(X, Y)$ for the partial dependency $X \rightarrow Y$, with primary key $X$.
2. Remove the partially dependent attributes $Y$ from the original relation to get $R_2 = R - Y$ (keeping $X$ inside $R_2$ since $X$ is part of $R_2$'s candidate key).
3. If there are multiple partial dependencies with different determinants, repeat for each one.
4. **Lossless-Join Check:** Verify that the shared attributes between $R_1$ and $R_2$ determine all of $R_1$:

$$
(R_1 \cap R_2) \rightarrow R_1 \quad \text{or} \quad (R_1 \cap R_2) \rightarrow R_2
$$

Since $R_1 \cap R_2 = X$ and $X$ is the candidate key of $R_1$, the decomposition is always lossless.

## Lecture Walkthrough: Complex 2NF Testing (Deck 06 Slides 35–36)

Consider schema $R(A, B, C, D, E, F)$ with the functional dependency set:

$$
FD = \{A \rightarrow B, \; C \rightarrow F, \; EC \rightarrow D, \; E \rightarrow A\}
$$

### Step 1: Candidate Key Derivation

- Inspect the right-hand sides: attributes $B, F, D, A$ appear on the RHS.
- Attributes $C$ and $E$ never appear on any RHS, so they must belong to every candidate key.
- Compute the closure of $\{C, E\}$:
  - Start: $\{C, E\}$
  - Apply $C \rightarrow F$: $\{C, E, F\}$
  - Apply $EC \rightarrow D$: $\{C, D, E, F\}$
  - Apply $E \rightarrow A$: $\{A, C, D, E, F\}$
  - Apply $A \rightarrow B$: $\{A, B, C, D, E, F\} = R$
- Since $(CE)^+ = R$ and neither $C^+$ nor $E^+$ reaches $R$, $\{CE\}$ is the unique candidate key.

### Step 2: Attribute Classification

- **Prime Attributes:** $\{C, E\}$
- **Non-Prime Attributes:** $\{A, B, D, F\}$

### Step 3: Analysis of Each Functional Dependency

1. $EC \rightarrow D$: $EC$ is the entire candidate key, so this is a **full functional dependency** (satisfies 2NF).
2. $A \rightarrow B$: Both $A$ and $B$ are non-prime attributes, and $A$ is not a subset of the candidate key $CE$. This is a **transitive dependency**, which violates 3NF later but does **not** directly form a partial dependency on $CE$. (Note, however, that since $E \rightarrow A$ and $A \rightarrow B$ imply $E \rightarrow B$, both $A$ and $B$ ultimately depend only on $E$!)
3. $C \rightarrow F$: $C$ is a proper subset of the composite key $CE$, and $F$ is non-prime. This is a **partial functional dependency** (violates 2NF).
4. $E \rightarrow A$: $E$ is a proper subset of the composite key $CE$, and $A$ is non-prime. This is a **partial functional dependency** (violates 2NF).

Because partial dependencies exist, relation $R$ is **not in 2NF**.

### Step 4: Decomposing the Lecture Walkthrough into 2NF

To convert $R(A, B, C, D, E, F)$ into 2NF, we pull each partial dependency chain out into its own table:
- From $C \rightarrow F$: create $R_1(\underline{C}, F)$ with candidate key $\{C\}$.
- From $E \rightarrow A$ (which also carries $A \rightarrow B$ along with it): create $R_2(\underline{E}, A, B)$ with candidate key $\{E\}$.
- From the remaining full dependency $EC \rightarrow D$: keep $R_3(\underline{C, E}, D)$ with composite candidate key $\{C, E\}$.

Now $R_1, R_2, R_3$ are all free of partial dependencies and satisfy **2NF**! (Notice that $R_2(\underline{E}, A, B)$ is in 2NF because its key $\{E\}$ is a single attribute, even though $E \rightarrow A \rightarrow B$ still has a transitive dependency that would be split in 3NF.)

## 🏆 Golden Questions (Past Exam Archive)

### 🎯 GQ1 · 2021 Q.5(c) · Testing and Converting Relation to 2NF

> **Appeared:** 2021 Q.5(c) — (04 Marks, Section B, CLO1)

**Question:**

Given a relation R (A, B, C, D) and functional dependency at FD = { AB $\to$ CD, B $\to$ C }. Determine whether the given R is in 2NF? If not, convert it into 2NF.

*(Note: "functional dependency at FD" printed verbatim from original question paper)*

**Full Answer:**

#### 1. Determine Candidate Key and Attribute Classification

Given relation $R(A, B, C, D)$ and functional dependencies:
$$
FD = \{AB \rightarrow CD, \; B \rightarrow C\}
$$

1. **Find Candidate Key:**
   - Attribute $A$ never appears on the right-hand side of any functional dependency. Therefore, attribute $A$ must be present in every candidate key.
   - Compute the closure of $AB$:
     - Initial: $\{A, B\}$
     - Apply $AB \rightarrow CD$: $\{A, B, C, D\}$
     - Result: $AB^+ = \{A, B, C, D\} = R$
   - Test proper subsets for minimality:
     - $A^+ = \{A\} \neq R$
     - $B^+ = \{B, C\} \neq R$
   - Neither proper subset is a superkey. Therefore, $AB$ is minimal.

$$
\text{Candidate Key} = \{AB\}
$$

2. **Classify Attributes:**
   - **Prime Attributes:** $\{A, B\}$ (members of candidate key $AB$).
   - **Non-Prime Attributes:** $\{C, D\}$ (attributes not in any candidate key).

#### 2. Test for Second Normal Form (2NF)

A relation is in Second Normal Form (2NF) if:
1. It is in First Normal Form (1NF).
2. No non-prime attribute is partially dependent on any candidate key. Every non-prime attribute must be fully functionally dependent on the complete candidate key.

Examine the dependencies in $FD$:
- **$AB \rightarrow CD$:** The determinant $AB$ is the full candidate key. Both $C$ and $D$ are fully dependent on the complete key. This is a **full functional dependency**.
- **$B \rightarrow C$:** The determinant $B$ is a proper subset of candidate key $AB$, and dependent attribute $C$ is a non-prime attribute. This is a **partial functional dependency**.

Because partial functional dependency $B \rightarrow C$ exists, **relation $R$ is NOT in 2NF**.

#### 3. Conversion to 2NF (Decomposition)

To convert $R$ into 2NF, we decompose the schema into two relations by isolating the partial dependency:

1. **Relation $R_1$ (Isolating the Partial Dependency):**  
   Group the partial determinant $B$ with its dependent attribute $C$:
   $$
   R_1(B, C)
   $$
   $$
   FD_1 = \{B \rightarrow C\}
   $$
   $$
   \text{Primary Key of } R_1 = B
   $$

2. **Relation $R_2$ (Original Relation without Dependent Attribute):**  
   Remove attribute $C$ from relation $R$, retaining the full candidate key $AB$ and the fully dependent attribute $D$:
   $$
   R_2(A, B, D)
   $$
   $$
   FD_2 = \{AB \rightarrow D\}
   $$
   $$
   \text{Primary Key of } R_2 = AB
   $$

#### 4. Verification of 2NF Decomposition

- **2NF Satisfaction:**
  - In $R_1(B, C)$, candidate key is single attribute $B$. Partial dependency is impossible. $R_1$ is in 2NF.
  - In $R_2(A, B, D)$, non-prime attribute $D$ depends on full candidate key $AB$. No partial dependency exists. $R_2$ is in 2NF.
- **Lossless-Join Verification:**
  - $R_1 \cap R_2 = \{B, C\} \cap \{A, B, D\} = \{B\}$
  - Attribute $B$ is the candidate key of $R_1$ ($B \rightarrow BC$ holds in $R_1$).
  - Because $(R_1 \cap R_2) \rightarrow R_1$, the decomposition is guaranteed to be **lossless**.

$$
\boxed{\text{Decomposed 2NF Relations: } R_1(B, C) \text{ and } R_2(A, B, D)}
$$

## 📖 High-Yield Exercises from the Book

### 🎯 HYE-01 · Exercise 7.19 · Testing 2NF Violation & Partial Dependency Elimination

> **Source:** Silberschatz 7e · Chapter 7 (Exercise 7.19)  
> **Exam Relevance:** High-Probability Exam Drill  
> **Key Tested Concept:** Identification of partial functional dependencies and lossless decomposition into Second Normal Form (2NF).

**Problem Statement:**
> Given relation schema $R = (A, B, C, D)$ and set of functional dependencies $F$:
> $$
> F = \{AB \rightarrow C, \; B \rightarrow D\}
> $$
> 1. Find all candidate keys of $R$.
> 2. Determine whether $R$ is in 2NF. If not, explain why.
> 3. Decompose $R$ into a set of 2NF relations.

**Model Exam-Style Solution:**
1. **Find Candidate Keys of $R$:**
   - Attribute $A$ appears only on the LHS of $AB \rightarrow C$.
   - Attribute $B$ appears only on the LHS of $AB \rightarrow C$ and $B \rightarrow D$.
   - Therefore, $AB$ must be part of every candidate key.
   - Compute $\{AB\}^+$:
     - $\{AB\}^+ = \{A, B\}$
     - $AB \rightarrow C \implies \{A, B, C\}$
     - $B \rightarrow D \implies \{A, B, C, D\} = R$
   - Proper subsets: $A^+ = \{A\} \neq R$; $B^+ = \{B, D\} \neq R$.
   - **Candidate Key:** $\{A, B\}$ (Composite Key).
   - **Prime Attributes:** $\{A, B\}$
   - **Non-Prime Attributes:** $\{C, D\}$

2. **2NF Violation Test:**
   - **Definition of 2NF:** A relation is in 2NF if it is in 1NF and **no non-prime attribute is partially dependent on any candidate key**.
   - Check dependency $B \rightarrow D$:
     - $D$ is a non-prime attribute.
     - $B$ is a proper subset of candidate key $\{A, B\}$.
     - Hence, $B \rightarrow D$ is a **partial dependency**.
   - **Verdict:** $R$ is **NOT in 2NF**.

3. **2NF Decomposition:**
   - To eliminate the partial dependency, separate the determinant and its dependent attribute:
     - $R_1 = (B, D)$ with primary key $B$ and FD $B \rightarrow D$.
     - $R_2 = (A, B, C)$ with primary key $AB$ and FD $AB \rightarrow C$.
   - **Verification:**
     - $R_1 \cap R_2 = \{B\}$, and $B$ is a candidate key of $R_1$. Thus, the decomposition is **lossless-join**.
     - All dependencies in $F$ are preserved.
     - Both $R_1$ and $R_2$ have no partial dependencies.

**💡 RUET Exam Takeaway:**
A relation with a single-attribute candidate key is ALWAYS automatically in 2NF. 2NF violations can ONLY occur when the candidate key is composite!

## ⚡ Exam Tips & Common Mistakes

1. **Do not confuse partial and transitive dependencies:**  
   - Partial dependency: Proper subset of candidate key $\rightarrow$ non-prime attribute (violates 2NF).
   - Transitive dependency: Non-prime attribute $\rightarrow$ non-prime attribute (violates 3NF, but does NOT violate 2NF). In Deck 06 Slide 36, $A \rightarrow B$ does not violate 2NF because $A$ is non-prime, not a proper subset of key $CE$.
2. **Single-attribute keys can never violate 2NF:** If a relation's only candidate key is a single attribute (like $\text{StudentID}$), the relation is automatically in 2NF. Always state this rule explicitly on exams.
3. **Remove determined attributes from the parent relation:** When decomposing for $B \rightarrow C$, you must drop $C$ from $R_2$. Keeping $C$ in both relations ($R_2(A, B, C, D)$) fails to resolve the anomaly.
4. **Always state candidate keys for decomposed tables:** Full marks require explicitly stating the primary key or candidate key for each new relation.
