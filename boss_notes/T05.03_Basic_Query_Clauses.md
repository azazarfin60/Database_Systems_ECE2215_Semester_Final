# T05.3: Basic SQL Query Clauses (DISTINCT, ORDER BY, AS, LIKE)

> **Topic:** T05 — SQL (DDL, DML, Aggregates, Subqueries) | **Priority:** 🟢 | **Exam Frequency:** CT-02 Q1(b) (2 marks) + cross-tested in 2019 Q7a(ii), 2021 Q3a(iv), 2024 Q7b(iii–iv)
> **Sources:** Silberschatz 7e Ch. 3 (§3.3, §3.4) · Lecture Deck 03 (Slides 14, 17–24) · Raidah Notes (pp. 2–4) · Fahim Notes (pp. 39–42)

## Why This Topic Matters

Basic query clauses give precision and structure to SQL data retrieval. While primary query questions often focus on grouping or subqueries, examiners frequently test `ORDER BY`, `DISTINCT`, `AS`, and `LIKE` as specific sub-questions, short notes, or sorting requirements. Mastering these clauses ensures you write idiomatic, bug-free queries and easily answer dedicated 2-mark to 3-mark theory questions.

---

## 📝 Key Definitions

> **Distinct and All Clauses:** "In those cases where we want to force the elimination of duplicates, we insert the keyword distinct after select... SQL allows duplicates in database relations as well as in the results of SQL expressions... The keyword all specifies that duplicates should not be removed." — Silberschatz, Korth & Sudarshan, *Database System Concepts* (7th Ed.), §3.3.1 (pp. 72–73)

> **Order By Clause:** "The order by clause causes the tuples in the result of a query to appear in sorted order... By default, the order by clause lists items in ascending order. To specify the sort order, we may specify desc for descending order or asc for ascending order. Furthermore, ordering can be performed on multiple attributes." — Silberschatz, Korth & Sudarshan, *Database System Concepts* (7th Ed.), §3.4.4 (pp. 83–84)

> **Rename Operation (AS):** "SQL provides a way of renaming the attributes of a result relation. It uses the as clause, taking the form: old-name as new-name. The as clause can appear in both the select and from clauses." — Silberschatz, Korth & Sudarshan, *Database System Concepts* (7th Ed.), §3.4.1 (p. 80)

> **Pattern Matching (LIKE):** "Pattern matching can be performed on strings using the operator like. We describe patterns by using two special characters: Percent (%): The % character matches any substring. Underscore (_): The _ character matches any character." — Silberschatz, Korth & Sudarshan, *Database System Concepts* (7th Ed.), §3.4.2 (p. 82)

## Core Query Clauses: Mechanics & Syntax

A complete SQL retrieval query follows a strict grammatical order. Knowing how the database engine evaluates each clause helps you avoid syntax errors and unexpected results.

```sql
SELECT [DISTINCT | ALL] attribute1 [AS alias1], attribute2
FROM table1 [AS t1]
WHERE search_condition
ORDER BY attribute1 [ASC | DESC];
```

### 1. Duplicate Handling: `DISTINCT` vs. `ALL`

In formal relational algebra, relations are mathematical sets that never allow duplicate tuples. However, real database engines work on multisets (bags) instead. Because removing duplicates requires sorting or hashing every row in the result, doing it automatically on every query would be too slow.

To save time, SQL keeps duplicate rows by default:
- `SELECT ALL dept_name FROM instructor;` keeps all duplicate rows. Since `ALL` is the default behavior, programmers rarely write it out.
- `SELECT DISTINCT dept_name FROM instructor;` tells the query engine to strip out duplicates and return only unique values.

```sql
-- Query without DISTINCT: Returns 12 rows (e.g., 'Comp. Sci.' appears 3 times)
SELECT dept_name FROM instructor;

-- Query with DISTINCT: Returns 7 rows (each department name appears at most once)
SELECT DISTINCT dept_name FROM instructor;
```

#### Multi-Attribute DISTINCT
When you list multiple columns after `DISTINCT`, the database checks uniqueness across the entire row combination rather than a single column:

```sql
SELECT DISTINCT dept_name, salary
FROM instructor;
```

Here, two rows are considered duplicates only if they share both the same `dept_name` and the same `salary`.

#### DISTINCT Inside Aggregate Functions
You can also place `DISTINCT` inside aggregate functions like `COUNT`, `SUM`, or `AVG` so the calculation only considers unique values:

```sql
-- Counts total non-null department entries:
SELECT COUNT(dept_name) FROM instructor;

-- Counts only unique department names:
SELECT COUNT(DISTINCT dept_name) FROM instructor;
```

---

### 2. Sorting Output: The `ORDER BY` Clause

Because tables store rows on disk without any guaranteed order, running a basic `SELECT` query can return rows in any sequence. Whenever you want your output sorted in a predictable way, you need to add an `ORDER BY` clause at the very end of the query.

#### Sorting Direction
- `ASC`: Sorts in ascending order (smallest to largest, or A to Z). SQL uses this by default whenever you leave out the direction keyword.
- `DESC`: Sorts in descending order (largest to smallest, or Z to A).

```sql
-- Ascending order by name (A to Z):
SELECT name FROM instructor ORDER BY name ASC;

-- Descending order by salary (highest to lowest):
SELECT name, salary FROM instructor ORDER BY salary DESC;
```

#### Multi-Column Sorting
You can also sort by several columns at once by listing them in priority order. The database sorts everything by the first column first, and whenever two rows tie on that first column, it uses the next column to break the tie:

```sql
SELECT name, dept_name, salary
FROM instructor
ORDER BY dept_name ASC, salary DESC;
```

In this query, instructors are first grouped alphabetically by department name, and within each department, they are listed from highest to lowest salary.

#### Evaluation Order of ORDER BY
Behind the scenes, the query engine processes SQL clauses in a strict logical pipeline:
1. `FROM` (identifies source tables and joins)
2. `WHERE` (filters individual rows)
3. `GROUP BY` (forms summary groups)
4. `HAVING` (filters summary groups)
5. `SELECT` (evaluates expressions and projections)
6. `ORDER BY` (sorts the final projected relation)

Because `ORDER BY` runs at the very end after `SELECT`, it is the only clause where you are guaranteed to be able to use column aliases created in your `SELECT` list.

### 3. Renaming Attributes & Relations: The `AS` Clause

The `AS` keyword lets you give temporary nicknames (aliases) to columns or tables for the duration of a query. This is helpful both for making output headers readable and for referencing tables cleanly inside your query.

#### Attribute Aliasing in the SELECT Clause
Renaming output columns is especially useful in three everyday situations:
1. Giving a clean name to arithmetic expressions (such as `sell_price * 15 AS new_price`).
2. Labeling summary outputs from aggregate functions (such as `COUNT(*) AS total_students`).
3. Distinguishing identically named columns when joining two tables.

```sql
SELECT name AS instructor_name,
       salary / 12 AS monthly_salary
FROM instructor;
```

#### Relation Aliasing in the FROM Clause
When you use `AS` in the `FROM` clause, it creates a correlation variable (table alias) that represents a specific copy of the table. You need table aliases for two main tasks:
1. Keeping multi-table queries short and readable instead of typing long table names over and over.
2. Comparing a table against itself in a self-join, where two separate pointers must scan the same table at once.

```sql
-- Self-join comparing instructors within the same table:
SELECT DISTINCT T.name
FROM instructor AS T, instructor AS S
WHERE T.salary > S.salary AND S.dept_name = 'Biology';
```

In this self-join, you can think of `T` and `S` as two separate finger pointers scanning through the `instructor` table independently.

> [!NOTE]
> In standard SQL and MySQL, the `AS` keyword in the `FROM` clause is optional:
> 
> $$
> \text{instructor AS } T \equiv \text{instructor } T
> $$
> 
> Both forms run identically.

### 4. String Pattern Matching: The `LIKE` Operator

When you do not know the exact text stored in a string column (`CHAR` or `VARCHAR`), equality (`=`) will not help because it only checks for an exact character-for-character match. Instead, the `LIKE` operator lets you search for flexible text patterns using two wildcard symbols:
- **Percent (`%`):** Matches any string of zero, one, or many characters.
- **Underscore (`_`):** Matches any single character in that exact position.

#### Pattern Matching Reference Table

| Pattern | Meaning | Example Matches | Non-Matching Examples |
| :--- | :--- | :--- | :--- |
| `'A%'` | Begins with the letter "A". | `'Amelia'`, `'Ahmad'`, `'Apple'` | `'Sansa'`, `'Mohammad'` |
| `'%ECE%'` | Contains substring "ECE" anywhere. | `'ECE 2215'`, `'DECE'`, `'ECE'` | `'CSE 2201'`, `'EEE 1101'` |
| `'___'` | Contains exactly three characters. | `'ECE'`, `'CSE'`, `'101'` | `'EC'`, `'RUET'` |
| `'___%'` | Contains at least three characters. | `'ECE'`, `'RUET'`, `'Oliver'` | `'E'`, `'AB'` |
| `'_b%'` | Second character is lowercase "b". | `'Abdullah'`, `'Ibrahim'` | `'Amelia'`, `'Bob'` |
| `'%g'` | Ends with the letter "g". | `'Spring'`, `'Building'` | `'Fall'`, `'Summer'` |

#### Escaping Wildcard Characters
Sometimes the text you are searching for actually contains a literal percent sign (`%`) or underscore (`_`), such as `"100%"`. To tell SQL to treat `%` as normal text rather than a wildcard, place an escape character right before it and declare that character with `ESCAPE`:

```sql
-- Matches any discount string containing literal '100%':
SELECT *
FROM promotions
WHERE description LIKE '%100 \%' ESCAPE '\';
```

#### Case Sensitivity Nuance
Under the official ANSI SQL standard, `LIKE` is case sensitive, meaning `'Intro%'` will not match `'intro'`. However, MySQL uses case-insensitive collations (like `utf8mb4_0900_ai_ci`) by default, so `'a%'` and `'A%'` match the same rows unless you force binary comparison. PostgreSQL stays strictly case sensitive for `LIKE` and offers `ILIKE` when you want case-insensitive searches.

## Worked Example: Combining Pattern Matching, Aliasing, and Multi-Column Sorting

Let's walk through a compact example that combines `DISTINCT`, `AS`, `LIKE`, and `ORDER BY` in a single query before looking at past exam questions.

### Problem Statement
Given the course catalog schema:

$$
\text{COURSE}(\text{CourseCode}, \text{Title}, \text{Department}, \text{Credits})
$$

Write an SQL query to display the course code, title, and weekly study hours (calculated as $\text{Credits} \times 3$, renamed as `weekly_hours`) for all courses whose code starts with `'ECE'`, sorted by `weekly_hours` from highest to lowest and then alphabetically by `Title`.

### Step-by-Step Construction
1. **Filter with `LIKE`:** To match course codes beginning with `'ECE'`, we write `WHERE CourseCode LIKE 'ECE%'`.
2. **Compute and alias with `AS`:** In the `SELECT` list, we calculate `Credits * 3 AS weekly_hours`.
3. **Sort with `ORDER BY`:** We sort first by `weekly_hours DESC`, and break any ties with `Title ASC`.

```sql
SELECT CourseCode,
       Title,
       Credits * 3 AS weekly_hours
FROM COURSE
WHERE CourseCode LIKE 'ECE%'
ORDER BY weekly_hours DESC, Title ASC;
```

### Quick Trace
Suppose `COURSE` contains three rows:
- `('ECE 2215', 'Database Systems', 'ECE', 3.0)` $\to$ Matches `'ECE%'`, `weekly_hours = 9.0`.
- `('CSE 2101', 'Data Structures', 'CSE', 3.0)` $\to$ Rejected by `LIKE 'ECE%'`.
- `('ECE 2201', 'Analog Electronics', 'ECE', 3.0)` $\to$ Matches `'ECE%'`, `weekly_hours = 9.0`.

Both surviving ECE courses tie at `9.0` weekly hours, so the tie-breaker `Title ASC` places `'Analog Electronics'` first and `'Database Systems'` second.

## 🏆 Golden Questions (Past Exam Archive)

### 🎯 GQ1 · CT-02 Q.01(b) · Department and CGPA Filter with Descending Sort

> **Appeared:** CT-02 Q.01(b) — (02 marks)

**Question:**

Given $\text{STUDENT}(\text{StudentID}, \text{Name}, \text{Department}, \text{Semester}, \text{CGPA})$, write SQL query:  
**(b)** Display students from the ECE department whose CGPA is greater than 3.50, arranged by CGPA in descending order.

**Full Answer:**

We apply a compound `WHERE` filter combining the equality predicate on `Department` and the inequality on `CGPA`, followed by an `ORDER BY` clause using `DESC`:

```sql
SELECT *
FROM STUDENT
WHERE Department = 'ECE' AND CGPA > 3.50
ORDER BY CGPA DESC;
```

### 🎯 GQ2 · Cross-Ref: 2019 Q.7(a)(ii) · Name Filter Using LIKE Pattern Matching

> **Appeared:** 2019 Q.7(a)(ii) — (03 marks)

**Question:**

Considering the following data tables (Student, GPA, Credits) answer (ii):  
`Student (St_ID, St Name)`  
`GPA (St_ID, Sub_Code, gpa)`  
`Credit (Sub_Code, Credit)`  
(ii) Write down the SQL query to find out the registered subjects of those students whose name started with "A".

**Full Answer:**

To identify students whose names begin with "A", we use the string pattern `'A%'` with the `LIKE` operator. We join `Student` with `GPA` on `St_ID` to retrieve their registered subject codes:

```sql
SELECT DISTINCT g.Sub_Code
FROM Student s
JOIN GPA g ON s.St_ID = g.St_ID
WHERE s.`St Name` LIKE 'A%';
```

*Notes:*
- In table `Student`, the attribute name is printed with a space as `St Name`. In MySQL, identifiers containing spaces must be enclosed in backticks (`\``St Name`\``).
- Adding `DISTINCT` ensures subject codes are not repeated if multiple qualifying students registered for the same subject.

### 🎯 GQ3 · Cross-Ref: 2024 Q.7(b)(iii–iv) · Short Notes on ORDER BY and AS Clauses

> **Appeared:** 2024 Q.7(b)(iii–iv) — (02 marks total; 1 mark each out of 04 marks)

**Question:**

Write short note on the following statements –  
iii) Order By  
iv) As

**Full Answer:**

#### (iii) Short Note: ORDER BY Clause

1. **Purpose:** The `ORDER BY` clause sorts the result tuples of a query in ascending or descending sequence according to one or more specified attributes.
2. **Sort Direction:**
   - Ascending (`ASC`): Default behavior. Arranges numbers from lowest to highest and strings alphabetically (A to Z).
   - Descending (`DESC`): Reverses the order, arranging values from highest to lowest.
3. **Multi-Column Sorting:** Multiple attributes can be specified separated by commas. Sorting evaluates from left to right:
   ```sql
   SELECT name, dept_name, salary
   FROM instructor
   ORDER BY dept_name ASC, salary DESC;
   ```
4. **Execution Position:** It is evaluated as the final step of query processing, immediately after `SELECT`.

#### (iv) Short Note: AS Clause (Rename Operation)

1. **Purpose:** The `AS` clause renames attributes in the projection list or relations in the `FROM` clause.
2. **Attribute Renaming:** Used to provide meaningful column headings for calculated expressions or aggregate functions:
   ```sql
   SELECT salary * 1.10 AS revised_salary,
          COUNT(*) AS total_staff
   FROM instructor;
   ```
3. **Relation Renaming (Table Aliases):** Assigns a short alias or correlation variable to a relation. This is critical for self-joins where a relation must be compared against itself:
   ```sql
   SELECT T.name
   FROM instructor AS T, instructor AS S
   WHERE T.salary > S.salary AND S.dept_name = 'Comp. Sci.';
   ```
4. **Optional Usage:** In SQL-92 and later standards, the keyword `AS` is optional when declaring table aliases (`FROM instructor T`).

## ⚡ Exam Tips & Common Mistakes

1. **Strict Clause Sequence:** Always write SQL clauses in grammatical order:
   
   $$
   \text{SELECT} \longrightarrow \text{FROM} \longrightarrow \text{WHERE} \longrightarrow \text{GROUP BY} \longrightarrow \text{HAVING} \longrightarrow \text{ORDER BY}
   $$
   
   Placing `ORDER BY` before `WHERE` causes a syntax error.
2. **`DESC` vs `DESCENDING`:** The valid SQL keyword is `DESC`. Writing `DESCENDING` is invalid syntax in MySQL.
3. **Equality vs Pattern Matching:** Never write `WHERE name = 'A%'`. The equality operator `=` searches for the literal two-character string `"A%"`. Always use `LIKE 'A%'` for wildcard pattern matching.
4. **Enclosing Multi-Word Identifiers:** When table attribute names contain spaces (e.g., `St Name` in 2019 Q.7(a)), enclose the identifier in backticks in MySQL (`` `St Name` ``) or double quotes in standard SQL.
5. **Aliasing in WHERE:** Standard SQL does not allow column aliases defined in `SELECT` to be used in the `WHERE` clause because `WHERE` is evaluated before `SELECT`. Always repeat the expression or filter in `HAVING`.
