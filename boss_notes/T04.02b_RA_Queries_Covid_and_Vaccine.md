# T04.2b: RA Queries — Covid and Vaccine Schemas

> **Topic:** T04 — Relational Algebra & Calculus | **Priority:** 🔴 | **Exam Frequency:** 6/7 finals (+ CT-01 Q4) (41 marks in T04.2)
> **Sources:** Silberschatz 7e Ch. 2 (§2.6), Ch. 16 (§16.1) · Lecture Deck 02 (Slides 11–29) · Raidah Class Notes (pp. 13–14)

## Why This Topic Matters

Healthcare and vaccination databases are a favorite source of custom RUET exam questions, appearing in 2019, 2020, and again in 2024. Instead of lifting a schema straight from Silberschatz, the examiners designed two custom schemas around Covid-19 test reports and vaccination dose records. These questions test three classic relational algebra skills: finding the highest daily count using two-stage aggregation ($\gamma$), matching patients who have both a specific symptom and a specific test outcome ($\cap$), and filtering for people who took the "1st dose only" using set difference ($-$).

---

## 📝 Key Definitions

> **Join Operation ($\bowtie_\theta$):** The theta-join operation combines a Cartesian product and a selection into a single binary step. Written as $r \bowtie_\theta s$, it equals $\sigma_\theta(r \times s)$ and returns all pairs of tuples from $r$ and $s$ that satisfy the join condition $\theta$.

> **Natural Join ($\bowtie$):** The natural join is a binary operator written as $r \bowtie s$ that pairs tuples from $r$ and $s$ having equal values on all shared attribute names. It removes duplicate copies of the common columns from the output schema.

> **Intersection Operation ($\cap$):** The intersection operation takes two union-compatible relations $r$ and $s$ and returns a relation containing only the tuples that appear in both $r$ and $s$. It is written as $r \cap s$ and can be derived from set difference as $r - (r - s)$.

> **Set-Difference Operation ($-$):** The set-difference operation takes two union-compatible relations $r$ and $s$ and returns all tuples that are present in $r$ but absent from $s$. It is written as $r - s$.

> **Aggregate Functions:** Aggregate functions compute a single summary value (`count`, `sum`, `avg`, `min`, or `max`) from a multiset of attribute values. In relational algebra, they are evaluated inside the aggregate operator ${}_G\gamma_F(r)$ over each group defined by $G$.

## Healthcare Schema Query Patterns

In RUET finals, healthcare questions follow two simple table layouts where a person or patient table links to one or more event tables (`History`, `Report`, or `vaccine`):

```text
Pattern A: Covid Diagnostic Schema (3 Tables)
┌──────────────┐         ┌──────────────┐         ┌──────────────┐
│   Patient    │ 1     * │   History    │         │    Report    │ 1     *
│ (Patient_ID) ├─────────┤ (Patient_ID, ├─────────┤ (Patient_ID, ├─────────
│              │         │  Symptom)    │         │  Test_result)│
└──────────────┘         └──────────────┘         └──────────────┘

Pattern B: Vaccination Tracking Schema (2 Tables)
┌──────────────┐         ┌──────────────────────────────┐
│    person    │ 1     * │           vaccine            │
│     (id)     ├─────────┤ (id, center, dose_no, date)  │
└──────────────┘         └──────────────────────────────┘
```

### Pattern 1: Handling Typographical Errors in Exam Schemas
In the 2019 exam paper, the `Report` table was printed with `Parient_ID` instead of `Patient_ID`. Similarly, the 2024 paper printed `relation database` and `queris`. Whenever you spot an obvious spelling typo in an exam schema:
1. Write a brief one-line assumption at the top of your answer: `*Assumption: Parient_ID in Report is a typo for Patient_ID.*`
2. Use `Patient_ID` consistently so your natural joins ($\bowtie$) work cleanly.
3. Never panic or leave a question blank because of a typo in the prompt.

### Pattern 2: The Two-Stage Daily Peak Pattern (Max on a Date)
**Intuition:** Suppose an exam asks for the "maximum number of suspected patients in a date." In SQL, you might group by date, order by count descending, and take `LIMIT 1`. Relational algebra has no `LIMIT` operator, so we compute the answer in two stages with $\gamma$: first we count patients per date, and then we take the maximum of those daily counts.

1. **Stage 1 (Group by Date and Count):** First we filter `History` for the target symptom, group the rows by `Date`, and count how many patients appeared on each date:

$$
T_{\text{daily}} \leftarrow {}_{\text{Date}}\gamma_{\text{count}(\text{Patient\_ID}) \ \text{as} \ \text{patient\_count}}(\sigma_{\text{condition}}(\text{History}))
$$

2. **Stage 2 (Overall Maximum):** Next we apply $\gamma_{\text{max}}$ across all rows of $T_{\text{daily}}$ (with no grouping column on the left of $\gamma$) to pull out the single highest daily count:

$$
\gamma_{\text{max}(\text{patient\_count})}(T_{\text{daily}})
$$

### Pattern 3: The "Only" Constraint Pattern (Set Difference)
**Intuition:** Why does $\sigma_{\text{dose\_no} = 1}(\text{vaccine})$ fail when a question asks for people who took the **"1st dose only"**? Because the `vaccine` table stores one row per dose! If Rahim took both Dose 1 and Dose 2, he has two rows in `vaccine`: one with `dose_no = 1` and another with `dose_no = 2`. Filtering for `dose_no = 1` still grabs Rahim's first row, even though he also took Dose 2.

To get people who took **only** Dose 1, we have to find everyone who took Dose 1 and **subtract** everyone who took Dose 2:

```text
All Dose 1 Recipients:              T_dose1 = Π_{id}(σ_{dose_no = 1}(vaccine))
All Dose 2 Recipients (Forbidden):  T_dose2 = Π_{id}(σ_{dose_no = 2}(vaccine))
Strictly Dose 1 Only:               T_only1 = T_dose1 - T_dose2
```

```text
          ┌──────────────────────────────────────────────┐
          │ T_dose1: All persons who received Dose 1     │
          │                                              │
          │   ┌────────────────┐      ┌──────────────┐   │
          │   │ Persons with   │      │ Persons who  │   │
          │   │ DOSE 1 ONLY    │      │ also took    │   │
          │   │ (Desired Set)  │      │ DOSE 2       │   │
          │   │                │      │ (Subtracted) │   │
          │   └────────────────┘      └──────────────┘   │
          └──────────────────────────────────────────────┘
```

#### Why We Must Project `id` Before Subtracting
Think about what would happen if you wrote $\sigma_{\text{dose\_no}=1}(\text{vaccine}) - \sigma_{\text{dose\_no}=2}(\text{vaccine})$ without projecting `id` first. A row in the first set has `dose_no = 1` and a date from January, while a row in the second set has `dose_no = 2` and a date from March. Because those two full rows are not identical, the set difference would subtract nothing! You must project both sets down to just $\Pi_{\text{id}}(\dots)$ first so that you are subtracting person IDs from person IDs.

## Worked Example: Combining Symptoms and Lab Outcomes

Consider a clinic database:
- $\text{Patient}(\text{Patient\_ID}, \text{Patient\_name}, \text{Age})$
- $\text{History}(\text{Patient\_ID}, \text{Symptom}, \text{Date})$
- $\text{Report}(\text{Patient\_ID}, \text{Corona\_center}, \text{Test\_result})$

### Problem Statement
Find the names of all patients who reported the symptom `"cough"` and tested `"positive"`, but who have **never** reported the symptom `"fever"`.

### Step-by-Step Derivation

1. **First, find patient IDs with a cough:** We filter `History` for `Symptom = "cough"` and project `Patient_ID`:

$$
T_{\text{cough}} \leftarrow \Pi_{\text{Patient\_ID}}(\sigma_{\text{Symptom} = \text{"cough"}}(\text{History}))
$$

2. **Next, find patient IDs with a positive test:** We filter `Report` for `Test_result = "positive"` and project `Patient_ID`:

$$
T_{\text{pos}} \leftarrow \Pi_{\text{Patient\_ID}}(\sigma_{\text{Test\_result} = \text{"positive"}}(\text{Report}))
$$

3. **Then, keep patients who have both:** We intersect $T_{\text{cough}}$ and $T_{\text{pos}}$ using $\cap$ so we keep only patient IDs present in both lists:

$$
T_{\text{cough\_and\_pos}} \leftarrow T_{\text{cough}} \cap T_{\text{pos}}
$$

4. **Next, find the forbidden set (patients with fever):** We filter `History` for `Symptom = "fever"` and project `Patient_ID`:

$$
T_{\text{fever}} \leftarrow \Pi_{\text{Patient\_ID}}(\sigma_{\text{Symptom} = \text{"fever"}}(\text{History}))
$$

5. **Then, remove anyone who ever had a fever:** We subtract $T_{\text{fever}}$ from $T_{\text{cough\_and\_pos}}$ using set difference ($-$):

$$
T_{\text{target\_ids}} \leftarrow T_{\text{cough\_and\_pos}} - T_{\text{fever}}
$$

6. **Finally, look up their names:** We natural-join `Patient` with $T_{\text{target\_ids}}$ on `Patient_ID` and project `Patient_name`:

$$
\Pi_{\text{Patient\_name}}(\text{Patient} \bowtie T_{\text{target\_ids}})
$$

### 🎯 GQ1 · 2019 Q.2(b) / 2024 Q.5(a) · Covid-19 Relational Database Queries

> **Appeared:** 2019 Q.2(b) (8 marks), 2024 Q.5(a) (4 marks, CO2) — (12 total marks)

**Question (2019 Q.2(b)):**

Consider the following relational database.  
`Patient (Patient_ID, Patient_name, Mobile)`  
`History (Patient_ID, Symptom, Date)`  
`Report (Parient_ID, Corona_center, Test_result)`

Now write down the relational algebra (Not SQL) to find out the following queries.  
(i) Find the names of those patients who have fever symptom.  
(ii) Consider that if any patient has high-fever symptom he/she will be suspected as corona patient. Find out such maximum number of patients in a date.  
(iii) Find out the mobile numbers of those patients who have provided samples in Rajshahi corona center and their results have become positive.  
(iv) Find out the name of those patients who have high fever symptom but test result have become negative.

*(Note: Printed as "Parient_ID" in Report schema in original question paper; refers to "Patient_ID")*

*(Sorting Note: Part ii uses $\gamma$ aggregation, see T04.4)*

**Question (2024 Q.5(a)):**

Consider the following relation database:  
Patient (Patient_ID, Patient_Name, Mobile)  
History (Patient_ID, Symptom, Date)  
Report (Patient_ID, Corona_center, Test_result)  
Now, write down the relational algebra (Not SQL) to find out the following queris:  
i) Find the names of those patients who have fever symptom  
ii) Find out the mobile numbers of those patients who have provided samples in Rangpur corona center and their results have become positive.  
*(Note: "relation database" and "queris" printed verbatim in original paper; refers to relational database and queries)*

**Full Answer:**

*Assumption: In relation `Report` (2019 paper), `Parient_ID` is a typo for `Patient_ID`.*

#### (i) Names of patients who have fever symptom

First we filter `History` using $\sigma$ for rows where `Symptom = "fever"`. Then we natural-join that result with `Patient` on `Patient_ID`, and finally we project `Patient_name`:

$$
\Pi_{\text{Patient\_name}}(\text{Patient} \bowtie \sigma_{\text{Symptom} = \text{"fever"}}(\text{History}))
$$

#### (ii) Maximum number of suspected patients (high-fever symptom) on a date

1. First we filter `History` using $\sigma$ to keep only rows where `Symptom = "high-fever"`:

$$
T_1 \leftarrow \sigma_{\text{Symptom} = \text{"high-fever"}}(\text{History})
$$

2. Next we group $T_1$ by `Date` using $\gamma$ and count `Patient_ID` to get the number of suspected patients for each date:

$$
T_{\text{daily}} \leftarrow {}_{\text{Date}}\gamma_{\text{count}(\text{Patient\_ID}) \ \text{as} \ \text{patient\_count}}(T_1)
$$

3. Finally, we apply $\gamma_{\text{max}}$ on `patient_count` to find the highest single-day count across all dates:

$$
\gamma_{\text{max}(\text{patient\_count})}(T_{\text{daily}})
$$

#### (iii) Mobile numbers of patients tested in Rajshahi corona center with positive results

1. First we filter `Report` for rows where `Corona_center = "Rajshahi"` and `Test_result = "positive"`:

$$
T_{\text{rajshahi\_pos}} \leftarrow \sigma_{\text{Corona\_center} = \text{"Rajshahi"} \land \text{Test\_result} = \text{"positive"}}(\text{Report})
$$

2. Next we natural-join `Patient` with $T_{\text{rajshahi\_pos}}$ on `Patient_ID`:

$$
T_{\text{patient\_contact}} \leftarrow \text{Patient} \bowtie T_{\text{rajshahi\_pos}}
$$

3. Finally, we project `Mobile` to output only their phone numbers:

$$
\Pi_{\text{Mobile}}(T_{\text{patient\_contact}})
$$

Or as a single one-line expression:

$$
\Pi_{\text{Mobile}}(\text{Patient} \bowtie \sigma_{\text{Corona\_center} = \text{"Rajshahi"} \land \text{Test\_result} = \text{"positive"}}(\text{Report}))
$$

#### (iv) Names of patients who have high fever symptom but negative test result

1. First we filter `History` for `Symptom = "high-fever"` and project `Patient_ID`:

$$
T_{\text{high}} \leftarrow \Pi_{\text{Patient\_ID}}(\sigma_{\text{Symptom} = \text{"high-fever"}}(\text{History}))
$$

2. Next we filter `Report` for `Test_result = "negative"` and project `Patient_ID`:

$$
T_{\text{neg}} \leftarrow \Pi_{\text{Patient\_ID}}(\sigma_{\text{Test\_result} = \text{"negative"}}(\text{Report}))
$$

3. Finally, we intersect $T_{\text{high}}$ and $T_{\text{neg}}$ using $\cap$ to find patient IDs in both sets, natural-join with `Patient`, and project `Patient_name`:

$$
\Pi_{\text{Patient\_name}}(\text{Patient} \bowtie (T_{\text{high}} \cap T_{\text{neg}}))
$$

#### Adaptation for 2024 Q.5(a)

The 2024 paper asks the exact same schema with two sub-questions:
- **Part (i)** is identical to Part (i) above (only the column capitalization is `Patient_Name`):

$$
\Pi_{\text{Patient\_Name}}(\text{Patient} \bowtie \sigma_{\text{Symptom} = \text{"fever"}}(\text{History}))
$$

- **Part (ii)** is identical to Part (iii) above, except the center is `"Rangpur"` instead of `"Rajshahi"`:

$$
\Pi_{\text{Mobile}}(\text{Patient} \bowtie \sigma_{\text{Corona\_center} = \text{"Rangpur"} \land \text{Test\_result} = \text{"positive"}}(\text{Report}))
$$

### 🎯 GQ2 · 2020 Q.2(a) · Vaccine Tracking Database & Dose-1 Only Filter

> **Appeared:** 2020 Q.2(a) — (6 marks)

**Question:**

Consider the following relation schema:  
  person(<u>id</u>, name, age)  
  vaccine(<u>id</u>, center, dose_no, date)  
Now give expression in relational algebra to express-  
(i) Find the names of all persons who are adult.  
(ii) Find the names of all persons who have taken the $1^{\text{st}}$ dose only.  
(iii) Find the details of all persons who were given vaccine from "RMC" center and completed $2^{\text{nd}}$ dose.

**Full Answer:**

*Assumption: A person is considered an adult when $\text{age} \ge 18$, and `vaccine.id` is a foreign key referencing `person.id`.*

#### (i) Names of all adult persons

First we filter `person` using $\sigma$ for rows with `age >= 18`, and then we project `name`:

$$
\Pi_{\text{name}}(\sigma_{\text{age} \ge 18}(\text{person}))
$$

#### (ii) Names of all persons who have taken the $1^{\text{st}}$ dose only

Because a person who took both doses has both a `dose_no = 1` row and a `dose_no = 2` row in `vaccine`, we must project the IDs for each dose and subtract the Dose 2 IDs from the Dose 1 IDs:

1. First we filter `vaccine` for `dose_no = 1` and project `id`:

$$
T_{\text{dose1}} \leftarrow \Pi_{\text{id}}(\sigma_{\text{dose\_no} = 1}(\text{vaccine}))
$$

2. Next we filter `vaccine` for `dose_no = 2` and project `id`:

$$
T_{\text{dose2}} \leftarrow \Pi_{\text{id}}(\sigma_{\text{dose\_no} = 2}(\text{vaccine}))
$$

3. Then we subtract $T_{\text{dose2}}$ from $T_{\text{dose1}}$ using $-$ so only people who never took Dose 2 remain:

$$
T_{\text{only1}} \leftarrow T_{\text{dose1}} - T_{\text{dose2}}
$$

4. Finally, we natural-join `person` with $T_{\text{only1}}$ on `id` and project `name`:

$$
\Pi_{\text{name}}(\text{person} \bowtie T_{\text{only1}})
$$

Or as a single nested expression:

$$
\Pi_{\text{name}}(\text{person} \bowtie (\Pi_{\text{id}}(\sigma_{\text{dose\_no} = 1}(\text{vaccine})) - \Pi_{\text{id}}(\sigma_{\text{dose\_no} = 2}(\text{vaccine}))))
$$

#### (iii) Details of all persons vaccinated from "RMC" center who completed $2^{\text{nd}}$ dose

1. First we filter `vaccine` for rows where `center = "RMC"` and `dose_no = 2`:

$$
T_{\text{rmc2}} \leftarrow \sigma_{\text{center} = \text{"RMC"} \land \text{dose\_no} = 2}(\text{vaccine})
$$

2. Next we natural-join `person` with $T_{\text{rmc2}}$ on `id` to get the full details:

$$
\text{person} \bowtie T_{\text{rmc2}}
$$

If you want to output only the columns from the `person` table (`id, name, age`), wrap the join in a projection:

$$
\Pi_{\text{person.id}, \text{name}, \text{age}}(\text{person} \bowtie T_{\text{rmc2}})
$$

## ⚡ Exam Tips & Common Mistakes

1. **Never Confuse Set Difference with Attribute Selection:** To find entities that have property A *only*, you must subtract entities having property B. Writing $\sigma_{\text{dose\_no} = 1}(\text{vaccine})$ is the most common student error. It fails because two-dose recipients also satisfy that selection predicate.
2. **Project Identifiers Before Set Operations:** You cannot perform set difference or intersection directly between relations with different columns (such as `person` and `vaccine`). Project both relations down to the common primary key `id` first.
3. **State Age Threshold Explicitly:** Exam questions asking for "adult" do not define the numeric age. Always state `age >= 18` as an explicit assumption line before writing your algebraic expression.
4. **Use Set Intersection for Joint Diagnoses:** In queries asking for patients with "symptom X but lab result Y", project patient IDs from both tables and intersect them ($T_X \cap T_Y$). Do not attempt to join symptom strings with test outcome strings.
5. **Handle Schema Typos Calmly:** When exam scripts include misspelled column names like `Parient_ID`, write an assumption and proceed. Never stop writing or leave marks on the table.
