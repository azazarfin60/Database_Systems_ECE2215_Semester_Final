# T05.1: What Is SQL?

> **Topic:** T05 — SQL (DDL, DML, Aggregates, Subqueries) | **Priority:** 🟢 | **Exam Frequency:** 1/7 finals (2 marks)
> **Sources:** Silberschatz 7e Ch. 3 (§3.1 pp. 65–66) · Lecture Deck 03 (Slides 3–4) · Classnote by Raidah (Pages 2–4)

## Why This Topic Matters

SQL is the standard language used by almost every relational database in the world, and Topic T05 is the single largest topic on the RUET syllabus, accounting for 130 final exam marks (over 20% of the entire course). In 2019 Q.5(a), examiners asked a direct 2-mark short note on SQL. Knowing its history, its declarative nature, and its four sublanguages (DDL, DML, DCL, and TCL) gives you the big picture before writing complex queries.

---

## 📝 Key Definitions

> **SQL (Structured Query Language):** SQL is the standard declarative language for relational databases. IBM originally developed it as Sequel in the early 1970s. It lets users create schemas, query tables, update rows, and manage database security.

> **Data-Definition Language (DDL):** DDL is the subset of SQL used to build and modify the structure of database tables and schemas. Its main commands are `CREATE`, `ALTER`, `DROP`, and `TRUNCATE`. It also defines integrity constraints and indexes on tables.

> **Data-Manipulation Language (DML):** DML is the subset of SQL used to read and change the data stored inside tables. Its main commands are `SELECT`, `INSERT`, `UPDATE`, and `DELETE`. Unlike DDL, DML works on table rows rather than table definitions.

> **Declarative Query Language:** A declarative query language lets the user state what data they want without specifying how to fetch it step by step. The database query optimizer figures out the fastest execution plan automatically. SQL is a declarative language.

---

## Historical Evolution of SQL

Lecture Deck 03 (Slide 3) and Silberschatz §3.1 trace how SQL became the industry standard:

1. **System R and Sequel (Early 1970s):** Donald Chamberlin and Raymond Boyce developed the original language at IBM's San Jose Research Laboratory as part of the System R project, designing it so users could query tables with readable English keywords.
2. **Name Change to SQL:** Because "Sequel" (Structured English QUEry Language) was already an existing trademark, IBM shortened the name to **SQL** (Structured Query Language).
3. **ANSI and ISO Standards:**
   - **SQL-86 & SQL-89:** The first official ANSI/ISO standards, which established basic queries and integrity constraints.
   - **SQL-92:** A major expansion that still forms the backbone of everyday SQL syntax.
   - **SQL:1999:** Added triggers, recursive queries, and regular expressions.
   - **SQL:2003 through SQL:2016:** Added XML support, window functions, and JSON features.

## The Core Components of SQL

### Intuitive Analogy: Building and Running an Apartment Building

Even though the name says "Query Language", SQL does much more than just read data. You can picture its four main sublanguages like managing an apartment building:
- **DDL (Data Definition Language)** is the **architect and construction crew**: it builds the rooms (`CREATE`), remodels walls (`ALTER`), or demolishes a structure (`DROP`).
- **DML (Data Manipulation Language)** is the **moving crew and directory**: it moves tenants in (`INSERT`), updates their details (`UPDATE`), moves them out (`DELETE`), or looks up who lives where (`SELECT`).
- **DCL (Data Control Language)** is the **security desk**: it hands out keycards (`GRANT`) or takes them back (`REVOKE`).
- **TCL (Transaction Control Language)** is the **checkpoint log**: it makes a batch of changes permanent (`COMMIT`) or hits undo if something goes wrong (`ROLLBACK`).

```text
+-------------------------------------------------------------------+
|                   SQL (Structured Query Language)                 |
+-------------------------------------------------------------------+
| 1. DDL: Data Definition Language (Schemas, Tables, Alter, Drop)   |
| 2. DML: Data Manipulation Language (Select, Insert, Update)      |
| 3. DCL: Data Control Language (Grant, Revoke Permissions)         |
| 4. TCL: Transaction Control Language (Commit, Rollback)           |
| 5. Integrity Constraints (Primary Key, Foreign Key, Check)        |
| 6. View Definition (Create View, Materialized Views)              |
| 7. Embedded & Dynamic SQL (Interfacing C, C++, Java, Python)     |
+-------------------------------------------------------------------+
```

### Breakdown of SQL Sublanguages

| Sublanguage | Primary Role | Key Commands | What It Modifies |
| :--- | :--- | :--- | :--- |
| **DDL** (Data Definition Language) | Defines and modifies database schemas and table structures. | `CREATE`, `ALTER`, `DROP`, `TRUNCATE` | Database catalog (metadata) |
| **DML** (Data Manipulation Language) | Queries, inserts, updates, and deletes rows inside tables. | `SELECT`, `INSERT`, `UPDATE`, `DELETE` | Table data (relation instances) |
| **DCL** (Data Control Language) | Manages user permissions and security access control. | `GRANT`, `REVOKE` | Security catalog / user roles |
| **TCL** (Transaction Control Language) | Controls transaction boundaries and guarantees atomicity. | `COMMIT`, `ROLLBACK`, `SAVEPOINT` | Transaction log / buffer states |

### Additional Built-In Features

Beyond those four sublanguages, the SQL standard also provides:
1. **Integrity Enforcement:** Clauses inside DDL (`PRIMARY KEY`, `FOREIGN KEY`, `NOT NULL`, `UNIQUE`, `CHECK`) that automatically reject any data update that breaks your business rules.
2. **View Definition:** Commands (`CREATE VIEW`) that let you save a query as a virtual table to simplify reporting or hide sensitive columns like salaries.
3. **Authorization:** Fine-grained rules specifying which users can read, insert, update, or delete specific tables and views.
4. **Embedded and Dynamic SQL:** Connectors (such as JDBC, ODBC, or Python DB-API) that let general-purpose programming languages like C, C++, Java, and Python run SQL queries.

## Declarative vs. Procedural Programming

SQL is a **declarative (non-procedural)** language. That means you tell the database *what* result you want to see, and the database figures out *how* to fetch it as fast as possible.

### Comparison Table

| Feature | Declarative Language (SQL) | Procedural Language (C, C++, Java) |
| :--- | :--- | :--- |
| **User Focus** | Describes **what** data is needed. | Describes **how** to compute the result step by step. |
| **Control Flow** | No explicit `for`/`while` loops or memory pointers in standard queries. | Uses explicit loops, branches, and memory structures. |
| **Optimization** | The DBMS query optimizer automatically picks the fastest plan. | The programmer must manually design fast algorithms. |
| **Execution Path** | Engine decides whether to use a B+-tree index or a full table scan. | Code dictates the exact step-by-step traversal in memory. |
| **Unit of Operation** | Operates on entire sets of rows at once. | Processes one variable or array element at a time. |

## Fundamental SQL Data Types

When you create a table in SQL (Lecture Deck 03, Slide 6), every column is assigned a domain data type:

- **`CHAR(n)`:** Fixed-length text string of exactly $n$ characters. If you store a shorter word, SQL pads the remaining space with blanks.
- **`VARCHAR(n)`:** Variable-length text string up to $n$ characters long. It stores only the characters you type without padding extra spaces.
- **`INT` / `INTEGER`:** Full-sized whole number.
- **`SMALLINT`:** Smaller whole number that uses less memory.
- **`NUMERIC(p, d)` / `DECIMAL(p, d)`:** Exact fixed-point decimal number with $p$ total digits and $d$ digits after the decimal point. For example, `NUMERIC(4, 2)` stores `45.80` with zero rounding error.
- **`REAL`, `DOUBLE PRECISION`:** Approximate floating-point numbers for scientific data.
- **`FLOAT(n)`:** Floating-point number with at least $n$ digits of precision.
- **`DATE`, `TIME`, `TIMESTAMP`:** Calendar date (`YYYY-MM-DD`), clock time (`HH:MM:SS`), and combined date-plus-time values.

## How to Structure a 2-Mark Short Note on SQL

When an exam question asks you to "Write a short note on SQL" for 2 marks, use this four-point checklist so you hit every grading keyword in under three minutes:

1. **Name and Origin:** Write out *Structured Query Language* and mention that it originated as *Sequel* in IBM's System R project in the 1970s before being standardized by ANSI and ISO.
2. **Declarative Nature:** State clearly that SQL is declarative, meaning the user specifies *what* data is wanted while the DBMS query optimizer decides *how* to retrieve it.
3. **Four Sublanguages:** List DDL, DML, DCL, and TCL along with 2–3 example commands for each.
4. **Extra Capabilities:** Briefly mention integrity constraints, view definitions, and embedded SQL.

## 🏆 Golden Questions (Past Exam Archive)

### 🎯 GQ1 · 2019 Q.5(a) · Short Note on SQL

> **Appeared:** 2019 Q.5(a) — (02 Marks | Sec B)

> **Question:**
>
> Write a short note on SQL.

**Full Answer:**

**SQL (Structured Query Language)** is the standard declarative language used to define, query, and manage data in relational database management systems (RDBMS). Originally developed by IBM in the early 1970s under the name *Sequel* for the System R project, it is now standardized by ANSI and ISO.

SQL is divided into four core sublanguages:
1. **Data Definition Language (DDL):** Defines and modifies table schemas, data types, and integrity constraints (`CREATE`, `ALTER`, `DROP`, `TRUNCATE`).
2. **Data Manipulation Language (DML):** Queries and modifies rows stored inside tables (`SELECT`, `INSERT`, `UPDATE`, `DELETE`).
3. **Data Control Language (DCL):** Manages user security permissions and access rights (`GRANT`, `REVOKE`).
4. **Transaction Control Language (TCL):** Controls atomic transactions so changes can be saved or undone safely (`COMMIT`, `ROLLBACK`, `SAVEPOINT`).

Because SQL is a **declarative** language, the user only specifies *what* data is needed, and the DBMS query optimizer automatically chooses the most efficient execution plan to retrieve it.

### 🎯 GQ2 · Likely Exam Question · DDL vs. DML Distinctions

> **Appeared:** Likely Question (Silberschatz 7e Ch. 3 §3.1 & Lecture Deck 03) — (03 Marks)

> **Question:**
>
> Distinguish between Data Definition Language (DDL) and Data Manipulation Language (DML) in SQL. Provide two distinct command examples for each.

**Full Answer:**

| Comparison Parameter | Data Definition Language (DDL) | Data Manipulation Language (DML) |
| :--- | :--- | :--- |
| **Primary Purpose** | Defines, alters, and removes database schemas and tables. | Retrieves, inserts, modifies, and deletes data rows inside tables. |
| **Target of Operation** | Operates on the database schema and system catalog (metadata). | Operates on the actual data tuples stored inside relations. |
| **Effect on Table Structure** | Changes column definitions, data types, and constraints. | Leaves the table structure unchanged and affects only stored rows. |
| **Transaction Behavior** | Auto-commits immediately in most database engines. | Can be committed or rolled back using `COMMIT` and `ROLLBACK`. |
| **Standard Commands** | `CREATE TABLE`, `ALTER TABLE`, `DROP TABLE`, `TRUNCATE` | `SELECT`, `INSERT`, `UPDATE`, `DELETE` |

**Command Examples:**
- **DDL Examples:**
  ```sql
  CREATE TABLE instructor (ID CHAR(5), name VARCHAR(20), salary NUMERIC(8,2));
  ALTER TABLE instructor ADD dept_name VARCHAR(20);
  ```
- **DML Examples:**
  ```sql
  INSERT INTO instructor VALUES ('10101', 'Srinivasan', 65000, 'Comp. Sci.');
  SELECT name FROM instructor WHERE salary > 60000;
  ```

### 🎯 GQ3 · Likely Exam Question · Why SQL Is Declarative

> **Appeared:** Likely Question (Silberschatz 7e Ch. 2 §2.5 & Ch. 3 §3.1) — (03 Marks)

> **Question:**
>
> Why is SQL referred to as a declarative query language, and how does the DBMS execute declarative SQL statements?

**Full Answer:**

SQL is called a declarative query language because users state **what** data they want to see without writing step-by-step instructions on **how** the computer should search disk files or memory to find it.

In a procedural language like C or Java, a programmer must write explicit loops to open a file, scan records one by one, and check conditions. In SQL, the user simply writes a declarative statement:

```sql
SELECT name FROM student WHERE dept_name = 'ECE';
```

**How the DBMS Executes a Declarative SQL Query:**
1. **Parsing and Translation:** The parser checks the SQL syntax and translates the query into an internal relational algebra expression tree.
2. **Query Optimization:** The query optimizer compares different ways to run the tree (for example, using a B+-tree index versus scanning the whole table) and uses table statistics to pick the lowest-cost plan.
3. **Evaluation:** The execution engine runs the chosen physical plan, reads the needed disk pages into buffer memory, and returns the matching rows to the user.

## ⚡ Exam Tips & Common Mistakes

1. **Never say SQL only queries data:** A very common mistake is writing that SQL is "just a language for selecting rows". Always mention that SQL also defines schemas (DDL), controls permissions (DCL), and manages transactions (TCL).
2. **Remember that `TRUNCATE` is DDL, not DML:** Even though `TRUNCATE TABLE` empties all rows from a table, it is classified as a DDL command because it drops and re-allocates the data pages at the storage level rather than deleting rows one by one.
3. **Include the System R history:** Mentioning IBM's System R project and the original name *Sequel* makes your 2-mark short note stand out immediately.
4. **Use the "what vs. how" phrase:** Whenever you explain declarative languages, include the contrast: *"Users specify **what** data they want, not **how** to compute it."*
