# T05.5b: Weighted CGPA and Extremes Without LIMIT

> **Topic:** T05 — SQL (DDL, DML, Aggregates, Subqueries) | **Priority:** 🟠 | **Exam Frequency:** 3/7 finals + CT-02 (24 marks total) | Flagship 12m & 4m Problems

## Why This Topic Matters

RUET semester finals frequently test two advanced SQL patterns: multi-table weighted formula calculations (CGPA) and dynamic ranking without vendor-specific keywords like `LIMIT`. The 12-mark flagship question in 2019 Q.7(a) and the 2024 Q.1(c) problem test multi-table joins, mathematical aggregation ratios, and subquery comparisons. ## 📝 Key Definitions

> **Subquery:** "A subquery is a select-from-where expression that is nested within another query. A common use of subqueries is to perform tests for set membership, make set comparisons, and determine set cardinality, by nesting a subquery in the where clause." — Silberschatz, Korth & Sudarshan, *Database System Concepts* (7th Ed.), §3.8 (p. 98)

> **Set Comparison (> all):** "The construct > all corresponds to the phrase 'greater than all.' ... As it does for some, SQL also allows < all, <= all, >= all, = all, and <> all comparisons." — Silberschatz, Korth & Sudarshan, *Database System Concepts* (7th Ed.), §3.8.2 (p. 100)

> **Scalar Subquery:** "SQL allows subqueries to occur wherever an expression returning a value is permitted, provided the subquery returns only one tuple containing a single attribute; such subqueries are called scalar subqueries." — Silberschatz, Korth & Sudarshan, *Database System Concepts* (7th Ed.), §3.8.7 (p. 106)

## Pattern 1: Weighted CGPA Calculation Across Joined Tables

Unlike a simple average (`AVG(gpa)`), an academic Cumulative Grade Point Average (CGPA) weights each course grade by its credit hours. That means a 3.00-credit theory course counts twice as much toward a student's CGPA as a 1.50-credit lab course:

$$
\text{CGPA} = \frac{\sum (\text{GPA} \times \text{Credit})}{\sum \text{Credit}}
$$

### The Three-Table Relational Architecture

In normalized university schemas (like 2017 Q.4(a) and 2019 Q.7(a)), the data needed for this formula is split across three separate tables:
1. **`Student (St_ID, St Name)`**: Stores student identity details.
2. **`GPA (St_ID, Sub_Code, gpa)`**: Records the grade point a student earned in each subject.
3. **`Credit (Sub_Code, Credit)`**: Lists the credit hours assigned to each subject code.

```sql
SELECT s.St_ID,
       s.`St Name`,
       SUM(g.gpa * c.Credit) / SUM(c.Credit) AS cgpa
FROM Student s
JOIN GPA g ON s.St_ID = g.St_ID
JOIN Credit c ON g.Sub_Code = c.Sub_Code
GROUP BY s.St_ID, s.`St Name`;
```

### Step-by-Step Execution Mechanics

1. **Joining the Three Tables:**
   First, we join `Student` with `GPA` on `St_ID` to pair each student with the courses they took. Next, we join that result with `Credit` on `Sub_Code` so every course row now knows both the grade earned (`g.gpa`) and the course credit weight (`c.Credit`).
2. **Grouping by Student Identity:**
   Adding `GROUP BY s.St_ID, s.`St Name`` gathers all course rows for a single student into one bucket. Remember the cardinal rule of grouping: because both `s.St_ID` and ``s.`St Name` `` appear in `SELECT` outside the `SUM()` functions, both must be listed in `GROUP BY`.
3. **Computing the Weighted Ratio:**
   Inside each student's group, SQL multiplies `g.gpa * c.Credit` for every course and adds them up via `SUM(g.gpa * c.Credit)` to get the numerator (total quality points). Then it divides by `SUM(c.Credit)` (total credits taken) to produce the exact weighted CGPA.

### Handling Column Names with Spaces in MySQL

In the 2019 Q.7(a) exam paper, the student name column is printed with a space as `St Name`. Because standard SQL treats a space as the end of an identifier, writing `s.St Name` directly causes a syntax error. In MySQL, you must wrap any column name containing spaces or special characters in backticks (`` s.`St Name` ``).

## Pattern 2: Finding Extremes Without LIMIT

Exam prompts often include the strict instruction: *"without using LIMIT"*. Knowing why examiners ban `LIMIT` makes it much easier to remember the right subquery pattern.

### Why Examiners Forbid LIMIT

1. **Non-Standard Vendor Syntax:**
   The `LIMIT` keyword is not part of core ANSI SQL. While MySQL and PostgreSQL support `LIMIT`, Oracle uses `ROWNUM` or `FETCH FIRST n ROWS ONLY`, and Microsoft SQL Server uses `SELECT TOP n`. Because university exams test standard relational concepts rather than vendor-specific shortcuts, they require standard subquery solutions that run on any database engine.
2. **The Tie Problem (Data Integrity):**
   Even in MySQL, `LIMIT 1` gives an incomplete answer whenever there is a tie. For example, suppose three students tie for the lowest GPA in the class with `3.00`. Running `ORDER BY gpa ASC LIMIT 1` chops off the output after the first row and hides the other two tied students. In contrast, a relational query using `MIN()` or `MAX()` inside a subquery returns all three tied students fairly.

### Method A: Absolute Minimum or Maximum Using Scalar Subqueries

To find everyone who holds the lowest or highest score, compare the column against a scalar subquery that computes `MIN()` or `MAX()`:

```sql
-- Lowest GPA (returns all tied students)
SELECT s.St_ID, s.`St Name`, g.Sub_Code, g.gpa
FROM Student s
JOIN GPA g ON s.St_ID = g.St_ID
WHERE g.gpa = (
    SELECT MIN(gpa)
    FROM GPA
);
```

**How it works:**
First, the inner query `(SELECT MIN(gpa) FROM GPA)` scans the `GPA` table once and returns a single number (say, `3.00`). Then the outer query checks every student's row against `WHERE g.gpa = 3.00`, keeping every student who tied for that lowest score.

### Method B: Second-Highest Value Using Nested MAX

Intuitively, how do you find the runner-up (second-highest score) in a class? You temporarily ignore everyone who got the #1 top score, and then find the highest score among everyone left over:

$$
\text{Second Highest} = \max \{ x \in S \mid x < \max(S) \}
$$

In SQL, we write this directly by nesting one `MAX()` subquery inside another:

```sql
SELECT *
FROM STUDENT
WHERE CGPA = (
    SELECT MAX(CGPA)
    FROM STUDENT
    WHERE CGPA < (
        SELECT MAX(CGPA)
        FROM STUDENT
    )
);
```

**How it works from the inside out:**
- **Innermost query:** `SELECT MAX(CGPA) FROM STUDENT` finds the #1 highest CGPA in the table (for example, `4.00`).
- **Middle query:** `SELECT MAX(CGPA) FROM STUDENT WHERE CGPA < 4.00` looks at everyone strictly below `4.00` and finds the highest CGPA in that remaining group (for example, `3.85`).
- **Outer query:** `WHERE CGPA = 3.85` returns every student who earned that second-highest CGPA, automatically handling ties.

### Method C: Correlated Subquery Counting Higher Distinct Values

What if an exam asks for the 3rd-highest or $N$-th highest value, where nesting `MAX()` over and over becomes messy? Think about what makes a score the $N$-th highest: there are exactly $N - 1$ distinct scores in the table that are strictly greater than it:

$$
(N - 1) = \left| \{ y \in S \mid y > x \} \right|
$$

For example, the 1st-highest score has `0` distinct scores above it, and the 2nd-highest score has `1` distinct score above it:

```sql
-- Finding the 2nd highest CGPA (N = 2, so N - 1 = 1)
SELECT *
FROM STUDENT s1
WHERE 1 = (
    SELECT COUNT(DISTINCT s2.CGPA)
    FROM STUDENT s2
    WHERE s2.CGPA > s1.CGPA
);
```

## Pattern 3: Grouped Averages and Extremes Per Course

When a question asks for the highest GPA or average grade *for each subject* rather than across the entire university, we do not need a subquery at all. Instead, we partition the table by course code with `GROUP BY` and apply `MAX()` or `AVG()` directly:

```sql
-- Highest GPA per subject code
SELECT Sub_Code,
       MAX(gpa) AS highest_gpa
FROM GPA
GROUP BY Sub_Code;

-- Average grade per course
SELECT CID,
       AVG(Grade) AS avg_grade
FROM ENROLLMENT
GROUP BY CID;
```

### 🎯 GQ2 · 2024 Q.1(c) · Average Grade Per Course

> **Appeared:** 2024 Q.1(c) — (04 Marks | Sec A | CO2)

**Question:**

STUDENT (SID, Name, Age, Major)  
COURSE (CID, Title, Credits)  
ENROLLMENT (SID, CID, Grade)  
Using the above schema, write a SQL query to find the average grade for each course.

**Full Answer:**

#### 1. Schema Analysis
- `STUDENT (SID, Name, Age, Major)`: Not required for this query.
- `COURSE (CID, Title, Credits)`: Holds course title and credits.
- `ENROLLMENT (SID, CID, Grade)`: Contains course identifier (`CID`) and numeric student grade (`Grade`).
- Grouping by `CID` on `ENROLLMENT` computes the arithmetic mean grade per course directly.

#### 2. SQL Query (Direct Version)

```sql
SELECT CID,
       AVG(Grade) AS avg_grade
FROM ENROLLMENT
GROUP BY CID;
```

#### 3. SQL Query (Joined Version with Course Title)
If the query must display descriptive course titles alongside the course IDs:

```sql
SELECT c.CID,
       c.Title,
       AVG(e.Grade) AS avg_grade
FROM COURSE c
JOIN ENROLLMENT e ON c.CID = e.CID
GROUP BY c.CID, c.Title;
```

#### 4. Trace Verification
Suppose `ENROLLMENT` contains:
- `('S01', 'ECE2215', 3.50)`
- `('S02', 'ECE2215', 4.00)`
- `('S01', 'ECE2205', 3.75)`

Group `'ECE2215'` evaluates to $\frac{3.50 + 4.00}{2} = 3.75$.
Group `'ECE2205'` evaluates to $3.75$.

### 🎯 GQ3 · CT-02 Q.01(d) · Second-Highest CGPA Without LIMIT

> **Appeared:** CT-02 Q.01(d) — (03 Marks | CO2)

**Question:**

Given $\text{STUDENT}(\text{StudentID}, \text{Name}, \text{Department}, \text{Semester}, \text{CGPA})$, write SQL query:  
**(d)** Display the students having the second-highest CGPA without using LIMIT.

**Full Answer:**

```sql
SELECT *
FROM STUDENT
WHERE CGPA = (
    SELECT MAX(CGPA)
    FROM STUDENT
    WHERE CGPA < (
        SELECT MAX(CGPA)
        FROM STUDENT
    )
);
```

#### Step-by-Step Logic:
1. `SELECT MAX(CGPA) FROM STUDENT`: Locates the highest CGPA across all students.
2. `WHERE CGPA < (SELECT MAX(CGPA) FROM STUDENT)`: Filters out all students who achieved the top rank.
3. `SELECT MAX(CGPA) ...`: Computes the highest CGPA among the remaining students. This is the true second-highest CGPA.
4. The outer query retrieves all student records matching this second-highest value. If multiple students tie for second place, all tied records are returned.

```sql
SELECT i.roll,
       i.name,
       SUM(m.gpa * c.credit) / SUM(c.credit) AS cgpa
FROM INFO i
JOIN MARKS m ON i.roll = m.roll
JOIN CREDIT c ON m.sub_code = c.sub_code

```

- Total Registered Credits: $3.00 + 3.00 = 6.00$
- Calculated CGPA: $\frac{21.75}{6.00} = 3.625$

### 🎯 HYE-01 · Practice Exercise 3.2 · SQL CGPA Calculation with Grade Points Mapping

> **Source:** Silberschatz 7e · Chapter 3 (Practice Exercise 3.2)  
> **Exam Relevance:** Prime Overdue RUET Classic Drill (Appeared in 2019 Q.3(b), 2024 Q.3(a))  
> **Key Tested Concept:** Multi-table join, `CASE` statement grade mapping, and weighted GPA formula: $\frac{\sum (\text{points} \times \text{credits})}{\sum \text{credits}}$.

**Problem Statement:**
> Using the university database schema:
> - $\text{student}(\underline{\text{ID}}, \text{name}, \text{dept\_name}, \text{tot\_cred})$
> - $\text{takes}(\underline{\text{ID}, \text{course\_id}, \text{sec\_id}, \text{semester}, \text{year}}, \text{grade})$
> - $\text{course}(\underline{\text{course\_id}}, \text{title}, \text{dept\_name}, \text{credits})$
> Assume letter grades map to numerical grade points as follows: `'A'` = 4.0, `'B'` = 3.0, `'C'` = 2.0, `'D'` = 1.0, and `'F'` = 0.0.
> Write an SQL query to compute the **Cumulative Grade Point Average (CGPA)** for every student who has taken at least one course, displaying the student's `ID`, `name`, and calculated `CGPA`.

**Model Exam-Style Solution:**

```sql
SELECT 
    s.ID,
    s.name,
    ROUND(
        SUM(
            CASE t.grade
                WHEN 'A' THEN 4.0
                WHEN 'B' THEN 3.0
                WHEN 'C' THEN 2.0
                WHEN 'D' THEN 1.0
                ELSE 0.0
            END * c.credits
        ) / SUM(c.credits), 
        2
    ) AS CGPA
FROM student s
JOIN takes t ON s.ID = t.ID
JOIN course c ON t.course_id = c.course_id
WHERE t.grade IS NOT NULL
GROUP BY s.ID, s.name;
```

**Step-by-Step Logic:**
1. **Three-Table Join:** Joins `student` to `takes` on `ID`, and `takes` to `course` on `course_id` to access student names, grades, and course credit weights.
2. **`CASE` Expression:** Converts categorical letter grades into numerical grade point values dynamically.
3. **Credit Weighting:** Multiplies each course's grade point by its corresponding `c.credits`.
4. **Weighted Formula:** Divides total earned grade points $\sum(\text{points} \times \text{credits})$ by total registered credits $\sum(\text{credits})$.
5. **`GROUP BY`:** Groups by `s.ID` and `s.name` to produce a single aggregated row per student.

**💡 RUET Exam Takeaway:**
Always filter out `WHERE t.grade IS NOT NULL`! Students currently taking courses with null grades will skew both the numerator and denominator if null checks are omitted.

### 🎯 HYE-02 · Exercise 3.35 · Maximum Enrollment Section Without `LIMIT`

> **Source:** Silberschatz 7e · Chapter 3 (Exercise 3.35)  
> **Exam Relevance:** Prime Overdue Exam Question (Strict RUET Constraint: "Without using LIMIT")  
> **Key Tested Concept:** Finding extreme records using `>= ALL` subqueries and `HAVING count(*) >= (SELECT MAX...)`.

**Problem Statement:**
> Using the university database relation:
> - $\text{takes}(\underline{\text{ID}, \text{course\_id}, \text{sec\_id}, \text{semester}, \text{year}}, \text{grade})$
> Write an SQL query to find the section (or sections in case of a tie) that had the **maximum number of students enrolled**, without using the `LIMIT` or `TOP` clause. Display `course_id`, `sec_id`, `semester`, `year`, and total student enrollment count.

**Model Exam-Style Solution:**

**Method 1: Using `HAVING` with Subquery Aggregation (Standard ANSI SQL):**
```sql
SELECT 
    course_id, 
    sec_id, 
    semester, 
    year, 
    COUNT(ID) AS enrollment_count
FROM takes
GROUP BY course_id, sec_id, semester, year
HAVING COUNT(ID) >= ALL (
    SELECT COUNT(ID)
    FROM takes
    GROUP BY course_id, sec_id, semester, year
);
```

**Method 2: Using Derived Table / `WITH` Clause (MySQL 8.0+ Compatible):**
```sql
WITH SectionEnrollment AS (
    SELECT 
        course_id, 
        sec_id, 
        semester, 
        year, 
        COUNT(ID) AS enrollment_count
    FROM takes
    GROUP BY course_id, sec_id, semester, year
)
SELECT *
FROM SectionEnrollment
WHERE enrollment_count = (
    SELECT MAX(enrollment_count) 
    FROM SectionEnrollment
);
```

**Step-by-Step Logic:**
1. Group `takes` tuples by section primary key components (`course_id, sec_id, semester, year`).
2. In Method 1, `HAVING COUNT(ID) >= ALL (...)` evaluates the count against every other section's count, selecting only those sections whose enrollment is greater than or equal to all others.
3. Automatically handles ties: If three sections each have 50 students, all three are returned.

**💡 RUET Exam Takeaway:**
When RUET question papers explicitly write: *"Find the maximum ... without using LIMIT"*, examiners are specifically testing your ability to use **`>= ALL`** or **`HAVING count = (SELECT MAX ...)`**.

## ⚡ Exam Tips & Common Mistakes

1. **Backticks on Column Names with Spaces:** If the question defines attributes like `` `St Name` `` or `` `Hrs. Billed` ``, always wrap them in backticks.
2. **Never Hardcode Extrema:** In 2019 Q.7(a)(i), writing `WHERE gpa = 3.00` receives 0 marks. The minimum must be computed dynamically using `(SELECT MIN(gpa) FROM GPA)`.
3. **Avoid Unnecessary Table Joins:** In 2024 Q.1(c), joining `STUDENT` is redundant. The attributes `CID` and `Grade` reside entirely within `ENROLLMENT`.
4. **Group By Projection Integrity:** When calculating CGPA per student, ensure all non-aggregated columns in `SELECT` (`s.St_ID`, `s.Name`) appear in the `GROUP BY` clause.
5. **Always Use Scalar Subqueries for Extremes:** When `LIMIT` is forbidden or ties are possible, write `WHERE col = (SELECT MIN/MAX(col) FROM ...)`.
