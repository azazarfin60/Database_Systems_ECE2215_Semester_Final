## Modeling Real-World Transactions: Entities vs. Relationships

**Entity Sets vs. Relationship Sets:** In E-R design, a simple connection between nouns is modeled as a relationship diamond. When an action possesses its own tracking identifier, multiple descriptive attributes, or links more than two entities, it is modeled as an independent entity set.

**Descriptive Attribute:** An attribute attached to a relationship set rather than an entity set. It records data about the connection itself, such as `booking_date` on a booking link or `arrival_time` on a train stop.

**Mapping Cardinality:** The maximum number of entities to which another entity can be associated via a relationship set ($1:1$, $1:N$, $N:1$, $M:N$).

**Participation Constraint:** Specifies whether every entity in an entity set must take part in a relationship set (total participation = double line; partial = single line).

### When an Action Stays a Relationship Diamond
Keep an action as a relationship diamond when it only links two entities, has few descriptive attributes, and does not need its own tracking key (for example, `Advises` or `Teaches`).

### When an Action Must Become an Entity Set
Promote an action to an independent entity rectangle when:
1. **The action has its own real-world identifier:** A train ticket has a `ticket_no`, and a loan has a `borrow_id`.
2. **The action has multiple attributes:** A ticket holds seat number, journey date, class, and fare.
3. **The action links multiple parties:** A checkout involves a member, a book, and a issuing staff member. Modeling it as an entity keeps relationships clean and binary.
4. **The prompt explicitly demands it:** In 2023 Q.1(a), `Borrowing` and `Reservations` are explicitly listed as entities. Modeling them as diamonds violates the prompt.

## Comparing the Three Classic RUET Exam Domains

1. **Train E-Ticketing (Rajshahi High-Tech Authority):**
   - **Entities:** `PASSENGER`, `TICKET`, `TRAIN`, `STATION`.
   - `TICKET` is an entity placed between passenger and train ($1:N$ from `PASSENGER`, $N:1$ to `TRAIN`).
   - `Stops_At` is an $M:N$ relationship between `TRAIN` and `STATION`, carrying `arrival_time` and `dep_time`.

2. **Library Management (RUET Central Library):**
   - **Entities:** `BOOKS`, `MEMBERS`, `STAFF`, `BORROWING`, `RESERVATIONS`.
   - Both `BORROWING` and `RESERVATIONS` are modeled as rectangles.
   - Staff issues borrowings ($1:N$); members initiate borrowings ($1:N$) and reservations ($1:N$); both point to books ($N:1$).

3. **University Course Management (CT-02):**
   - **Entities:** `STUDENT`, `COURSE`, `TEACHER`.
   - `COURSE` acts as the central hub: students enroll in courses ($M:N$), and teachers instruct courses ($1:N$). Teachers and students connect through shared courses, not via a direct diagonal line.

## 🏆 Golden Questions (Past Exam Archive)

### 🎯 GQ1 · 2019 Q.1(c) · Train E-Ticketing System · [06 Marks]

> *Section A · Asked in: 2019 · L1 (asked once)*

**Question (2019 Q.1(c)).** Suppose you are recruited as a database specialist by the Rajshahi High-Tech authority to help them design a database for train e-ticketing system efficiently. Now think the regular features and draw an E-R diagram accordingly.

**Answer.**

#### 1. System Requirements and Entities
1. **PASSENGER:** Stores account details. Attributes: `user_id` (PK, underlined), `name`, `nid`, `phone`.
2. **TICKET:** Represents booked travel tickets. Attributes: `ticket_no` (PK, underlined), `journey_date`, `seat_no`, `fare`, `class`.
3. **TRAIN:** Represents scheduled trains. Attributes: `train_no` (PK, underlined), `train_name`, `total_seats`.
4. **STATION:** Represents railway stops. Attributes: `station_code` (PK, underlined), `station_name`, `city`.

#### 2. Relationships and Cardinalities
- **`Books` (1:N):** Connects `PASSENGER` and `TICKET`. A passenger books one or more tickets; each ticket belongs to one passenger. Total participation on `TICKET` (double line). Descriptive attribute on diamond: `booking_date`.
- **`For_Train` (N:1):** Connects `TICKET` and `TRAIN`. Many tickets belong to a specific train; each ticket is assigned to exactly one train. Total participation on `TICKET` (double line).
- **`Stops_At` (M:N):** Connects `TRAIN` and `STATION`. Trains stop at multiple stations; stations service multiple trains. Descriptive attributes on diamond: `arrival_time`, `dep_time`.

### 🎯 GQ2 · 2023 Q.1(a) · RUET Central Library Management System · [05 Marks]

> *Section A · CLO4 · Asked in: 2023 · L1 (asked once)*

**Question (2023 Q.1(a)).** Draw an ER diagram for RUET Central Library Management System. You have to consider the entities mentioned below:  
(i) Books (ii) Members (iii) Staff (iv) Borrowing (v) Reservations

**Answer.**

*Design Note: Borrowing and Reservations are explicitly specified as entity sets in the prompt; each is modeled as an entity rectangle with its own unique identifier and transaction attributes.*

#### 1. Entity Sets and Attributes
1. **`BOOKS`:** `book_id` (PK, underlined), `isbn`, `title`, `author`, `edition`.
2. **`MEMBERS`:** `member_id` (PK, underlined), `name`, `type`, `department`.
3. **`STAFF`:** `staff_id` (PK, underlined), `name`, `designation`.
4. **`BORROWING`:** `borrow_id` (PK, underlined), `borrow_date`, `due_date`, `return_date`.
5. **`RESERVATIONS`:** `res_id` (PK, underlined), `res_date`, `status`.

#### 2. Relationships and Cardinalities
- **`Issues` (1:N):** A staff member processes multiple borrowings.
- **`Borrows` (1:N):** A member initiates multiple borrowings.
- **`Includes` (N:1):** A borrowing record links to the specific book borrowed.
- **`Reserves` (1:N):** A member makes multiple book reservations.
- **`For_Book` (N:1):** A reservation is placed for a specific book.

### 🎯 GQ3 · CT-02 Q.02 · University Enterprise Database · [10 Marks]

> *CO3 · Asked in: CT-02 · L1 (asked once)*

**Question (CT-02 Q.02).** A university maintains information about Students, Courses, and Teachers. A student can enroll in several courses and each course can have many students. Each course is taught by one teacher, though a teacher may teach several courses.  
**(a)** Identify the entities, attributes, primary keys, relationships, and cardinalities. `[04 Marks]`  
**(b)** Draw the complete ER diagram. `[06 Marks]`

**Answer.**

#### (a) Identification of Components (4 Marks)

| Component | Type | Details | Primary Key |
| :--- | :--- | :--- | :--- |
| **`STUDENT`** | Entity Set | Attributes: `student_id`, `name`, `email`, `dept_name` | `student_id` |
| **`COURSE`** | Entity Set | Attributes: `course_id`, `title`, `credits` | `course_id` |
| **`TEACHER`** | Entity Set | Attributes: `teacher_id`, `name`, `dept_name`, `phone` | `teacher_id` |
| **`Enrolls`** | Relationship Set | Connects `STUDENT` and `COURSE` | `(student_id, course_id)` |
| **`Teaches`** | Relationship Set | Connects `TEACHER` and `COURSE` | `course_id` |

**Cardinalities:**
- **Student to Course (`Enrolls`):** Many-to-Many (**M:N**). A student enrolls in several courses; each course has many students.
- **Teacher to Course (`Teaches`):** One-to-Many (**1:N** from `TEACHER` to `COURSE`). A teacher teaches several courses; each course is taught by exactly one teacher.

## ⚡ Exam Tips & Common Mistakes

- **Prompt-Mandated Entities:** In 2023 Q.1(a), the question explicitly requires Borrowing and Reservations as entities. Drawing them as diamonds results in heavy mark penalties.
- **No Direct Teacher-Student Line:** Teachers and students interact through courses. Never draw a direct relationship between Teacher and Student in standard university schemas.
- **Timetable Attributes on Junctions:** For railway systems, place `arrival_time` and `dep_time` on the `Stops_At` relationship diamond. Arrival times depend on both the train and the station.
- **Tabular Format for Identification:** When a question has an identification part (CT-02 Q.02a), provide a structured Markdown table to secure component marks cleanly.
