## The Insurance Schema: Structure and Join Traversal

The Insurance schema originates from Silberschatz Exercises 3.4 and 3.14:

```text
Person (driver_id, name, address)
Car (license, model, year)
Accident (report_no, date, location)
Owner (driver_id, license)
Participated (driver_id, report_no, car, damage_amount)
```

**Relational Database Management System (RDBMS):** Database management software based on the relational data model. It stores information in tables of rows and columns, enforces data integrity using keys and constraints, and provides a structured declarative query language (SQL) for retrieval and manipulation.

**Update Statement (`UPDATE`):** Modifies specific column values in existing tuples without replacing entire rows.

**Insert Statement (`INSERT`):** Adds one or more new tuples into a relation using explicit column values or a nested query.

### The Driver vs. Owner Relationship Trap

In accident records, the driver is not necessarily the owner of the vehicle:
- **Ownership Path (cars belonging to a person):**
  `Person` $\to$ `Owner` (via `driver_id`) $\to$ `Participated` (via `Owner.license = Participated.car`).
- **Driving Path (person behind the wheel):**
  `Person` $\to$ `Participated` (via `driver_id`).

When a query specifies accidents in which cars **belonging to** a person were involved, follow the ownership path through `Owner`. Use `COUNT(DISTINCT p.report_no)` to prevent double-counting accidents where multiple cars of the same owner were involved.

## Data Modification Across Joined Relations

### 1. Inserting an Accident Record
```sql
INSERT INTO Accident (report_no, date, location)
VALUES ('AR-2024-01', '2024-10-15', 'Dhaka-Rajshahi Highway');
```

### 2. Multi-Table Updates
When updating attributes in `Car` based on conditions in `Person`, MySQL supports joined updates directly:
```sql
UPDATE Car c
JOIN Owner o ON c.license = o.license
JOIN Person p ON o.driver_id = p.driver_id
SET c.year = 2022
WHERE p.name = 'John'
  AND c.model = 'Mazda';
```

Alternative standard SQL subquery syntax:
```sql
UPDATE Car
SET year = 2022
WHERE model = 'Mazda'
  AND license IN (
      SELECT o.license
      FROM Owner o
      JOIN Person p ON o.driver_id = p.driver_id
      WHERE p.name = 'John'
  );
```

### 3. Updates with Composite Keys
In `Participated`, updating a specific damage amount requires filtering by both the car's license plate and the accident report number:
```sql
UPDATE Participated
SET damage_amount = 3000
WHERE car = 'YJK-100'
  AND report_no = 'APR2197';
```

## E-Commerce Schema and Anti-Join Mechanics

The E-commerce schema features five related tables:
```text
client (c_no, name, city, state, baldue)
product (p_no, description, profit_percent, quantity, sell_price, cost_price)
salesman (s_no, name, city, state, sal_amount, target, sold_yearly, remarks)
order (order_no, client_no, order_date, delivery_address, salesman_no, del_type, del_date, order_status)
order_details (order_no, product_no, quantity_ordered, product_rate)
```

### Escaping the Reserved Keyword `order`
Because `ORDER` is a reserved SQL keyword used in `ORDER BY`, enclose the table name in backticks in MySQL: `` `order` ``.

### Sales Revenue Aggregation
To calculate total revenue per product sold, multiply line-item quantity by rate, sum the products, and group by product attributes:
```sql
SELECT od.product_no,
       p.description,
       SUM(od.quantity_ordered * od.product_rate) AS total_value
FROM order_details od
JOIN product p ON od.product_no = p.p_no
GROUP BY od.product_no, p.description;
```

### Anti-Join: Identifying Unsold Products
**Anti-Join:** A query pattern that returns rows from one table having no matching records in a referenced table ($\text{All Products} - \text{Sold Products}$). An inner join drops unsold products because they have zero matching rows in `order_details`.

1. **Using `NOT IN`:**
   ```sql
   SELECT p_no, description
   FROM product
   WHERE p_no NOT IN (
       SELECT DISTINCT product_no
       FROM order_details
   );
   ```
2. **Using `NOT EXISTS`:**
   ```sql
   SELECT p.p_no, p.description
   FROM product p
   WHERE NOT EXISTS (
       SELECT 1
       FROM order_details od
       WHERE od.product_no = p.p_no
   );
   ```
3. **Using `LEFT JOIN ... IS NULL`:**
   ```sql
   SELECT p.p_no, p.description
   FROM product p
   LEFT JOIN order_details od ON p.p_no = od.product_no
   WHERE od.product_no IS NULL;
   ```

(i) Find the number of accidents in which the cars belonging to "John Smith" were involved.  
(ii) Add a new accident to the database, assuming any values for required attributes.  
(iii) Update the car "Mazda" belonging to "John".  
(iv) Update the damage amounts \$3000 for the car with license number "YJK-100" in the accident with report number "APR2197".  
*(Note: Printed as "RDMS" in original question paper; refers to "RDBMS")*

**Question (2024 Q.5(b)).** Define RDMS. Consider the following insurance database where the primary keys are underlined.  
Person (<u>driver_id</u>, name, address)

Accident (<u>report_no</u>, data, location)

*(Note: "RDMS" and "data" printed verbatim in original paper; refers to RDBMS and date)*

**Answer.**

**Definition of RDBMS:** An **RDBMS (Relational Database Management System)** is a database management software based on the relational model of data. It stores information in tables (relations) of rows and columns, enforces data integrity using keys and constraints, and provides a structured declarative query language (SQL) for retrieval and manipulation.

*(i) Number of accidents involving cars owned by "John Smith":*

```sql
SELECT COUNT(DISTINCT p.report_no) AS accident_count
FROM Participated p
JOIN Owner o ON p.car = o.license
JOIN Person per ON o.driver_id = per.driver_id
WHERE per.name = 'John Smith';
```

*(ii) Add a new accident with sample values:*

```sql
INSERT INTO Accident (report_no, date, location)
VALUES ('AR-2024-01', '2024-10-15', 'Dhaka-Rajshahi Highway');
```

*(iii) Update the car "Mazda" belonging to "John":*

*Assumption: The query updates the manufacturing year of John's Mazda to 2022.*

```sql
UPDATE Car c
JOIN Owner o ON c.license = o.license
JOIN Person p ON o.driver_id = p.driver_id
SET c.year = 2022
WHERE p.name = 'John'
  AND c.model = 'Mazda';
```

*(Alternative standard SQL subquery:*
```sql
UPDATE Car
SET year = 2022
WHERE model = 'Mazda'
  AND license IN (
      SELECT o.license
      FROM Owner o
      JOIN Person p ON o.driver_id = p.driver_id
      WHERE p.name = 'John'
  );
```
*)*

*(iv) Update damage amount to \$3,000 for car "YJK-100" in accident "APR2197":*

```sql
UPDATE Participated
SET damage_amount = 3000
WHERE car = 'YJK-100'
  AND report_no = 'APR2197';
```

### 🎯 GQ2 · 2021 Q.4(a) · E-Commerce Database Schema Queries · 12 Marks

> *Section A · CLO2 · Asked in: 2021 · L1 (asked once)*

**Question.** Consider the following E-comerce database:  
  client (<u>c_no</u>, name, city, state, Baldue)  
  product (<u>p_no</u>, description, profit_percent, quantity, sell_price, cost_price)  
  salesman (<u>s_no</u>, name, city, state, sal_amount, target, sold_yearly, remarks)  
  order (<u>order_no</u>, client_no, order_date, delivery_address, salesman_no, del_type, del_date, order_status)  
  order_details (<u>order_no</u>, product_no, quantity_ordered, product_rate)

(i) Find the total value of each product sold.  
(ii) Find the products and their quantities for the orders placed by client no "C0001" and "C0002".  
(iii) Find the product no and description of the products not being sold.  
(iv) Find if the product "Lyera Top" has been ordered by any client and print the client_no, name to whom it was sold.

*(Note: "E-comerce" and "Lyera Top" printed verbatim from original question paper)*

**Answer.**

*(i) Total value of each product sold:*

```sql
SELECT od.product_no,
       p.description,
       SUM(od.quantity_ordered * od.product_rate) AS total_value
FROM order_details od
JOIN product p ON od.product_no = p.p_no
GROUP BY od.product_no, p.description;
```

*(ii) Products and quantities ordered by client "C0001" and "C0002":*

```sql
SELECT o.client_no,
       od.product_no,
       p.description,
       od.quantity_ordered
FROM `order` o
JOIN order_details od ON o.order_no = od.order_no
JOIN product p ON od.product_no = p.p_no
WHERE o.client_no IN ('C0001', 'C0002');
```

*(iii) Product number and description of products not sold:*

```sql
SELECT p_no, description
FROM product
WHERE p_no NOT IN (
    SELECT DISTINCT product_no
    FROM order_details
);
```

*(Alternative using `NOT EXISTS`:*
```sql
SELECT p.p_no, p.description
FROM product p
WHERE NOT EXISTS (
    SELECT 1
    FROM order_details od
    WHERE od.product_no = p.p_no
);
```
*)*

*(iv) Check if "Lyera Top" was ordered and display client number and name:*

```sql
SELECT DISTINCT c.c_no, c.name
FROM client c
JOIN `order` o ON c.c_no = o.client_no
JOIN order_details od ON o.order_no = od.order_no
JOIN product p ON od.product_no = p.p_no
WHERE p.description = 'Lyera Top';
```

## ⚡ Exam Tips & Common Mistakes

- **Escape `order` Table Name:** Always write ``FROM `order` `` with backticks to prevent MySQL keyword collision errors.
- **Trace Ownership Accurately:** When asked for cars belonging to a person, join `Person` $\to$ `Owner` $\to$ `Participated`. Do not join `Person` directly to `Participated`.
- **State Assumptions on Incomplete Updates:** In 2020 Q.7(b)(iii), provide an explicit assumption specifying which attribute to update (e.g. `SET c.year = 2022`).
- **Use Anti-Joins for Unsold Products:** Never use `INNER JOIN` to find unsold products. Use `NOT IN` or `NOT EXISTS`.
- **Preserve Verbatim Literals:** Keep exact string casing from the exam question, such as `'Lyera Top'`.
