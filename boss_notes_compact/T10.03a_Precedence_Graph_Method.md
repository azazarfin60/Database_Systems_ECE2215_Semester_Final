# T10.3a: Precedence-Graph Method and Cycle Detection

> **Topic:** T10 · Serializability | **Priority:** 🔴 | **Exam Frequency:** 5/7 finals (+ CT-04) (26 marks)
> **Sources:** Silberschatz 7e Ch. 17 (§17.6) · Lecture Deck 07 (Slides 25–26) · Raidah Notes (p. 26)

---

## 1. What Is a Precedence Graph?

**Precedence Graph:** A precedence graph (or serialization graph) for a schedule $S$ is a directed graph $G = (V, E)$ where vertices $V$ represent active transactions and directed edges $T_i \to T_j$ ($i \neq j$) represent conflicting operations where $T_i$ acts before $T_j$ on a shared item $Q$.

An arrow $T_i \to T_j$ means $T_i$ performed a non-swappable operation on a shared item before $T_j$. Thus, in any equivalent serial schedule, $T_i$ must execute before $T_j$.

### The Three Conflict Edge Conditions

| Condition Name | Operation Order | Why They Conflict | Graph Edge |
| :--- | :--- | :--- | :---: |
| **Read-Write Conflict ($R \to W$)** | $T_i$ executes $\text{read}(Q)$ before $T_j$ executes $\text{write}(Q)$ | $T_i$ reads old value before $T_j$ overwrites it | $T_i \longrightarrow T_j$ |
| **Write-Read Conflict ($W \to R$)** | $T_i$ executes $\text{write}(Q)$ before $T_j$ executes $\text{read}(Q)$ | $T_j$ reads updated value written by $T_i$ | $T_i \longrightarrow T_j$ |
| **Write-Write Conflict ($W \to W$)** | $T_i$ executes $\text{write}(Q)$ before $T_j$ executes $\text{write}(Q)$ | $T_j$ overwrites the value written by $T_i$ | $T_i \longrightarrow T_j$ |

### Operations That Never Create Graph Edges

- **Two reads ($R \to R$):** Reading does not alter database state. Two reads on item $Q$ never conflict.
- **Different data items:** Operations on item $A$ and item $B$ ($A \neq B$) are independent.
- **Same transaction:** Instructions within $T_i$ follow program order and never create self-loops.

## 2. Graph Construction and Cycle Detection

```text
Algorithm: Precedence Graph Construction
1. Filter operations: Discard local arithmetic (e.g., A := A + 10). Keep only read(Q) and write(Q).
2. Number operations chronologically: 1, 2, ..., m.
3. For each pair of steps k < p where Ti != Tj on the same item Q:
     If Op_k is a write or Op_p is a write:
       Add directed edge Ti -> Tj to E.
4. Deduplicate multiple edges between the same pair of nodes.
```

**Conflict Serializability Test (Theorem):** A schedule $S$ is conflict serializable if and only if its precedence graph $G$ has no directed cycles (it is a DAG).

- **Cycle detected:** The schedule is **not conflict serializable**. No equivalent serial schedule exists.
- **Acyclic graph (DAG):** The schedule is **conflict serializable**. Cycle detection runs in $\mathcal{O}(V + E)$ time.

## 3. Topological Sorting: Generating Serial Orders

**Topological Sorting:** A linear ordering of the vertices of a directed acyclic graph such that for every directed edge $T_i \to T_j$, $T_i$ appears before $T_j$.

**In-Degree:** The number of directed edges pointing into a vertex.
- A vertex with $\text{in-degree} = 0$ has no predecessor constraints and can execute next.
- If multiple vertices have $\text{in-degree} = 0$ at the same step, choosing each gives a distinct valid serial schedule.

![Precedence graph DAG and its topological sorting orders](diagrams/T10.03a_topological_sort__L07_p26_fig01.jpg)
*Figure 1: Precedence graph DAG (a) with two valid topological sort orders (b) and (c) (Source: Lecture Deck 07, Slide 26).*

In Figure 1, graph (a) has edges $T_i \to T_j$, $T_i \to T_k$, $T_j \to T_m$, and $T_k \to T_m$. Once $T_i$ executes, both $T_j$ and $T_k$ have in-degree 0. This yields two valid serial schedules:
$$
\langle T_i, T_j, T_k, T_m \rangle \quad \text{and} \quad \langle T_i, T_k, T_j, T_m \rangle
$$

Determine whether the schedule is conflict serializable or not?

*(Reprinted in 2024 Q.8(c): identical schedule in vertical block formatting).*

**Answer.**

We extract the sequence of database operations in chronological order:
1. $T_1: \text{read}(A)$
2. $T_2: \text{read}(A)$
3. $T_2: \text{write}(A)$
4. $T_2: \text{read}(B)$
5. $T_1: \text{write}(A)$
6. $T_1: \text{read}(B)$
7. $T_1: \text{write}(B)$
8. $T_2: \text{write}(B)$

#### Conflicting Pairs Analysis

A conflict occurs when two instructions from different transactions access the same item and at least one is a write:
- **On item $A$:**
  - $T_1: \text{read}(A)$ (step 1) occurs before $T_2: \text{write}(A)$ (step 3) $\implies T_1 \to T_2$.
  - $T_2: \text{read}(A)$ (step 2) occurs before $T_1: \text{write}(A)$ (step 5) $\implies T_2 \to T_1$.
  - $T_2: \text{write}(A)$ (step 3) occurs before $T_1: \text{write}(A)$ (step 5) $\implies T_2 \to T_1$.
- **On item $B$:**
  - $T_2: \text{read}(B)$ (step 4) occurs before $T_1: \text{write}(B)$ (step 7) $\implies T_2 \to T_1$.
  - $T_1: \text{read}(B)$ (step 6) occurs before $T_2: \text{write}(B)$ (step 8) $\implies T_1 \to T_2$.
  - $T_1: \text{write}(B)$ (step 7) occurs before $T_2: \text{write}(B)$ (step 8) $\implies T_1 \to T_2$.

#### Precedence Graph

![2018 Q.6(c) Precedence Graph showing directed cycle between T1 and T2](diagrams/T10_2018_Q6c_precedence_graph.jpg)
*Figure 2: Precedence graph for 2018 Q.6(c) showing conflicting cycle between T1 and T2.*

![2024 Q.8(c) Precedence Graph showing cycle T1-T2](diagrams/T10_2024_Q8c_precedence_graph.jpg)

The graph contains directed edges $T_1 \to T_2$ and $T_2 \to T_1$. This creates a cycle:
$$
T_1 \longleftrightarrow T_2
$$

**Result:** Because the precedence graph contains a cycle, the schedule is **NOT conflict serializable**.

### 🎯 GQ2 · CT-04 Q.04 · 06 Marks

> *Asked in: CT-04 · CO3 · L1 (asked once)*

**Question (CT-04 Q.04).** Determine whether the schedule is conflict serializable or not. If it is serializable, give the equivalent serial order.

| $T_1$ | $T_2$ | $T_3$ |
| :---: | :---: | :---: |
| $\text{Write}(A)$ | | |
| | $\text{Read}(A)$ | |
| | | $\text{Write}(B)$ |
| $\text{Write}(B)$ | | |
| | | $\text{Write}(B)$ |
| | $\text{Write}(A)$ | |
| | | $\text{Read}(B)$ |
| | $\text{Read}(B)$ | |

**Answer.**

We number the instructions of the schedule chronologically from 1 to 8:
- Step 1: $T_1: \text{Write}(A)$
- Step 2: $T_2: \text{Read}(A)$
- Step 3: $T_3: \text{Write}(B)$
- Step 4: $T_1: \text{Write}(B)$
- Step 5: $T_3: \text{Write}(B)$
- Step 6: $T_2: \text{Write}(A)$
- Step 7: $T_3: \text{Read}(B)$
- Step 8: $T_2: \text{Read}(B)$

#### Conflicting Pairs Analysis

- **On item $A$:**
  - Step 1 ($T_1: \text{Write}(A)$) precedes Step 2 ($T_2: \text{Read}(A)$) $\implies T_1 \to T_2$
  - Step 1 ($T_1: \text{Write}(A)$) precedes Step 6 ($T_2: \text{Write}(A)$) $\implies T_1 \to T_2$
- **On item $B$:**
  - Step 3 ($T_3: \text{Write}(B)$) precedes Step 4 ($T_1: \text{Write}(B)$) $\implies T_3 \to T_1$
  - Step 3 ($T_3: \text{Write}(B)$) precedes Step 8 ($T_2: \text{Read}(B)$) $\implies T_3 \to T_2$
  - Step 4 ($T_1: \text{Write}(B)$) precedes Step 5 ($T_3: \text{Write}(B)$) $\implies T_1 \to T_3$
  - Step 4 ($T_1: \text{Write}(B)$) precedes Step 7 ($T_3: \text{Read}(B)$) $\implies T_1 \to T_3$
  - Step 4 ($T_1: \text{Write}(B)$) precedes Step 8 ($T_2: \text{Read}(B)$) $\implies T_1 \to T_2$
  - Step 5 ($T_3: \text{Write}(B)$) precedes Step 8 ($T_2: \text{Read}(B)$) $\implies T_3 \to T_2$

#### Precedence Graph

![CT-04 Q.04 Precedence Graph showing cycle between T1 and T3](diagrams/T10_CT04_Q04_precedence_graph.jpg)
*Figure 4: Precedence graph for CT-04 Q.04 showing cycle between T1 and T3.*

The edges of the graph are:
- $T_1 \to T_2$

$$
T_1 \longleftrightarrow T_3

## ⚡ Exam Tips & Common Mistakes

- **Ignore local variable math:** Instructions like `A := A + 10` only affect local CPU memory. Focus exclusively on database `read` and `write` calls.
- **Never draw edges between steps of the same transaction:** If $T_2$ reads $A$ and later $T_2$ writes $A$, this is internal program order. It never creates a graph edge.
- **Analyze all items:** Even after spotting a cycle on item $A$, list the conflicts on item $B$ as well to secure full presentation marks.
- **State explicitly when no serial order exists:** If a schedule contains a cycle, explicitly state: *"No equivalent serial execution order exists."*
