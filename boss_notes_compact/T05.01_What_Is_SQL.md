# T05.01: What Is SQL?

> **Topic:** T05 · SQL (DDL, DML, Aggregates, Subqueries) | **Priority:** 🟢 | **Exam Frequency:** 1/7 finals (2 marks)
> **Sources:** Silberschatz 7e Ch. 3 (§3.1 pp. 65–66) · Lecture Deck 03 (Slides 3–4) · Classnote by Raidah (Pages 2–4)

---

## Historical Evolution and Meaning

**SQL (Structured Query Language):** SQL is the standard declarative computer language used to define, query, and manipulate data in relational database management systems (RDBMS).

Donald Chamberlin and Raymond Boyce created the original language at IBM Research in the early 1970s under the name **Sequel** (Structured English Query Language) for the System R project. IBM later shortened the name to **SQL** due to trademark issues.

The language has undergone steady standardization:
- **ANSI / ISO Standards:** SQL-86 and SQL-89 established basic queries and integrity checks.
- **SQL-92:** Introduced major expansions to queries, joins, and data types.
- **SQL:1999 to SQL:2016:** Added triggers, recursive queries, object features, JSON, and analytical window functions.

---

## Core Components and Sublanguages

SQL is much more than a retrieval tool. It divides into four core sublanguages:

**Data Definition Language (DDL):** DDL defines and modifies database schemas, table structures, constraints, and indexes. Its main commands are `CREATE`, `ALTER`, `DROP`, and `TRUNCATE`. DDL changes the system catalog metadata.

**Data Manipulation Language (DML):** DML accesses and modifies rows inside existing tables. Its primary commands are `SELECT`, `INSERT`, `UPDATE`, and `DELETE`. DML changes table instances without altering relation schemas.

**Data Control Language (DCL):** DCL manages access rights and permissions for database users. Key commands are `GRANT` and `REVOKE`.

**Transaction Control Language (TCL):** TCL manages transaction boundaries and guarantees atomicity. Key commands are `COMMIT`, `ROLLBACK`, and `SAVEPOINT`.

| Sublanguage | Primary Role | Key Commands | Target of Operation |
| :--- | :--- | :--- | :--- |
| **DDL** | Builds and alters schemas and tables | `CREATE`, `ALTER`, `DROP`, `TRUNCATE` | System catalog metadata |
| **DML** | Reads and modifies table rows | `SELECT`, `INSERT`, `UPDATE`, `DELETE` | Stored relation rows |
| **DCL** | Controls user rights and security | `GRANT`, `REVOKE` | Security catalog / roles |
| **TCL** | Manages transaction boundaries | `COMMIT`, `ROLLBACK`, `SAVEPOINT` | Transaction log / buffers |

### Additional Built-In Features
1. **Integrity Constraints:** Predicates inside DDL (`PRIMARY KEY`, `FOREIGN KEY`, `NOT NULL`, `UNIQUE`, `CHECK`) that reject invalid data entries.
2. **View Definition:** Commands (`CREATE VIEW`) that define virtual tables to simplify complex queries or secure sensitive columns.
3. **Embedded and Dynamic SQL:** Interfaces (such as JDBC, ODBC, or Python DB-API) that allow general-purpose programming languages to run SQL statements.

## Declarative vs. Procedural Nature

**Declarative Query Language:** A language where the user specifies *what* data is needed rather than *how* to locate or compute it. SQL is declarative. The query optimizer in the DBMS analyzes table statistics and automatically selects the fastest physical execution plan.

| Feature | Declarative (SQL) | Procedural (C, C++, Java) |
| :--- | :--- | :--- |
| **Focus** | Specifies **what** data is wanted | Specifies **how** to compute results step by step |
| **Control Flow** | No explicit loops or pointers | Explicit loops, conditionals, and memory pointers |
| **Optimization** | Query optimizer picks the lowest-cost plan | Programmer designs and tunes algorithms manually |
| **Operation Unit** | Operates on entire sets of tuples at once | Processes one record or variable at a time |

## Fundamental SQL Data Types

Every column in an SQL relation has an assigned domain type:
- `CHAR(n)`: Fixed-length character string of length $n$. Shorter strings are padded with spaces.
- `VARCHAR(n)`: Variable-length character string with maximum length $n$. Extra spaces are not padded.
- `INT` / `INTEGER`: Standard 4-byte integer.
- `SMALLINT`: Small integer using less storage space.
- `NUMERIC(p, d)` / `DECIMAL(p, d)`: Fixed-point number with $p$ total digits and $d$ digits to the right of the decimal point.
- `REAL`, `FLOAT(n)`: Floating-point numbers for scientific calculations.
- `DATE`, `TIME`, `TIMESTAMP`: Calendar dates (`YYYY-MM-DD`), clock times (`HH:MM:SS`), and date-time combinations.

## 🏆 Golden Questions (Past Exam Archive)

### 🎯 GQ1 · 2019 Q.5(a) · Short Note on SQL · 02 Marks

> *Section B · Asked in: 2019 · L1 (asked once)*

**Question.** Write a short note on SQL.

**Answer.**

**SQL (Structured Query Language)** is the standard declarative computer language used to define, query, and manipulate data in relational database management systems (RDBMS). It was originally developed at IBM in the 1970s for System R.

Key parts of SQL include:
1. **Data Definition Language (DDL):** Defines relation schemas, integrity constraints, and indexes (`CREATE`, `ALTER`, `DROP`).
2. **Data Manipulation Language (DML):** Queries and modifies table tuples (`SELECT`, `INSERT`, `UPDATE`, `DELETE`).
3. **Data Control & Transaction Control (DCL/TCL):** Manages user permissions (`GRANT`, `REVOKE`) and transaction boundaries (`COMMIT`, `ROLLBACK`).

SQL is declarative. The user specifies what result is wanted rather than how to calculate it.

### 🎯 GQ2 · Likely Exam Question · DDL vs. DML Distinctions · 03 Marks

> *Anticipated Exam Question · Sources: Silberschatz 7e Ch. 3 §3.1 · Lecture Deck 03 Slide 4*

**Question.** Distinguish between Data Definition Language (DDL) and Data Manipulation Language (DML) in SQL. Provide two distinct command examples for each.

**Answer.**

| Parameter | Data Definition Language (DDL) | Data Manipulation Language (DML) |
| :--- | :--- | :--- |
| **Primary Purpose** | Defines and modifies database schemas and structures | Reads, inserts, modifies, and deletes table rows |
| **Target Object** | System catalog metadata and table schemas | Stored data tuples inside relations |
| **Schema Effect** | Changes column types, constraints, and tables | Leaves schema unchanged; modifies data only |
| **Rollback Behavior** | Auto-commits immediately in most engines | Can be committed or rolled back via transactions |
| **Key Commands** | `CREATE TABLE`, `ALTER TABLE`, `DROP TABLE`, `TRUNCATE` | `SELECT`, `INSERT`, `UPDATE`, `DELETE` |

**Command Examples:**
- **DDL:**
  ```sql
  CREATE TABLE instructor (ID CHAR(5), name VARCHAR(20), salary NUMERIC(8,2));
  ALTER TABLE instructor ADD dept_name VARCHAR(20);
  ```
- **DML:**
  ```sql
  INSERT INTO instructor VALUES ('10101', 'Srinivasan', 65000, 'Comp. Sci.');
  SELECT name FROM instructor WHERE salary > 60000;
  ```

### 🎯 GQ3 · Likely Exam Question · Why SQL Is Declarative · 03 Marks

> *Anticipated Exam Question · Sources: Silberschatz 7e Ch. 2 §2.5 & Ch. 3 §3.1*

**Question.** Why is SQL referred to as a declarative query language, and how does the DBMS execute declarative SQL statements?

**Answer.**

SQL is called a declarative query language because users specify **what** data they want rather than **how** the system must retrieve it. The programmer does not write file-scanning loops or index traversals.

**Execution Steps by the DBMS:**
1. **Parsing and Translation:** The parser validates SQL syntax and translates the query into an internal relational algebra expression tree.
2. **Query Optimization:** The optimizer evaluates alternative query evaluation plans (such as B+-tree index lookup versus sequential table scan) using catalog statistics. It selects the plan with the lowest estimated disk and CPU cost.
3. **Code Execution:** The database engine executes the chosen physical plan, fetches data blocks into memory buffers, and outputs the resulting relation to the user.

## ⚡ Exam Tips & Common Mistakes

- **SQL is not just SELECT:** Always state that SQL defines schemas (DDL), controls rights (DCL), and manages transactions (TCL), not just queries.
- **TRUNCATE is DDL:** Remember that `TRUNCATE TABLE` is a DDL command because it deallocates data pages directly instead of deleting rows individually.
- **Mention System R:** Noting IBM's System R and the name *Sequel* guarantees full marks on 2-mark origin questions.
- **State "what vs. how":** When explaining declarative languages, always use the contrast: the user states *what* result is wanted, while the DBMS decides *how* to compute it.
