# T09.2: Consistency Property

> **Topic:** T09 · Transactions, ACID & Anomalies | **Priority:** 🟡 Medium Priority | **Exam Frequency:** 2/7 finals (6 marks: 2019 Q.3(b), 2024 Q.2(c))  
> **Sources:** Silberschatz 7e Ch. 17 (§17.1–§17.2, pp. 800–802) · Lecture Deck 07 (Slide 6) · Raidah Class Notes (p. 26)

## Core Concept: Two Tiers of Consistency

**Consistency:** Consistency requires that executing a transaction in isolation preserves database integrity. If the database starts in a valid state that satisfies all integrity rules, it must end in a valid state once the transaction completes.

**Consistency Requirement:** A transaction must preserve both explicit schema constraints and implicit application invariants. The DBMS integrity subsystem enforces schema rules, while the application programmer is responsible for business logic invariants.

Database consistency operates across two distinct levels:

1. **Explicit Constraints (Enforced by DBMS):**
   - Formal rules declared in SQL schema DDL.
   - Includes `PRIMARY KEY` (entity integrity), `FOREIGN KEY` (referential integrity), data type restrictions, `NOT NULL`, and `CHECK` rules (like `CHECK (balance >= 0)`).
   - If a transaction violates an explicit constraint, the DBMS engine immediately halts the statement and rolls back changes.

2. **Implicit Invariants (Enforced by Application Programmer):**
   - Business rules that cannot be written as simple table constraints.
   - For example, the total sum of money across all customer accounts must remain unchanged during a transfer.
   - The DBMS engine cannot verify program logic automatically. The application programmer must write code that preserves these invariants.

### Constraint Enforcement Summary

| Constraint Type | Definition | Enforced By | Handling on Violation |
| :--- | :--- | :--- | :--- |
| **Explicit Constraints** | Schema DDL rules (`PK`, `FK`, `CHECK`, `NOT NULL`) | DBMS Engine | DBMS aborts statement or transaction |
| **Implicit Invariants** | Real-world business rules and math balance | Application Programmer | Undetected by DBMS; creates corrupt data |

## The Temporary Inconsistency Window

A database transaction executes step by step. When updating two related data items, the database enters a **temporarily inconsistent state** between the first write and the second write.

### Example: Bank Transfer

Let account $A$ have initial balance \$1000 and account $B$ have initial balance \$2000. The invariant is $A + B = 3000$.

Transaction $T_1$ transfers \$50 from $A$ to $B$:

$$
\begin{aligned}
1.&\quad \text{read}(A) \\
2.&\quad A := A - 50 \\
3.&\quad \text{write}(A) \quad [A \text{ becomes } 950] \\
4.&\quad \text{read}(B) \\
5.&\quad B := B + 50 \\
6.&\quad \text{write}(B) \quad [B \text{ becomes } 2050] \\
7.&\quad \text{commit}
\end{aligned}
$$

| Timeline Point | Account $A$ (\$) | Account $B$ (\$) | Total Sum ($A + B$) (\$) | Consistency Status |
| :--- | :---: | :---: | :---: | :--- |
| **Initial State (Before Step 1)** | 1000 | 2000 | 3000 | **Consistent** |
| **Intermediate State (After Step 3)** | 950 | 2000 | 2950 | **Temporarily Inconsistent** (\$50 appears missing) |
| **Final State (After Step 6)** | 950 | 2050 | 3000 | **Consistent** (Restored) |

### Why Temporary Inconsistency is Safe

This temporary inconsistency is completely safe because of two other ACID properties:
1. **Isolation:** The concurrency-control system prevents other concurrent transactions from reading the intermediate sum 2950.
2. **Atomicity:** If the system crashes after step 3, the recovery system rolls back $A$ to 1000, leaving no partial state behind.

## 🏆 Golden Questions (Past Exam Archive)

### 🎯 GQ1 · 2019 Q.3(b) / 2024 Q.2(c) · Consistency Property with Example · 03 Marks

> *Section A · Asked in: 2019 Q.3(b), 2024 Q.2(c) (CO1) · L2 merge (identical question text)*

**Question (2019 Q.3(b), 2024 Q.2(c)).** Explain the consistency property of a database system with a proper example.

**Answer.**

#### 1. Definition
The **consistency** property requires that executing a transaction in isolation preserves the consistency of the database. If the database starts in a valid state that satisfies all integrity rules, it must end in a valid state after the transaction completes.

Consistency covers two categories:
- **Explicit Constraints:** Rules enforced automatically by the DBMS, including primary keys, foreign keys, data types, and `CHECK` constraints (such as `balance >= 0`).
- **Implicit Invariants:** Business rules that cannot easily be expressed in DDL, such as preserving total assets across account transfers.

#### 2. Example: Bank Transfer
Let account $A$ have \$1000 and account $B$ have \$2000. The consistency invariant requires total funds to remain constant:

$$
A + B = 1000 + 2000 = 3000
$$

Transaction $T_1$ transfers \$50 from $A$ to $B$:
1. $\text{read}(A)$
2. $A := A - 50$
3. $\text{write}(A) \quad [A \text{ becomes } 950]$
4. $\text{read}(B)$
5. $B := B + 50$
6. $\text{write}(B) \quad [B \text{ becomes } 2050]$

#### 3. State Analysis
- **Initial State:** $A = 1000, B = 2000$. Total sum is $1000 + 2000 = 3000$. The database is consistent.
- **Temporary Inconsistency During Execution:** After step 3, $A = 950$ and $B = 2000$. The sum is $950 + 2000 = 2950$. The database enters a temporarily inconsistent state because \$50 is missing from the total.
- **Restored Consistency at End:** After step 6 completes, $A = 950$ and $B = 2050$. The sum is $950 + 2050 = 3000$. Database consistency is restored.
- **Responsibility:** Writing correct transaction logic is primarily the responsibility of the **application programmer**.

## ⚡ Exam Tips & Common Mistakes

- **Acknowledge Temporary Inconsistency:** Never state that a database is consistent at every microsecond. Multi-step operations must pass through temporary inconsistency. Full marks require stating that consistency holds before execution and after commit.
- **Contrast Explicit vs Implicit Rules:** Point out that the DBMS checks schema constraints, while the programmer must guarantee application invariants.
- **Write Out the Three Sums:** Always write \$3000 (initial), \$2950 (intermediate), and \$3000 (final).
- **Link to Isolation:** Add one sentence stating that Isolation prevents other users from seeing the temporary sum 2950.
