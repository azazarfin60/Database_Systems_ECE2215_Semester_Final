# T06.4: SQL Views: Benefits and CREATE VIEW

> **Topic:** T06 · Joins & Views | **Priority:** 🟢 Foundation | **Exam Frequency:** 1/7 finals · 6 marks
> **Sources:** Silberschatz 7e Ch. 4 (§4.2.1, §4.2.2) · Lecture Deck 04 (Slides 24–28) · Raidah Notes (pp. 3, 11, 18) · Fahim Notes (pp. 58–59)

## Core Concepts: What is a View?

**View (Virtual Relation):** A view is a virtual relation defined by an SQL query. The database does not store view data on disk. Instead, it stores the query definition in the data dictionary and computes rows dynamically when referenced.

**View Definition:** In SQL, a view is created using `CREATE VIEW view_name AS <query_expression>`. The query expression can be any valid `SELECT` query.

**Logical Data Independence:** Logical data independence is the ability to change the logical schema of base tables without modifying external views or application programs.

### 1. View vs. Physical Table vs. Snapshot vs. CTE
- **Physical Table (`CREATE TABLE`):** Allocates disk storage for tuples and indexes. Updates write directly to disk.
- **Virtual View (`CREATE VIEW`):** Consumes zero disk space for data. It recomputes rows dynamically upon query execution.
- **Snapshot Table (`CREATE TABLE ... AS SELECT`):** Evaluates a query once and stores the resulting rows on disk. It becomes stale when underlying tables change.
- **Common Table Expression (`WITH`):** A temporary named result set valid only within the execution scope of a single SQL statement.

---

## Key Benefits of Database Views

1. **Security and Access Control:** Views restrict user access to specific rows and columns. Administrators can show non-sensitive fields while concealing confidential attributes (such as salaries or identification numbers).
2. **Query Simplicity:** Views hide complex joins, unions, and aggregate computations behind a single relation name. Users query the view with straightforward `SELECT * FROM view_name` syntax.
3. **Logical Data Independence:** If administrators restructure, split, or rename base tables, updating the view definition keeps external application queries running without change.
4. **Data Standardization and Consistency:** Coding business formulas inside view definitions ensures that all users and reports retrieve identical, standardized metrics.

---

## SQL CREATE VIEW Syntax and Patterns

### 1. Basic Syntax
```sql
CREATE VIEW view_name AS
SELECT column1, column2
FROM table_name
WHERE condition;
```

### 2. Explicit Column Naming
When views compute calculated or aggregate columns, assign column names explicitly in parentheses:
```sql
CREATE VIEW dept_salary_summary (dept_name, total_salary, avg_salary) AS
SELECT dept_name, SUM(salary), AVG(salary)
FROM instructor
GROUP BY dept_name;
```

### 3. Multi-Table Join Views
Views frequently encapsulate multi-table joins:
```sql
CREATE VIEW faculty_courses AS
SELECT instructor.ID, instructor.name, course.title, section.semester, section.year
FROM instructor
JOIN teaches ON instructor.ID = teaches.ID
JOIN section ON teaches.course_id = section.course_id 
            AND teaches.sec_id = section.sec_id
            AND teaches.semester = section.semester 
            AND teaches.year = section.year
JOIN course ON section.course_id = course.course_id;
```

### 4. Dropping a View
To remove a view definition from the catalog, run:
```sql
DROP VIEW view_name;
```
Dropping a view deletes only the stored query text. It never drops data from underlying base tables.

## 🏆 Golden Questions (Past Exam Archive)

### 🎯 GQ1 · 2023 Q.5(a) · 03 Marks

> *Section B · CLO2 · Asked in: 2023 (3 marks)*

**Question (2023 Q.5(a)).** What are the benefits of VIEW?

**Answer.**

A view is a virtual relation defined by an SQL query. The database does not store the view data on disk. Instead, it stores the query definition and executes it when referenced.

**Key Benefits of Views:**
1. **Security and Access Control:** Views hide sensitive columns and rows from unauthorized users. For example, a view can display employee names and departments while hiding salary data.
2. **Query Simplicity:** Views hide complex joins, unions, and aggregate calculations behind a single virtual table name. Users run simple `SELECT` queries on the view.
3. **Logical Data Independence:** If base tables are restructured, split, or renamed, the administrator updates only the view query. Applications using the view continue running without changes.
4. **Consistent and Standardized Data Representation:** Views provide uniform business calculations across multiple users and departments. This avoids duplicate and conflicting query logic.

**Answer.**

*Assumption: Schema consists of Employee(EmpID, EmployeeName, Salary, DeptID) and Department(DeptID, DepartmentName).*

**SQL Query (Standard 2-Table Schema):**
```sql
CREATE VIEW High_Salary_Employees AS
SELECT Employee.EmployeeName, Department.DepartmentName, Employee.Salary
FROM Employee
JOIN Department ON Employee.DeptID = Department.DeptID
WHERE Employee.Salary > 55000;
```

**Alternative SQL Query (Using Printed Tables E, D, and S):**
Joining table **E**, table **D**, and table **S**:
```sql
CREATE VIEW High_Salary_Employees AS
SELECT E.EmployeeName, D.DepartmentName, S.Salary
FROM E
JOIN D ON E.`Department ID` = D.DepartmentID
JOIN S ON E.EmployeeID = S.EmployeeID
WHERE S.Salary > 55000;
```

**View Output:**

| EmployeeName | DepartmentName | Salary |
| :--- | :--- | :--- |
| Jane | HR | 60,000 |
| Bob | IT | 70,000 |

*(Note: Employees Jhon with 50,000 and Alice with 55,000 are excluded because their salaries do not exceed 55,000).*

## ⚡ Exam Tips & Common Mistakes

- **Strict Inequality Trap:** The question asks for "salary of more than 55,000". Use `> 55000`. Writing `>= 55000` incorrectly includes Alice (\$55,000).
- **Backticks for Columns with Spaces:** In table **E**, the column is named `Department ID`. Wrap it in backticks: `` `Department ID` ``.
- **Select Specific Attributes Only:** The question requests `EmployeeName, DepartmentName and salary`. Do not write `SELECT *`.
- **Views Do Not Store Tuples:** Always state that views store the query definition, not data records.
