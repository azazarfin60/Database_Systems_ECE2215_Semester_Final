# T10.2: Conflict Equivalence by Swapping Non-Conflicting Instructions

> **Topic:** T10 · Serializability | **Priority:** 🟢 | **Exam Frequency:** 1/7 finals (4 marks: 2020 Q.5(c))
> **Sources:** Silberschatz 7e Ch. 17 (§17.6) · Lecture Deck 07 (Slides 19–20) · Raidah Notes (pp. 26–27)

---

## 1. Principles of Instruction Swapping

**Conflict Equivalent:** Two schedules $S$ and $S'$ are conflict equivalent if $S$ transforms into $S'$ through a finite sequence of swaps of adjacent non-conflicting instructions.

**Conflict Serializable:** A schedule $S$ is conflict serializable if it is conflict equivalent to some serial schedule.

**The Swapping Rule:** Two adjacent instructions $I_i$ and $I_j$ from distinct transactions ($T_i \neq T_j$) can be swapped if and only if they do not conflict.

1. **Operations on distinct items ($A \neq B$):** Swapping is always valid. Updating account $A$ does not affect account $B$.
2. **Two reads on the same item ($\text{read}(A)$ vs $\text{read}(A)$):** Swapping is always valid. Reading leaves the stored value unchanged.
3. **Read vs write or write vs write on the same item ($A$ vs $A$):** Swapping is strictly forbidden. Swapping changes the values read or the final stored value.
4. **Instructions of the same transaction ($T_i$ vs $T_i$):** Swapping is strictly forbidden. Instructions must follow internal program order.

### Why Every Swap Must Be Adjacent

Instructions cannot jump over multiple steps at once. Like bubble sort, an instruction moves past other steps one adjacent neighbor at a time. Each adjacent swap must be checked for conflicts.

---

## 2. When Swapping Is Impossible (Non-Serializable Schedule)

Consider Schedule 7 from Silberschatz Ch. 17 (Lecture Deck 07, Slide 21):

| Step | Transaction $T_3$ | Transaction $T_4$ | Target Item |
| :---: | :--- | :--- | :---: |
| 1 | $\text{read}(Q)$ | | $Q$ |
| 2 | | $\text{write}(Q)$ | $Q$ |
| 3 | $\text{write}(Q)$ | | $Q$ |

- To reach serial order $\langle T_3, T_4 \rangle$, Step 2 ($T_4:\text{write}(Q)$) and Step 3 ($T_3:\text{write}(Q)$) must swap. But both are writes on item $Q$ (WW conflict). Swapping is forbidden.
- To reach serial order $\langle T_4, T_3 \rangle$, Step 1 ($T_3:\text{read}(Q)$) and Step 2 ($T_4:\text{write}(Q)$) must swap. But a read and write on item $Q$ conflict (RW conflict). Swapping is forbidden.

Because every adjacent cross-transaction pair conflicts, zero valid swaps exist. Schedule 7 is not conflict serializable.

## 🏆 Golden Questions (Past Exam Archive)

### 🎯 GQ1 · 2020 Q.5(c) · 04 Marks

> *Section B · Asked in: 2020 · L1 (asked once)*

**Question (2020 Q.5(c)).** Draw a concurrent schedule equivalent to serial schedule. Prove its step by step swapping process.

**Answer.**

Consider two transactions $T_1$ and $T_2$ executing on accounts $A$ and $B$:
- $T_1$: $\text{read}(A) \to \text{write}(A) \to \text{read}(B) \to \text{write}(B)$
- $T_2$: $\text{read}(A) \to \text{write}(A) \to \text{read}(B) \to \text{write}(B)$

Below is a concurrent (interleaved) schedule $S$ that is equivalent to serial schedule $\langle T_1, T_2 \rangle$:

| Step | $T_1$ | $T_2$ | Target Item |
| :--: | :--- | :--- | :---: |
| 1 | $\text{read}(A)$ | | $A$ |
| 2 | $\text{write}(A)$ | | $A$ |
| 3 | | $\text{read}(A)$ | $A$ |
| 4 | | $\text{write}(A)$ | $A$ |
| 5 | $\text{read}(B)$ | | $B$ |
| 6 | $\text{write}(B)$ | | $B$ |
| 7 | | $\text{read}(B)$ | $B$ |
| 8 | | $\text{write}(B)$ | $B$ |

#### Step-by-Step Swapping Proof

Two consecutive instructions can be swapped if they belong to different transactions and do not conflict. Instructions on different data items ($A$ and $B$) never conflict. We transform $S$ into serial schedule $\langle T_1, T_2 \rangle$ through 4 swaps:

1. **Swap 1:** Instruction 4 is $T_2: \text{write}(A)$ and instruction 5 is $T_1: \text{read}(B)$. They access different items ($A \neq B$). Swap them.
   - Order becomes: $T_1:\text{r}(A), T_1:\text{w}(A), T_2:\text{r}(A), T_1:\text{r}(B), T_2:\text{w}(A), T_1:\text{w}(B), T_2:\text{r}(B), T_2:\text{w}(B)$.
2. **Swap 2:** $T_2: \text{read}(A)$ is adjacent to $T_1: \text{read}(B)$. They access different items ($A \neq B$). Swap them.
   - Now $T_1: \text{read}(B)$ moves directly after $T_1: \text{write}(A)$.
3. **Swap 3:** $T_2: \text{write}(A)$ is adjacent to $T_1: \text{write}(B)$. They access different items ($A \neq B$). Swap them.
4. **Swap 4:** $T_2: \text{read}(A)$ is adjacent to $T_1: \text{write}(B)$. They access different items ($A \neq B$). Swap them.

**Resulting schedule ($S'$):**

| Step | $T_1$ | $T_2$ | Target Item |
| :--: | :--- | :--- | :---: |
| 1 | $\text{read}(A)$ | | $A$ |
| 2 | $\text{write}(A)$ | | $A$ |
| 3 | $\text{read}(B)$ | | $B$ |
| 4 | $\text{write}(B)$ | | $B$ |
| 5 | | $\text{read}(A)$ | $A$ |
| 6 | | $\text{write}(A)$ | $A$ |
| 7 | | $\text{read}(B)$ | $B$ |
| 8 | | $\text{write}(B)$ | $B$ |

All operations of $T_1$ now precede all operations of $T_2$. This is exactly the serial schedule $\langle T_1, T_2 \rangle$.

**Result:** Because $S$ was transformed into serial schedule $\langle T_1, T_2 \rangle$ using only valid swaps of non-conflicting adjacent instructions, $S$ is **conflict equivalent** to $\langle T_1, T_2 \rangle$ and is **conflict serializable**.

## ⚡ Exam Tips & Common Mistakes

- **Draw both schedule tables:** In 2020 Q.5(c), always draw the starting concurrent schedule table and the final serial schedule table.
- **Show all 4 discrete swaps:** Never skip ahead. Show each swap step with the exact justification ($A \neq B$).
- **Never swap across same-item writes:** $T_1:\text{write}(A)$ and $T_2:\text{read}(A)$ cannot swap because both touch $A$. Move operations on $B$ upward instead.
