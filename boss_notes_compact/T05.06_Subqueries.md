# T05.06: SQL Subqueries (IN, SOME, ALL, EXISTS, Correlated)

> **Sources:** Silberschatz 7e Ch. 3 (§3.8) · Lecture Deck 03 (Slides 35–52) · Raidah Notes (pp. 16–17) · Fahim Notes (pp. 56–58)

## Subquery Foundations and Structural Placement

**Subquery (Nested Query):** A `SELECT-FROM-WHERE` query embedded inside another SQL statement. The outer query uses the intermediate result set or scalar value computed by the inner query.

**Correlated Subquery:** An inner query that references an attribute or table alias from the outer query. The database re-evaluates the inner query once for every candidate row examined by the outer query.

**Scalar Subquery:** A subquery that returns exactly one row and one column. It can appear anywhere a single value is expected, including comparison expressions and the `SELECT` projection list. If a scalar subquery returns multiple rows at runtime, the query engine raises an error.

**The WITH Clause (Common Table Expression):** A clause that defines a named temporary relation at the top of a query. The temporary relation exists only for the duration of that single query.

Subqueries can be nested in three primary clauses:
1. **WHERE Clause:** Compares an attribute against a set or scalar computed by the subquery.
2. **FROM Clause:** Replaces a relation with a subquery, creating a temporary derived relation (requires an alias in MySQL).
3. **SELECT Clause:** Computes a dynamic scalar value for each outer tuple.

## Set Membership: IN and NOT IN

The `IN` operator checks whether a value belongs to the set returned by a subquery. `NOT IN` tests for absence of membership:

```sql
SELECT DISTINCT course_id
FROM section
WHERE semester = 'Fall' AND year = 2017
  AND course_id IN (
      SELECT course_id
      FROM section
      WHERE semester = 'Spring' AND year = 2018
  );
```

### The Three-Valued Logic NULL Trap with NOT IN
If the inner subquery returns a set containing `NULL` (e.g. `{10, 20, NULL}`), `val NOT IN (...)` expands to `val <> 10 AND val <> 20 AND val <> NULL`. Because `val <> NULL` evaluates to `UNKNOWN`, the whole condition becomes `UNKNOWN`, causing the query to return zero rows. Always filter out nulls (`WHERE col IS NOT NULL`) in subqueries used with `NOT IN`.

## Set Comparison: SOME / ANY and ALL

**`SOME` / `ANY`:** Evaluates to `TRUE` if the comparison is satisfied by at least one element in the subquery result (equivalent to comparing against the minimum or maximum appropriately).

$$
F \quad \langle\text{comp}\rangle \quad \textbf{some } r \iff \exists t \in r \ (F \ \langle\text{comp}\rangle \ t)
$$

**`ALL`:** Evaluates to `TRUE` only if the comparison is satisfied by every element in the subquery result.

$$
F \quad \langle\text{comp}\rangle \quad \textbf{all } r \iff \forall t \in r \ (F \ \langle\text{comp}\rangle \ t)
$$

### Equivalence and Non-Equivalence Rules

| Expression | Standard Form | Status | Reason |
| :--- | :--- | :---: | :--- |
| `= SOME` | `IN` | **Identical** | Matches at least one value in the set |
| `<> SOME` | `NOT IN` | **NOT Equivalent** | True if there exists any value different from the operand |
| `<> ALL` | `NOT IN` | **Identical** | Value is distinct from every single element in the set |
| `= ALL` | `IN` | **NOT Equivalent** | True only if every element in the set equals the operand |

## Testing for Empty Relations: EXISTS and NOT EXISTS

- $\textbf{exists } r \iff r \ne \emptyset$ (evaluates to `TRUE` if the subquery returns 1 or more tuples).
- $\textbf{not exists } r \iff r = \emptyset$ (evaluates to `TRUE` if the subquery returns zero tuples).

```sql
SELECT course_id
FROM section AS S
WHERE semester = 'Fall' AND year = 2017
  AND EXISTS (
      SELECT *
      FROM section AS T
      WHERE semester = 'Spring' AND year = 2018
        AND S.course_id = T.course_id
  );
```

### Universal Quantification via Double Negation
To find students who have taken all courses in the Biology department:

$$
\text{Required Courses} - \text{Student's Taken Courses} = \emptyset
$$

```sql
SELECT DISTINCT S.ID, S.name
FROM student AS S
WHERE NOT EXISTS (
    (SELECT course_id FROM course WHERE dept_name = 'Biology')
    EXCEPT
    (SELECT T.course_id FROM takes AS T WHERE T.ID = S.ID)
);
```

## Derived Tables and the WITH Clause

### Derived Tables in FROM
```sql
SELECT dept_name, avg_salary
FROM (
    SELECT dept_name, AVG(salary) AS avg_salary
    FROM instructor
    GROUP BY dept_name
) AS dept_avg
WHERE avg_salary > 42000;
```
Every derived table in `FROM` must have an explicit table alias in MySQL.

### The WITH Clause (Common Table Expression)
```sql
WITH max_budget (value) AS (
    SELECT MAX(budget) FROM department
)
SELECT department.dept_name
FROM department, max_budget
WHERE department.budget = max_budget.value;
```

## 🏆 Golden Questions (Past Exam Archive)

### 🎯 GQ1 · 2024 Q.6(a) / 2019 Q.8(b) · Explain Subqueries with Two Suitable Examples · 04 Marks

> *Section B · CO2 · Asked in: 2024, 2019 · L2 merge*

**Question (2024 Q.6(a)).** Explain sub-queries with two suitable examples.

**Question (2019 Q.8(b)).** Write down two examples of using sub-queries.

**Answer.**

**Explanation:** A **subquery** (or nested query) is a `SELECT` statement embedded inside another SQL statement (the outer query). It can appear in the `WHERE` clause to filter tuples, in the `FROM` clause as a temporary derived relation, or in the `SELECT` clause as a scalar expression. Subqueries allow multi-step data retrieval in a single query.

**Example 1: Set Membership Subquery (`IN`)**  
Find all courses offered in Fall 2017 that were also offered in Spring 2018:

```sql
SELECT DISTINCT course_id
FROM section
WHERE semester = 'Fall' AND year = 2017
  AND course_id IN (
      SELECT course_id
      FROM section
      WHERE semester = 'Spring' AND year = 2018
  );
```

The inner subquery generates the set of courses running in Spring 2018. The outer query checks whether Fall 2017 courses belong to that generated set.

**Example 2: Scalar Comparison Subquery (`AVG`)**  
Find instructors whose salary is higher than the average salary of all instructors:

```sql
SELECT name, salary
FROM instructor
WHERE salary > (
    SELECT AVG(salary)
    FROM instructor
);
```

The inner query computes a single numeric value (the overall average salary). The outer query evaluates the `>` predicate against this scalar value for each instructor.

*Variant for 2019 Q.8(b) (4 marks):* Presenting the two SQL examples with their purpose answers the question.

### 🎯 GQ2 · CT-02 Q.01(c) · Students with CGPA Greater than Overall Average · 03 Marks

> *CO2 · Asked in: CT-02 · L1 (asked once)*

**Question.** Given $\text{STUDENT}(\text{StudentID}, \text{Name}, \text{Department}, \text{Semester}, \text{CGPA})$, write SQL query:  
**(c)** Find students whose CGPA is greater than the overall average CGPA.

**Answer.**

```sql
SELECT *
FROM STUDENT
WHERE CGPA > (
    SELECT AVG(CGPA)
    FROM STUDENT
);
```

*Execution Logic:*
1. Aggregate functions like `AVG()` cannot appear directly in the `WHERE` clause of the same query block (e.g. `WHERE CGPA > AVG(CGPA)` is invalid).
2. The nested subquery computes the table-wide average CGPA as a single scalar.
3. The outer query compares each student's CGPA against this computed average.

## ⚡ Exam Tips & Common Mistakes

- **No Aggregates in WHERE:** Never write `WHERE salary > AVG(salary)`. Always write `WHERE salary > (SELECT AVG(salary) FROM ...)`.
- **Derived Tables Require Aliases:** In MySQL, every subquery in `FROM` must be followed by an alias (e.g., `FROM (...) AS temp`).
- **Single-Valued Scalar Rule:** Scalar comparison operators (`=`, `>`, `<`) fail if the subquery returns more than one row.
- **NOT IN and NULL:** Remember that `NOT IN` returns zero rows if the subquery contains a single `NULL`.
- **= SOME vs <> SOME:** Remember that `= SOME` is identical to `IN`, but `<> SOME` is NOT identical to `NOT IN`.
