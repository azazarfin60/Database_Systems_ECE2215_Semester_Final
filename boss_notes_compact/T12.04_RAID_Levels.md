# T12.4: RAID Levels and Storage Reliability

> **Topic:** T12 · Recovery System & RAID | **Priority:** 🟠 High | **Exam Frequency:** 3/7 finals · 15 marks across 5 question parts
> **Sources:** Silberschatz 7e Ch. 12 (§12.5), Ch. 19 (§19.2.1) · Classnote by Raidah (Pages 32–33)

## Core Features and Architecture of RAID

**RAID (Redundant Array of Independent Disks):** RAID is a storage organization technique that combines multiple physical disks into a single logical volume to boost I/O speed and protect against drive failures. It uses data striping for parallel read and write throughput, and mirroring or parity blocks for hardware fault tolerance.

**Mirroring:** Mirroring (used in RAID 1) is a redundancy technique that duplicates every data block onto an identical companion disk. Every write updates both drives so if one drive fails, the system serves requests from the surviving mirror with zero downtime.

**Data Striping:** Data striping segments data files into fixed-size units (blocks or bytes) and distributes them across multiple physical disks. Because independent drives read and write concurrently, striping increases aggregate data transfer rates.

**Parity Block:** A parity block is an error-correcting block computed as the bitwise exclusive-OR ($\oplus$) of all data blocks in a stripe. If any single drive in the stripe fails, the controller reconstructs the missing block on the fly by XOR-ing the surviving data blocks with the parity block.

**Hot Swapping and Data Scrubbing:** Hot swapping allows replacing a failed physical drive while the server stays powered on, rebuilding data onto hot spares in the background. Data scrubbing is a background check that scans idle sectors to detect and repair latent bit rot before further drive failures occur.

### Five Major Features of RAID Systems
1. **Parallel Data Striping:** Distributes contiguous data blocks across multiple drives to enable parallel I/O and balance disk workloads.
2. **Data Redundancy:** Provides fault tolerance using duplicate disk blocks (RAID 1) or parity codes (RAID 5 and 6) so drive failures cause zero data loss.
3. **Storage Virtualization:** Presents an array of multiple physical drives to the operating system and DBMS as a single logical drive.
4. **Online Hot Swapping & Rebuild:** Enables replacing failed drives without shutting down the system, reconstructing data onto standby disks in the background.
5. **Background Data Scrubbing:** Periodically reads idle sectors to detect latent sector errors and fixes them using redundant parity blocks.

## Primary RAID Levels

![RAID levels showing disk cylinder configurations for RAID 0, RAID 1, RAID 5, and RAID 6](diagrams/T12.04_raid_levels_cylinders__TB_fig_12_04.jpg)
*Figure 12.4: RAID levels showing cylinder configurations for RAID 0, RAID 1, RAID 5, and RAID 6 (Silberschatz Figure 12.4).*

### RAID 0: Non-Redundant Block Striping
- **Architecture:** Blocks are striped cyclically across all $N$ disks ($B_0 \to \text{Disk 0}, B_1 \to \text{Disk 1}$, etc.).
- **Redundancy:** None.
- **Fault Tolerance:** 0 disks. If any single drive fails, all data is lost.
- **Usable Capacity:** $100\%$ ($N \times \text{disk size}$).
- **Use Case:** High-speed scratch space, temporary query tables, and video editing buffers.

### RAID 1: Mirrored Disks
- **Architecture:** Every primary disk has an identical duplicate mirror disk. Every write operation updates both drives.
- **Fault Tolerance:** 1 disk per mirrored pair (tolerates any single drive crash, and up to $N/2$ failures if they occur in different pairs).
- **Usable Capacity:** $50\%$ ($N/2 \times \text{disk size}$). Incurs 100% storage overhead.
- **Performance:** Fast read throughput via load balancing; excellent sequential write speed.
- **Use Case:** Write-Ahead Log (`WAL`) files and operating system boot volumes.

### RAID 1+0 (RAID 10) vs. RAID 0+1
- **RAID 1+0 (Striped Mirrors):** Disks are paired into RAID 1 mirrors first, then data is striped across the mirrored pairs with RAID 0. It survives multiple disk crashes as long as no two failed drives share the same mirror pair.
- **RAID 0+1 (Mirrored Stripes):** Disks are striped with RAID 0 first, then mirrored. If one drive fails, its entire stripe becomes unavailable. RAID 1+0 is strictly superior and standard in transactional databases.

### Legacy Parity Schemes: RAID 2, RAID 3, and RAID 4
- **RAID 2:** Bit-level striping using dedicated Hamming error-correcting code disks (obsolete; modern hard drives have internal sector ECC).
- **RAID 3:** Byte-level striping with a single dedicated parity disk (obsolete; requires synchronized spindle spinning).
- **RAID 4:** Block-level striping with a single dedicated parity disk. Suffers from a severe **parity write bottleneck**: every write to any data disk must update the single dedicated parity drive.

### RAID 5: Block-Interleaved Distributed Parity
- **Architecture:** Eliminates the RAID 4 bottleneck by distributing data blocks and parity blocks circularly across all $N + 1$ disks.
- **Fault Tolerance:** Survives the failure of **any 1 disk**.
- **Parity Calculation (XOR):** The parity block $P$ equals the bitwise exclusive-OR of all data blocks in the stripe:

$$
P = B_0 \oplus B_1 \oplus B_2 \oplus B_3
$$

- **Data Reconstruction on Disk Failure:** If Disk 1 crashes (losing block $B_1$), the controller recovers $B_1$ on the fly:

$$
B_1 = P \oplus B_0 \oplus B_2 \oplus B_3
$$

- **Small Write Penalty:** Updating a single random block requires **2 reads and 2 writes** (4 I/Os total): read old data $B_{\text{old}}$ and old parity $P_{\text{old}}$, compute new parity via $P_{\text{new}} = P_{\text{old}} \oplus B_{\text{old}} \oplus B_{\text{new}}$, and write $B_{\text{new}}$ and $P_{\text{new}}$ back to disk.
- **Usable Capacity:** $\frac{N-1}{N} \times \text{total array capacity}$.
- **Use Case:** Read-heavy databases, web servers, and general file storage.

### RAID 6: P + Q Dual Distributed Parity
- **Architecture:** Extends RAID 5 by computing two independent error-correcting codes ($P$ standard parity and $Q$ Reed-Solomon code), distributed across all drives.
- **Fault Tolerance:** Survives up to **2 simultaneous disk failures**.
- **Usable Capacity:** $\frac{N-2}{N} \times \text{total array capacity}$.
- **Use Case:** Enterprise storage arrays using massive multi-terabyte drives with lengthy rebuild times.

## Comparison Matrix of RAID Levels

| RAID Level | Striping Unit | Redundancy Mechanism | Fault Tolerance | Usable Capacity | Sequential Read Speed | Random Write Speed | Primary Enterprise Use Case |
| :--- | :--- | :--- | :---: | :---: | :---: | :---: | :--- |
| **RAID 0** | Block | None | 0 disks | $100\%$ | Very Fast | Very Fast | Temporary scratch space, caches |
| **RAID 1** | Block / Drive | Mirroring (1:1 copy) | 1 disk per pair | $50\%$ | Fast | Fast (sequential) | Transaction logs (`WAL`), boot volumes |
| **RAID 1+0** | Block | Mirroring + Striping | 1 disk per pair | $50\%$ | Very Fast | Fast | High-throughput OLTP database tables |
| **RAID 3** | Byte | Dedicated Parity Disk | 1 disk | $\frac{N-1}{N}$ | Fast (large) | Slow | Legacy media streaming (obsolete) |
| **RAID 4** | Block | Dedicated Parity Disk | 1 disk | $\frac{N-1}{N}$ | Fast | Bottlenecked | Specialized NetApp WAFL storage |
| **RAID 5** | Block | Distributed Parity ($P$) | 1 disk | $\frac{N-1}{N}$ | Very Fast | Moderate (penalty) | Read-heavy web databases, file shares |
| **RAID 6** | Block | Distributed $P+Q$ Parity | 2 disks | $\frac{N-2}{N}$ | Very Fast | Slower (penalty) | Massive multimedia archives, multi-TB disks |

## Workload Selection: Multimedia Archives

Examiners often test RAID selection for a **multimedia archive** storing large image and video files (2024 Q.7(c)):
- **Workload Traits:** Multi-gigabyte file sizes, read-dominated sequential streaming/downloads, rare writes (write-once, read-many), and very large capacity needs.
- **Candidate Evaluation:**
  - *RAID 0:* Rejected due to zero fault tolerance.
  - *RAID 1 / RAID 1+0:* Rejected because 50% capacity waste is cost-prohibitive for petabyte archives.
  - *RAID 5:* Good capacity and fast reads, but multi-terabyte drives take days to rebuild, risking total data loss if a second drive fails during rebuild.
  - *RAID 6:* **Recommended**. Provides high storage efficiency ($\frac{N-2}{N}$) and tolerates a second drive failure during lengthy rebuild windows.

---

## Significance of RAID in Database Recovery

RAID supports DBMS recovery in four fundamental ways:
1. **Physical Foundation for Stable Storage:** Recovery algorithms like Write-Ahead Logging assume the existence of stable storage that survives system crashes and media defects. RAID mirroring (RAID 1) and parity (RAID 5/6) provide this physical realization.
2. **Eliminates Costly Offline Restores:** A single disk failure does not stop database operation. The system avoids hours of downtime restoring tape backups and replaying redo logs.
3. **High Availability During Online Rebuild:** Queries and transactions run normally while the controller reconstructs lost data onto hot-spare drives in the background.
4. **Protects Transaction Logs:** Hosting WAL log files on dedicated RAID 1 arrays guarantees rapid sequential write speeds and protects commit records against media failures.

## 🏆 Golden Questions (Past Exam Archive)

### 🎯 GQ1 · 2018 Q.5(c) [Part 2] · How RAID Helps System Recovery · [02 Marks]

> *Section B · Asked in: 2018 Q.5(c) [Part 2] (2 of 4 marks)*

**Question.** Discuss each type of failure that can happen in DBMS. How does RAID model help to recover a system?

*(Note: 4-mark question split 2 + 2 with T12.1. This is Part 2 covering RAID recovery for 2 marks. Part 1 covering failure classification is in T12.1).*

**Answer.**

The RAID (Redundant Array of Independent Disks) model protects the database system from disk and media failures in three ways:

1. **Immediate Failover via Mirroring (RAID 1):** If a primary disk fails, the system instantly directs read and write requests to the mirror drive. The database continues running with zero downtime and zero data loss.
2. **On-the-Fly Parity Reconstruction (RAID 5 / RAID 6):** When a disk fails, the RAID controller reconstructs lost data blocks on the fly using a bitwise XOR of the surviving data and parity blocks.
3. **Online Rebuild with Hot Spares:** The controller copies reconstructed data onto a standby spare disk in the background. The repair completes without taking the database offline.

### 🎯 GQ2 · 2018 Q.8(c) · Description of RAID Levels · [03 Marks]

> *Section B · Asked in: 2018 Q.8(c) (3 marks) · L1*

**Question.** Describe the different RAID levels.

**Answer.**

![RAID levels showing disk cylinder configurations for (a) RAID 0, (b) RAID 1, (c) RAID 5, and (d) RAID 6](diagrams/T12.04_raid_levels_cylinders__TB_fig_12_04.jpg)
*Figure 12.4: RAID levels (Textbook Ch. 12, Figure 12.4)*

RAID organizes multiple physical disks to provide performance and fault tolerance. The primary levels are:

- **RAID 0 (Block Striping, No Redundancy):** Blocks are striped across multiple disks. It offers high read and write throughput, but any single drive failure causes complete data loss.
- **RAID 1 (Mirrored Disks):** Every disk has an identical duplicate disk. It provides 100% data redundancy and fast recovery, but requires double the storage capacity.
- **RAID 5 (Block-Interleaved Distributed Parity):** Data and parity blocks are distributed across all $N + 1$ disks. It survives any single disk failure with low storage overhead ($1 / (N+1)$).
- **RAID 6 (P + Q Redundancy):** Uses two independent error-correcting blocks (P and Q) across all disks. It tolerates up to two simultaneous disk failures.

*Summary of Other Levels:*
- **RAID 2:** Bit-level striping with Hamming error-correcting codes (obsolete).
- **RAID 3:** Byte-level striping with a single dedicated parity disk (obsolete).
- **RAID 4:** Block-level striping with a single dedicated parity disk (suffers from parity disk write bottlenecks).
- **RAID 1+0 (RAID 10):** Combines mirroring and striping to deliver high fault tolerance and fast I/O.

### 🎯 GQ3 · 2023 Q.4(a) · Features of RAID Models · [04 Marks]

> *Section A · Asked in: 2023 Q.4(a) (4 marks, CLO1) · L1*

**Question.** Discuss the features of RAID models.

**Answer.**

A Redundant Array of Independent Disks (RAID) provides four major architectural features:

1. **Data Striping (Performance Enhancement):** Data is segmented into blocks or bytes and distributed across multiple physical drives. This enables parallel disk I/O, which boosts transfer rates for large accesses and balances access loads.
2. **Data Redundancy (Fault Tolerance):** Redundancy is achieved through mirroring (duplicate blocks in RAID 1) or parity codes (XOR parity in RAID 5; Reed-Solomon P+Q codes in RAID 6). If a disk fails, data is restored without data loss.
3. **Storage Virtualization:** An array of physical drives appears to the operating system and DBMS as a single, large logical volume.
4. **Online Rebuild and Hot Swapping:** Failed drives can be replaced while the system remains powered on. The controller automatically rebuilds data onto hot-spare disks in the background.
5. **Background Data Scrubbing:** The controller continuously reads idle sectors to detect and repair latent sector corruption (bit rot) before additional drive failures occur.

### 🎯 GQ4 · 2023 Q.7(c) · RAID Model and Significance in Database Recovery · [03 Marks]

> *Section B · Asked in: 2023 Q.7(c) (3 marks, CLO2) · L1*

**Question.** Briefly describe the RAID model and its significance in database recovery.

**Answer.**

#### Description of RAID Model
The RAID (Redundant Array of Independent Disks) model combines multiple physical disk drives into a single logical unit. It uses data striping for parallel speed and data redundancy (mirroring or parity) for reliability.

#### Significance in Database Recovery
1. **Physical Realization of Stable Storage:** Standard database recovery algorithms (such as Write-Ahead Logging) assume the existence of **stable storage** that survives system crashes and media failures. RAID 1, 5, and 6 provide this physical foundation.
2. **Prevents Costly Offline Restores:** A single physical drive failure does not force the database offline. The system avoids hours of downtime spent restoring tape archives and replaying redo logs.
3. **High Availability During Rebuild:** Transactions continue processing queries normally while the controller reconstructs failed data blocks in the background.
4. **Guarantees Transaction Log Durability:** Database transaction logs are typically placed on RAID 1 volumes, ensuring sequential write speed and protection against log loss.

### 🎯 GQ5 · 2024 Q.7(c) · Multimedia Archive RAID Comparison & Recommendation · [03 Marks]

> *Section B · Asked in: 2024 Q.7(c) (3 marks, CO3) · L1*

**Question.** A multimedia archive contains very large image and video files. RAID is recommended for storage. Compare different RAID levels.

**Answer.**

#### Workload Characteristics
Multimedia archives store multi-gigabyte image and video files. The workload consists of high-throughput sequential reads (streaming, downloading), rare updates (write-once, read-many), and very high total capacity demands.

#### Comparison of RAID Levels

| RAID Level | Striping Unit | Redundancy Mechanism | Fault Tolerance | Usable Storage Capacity | Read Speed (Large Files) | Write Speed |
| :--- | :--- | :--- | :---: | :---: | :---: | :--- |
| **RAID 0** | Block | None | 0 disks | 100% | Very Fast | Very Fast |
| **RAID 1** | Block / Drive | Mirroring (copy) | 1 disk per pair | 50% | Fast | Moderate |
| **RAID 5** | Block | Distributed Parity | 1 disk | $\frac{N-1}{N}$ (High) | Very Fast | Fast for sequential |
| **RAID 6** | Block | Distributed P + Q | 2 disks | $\frac{N-2}{N}$ (High) | Very Fast | Moderate |
| **RAID 1+0** | Block | Mirroring + Striping | 1 disk per pair | 50% | Very Fast | Very Fast |

#### Recommendation and Justification
- **Recommended Level:** **RAID 6** (or **RAID 5** for smaller arrays).
- **Justification:** Multimedia archives require high storage efficiency and sequential read throughput, making parity schemes far more economical than mirroring (which wastes 50% capacity). Because archives use massive multi-terabyte drives, rebuild times can take days; RAID 6 tolerates a second drive failure during rebuild, protecting against catastrophic data loss.

## ⚡ Exam Tips & Common Mistakes

- **RAID 0 Zero Fault Tolerance:** Never say RAID 0 provides fault tolerance. Any single disk crash destroys all data in the array.
- **Small Write Penalty Calculation:** Remember that a small random write in RAID 5 requires **2 reads and 2 writes (4 disk I/Os)** to update data and parity.
- **RAID vs. Transaction Logs:** RAID protects against hardware disk failures, not software bugs or accidental table drops. WAL is still necessary.
- **Multimedia Archive Justification:** Recommend RAID 6 (or RAID 5) for multimedia archives. Mention that parity preserves capacity while RAID 6 dual parity protects against a second failure during lengthy drive rebuilds.
