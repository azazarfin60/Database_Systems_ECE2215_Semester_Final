# T11.02: Two-Phase Locking (2PL) Protocol

> **Topic:** T11 · Concurrency Control Protocols | **Priority:** 🟢 | **Exam Frequency:** 1/7 finals (2 questions: 9 marks)
> **Sources:** Silberschatz 7e Ch. 18 (§18.1.3, pp. 841–844) · Lecture Deck 08 (Slides 13–18) · Raidah Notes (p. 30)

---

## Mechanics of Two-Phase Locking

**Two-Phase Locking Protocol (2PL):** A concurrency control protocol that guarantees conflict serializability by requiring each transaction to acquire and release locks in two separate, sequential phases:

1. **Growing Phase:**
   - A transaction may acquire new locks (`lock-S` or `lock-X`).
   - A transaction may upgrade a lock ($S \to X$).
   - A transaction cannot release any lock.
2. **Shrinking Phase:**
   - A transaction may release held locks (`unlock`).
   - A transaction may downgrade a lock ($X \to S$).
   - A transaction cannot acquire any new lock.

**Lock Point:** The exact point in a schedule where a transaction acquires its final lock. This marks the boundary between the growing phase and the shrinking phase.

*Figure: Two-Phase Locking Protocol growing and shrinking phases (Source: Deck 08, Slide 13)*

### Why 2PL Guarantees Conflict Serializability

A schedule is conflict serializable if its precedence graph contains no directed cycles. Under 2PL, cycles cannot form:

- For a conflict serialization edge $T_1 \to T_2$ to exist on item $Q$, $T_1$ must access and release $Q$ before $T_2$ accesses $Q$. Therefore, $T_1$ has already started its shrinking phase before $T_2$ reaches its lock point.
- For a reverse edge $T_2 \to T_1$ to form on item $R$, $T_2$ would have to release $R$ before $T_1$ locks $R$.
- But $T_1$ is already in its shrinking phase. By the 2PL rule, $T_1$ cannot acquire any new lock!
- Therefore, a circular dependency ($T_1 \to T_2 \to T_1$) is impossible.
- **Serialization Order:** Ordering transactions by their **lock points** produces a valid equivalent serial schedule:

$$
\text{Lock Point}(T_i) < \text{Lock Point}(T_j) \implies T_i \longrightarrow T_j
$$

---

## Lock Conversions: Upgrade and Downgrade

**Lock Conversion:** An operation that changes the mode of an existing lock to improve concurrency without violating 2PL:

- **Lock Upgrade ($S \to X$):** Converts a shared lock to an exclusive lock when the transaction is ready to write. Upgrades expand lock authority, so they are allowed **only during the growing phase**.
- **Lock Downgrade ($X \to S$):** Converts an exclusive lock to a shared lock after updates are finished, allowing other transactions to read. Downgrades release exclusive authority, so they are allowed **only during the shrinking phase**.

---

## Limitations of Basic 2PL

Although Basic 2PL guarantees conflict serializability, it has two major limitations:

1. **Deadlocks can still occur:** If $T_1$ holds $A$ and requests $B$, while $T_2$ holds $B$ and requests $A$, both are blocked in their growing phases. Neither can unlock.
2. **Cascading rollbacks can occur:** Basic 2PL allows releasing exclusive locks before commit. If a transaction reads uncommitted data and the writer aborts, the reader must roll back too.

*(Strict 2PL and Rigorous 2PL solve cascading rollbacks by holding locks until commit; see T11.03).*

## 🏆 Golden Questions (Past Exam Archive)

### 🎯 GQ1 · 2017 Q.6(b) · 2PL Protocol Definition, Mechanics, and Example · [04 Marks]

> *Section B · Asked in: 2017 · L1 (asked once)*

**Question (2017 Q.6(b)).** How concurrent execution of transactions are controlled using two phase based locking protocol? Briefly discuss with an example.

**Answer.**

**Two-Phase Locking (2PL) Protocol:**  
The Two-Phase Locking protocol controls concurrent transactions by dividing lock requests and releases into two distinct, sequential phases:

1. **Growing Phase:**
   - A transaction may obtain new locks (shared or exclusive).
   - It can also convert a shared lock to an exclusive lock (upgrade).
   - A transaction cannot release any lock in this phase.
2. **Shrinking Phase:**
   - A transaction may release held locks.
   - It can convert an exclusive lock to a shared lock (downgrade).
   - A transaction cannot obtain any new locks in this phase.

**Lock Point:**  
The point in time where a transaction acquires its final lock is called its **lock point**. Once a transaction releases its first lock, the shrinking phase begins. The 2PL protocol guarantees conflict serializability. Transactions execute in the order of their lock points.

**Example:**  
Consider transaction $T_1$ transferring money between accounts $A$ and $B$:

```text
lock-S(A);         -- Growing phase begins
read(A);
lock-X(B);         -- Lock point (last lock acquired)
read(B);
B := B - 50;
write(B);
unlock(A);         -- Shrinking phase begins (no more locks allowed)
unlock(B);         -- Final unlock
```

Here, all locks are obtained before any lock is released. Therefore, $T_1$ follows 2PL and guarantees conflict serializability with concurrent transactions.

### 🎯 GQ2 · 2017 Q.7(a) · Starvation, 2PL Instruction Insertion, and Deadlock Justification · [05 Marks]

> *Section B · Asked in: 2017 · L1 (asked once)*

**Question (2017 Q.7(a)).** What is starvation? Consider the following two transactions.

**T1:**  
  `read(A);`  
  `read(B);`  
  `if A = 0 then B:=B+15% of B;`  
  `write(B);`

**T2:**  
  `read(B);`  
  `read(A);`  
  `if B = 0 then A:=A+20% of A;`  
  `write(A);`

Add lock and unlock instructions to transaction T1 and T2, so that they observe the two phase locking protocol. Can the execution of these transactions result in a deadlock? Justify.

**Answer.**

**Starvation:**  
Starvation occurs when a transaction waits indefinitely for a lock on a data item. This happens when a continuous stream of other concurrent transactions keeps obtaining compatible locks on that item. The waiting transaction cannot make progress.

**Adding 2PL Instructions to T1 and T2:**  
Under Two-Phase Locking (2PL), all lock acquisitions must precede all unlock operations. $T_1$ reads $A$ (needs shared lock) and updates $B$ (needs exclusive lock). $T_2$ reads $B$ (needs shared lock) and updates $A$ (needs exclusive lock).

**Transaction T1:**
```text
lock-S(A);
read(A);
lock-X(B);
read(B);
if A = 0 then B := B + 15% of B;
write(B);
unlock(A);
unlock(B);
```

**Transaction T2:**
```text
lock-S(B);
read(B);
lock-X(A);
read(A);
if B = 0 then A := A + 20% of A;
write(A);
unlock(B);
unlock(A);
```

**Deadlock Analysis and Justification:**  
**Yes, the execution of these transactions can result in a deadlock.**

**Justification:**  
Consider the following interleaved execution sequence:

1. $T_1$ executes `lock-S(A)` and `read(A)`. $T_1$ holds a shared lock on $A$.
2. $T_2$ executes `lock-S(B)` and `read(B)`. $T_2$ holds a shared lock on $B$.
3. $T_1$ issues `lock-X(B)`. Because exclusive mode conflicts with shared mode (by the lock-compatibility matrix, S and X are incompatible), $T_1$ must wait for $T_2$ to release $B$.
4. $T_2$ issues `lock-X(A)`. Because exclusive mode conflicts with shared mode (by the lock-compatibility matrix, S and X are incompatible), $T_2$ must wait for $T_1$ to release $A$.

Now, $T_1$ waits for $T_2$, and $T_2$ waits for $T_1$. Under 2PL, neither transaction can unlock an item before acquiring all locks. A circular wait occurs:

$$
\text{Cycle: } T_1 \to T_2 \to T_1
$$

Neither transaction can make progress. Thus, a deadlock occurs.

## ⚡ Exam Tips & Common Mistakes

- **Every Lock Before the First Unlock:** In 2PL code questions, make sure every `lock-S` and `lock-X` instruction appears before the very first `unlock` instruction. Placing even one `unlock` before a later `lock` breaks 2PL.
- **2PL Does NOT Prevent Deadlocks:** Basic 2PL guarantees conflict serializability, but deadlocks can and do occur when locks are requested in conflicting orders. Never claim 2PL is deadlock-free!
- **Always State the Lock Point:** In descriptive 2PL questions, define the lock point (the moment the last lock is acquired) and state that transactions serialize in lock-point order.
- **Conversion Direction Rules:** Remember: Upgrades ($S \to X$) belong strictly in the growing phase; Downgrades ($X \to S$) belong strictly in the shrinking phase.
