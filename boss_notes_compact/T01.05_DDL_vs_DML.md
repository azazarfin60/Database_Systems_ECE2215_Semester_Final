# T01.5: DDL vs. DML

> **Topic:** T01 · DB Concepts & Architecture | **Priority:** 🟢 | **Exam Frequency:** 1/7 finals (2 marks) · 2023 Q1c
> **Sources:** Silberschatz 7e Ch. 1 (§1.4) · Lecture Deck 01 (Slides 16–19) · Class Notes (Raidah p. 11–12; Fahim p. 1–3)

---

## Core Theory: Data Definition Language (DDL)

**Data-Definition Language (DDL):** A specialized set of commands used to define, alter, and delete database schemas, table structures, and integrity constraints.

**Data Dictionary (System Catalog):** A set of internal system tables that stores metadata about schemas, column types, constraints, and permissions generated by DDL compilers.

### Functions of DDL

1. **Schema Definition:** Creates new tables, views, and entire schemas.
2. **Integrity Constraint Specification:** Enforces business rules on data values:
   - **Domain Constraints:** Declares allowed data types (`INT`, `VARCHAR(30)`, `DATE`).
   - **Primary Key Constraints:** Guarantees uniqueness and non-null values for row identifiers.
   - **Referential Integrity:** Links foreign keys to primary keys in parent tables.
3. **Authorization Specification:** Grants or revokes user read and write permissions.
4. **Metadata Generation:** Compiles definitions and writes them into the data dictionary.

### Common DDL Commands

- `CREATE TABLE`: Builds a new table structure.
- `ALTER TABLE`: Adds, modifies, or drops columns and constraints on an existing table.
- `DROP TABLE`: Removes an entire table and its schema definition from the data dictionary.
- `TRUNCATE TABLE`: Empties all records from a table quickly while keeping its empty schema intact.
- `CREATE INDEX`: Creates a search structure (B+ tree or hash) on specified columns.

```sql
-- DDL Example: Defining a course table schema
CREATE TABLE course (
    course_id CHAR(7),
    title VARCHAR(50) NOT NULL,
    credits INT CHECK (credits > 0),
    PRIMARY KEY (course_id)
);
```

## Core Theory: Data Manipulation Language (DML)

**Data-Manipulation Language (DML):** A language used to query, insert, update, or delete actual data rows stored inside database tables.

### Four Core DML Operations

1. **Retrieval:** Searching and reading stored rows (`SELECT`).
2. **Insertion:** Adding new tuples to a table (`INSERT`).
3. **Modification:** Updating attribute values in existing tuples (`UPDATE`).
4. **Deletion:** Removing tuples matching a condition (`DELETE`).

```sql
-- DML Examples on the course table

-- 1. Insert a record
INSERT INTO course VALUES ('ECE2215', 'Database Systems', 3);

-- 2. Query records (Retrieval)
SELECT title FROM course WHERE credits = 3;

-- 3. Update an existing record
UPDATE course SET title = 'Data Base Systems' WHERE course_id = 'ECE2215';

-- 4. Delete a record
DELETE FROM course WHERE course_id = 'ECE2215';
```

## Procedural vs. Declarative DML

**Procedural DML:** A query language where the user specifies both **what data is needed** and the step-by-step procedure of **how to fetch that data**.
- **Example:** Relational Algebra ($\sigma, \Pi, \bowtie$). The user directs file scans, selections, and join steps explicitly.

**Declarative DML (Nonprocedural DML):** A query language where the user specifies only **what data is needed** without stating how to fetch it.
- **Example:** SQL. The user states filtering predicates (`WHERE`) and columns (`SELECT`). The DBMS query optimizer evaluates candidate execution plans and selects the lowest-cost physical access path automatically.

## Comparison: DDL vs. DML

| Feature | Data Definition Language (DDL) | Data Manipulation Language (DML) |
| :--- | :--- | :--- |
| **Main Job** | Defines and modifies the database schema (table structure). | Queries and updates data rows (instance) stored inside tables. |
| **Target Object** | Table schemas, columns, constraints, and the data dictionary. | Individual records (tuples) and column values. |
| **Output Destination** | Metadata stored in the system catalog (data dictionary). | Result sets returned to the client or written to data blocks. |
| **Core SQL Commands** | `CREATE`, `ALTER`, `DROP`, `TRUNCATE`, `RENAME`. | `SELECT`, `INSERT`, `UPDATE`, `DELETE`. |
| **Transaction Behavior** | Implicitly commits immediately in engines like MySQL. | Can be rolled back using `ROLLBACK` within an active transaction. |
| **Row Triggers** | Does not fire row-level DML triggers. | Fires row-level triggers (`BEFORE`/`AFTER INSERT`, `UPDATE`, `DELETE`). |
| **Usage Frequency** | Executed during initial setup or periodic schema updates. | Executed thousands of times per minute during normal application operations. |

## 🏆 Golden Questions (Past Exam Archive)

### 🎯 GQ1 · 2023 Q.1(c) · 02 Marks

> *Section A · CLO1 · Asked in: 2023 · L1 (asked once)*

**Question.** Explain DDL and DML with example.

**Answer.**

- **DDL (Data Definition Language):** A specialized set of commands used to define, alter, and delete the database schema and storage structures.
  Example:
  ```sql
  CREATE TABLE instructor (
      ID CHAR(5),
      name VARCHAR(20),
      dept_name VARCHAR(20),
      salary NUMERIC(8,2)
  );
  ```
- **DML (Data Manipulation Language):** A language used to query, insert, update, or delete data stored in the database.
  Example:
  ```sql
  SELECT name FROM instructor WHERE dept_name = 'Comp. Sci.';
  ```

## ⚡ Exam Tips & Common Mistakes

- **Provide syntactically valid SQL code:** For 2-mark questions, examiners award 1 mark for definition and 1 mark for valid SQL syntax. Avoid informal pseudo-code.
- **`SELECT` is declarative DML:** Do not classify `SELECT` as a separate language category like "DQL" on exam papers unless explicitly asked. Silberschatz treats `SELECT` as nonprocedural DML.
- **`TRUNCATE` is DDL, not DML:** Although `TRUNCATE` deletes table rows, it deallocates data pages directly without row-by-row logging. It is a DDL command.
- **Note transaction commit differences:** DDL statements cause an implicit commit in MySQL. DML operations can be rolled back using `ROLLBACK` within an active transaction block.
