# T08.4: Attribute Closure and Finding Candidate Keys

> **Topic:** T08 · Normalization & Functional Dependencies | **Priority:** 🟢 Foundational | **Exam Frequency:** 1/7 finals · 4 marks (+ CT-03 Q01(a), 4 marks)
> **Sources:** Silberschatz 7e Ch. 7 (§7.4.2) · Lecture Deck 06 (Slides 25–29) · Raidah Class Notes (pp. 20–21)

## The Attribute Closure Algorithm ($X^+$)

Computing the complete closure of functional dependencies $F^+$ is exponential in the number of attributes. Computing the **attribute closure** of a specific attribute set takes linear time and answers all essential design questions.

**Closure of a Set of Functional Dependencies ($F^+$):** The complete set of all functional dependencies logically implied by $F$.

**Attribute Closure ($\alpha^+$):** The set of all attributes functionally determined by attribute set $\alpha$ under functional dependency set $F$. That is, $\alpha^+ = \{B \mid \alpha \rightarrow B \in F^+\}$.

**Superkey:** An attribute set $\alpha \subseteq R$ that uniquely identifies every tuple in relation instance $r(R)$. Formally, $\alpha$ is a superkey if $\alpha \rightarrow R$, meaning $\alpha^+ = R$.

**Candidate Key:** A minimal superkey of relation schema $R$. An attribute set $K$ is a candidate key if $K^+ = R$ and no proper subset $\gamma \subset K$ satisfies $\gamma^+ = R$.

### Algorithm Procedure

```text
result := alpha;
repeat
    for each functional dependency beta -> gamma in F do
    begin
        if beta is a subset of result then
            result := result union gamma;
    end
until (result does not change);
return result;
```

### Practical Applications of Attribute Closure

1. **Testing Superkeys:** Compute $\alpha^+$. If $\alpha^+ = R$, then $\alpha$ is a superkey of $R$.
2. **Testing Functional Dependencies:** To verify whether $\alpha \rightarrow \beta$ holds under $F$, compute $\alpha^+$. The dependency holds if and only if $\beta \subseteq \alpha^+$.
3. **Representing $F^+$:** Computing attribute closures for each subset of attributes generates all non-trivial dependencies implied by $F$.

## Finding All Candidate Keys: The L/R/M/N Shortcut

To find all candidate keys without checking all $2^n - 1$ subsets, classify every attribute of schema $R$ into four buckets based on its appearance in the functional dependencies of $F$:

| Class | Position in FDs | Status in Candidate Keys | Action |
| :--- | :--- | :--- | :--- |
| **L (Left-only)** | Appears only on LHS | **Must belong to every candidate key** | Add to base key set |
| **R (Right-only)** | Appears only on RHS | **Can never belong to any candidate key** | Discard from key search |
| **N (Neither)** | Appears on neither side | **Must belong to every candidate key** | Add to base key set |
| **M (Middle / Both)** | Appears on both LHS and RHS | **May or may not belong to candidate keys** | Combine with $(L \cup N)$ |

### Step-by-Step Search Procedure

1. **Classify Attributes:** Partition all attributes into sets $L$, $R$, $M$, and $N$.
2. **Form Base Core:** Define $K_{\text{core}} = L \cup N$.
3. **Check Base Core Closure:** Compute $K_{\text{core}}^+$.
   - If $K_{\text{core}}^+ = R$, then $K_{\text{core}}$ is the **unique candidate key**. Stop.
   - If $K_{\text{core}}^+ \neq R$, proceed to step 4.
4. **Test Combinations with $M$:** Combine $K_{\text{core}}$ with one attribute from $M$ at a time. Compute $(K_{\text{core}} \cup \{M_i\})^+$. If it equals $R$, it is a candidate key.
5. **Expand Combinations:** If needed, test pairs from $M$, moving systematically from smaller to larger attribute sets. Always skip any superset of an already identified candidate key to guarantee minimality.

## Lecture Key Drills (Deck 06 Slides 26–28)

1. **Linear Chain (Slide 26):** $R(A, B, C, D, E)$, $F = \{A \rightarrow B, B \rightarrow C, C \rightarrow D, D \rightarrow E\}$.  
   $L = \{A\}, R = \{E\}, M = \{B, C, D\}, N = \emptyset$.  
   $A^+ = \{A, B, C, D, E\} = R$.  
   Unique Candidate Key: $\{A\}$.

2. **Cyclic Dependencies (Slide 27):** $R(A, B, C, D)$, $F = \{A \rightarrow B, B \rightarrow C, C \rightarrow D, D \rightarrow A\}$.  
   $M = \{A, B, C, D\}$, $L = R = N = \emptyset$.  
   $A^+ = B^+ = C^+ = D^+ = R$.  
   Candidate Keys: $\{A\}, \{B\}, \{C\}, \{D\}$.

3. **Composite Core (Slide 28):** $R(A, B, C, D, E)$, $F = \{A \rightarrow B, B \rightarrow C, CD \rightarrow E\}$.  
   $L = \{A, D\}, R = \{E\}, M = \{B, C\}, N = \emptyset$.  
   $AD^+ = \{A, D, B, C, E\} = R$.  
   Unique Candidate Key: $\{AD\}$.

## 🏆 Golden Questions (Past Exam Archive)

### 🎯 GQ1 · 2021 Q.5(b) · Computing Closures and Candidate Keys · 04 Marks

> *Section B · CLO1 · Asked in: 2021*

**Question.** Compute the closure of the following set F of functional dependencies for relational schema r (A, B, C, D, E).

  $A \to BC$  
  $CD \to E$  
  $B \to D$  
  $E \to A$

List the candidate Keys for R.

**Answer.**

#### 1. Closure of Functional Dependencies ($F^+$)

The complete closure $F^+$ contains over one hundred trivial and non-trivial dependencies, which is too large to write out fully.

We compute the attribute closures of each single attribute and pair under $F$:

1. **$A^+$:**
   - Initial: $\{A\}$
   - Using $A \rightarrow BC$: $\{A, B, C\}$
   - Using $B \rightarrow D$: $\{A, B, C, D\}$
   - Using $CD \rightarrow E$: $\{A, B, C, D, E\}$
   - Result: $A^+ = \{A, B, C, D, E\}$

2. **$B^+$:**
   - Initial: $\{B\}$
   - Using $B \rightarrow D$: $\{B, D\}$
   - Result: $B^+ = \{B, D\}$

3. **$C^+$:**
   - No FD has $C$ on the LHS alone.
   - Result: $C^+ = \{C\}$

4. **$D^+$:**
   - No FD has $D$ on the LHS alone.
   - Result: $D^+ = \{D\}$

5. **$E^+$:**
   - Initial: $\{E\}$
   - Using $E \rightarrow A$: $\{E, A\}$
   - Since $A^+ = \{A, B, C, D, E\}$: $\{A, B, C, D, E\}$
   - Result: $E^+ = \{A, B, C, D, E\}$

6. **Key Two-Attribute Closures:**
   - $BC^+$: Using $B \rightarrow D$, we get $\{B, C, D\}$. Using $CD \rightarrow E$, we get $\{B, C, D, E\}$. Using $E \rightarrow A$, we get $\{A, B, C, D, E\}$. So $BC^+ = \{A, B, C, D, E\}$.
   - $CD^+$: Using $CD \rightarrow E$, we get $\{C, D, E\}$. Using $E \rightarrow A$, we get $\{A, C, D, E\}$. Using $A \rightarrow BC$, we get $\{A, B, C, D, E\}$. So $CD^+ = \{A, B, C, D, E\}$.

**Key Non-Trivial Functional Dependencies in $F^+$ (derived using Armstrong's Axioms):**
- $A \rightarrow D$ (by Decomposition of $A \rightarrow BC$ to $A \rightarrow B$, then Transitivity with $B \rightarrow D$).
- $A \rightarrow E$ (by Transitivity from $A \rightarrow CD$ and $CD \rightarrow E$).
- $E \rightarrow B, E \rightarrow C, E \rightarrow D$ (by Transitivity from $E \rightarrow A$ and $A \rightarrow BCDE$).
- $BC \rightarrow E$ (by Augmentation of $B \rightarrow D$ to $BC \rightarrow CD$, then Transitivity with $CD \rightarrow E$).
- $CD \rightarrow A, CD \rightarrow B$ (by Transitivity from $CD \rightarrow E$, $E \rightarrow A$, and $A \rightarrow B$).

#### 2. Candidate Keys for $R$

A candidate key is a minimal set of attributes whose closure contains all attributes $\{A, B, C, D, E\}$.

- $A^+ = \{A, B, C, D, E\} \implies \{A\}$ is a candidate key.
- $E^+ = \{A, B, C, D, E\} \implies \{E\}$ is a candidate key.
- $BC^+ = \{A, B, C, D, E\}$, while neither $B^+$ nor $C^+$ is a superkey $\implies \{BC\}$ is a candidate key.
- $CD^+ = \{A, B, C, D, E\}$, while neither $C^+$ nor $D^+$ is a superkey $\implies \{CD\}$ is a candidate key.

$$
\text{Candidate Keys} = \{A\}, \{E\}, \{BC\}, \{CD\}
$$

### 🎯 GQ2 · CT-03 Q.01(a) · Candidate Keys for ENROLLMENT Relation · 04 Marks

> *CO3 · Asked in: CT-03*

**Question.** Consider $\text{ENROLLMENT}(\text{StudentID}, \text{StudentName}, \text{CourseID}, \text{CourseName}, \text{InstructorID}, \text{InstructorName}, \text{Grade})$ with functional dependencies: $\text{StudentID} \rightarrow \text{StudentName}$; $\text{CourseID} \rightarrow \text{CourseName}, \text{InstructorID}$; $\text{InstructorID} \rightarrow \text{InstructorName}$; $(\text{StudentID}, \text{CourseID}) \rightarrow \text{Grade}$.  
**(a)** Identify all the possible candidate key of the relation.

**Answer.**

To find all candidate keys, we analyze the attributes that must appear in every key.

1. **Attributes not on any RHS:**
   Examining the right-hand sides of the given functional dependencies:
   - $\text{RHS} = \{\text{StudentName}, \text{CourseName}, \text{InstructorID}, \text{InstructorName}, \text{Grade}\}$
   - Attributes $\text{StudentID}$ and $\text{CourseID}$ never appear on any right-hand side.
   - Therefore, $\{\text{StudentID}, \text{CourseID}\}$ must be present in every candidate key.

2. **Compute the Attribute Closure of $\{\text{StudentID}, \text{CourseID}\}$:**
   - **Step 1 (Initial):**  
     $X^+ = \{\text{StudentID}, \text{CourseID}\}$
   - **Step 2 (Apply $\text{StudentID} \rightarrow \text{StudentName}$):**  
     $X^+ = \{\text{StudentID}, \text{CourseID}, \text{StudentName}\}$
   - **Step 3 (Apply $\text{CourseID} \rightarrow \text{CourseName}, \text{InstructorID}$):**  
     $X^+ = \{\text{StudentID}, \text{CourseID}, \text{StudentName}, \text{CourseName}, \text{InstructorID}\}$
   - **Step 4 (Apply $\text{InstructorID} \rightarrow \text{InstructorName}$):**  
     $X^+ = \{\text{StudentID}, \text{CourseID}, \text{StudentName}, \text{CourseName}, \text{InstructorID}, \text{InstructorName}\}$
   - **Step 5 (Apply $(\text{StudentID}, \text{CourseID}) \rightarrow \text{Grade}$):**  
     $X^+ = \{\text{StudentID}, \text{CourseID}, \text{StudentName}, \text{CourseName}, \text{InstructorID}, \text{InstructorName}, \text{Grade}\}$

3. **Check for Minimality:**
   We check proper subsets of $\{\text{StudentID}, \text{CourseID}\}$:
   - $\{\text{StudentID}\}^+ = \{\text{StudentID}, \text{StudentName}\} \neq R$
   - $\{\text{CourseID}\}^+ = \{\text{CourseID}, \text{CourseName}, \text{InstructorID}, \text{InstructorName}\} \neq R$

Neither proper subset determines all attributes. Therefore, $\{\text{StudentID}, \text{CourseID}\}$ is minimal.

$$
\boxed{\text{Candidate Key} = \{\text{StudentID}, \text{CourseID}\}}
$$

This is the only candidate key for the relation.

## ⚡ Exam Tips & Common Mistakes

- **Closure steps must be explicit:** When computing attribute closure in exams, show the intermediate sets after applying each functional dependency. Do not jump straight to the final answer.
- **Minimality check is mandatory:** A set of attributes whose closure is $R$ is merely a superkey. You must show that no proper subset can generate $R$ before declaring it a candidate key.
- **Attributes in N bucket:** Attributes that appear on neither the LHS nor RHS are often overlooked. They must be included in every candidate key because no dependency can ever generate them.
