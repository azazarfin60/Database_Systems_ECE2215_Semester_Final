# T10.5: View Serializability and Blind Writes

> **Topic:** T10 · Serializability | **Priority:** 🟢 | **Exam Frequency:** 1/7 finals (6 marks)
> **Sources:** Silberschatz 7e Ch. 18 (§18.5 Note 18.1, p. 867) · Lecture Deck 07 (Slides 22–23, 27) · Raidah Notes (pp. 27–28)

---

## 1. The Three Conditions of View Equivalence

**View Equivalence:** Two schedules $S$ and $S'$ over the same transactions are view equivalent if they satisfy three conditions for every data item $Q$:
1. **Initial Read:** If transaction $T_i$ reads the initial value of $Q$ in $S$, then $T_i$ must also read the initial value of $Q$ in $S'$.
2. **Updated Read (Read-From):** If transaction $T_i$ reads a value of $Q$ written by $T_j$ in $S$, then $T_i$ must read the value produced by that same $\text{write}(Q)$ of $T_j$ in $S'$.
3. **Final Write:** If transaction $T_k$ executes the final $\text{write}(Q)$ in $S$, then $T_k$ must execute the final $\text{write}(Q)$ in $S'$.

**View Serializability:** A schedule $S$ is view serializable if it is view equivalent to some serial schedule.

---

## 2. Blind Writes: Beyond Conflict Serializability

**Blind Write:** A $\text{write}(Q)$ operation executed by a transaction without having read item $Q$ first.

Every view-serializable schedule that is not conflict-serializable **must contain at least one blind write**.

### Why Conflict Serializability Rejects Safe Schedules

Consider schedule $S$:
$$
S: r_1(A); \quad w_2(A); \quad w_1(A); \quad w_3(A)
$$

1. **Precedence graph has a cycle:**
   - $r_1(A)$ precedes $w_2(A) \implies T_1 \to T_2$.
   - $w_2(A)$ precedes $w_1(A) \implies T_2 \to T_1$.
   - Cycle: $T_1 \longleftrightarrow T_2$. The schedule is **not conflict serializable**.
2. **View equivalence check against $\langle T_1, T_2, T_3 \rangle$:**
   - $T_1$ reads the initial value of $A$ in both schedules.
   - No transaction reads an updated value of $A$ in either schedule.
   - $T_3$ performs the final write on $A$ in both schedules.
3. Because all 3 conditions hold, $S$ is **view serializable** to $\langle T_1, T_2, T_3 \rangle$. $T_2$'s blind write was overwritten before any transaction ever read it.

---

## 3. Conflict Serializability vs. View Serializability

| Feature | Conflict Serializability | View Serializability |
| :--- | :--- | :--- |
| **Core Idea** | Preserves the order of all conflicting pairs ($RW, WR, WW$) | Preserves initial reads, read-from dependencies, and final writes |
| **Test Method** | Precedence graph cycle detection | Check 3 view conditions against candidate serial orders |
| **Complexity** | Fast polynomial time: $\mathcal{O}(V + E)$ | NP-complete in general |
| **Class Size** | Stricter subset | Broader superset |
| **Blind Writes** | Rejects safe schedules with unread blind writes | Accepts safe schedules with blind writes |
| **DBMS Use** | Standard 2PL lock managers and basic timestamp ordering | Theoretical standard; realized in optimizations like Thomas' Write Rule |

$$
\text{Conflict Serializable Schedules} \subset \text{View Serializable Schedules}
$$

**Answer.**

#### 1. What is View Serializability?

A schedule $S$ is **view serializable** if it is view equivalent to some serial schedule. Two schedules $S$ and $S'$ with the same set of transactions are **view equivalent** if three conditions are satisfied for every data item $Q$:
1. **Initial read:** If transaction $T_i$ reads the initial value of $Q$ in $S$, then $T_i$ must also read the initial value of $Q$ in $S'$.
2. **Read-from (updated read):** If transaction $T_i$ reads a value of $Q$ produced by $T_j$ in $S$, then $T_i$ must read the value produced by the same write of $T_j$ in $S'$.
3. **Final write:** The transaction that performs the final write on $Q$ in $S$ must also perform the final write on $Q$ in $S'$.

---

#### 2. Why Do We Need View Serializability?

- **Conflict serializability is too strict:** Conflict serializability only permits schedules that can be transformed into a serial schedule by swapping non-conflicting adjacent instructions.
- **Handling blind writes:** When transactions perform a write without first reading that item (known as a **blind write**), conflict equivalence can reject schedules that are entirely safe and consistent.
- **Wider class of valid schedules:** View serializability looks at the actual flow of data and the final state. Every conflict serializable schedule is view serializable, but view serializability also allows schedules with blind writes (like those accepted by Thomas' Write Rule).

---

#### 3. Checking View Serializability of the Given Schedule

Let the given schedule be $S$:

| Step | $T_1$ | $T_2$ | Target Item |
| :--: | :-- | :-- | :--: |
| 1 | $R(X)$ | | $X$ |
| 2 | $W(X)$ | | $X$ |
| 3 | | $R(X)$ | $X$ |
| 4 | | $W(X)$ | $X$ |
| 5 | $R(Y)$ | | $Y$ |
| 6 | $W(Y)$ | | $Y$ |
| 7 | | $R(Y)$ | $Y$ |
| 8 | | $W(Y)$ | $Y$ |

We check if $S$ is view equivalent to the serial schedule $S' = \langle T_1, T_2 \rangle$:

1. **Initial read condition:**
   - In $S$: $T_1$ reads the initial value of $X$ (step 1) and initial value of $Y$ (step 5).
   - In $\langle T_1, T_2 \rangle$: $T_1$ executes first, so $T_1$ reads initial $X$ and initial $Y$. Condition holds.
2. **Read-from condition:**
   - In $S$: $T_2$ reads $X$ written by $T_1$ (step 3 reads step 2). $T_2$ reads $Y$ written by $T_1$ (step 7 reads step 6).
   - In $\langle T_1, T_2 \rangle$: $T_2$ reads $X$ written by $T_1$, and $T_2$ reads $Y$ written by $T_1$. Condition holds.
3. **Final write condition:**
   - In $S$: $T_2$ performs the final write on $X$ (step 4) and final write on $Y$ (step 8).
   - In $\langle T_1, T_2 \rangle$: $T_2$ executes last, performing the final writes on $X$ and $Y$. Condition holds.

![2020 Q.6(b) Precedence Graph showing acyclic edge T1 to T2](diagrams/T10_2020_Q6b_precedence_graph.jpg)
*Figure 1: Precedence graph for 2020 Q.6(b) confirming acyclic conflict serialization order T1 to T2.*

All three conditions are satisfied with respect to the serial schedule $\langle T_1, T_2 \rangle$. (Also, every conflict edge goes $T_1 \to T_2$, so the schedule is also conflict serializable).

**Result:** The schedule is **view serializable**, equivalent to the serial schedule:
$$
\boxed{\langle T_1, T_2 \rangle}
$$

## ⚡ Exam Tips & Common Mistakes

- **State all three view conditions:** Listing only two conditions loses marks. Write (1) Initial read, (2) Read-from, and (3) Final write.
- **Mention blind writes:** The phrase "blind write" is the standard textbook reason why view serializability is needed.
- **Explain why DBMS engines avoid view testing:** Testing view serializability is NP-complete. Engines rely on conflict serializability instead.
- **Acyclic shortcut:** If a precedence graph is acyclic, the schedule is conflict serializable and therefore automatically view serializable.
