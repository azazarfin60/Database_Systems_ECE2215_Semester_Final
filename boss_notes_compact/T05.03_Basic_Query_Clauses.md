## Query Clause Syntax and Mechanics

SQL queries retrieve data using a standard clause sequence:

```sql
SELECT [DISTINCT | ALL] attribute1 [AS alias1], attribute2
FROM table1 [AS t1]
WHERE search_condition
ORDER BY attribute1 [ASC | DESC];
```

**DISTINCT and ALL Clauses:** By default, SQL queries retain duplicate rows in output, which corresponds to the `ALL` keyword. Writing `SELECT DISTINCT` removes duplicate tuples so every row in the output relation is unique.

**ORDER BY Clause:** Sorts output tuples based on one or more attributes. It sorts in ascending order (`ASC`) by default. Appending `DESC` sorts values in descending order.

**Rename Operation (AS):** Assigns a temporary alias to a column expression or relation in the form `old_name AS new_name`. Column aliases clarify output headers, while relation aliases shorten table references and allow self-joins.

**Pattern Matching (LIKE):** Matches character strings against patterns in the `WHERE` clause. It uses two wildcard symbols: percent (`%`) matches any substring of zero or more characters; underscore (`_`) matches any single character.

---

## Mechanics of Each Clause

### 1. Duplicate Handling (`DISTINCT` vs. `ALL`)

In formal relational algebra, relations are sets with no duplicate tuples. Real database engines process multisets (bags) because stripping duplicates requires sorting or hashing:
- `SELECT ALL dept_name FROM instructor;` keeps duplicate rows (default behavior).
- `SELECT DISTINCT dept_name FROM instructor;` strips duplicate rows.

```sql
-- Evaluates uniqueness across the combination of both attributes:
SELECT DISTINCT dept_name, salary FROM instructor;

-- Counts unique non-null departments:
SELECT COUNT(DISTINCT dept_name) FROM instructor;
```

### 2. Output Sorting (`ORDER BY`)

Because relational tables have no inherent row ordering, queries without `ORDER BY` produce indeterminate tuple sequences.

```sql
-- Multi-column sorting: sorts by dept_name ASC; ties broken by salary DESC
SELECT name, dept_name, salary
FROM instructor
ORDER BY dept_name ASC, salary DESC;
```

**Evaluation Order:**
1. `FROM` (table loading and joins)
2. `WHERE` (tuple filtering)
3. `GROUP BY` (group formation)
4. `HAVING` (group filtering)
5. `SELECT` (projection and expressions)
6. `ORDER BY` (output sorting)

Because `ORDER BY` executes after `SELECT`, it can sort on column aliases declared in the `SELECT` list.

### 3. Attribute and Relation Aliasing (`AS`)

- **Attribute Aliasing:** Renames calculated expressions or aggregate outputs:
  ```sql
  SELECT salary * 1.15 AS revised_salary FROM employee;
  ```
- **Relation Aliasing (Tuple Variables):** Distinguishes copies of the same relation in a self-join:
  ```sql
  SELECT DISTINCT T.name
  FROM instructor AS T, instructor AS S
  WHERE T.salary > S.salary AND S.dept_name = 'Biology';
  ```
In standard SQL, the keyword `AS` is optional for table aliases (`FROM instructor T`).

### 4. String Pattern Matching (`LIKE`)

| Pattern | Evaluation Rule | Example Match | Example Non-Match |
| :--- | :--- | :--- | :--- |
| `'A%'` | Starts with "A" | `'Amelia'`, `'Ahmad'` | `'Sansa'` |
| `'%ECE%'` | Contains "ECE" anywhere | `'ECE 2215'`, `'DECE'` | `'CSE 2101'` |
| `'___'` | Exactly 3 characters long | `'ECE'`, `'CSE'` | `'RUET'`, `'EC'` |
| `'_b%'` | Second letter is "b" | `'Ibrahim'`, `'Abdullah'` | `'Amelia'` |

To search for literal wildcard characters, specify an escape character:
```sql
SELECT * FROM discounts WHERE code LIKE '%100 \%' ESCAPE '\';
```

## 🏆 Golden Questions (Past Exam Archive)

### 🎯 GQ1 · CT-02 Q.01(b) · Department and CGPA Filter with Descending Sort · 02 Marks

> *CO2 · Asked in: CT-02 · L1 (asked once)*

**Question.** Given $\text{STUDENT}(\text{StudentID}, \text{Name}, \text{Department}, \text{Semester}, \text{CGPA})$, write SQL query:  
**(b)** Display students from the ECE department whose CGPA is greater than 3.50, arranged by CGPA in descending order.

**Answer.**

```sql
SELECT *
FROM STUDENT
WHERE Department = 'ECE' AND CGPA > 3.50
ORDER BY CGPA DESC;
```

### 🎯 GQ2 · 2019 Q.7(a)(ii) · Name Filter Using LIKE Pattern Matching · 03 Marks

> *Section B · Asked in: 2019 · L1 (asked once)*

**Question.** Considering the following data tables (Student, GPA, Credits) answer (ii):  
`Student (St_ID, St Name)`  
`GPA (St_ID, Sub_Code, gpa)`  
`Credit (Sub_Code, Credit)`  
(ii) Write down the SQL query to find out the registered subjects of those students whose name started with "A".

**Answer.**

```sql
SELECT DISTINCT g.Sub_Code
FROM Student s
JOIN GPA g ON s.St_ID = g.St_ID
WHERE s.`St Name` LIKE 'A%';
```

*Notes:*
- In table `Student`, the column name is printed with a space as `St Name`. In MySQL, identifiers containing spaces are wrapped in backticks (`` `St Name` ``).
- `DISTINCT` ensures subject codes appear only once if multiple qualifying students registered for the same subject.

### 🎯 GQ3 · 2024 Q.7(b)(iii–iv) · Short Notes on ORDER BY and AS Clauses · 02 Marks

> *Section B · CO1 · Asked in: 2024 · L1 (asked once)*

**Question.** Write short note on the following statements –  
iii) Order By  
iv) As

**Answer.**

**iii) ORDER BY:**  
An SQL clause that sorts query result rows in ascending (`ASC`, default) or descending (`DESC`) order based on one or more attributes. Multiple sort keys break ties sequentially from left to right.

```sql
SELECT name, salary
FROM instructor
ORDER BY salary DESC, name ASC;
```

**iv) AS:**  
An SQL keyword used to define an alias (an alternative temporary name). It can rename an attribute or computed expression in the `SELECT` clause for readability, or rename a table in the `FROM` clause to shorten table references and enable self-joins.

```sql
SELECT salary * 1.15 AS revised_salary
FROM employee AS e;
```

## ⚡ Exam Tips & Common Mistakes

- **Clause Order:** Keep SQL clauses in strict sequence: `SELECT` $\to$ `FROM` $\to$ `WHERE` $\to$ `GROUP BY` $\to$ `HAVING` $\to$ `ORDER BY`.
- **Use DESC, not DESCENDING:** The SQL keyword for descending sort is `DESC`.
- **Wildcard Matching:** Never write `WHERE name = 'A%'`. Equality searches for the exact 2-character string `"A%"`. Always use `LIKE 'A%'`.
- **Column Names with Spaces:** Enclose attribute names containing spaces in backticks (e.g. `` `St Name` ``).
- **Aliases in WHERE:** Column aliases created in `SELECT` cannot be evaluated in the `WHERE` clause because `WHERE` executes before `SELECT`.
