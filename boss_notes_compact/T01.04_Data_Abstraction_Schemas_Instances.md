# T01.4: Data Abstraction, Schemas, and Instances

## Purpose of Data Abstraction

**Data Abstraction:** Data abstraction is the practice of hiding complex, low-level physical storage details from users and programmers. It provides clean conceptual views of data across three levels: the physical level, the logical level, and the view level.

**Physical Data Independence:** Physical data independence is the ability to modify the physical schema (storage structures, disk layouts, or indexes) without altering the logical schema or application programs.

**Database Schema:** The overall structural blueprint of the database. It specifies table names, columns, and integrity rules. It is set up during design and rarely changes.

**Database Instance:** The collection of actual data rows stored in the database at a specific moment in time. It changes whenever rows are inserted, updated, or removed.

A database system uses complex data structures to achieve fast retrieval. Most end users and application programmers do not understand low-level disk management. Data abstraction addresses this complexity in three ways:

1. **Simplifies User Interaction:** Users and programmers interact with clean logical tables or tailored forms instead of managing byte offsets and disk blocks.
2. **Enforces Data Security:** Custom views expose only the specific data items a user group needs. This hides sensitive attributes (such as faculty salaries or password hashes).
3. **Enables Physical Data Independence:** Administrators can reorganize disk blocks or build new indexes without rewriting existing application queries.

---

## The Three Levels of Data Abstraction

A DBMS splits data representation into three distinct levels from bottom to top:

### 1. Physical Level (Lowest Level)
- Describes **how** records are stored on physical storage media (such as SSDs or magnetic disks).
- Covers byte alignments, disk block allocations (4 KB or 8 KB pages), variable-length record layouts, B+ tree pointers, and hash buckets.
- Managed by the DBMS storage manager. Application developers rarely interact with this level.

### 2. Logical Level (Intermediate Level)
- Describes **what** data is stored in the database and the relationships among those data items.
- Models the entire database as a set of logical tables, attributes, and constraints.
- Programmers and DBAs work at this level when designing schemas.
- In programming terms, defining a logical table resembles declaring a structured record type:

```text
type instructor = record
    ID : string;
    name : string;
    dept_name : string;
    salary : integer;
end;
```

### 3. View Level (Highest Level)
- Describes only a **specific subset** of the database tailored for a given user group or application.
- Hides irrelevant or sensitive columns to simplify interaction and enforce privacy.
- For example, a student registration view shows personal course enrollments but hides other students' grades and instructor payroll details.

## Schemas, Instances, and Data Independence

### Multi-Level Schemas

Because a database operates across three levels of abstraction, it maintains three corresponding schemas:

1. **Physical Schema:** Defines physical storage organization, file structures, and disk access methods.
2. **Logical Schema:** Defines the complete logical design of tables, column data types, and integrity constraints.
3. **Subschemas (View Schemas):** Multiple schemas at the view level describing different user windows into the database.

### Physical Data Independence in Practice

Applications access the database through the **logical schema**. The DBMS maps logical queries to the physical storage structures automatically.

- **Example 1:** A DBA creates a B+ tree index on `instructor(salary)` to accelerate budget reports:
  ```sql
  CREATE INDEX idx_salary ON instructor(salary);
  ```
  Existing applications running `SELECT name FROM instructor WHERE salary > 50000;` continue to execute without code modifications. The query optimizer automatically uses the new index.
- **Example 2:** A DBA moves data files from a heap file to a clustered index file on a faster SSD. Because the table and column names remain identical, no application software requires rewriting or recompiling.

### 🎯 GQ1 · 2017 Q.2(b), 2019 Q.2(a), CT-01 Q.01 · 04–05 Marks

> *Section A · Asked in: 2017, 2019, CT-01 (CO1, 5 Marks) · L2 merge*

**Question (2017 Q.2(b)).** What is the purpose of data abstraction? Describe the different level of data abstraction.

**Question (2019 Q.2(a)).** What is data abstraction? Describe the different level of data abstraction.

**Question (CT-01 · Q.01).** Define data abstraction. Describe different types of data abstractions.

**Answer.**

**Purpose of Data Abstraction:**  
A database contains complex data structures, storage blocks, and indexing schemes. Most end users and programmers are not trained in low-level storage details. Data abstraction hides this physical complexity. It simplifies user interactions, enforces security, and enables physical data independence.

**Levels of Data Abstraction:**
1. **Physical level:** The lowest abstraction level. It describes *how* records are stored on secondary storage media (such as byte offsets, data blocks, B+ trees, and hashing schemes).
2. **Logical level:** The intermediate level. It describes *what* data is stored in the database and the relationships among those data. Programmers and administrators work at this level using schemas.
   Example record:
   ```text
   type instructor = record
       ID : string;
       name : string;
       dept_name : string;
       salary : integer;
   end;
   ```
3. **View level:** The highest abstraction level. It describes only the subset of the database relevant to a specific user group. It hides other data and complex structures for ease of use and security (for example, hiding instructor salaries from students).

## ⚡ Exam Tips & Common Mistakes

- **Always sketch the three-level diagram:** Questions on data abstraction (4 or 5 marks) expect the three-tier block diagram showing View Level on top, Logical Level in the middle, and Physical Level at the bottom.
- **Differentiate logical level from view level:** The logical level describes the *entire* database using tables and schemas. The view level describes only a *subset* tailored for specific user groups.
- **Use the programming analogy:** A database schema corresponds to a variable type declaration, while a database instance corresponds to the actual runtime value.
