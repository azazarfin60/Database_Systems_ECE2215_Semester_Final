## Core Classification: Join Types vs. Join Conditions

**Join Operations:** A join operation combines rows from two relations into a single result relation based on a matching condition. In relational algebra, it acts as a Cartesian product followed by a selection filter and projection.

Every SQL join statement specifies two distinct aspects:
1. **Join Condition:** Dictates how rows match between relations.
2. **Join Type:** Dictates how the query handles unmatched (dangling) rows.

![Summary of SQL join types and join conditions](diagrams/T06.01_join_types_conditions__L04_p04_fig01.jpg)
*Figure: Summary of SQL join types and join conditions (Deck 04, Slide 4).*

### 1. Join Conditions
- **Natural Join:** A natural join ($\bowtie$) automatically pairs rows with equal values across all identically named columns and eliminates duplicate shared attributes.
- **ON Condition (`on <predicate>`):** Matches rows based on any explicit Boolean expression (for example, `course.course_id = prereq.course_id`).
- **USING Clause (`using (A1, A2, ...)`):** Matches rows strictly on the specified list of shared attribute names.

### 2. Join Types

**Outer Join:** An outer join ($\mathbin{⟕}$, $\mathbin{⟖}$, or $\mathbin{⟗}$) keeps all matching rows plus unmatched rows from one or both relations, padding missing attributes with `NULL` values to prevent information loss.

- **Inner Join:** Keeps only rows that satisfy the join condition in both tables. Unmatched rows are dropped.
- **Left Outer Join:** Preserves every row from the left table. It pads missing right-table columns with `NULL`.
- **Right Outer Join:** Preserves every row from the right table. It pads missing left-table columns with `NULL`.
- **Full Outer Join:** Preserves all rows from both tables. It pads missing columns from either table with `NULL`.

## Detailed Mechanics of Each Join Type

Consider two base tables from the university schema: `course` and `prereq`.

**Base Table: `course`**

| course_id | title | dept_name | credits |
| :--- | :--- | :--- | :---: |
| BIO-301 | Genetics | Biology | 4 |
| CS-190 | Game Design | Comp. Sci. | 4 |
| CS-315 | Robotics | Comp. Sci. | 3 |

**Base Table: `prereq`**

| course_id | prereq_id |
| :--- | :--- |
| BIO-301 | BIO-101 |
| CS-190 | CS-101 |
| CS-347 | CS-101 |

Notice the matching values:
- `BIO-301` and `CS-190` exist in both tables.
- `CS-315` exists only in `course`.
- `CS-347` exists only in `prereq`.

---

### 1. Inner Join (and Natural Join)

**Inner Join:** An inner join ($\bowtie$ or $\bowtie_\theta$) outputs only matching rows from both relations. Unmatched rows (`CS-315` and `CS-347`) are discarded.

Relational algebra:
$$
\text{course} \bowtie_{\text{course.course\_id} = \text{prereq.course\_id}} \text{prereq}
$$

SQL query:
```sql
SELECT course.course_id, title, dept_name, prereq_id
FROM course
INNER JOIN prereq ON course.course_id = prereq.course_id;
```

**Result Relation (2 rows):**

| course_id | title | dept_name | prereq_id |
| :--- | :--- | :--- | :--- |
| BIO-301 | Genetics | Biology | BIO-101 |
| CS-190 | Game Design | Comp. Sci. | CS-101 |

Because `course_id` is the only shared column, `NATURAL JOIN` produces the exact same result rows without needing an `ON` clause:
```sql
SELECT course_id, title, dept_name, prereq_id
FROM course
NATURAL JOIN prereq;
```

---

### 2. Left Outer Join

**Left Outer Join:** A left outer join ($\mathbin{⟕}$) preserves all rows from the left table (`course`). Missing attributes from the right table are padded with `NULL`.

Relational algebra:
$$
\text{course} \mathbin{⟕} \text{prereq}
$$

SQL query:
```sql
SELECT course.course_id, title, dept_name, prereq_id
FROM course
LEFT JOIN prereq ON course.course_id = prereq.course_id;
```

**Result Relation (3 rows):**

| course_id | title | dept_name | prereq_id |
| :--- | :--- | :--- | :--- |
| BIO-301 | Genetics | Biology | BIO-101 |
| CS-190 | Game Design | Comp. Sci. | CS-101 |
| CS-315 | Robotics | Comp. Sci. | `NULL` |

---

### 3. Right Outer Join

**Right Outer Join:** A right outer join ($\mathbin{⟖}$) preserves all rows from the right table (`prereq`). Missing attributes from the left table are padded with `NULL`.

Relational algebra:
$$
\text{course} \mathbin{⟖} \text{prereq}
$$

SQL query:
```sql
SELECT prereq.course_id, title, dept_name, prereq_id
FROM course
RIGHT JOIN prereq ON course.course_id = prereq.course_id;
```

**Result Relation (3 rows):**

| course_id | title | dept_name | prereq_id |
| :--- | :--- | :--- | :--- |
| BIO-301 | Genetics | Biology | BIO-101 |
| CS-190 | Game Design | Comp. Sci. | CS-101 |
| CS-347 | `NULL` | `NULL` | CS-101 |

---

### 4. Full Outer Join

**Full Outer Join:** A full outer join ($\mathbin{⟗}$) preserves all rows from both tables. Missing attributes on either side are padded with `NULL`.

Relational algebra:
$$
\text{course} \mathbin{⟗} \text{prereq}
$$

Standard SQL syntax:
```sql
SELECT course.course_id, title, dept_name, prereq_id
FROM course
FULL OUTER JOIN prereq ON course.course_id = prereq.course_id;
```

MySQL emulation via `UNION`:
MySQL lacks native `FULL OUTER JOIN` syntax. Combine `LEFT JOIN` and `RIGHT JOIN` with `UNION`:
```sql
SELECT course.course_id, title, dept_name, prereq_id
FROM course
LEFT JOIN prereq ON course.course_id = prereq.course_id
UNION
SELECT prereq.course_id, title, dept_name, prereq_id
FROM course
RIGHT JOIN prereq ON course.course_id = prereq.course_id;
```

**Result Relation (4 rows):**

| course_id | title | dept_name | prereq_id |
| :--- | :--- | :--- | :--- |
| BIO-301 | Genetics | Biology | BIO-101 |
| CS-190 | Game Design | Comp. Sci. | CS-101 |
| CS-315 | Robotics | Comp. Sci. | `NULL` |
| CS-347 | `NULL` | `NULL` | CS-101 |

---

### 5. Cross Join (Cartesian Product)

**Cross Join:** A cross join ($\times$) combines every row of the first relation with every row of the second relation without any matching condition.

Relational algebra:
$$
\text{course} \times \text{prereq}
$$

SQL query:
```sql
SELECT *
FROM course
CROSS JOIN prereq;
```

If `course` has 3 rows and `prereq` has 3 rows, this outputs $3 \times 3 = 9$ rows.

## Inner Joining vs. Outer Joining (Comparison)

| Feature | Inner Join | Outer Join |
| :--- | :--- | :--- |
| **Tuple Retention** | Keeps only matching rows from both relations. Unmatched rows are dropped. | Preserves matching rows plus unmatched rows from one or both relations. |
| **Missing Values** | Never produces `NULL` values to represent missing relational links. | Pads missing attributes of unmatched rows with `NULL`. |
| **Information Loss** | Loses dangling records that fail the join predicate. | Prevents information loss by keeping dangling records visible. |
| **Forms / Subtypes** | Theta join, equijoin, and natural join (`INNER JOIN`, `JOIN`). | Left outer, right outer, and full outer join (`LEFT JOIN`, `RIGHT JOIN`, `FULL JOIN`). |
| **Relational Algebra** | $\bowtie$ or $\bowtie_\theta$ | $\mathbin{⟕}$, $\mathbin{⟖}$, and $\mathbin{⟗}$ |

## The Natural Join Column Trap

`NATURAL JOIN` equates all columns that share identical names across tables.

Consider three relations:
- `student(ID, name, dept_name)`
- `takes(ID, course_id)`
- `course(course_id, title, dept_name)`

Evaluating `student NATURAL JOIN takes NATURAL JOIN course` forces two join conditions:
1. `student.ID = takes.ID` AND `takes.course_id = course.course_id`
2. `student.dept_name = course.dept_name`

If an ECE student takes an elective course offered by CSE, `student.dept_name != course.dept_name`. The natural join drops that valid record.

To avoid this trap, specify the exact join column using `USING`:
```sql
SELECT name, title
FROM (student NATURAL JOIN takes)
JOIN course USING (course_id);
```

#### 1. Inner Join (and Natural Join)
Retains only tuples that satisfy the join condition in both tables. Unmatched rows are dropped.

```sql
SELECT course.course_id, title, dept_name, prereq_id
FROM course
INNER JOIN prereq ON course.course_id = prereq.course_id;
```

Relational algebra:
$$
\text{course} \bowtie \text{prereq}

| course_id | title | dept_name | prereq_id |
| :--- | :--- | :--- | :--- |
| BIO-301 | Genetics | Biology | BIO-101 |
| CS-190 | Game Design | Comp. Sci. | CS-101 |

#### 2. Left Outer Join
Preserves every row from the left table (`course`). Fills right-table attributes with `NULL` when no match exists.

```sql
SELECT course.course_id, title, dept_name, prereq_id
FROM course
LEFT JOIN prereq ON course.course_id = prereq.course_id;
```

Relational algebra:
$$
\text{course} \mathbin{⟕} \text{prereq}
$$

**Result:**

| course_id | title | dept_name | prereq_id |
| :--- | :--- | :--- | :--- |
| BIO-301 | Genetics | Biology | BIO-101 |
| CS-190 | Game Design | Comp. Sci. | CS-101 |
| CS-315 | Robotics | Comp. Sci. | `NULL` |

---

#### 3. Right Outer Join
Preserves every row from the right table (`prereq`). Fills left-table attributes with `NULL` when no match exists.

```sql
SELECT prereq.course_id, title, dept_name, prereq_id
FROM course
RIGHT JOIN prereq ON course.course_id = prereq.course_id;
```

Relational algebra:
$$
\text{course} \mathbin{⟖} \text{prereq}
$$

**Result:**

| course_id | title | dept_name | prereq_id |
| :--- | :--- | :--- | :--- |
| BIO-301 | Genetics | Biology | BIO-101 |
| CS-190 | Game Design | Comp. Sci. | CS-101 |
| CS-347 | `NULL` | `NULL` | CS-101 |

---

#### 4. Full Outer Join
Retains all rows from both tables. It pairs matching rows and fills missing values with `NULL`. MySQL emulates it using `UNION`.

```sql
SELECT course.course_id, title, dept_name, prereq_id
FROM course
LEFT JOIN prereq ON course.course_id = prereq.course_id
UNION
SELECT prereq.course_id, title, dept_name, prereq_id
FROM course
RIGHT JOIN prereq ON course.course_id = prereq.course_id;
```

Relational algebra:
$$
\text{course} \mathbin{⟗} \text{prereq}
$$

**Result:**

| course_id | title | dept_name | prereq_id |
| :--- | :--- | :--- | :--- |
| BIO-301 | Genetics | Biology | BIO-101 |
| CS-190 | Game Design | Comp. Sci. | CS-101 |
| CS-315 | Robotics | Comp. Sci. | `NULL` |
| CS-347 | `NULL` | `NULL` | CS-101 |

---

#### 5. Cross Join (Cartesian Product)
Combines each row of the first table with every row of the second table without any condition.

```sql
SELECT *
FROM course
CROSS JOIN prereq;
```

$$
\text{course} \times \text{prereq}

**Question (2024 Q.3(c)).** Differentiate between inner joining and outer joining.

**Answer.**

| Feature | Inner Join | Outer Join |
| :--- | :--- | :--- |
| **Tuple Retention** | Keeps only matching tuples from both relations. Drops non-matching rows. | Preserves matching rows plus unmatched rows from one or both relations. |

## ⚡ Exam Tips & Common Mistakes

- **MySQL FULL OUTER JOIN:** MySQL lacks a `FULL OUTER JOIN` keyword. Always write `LEFT JOIN ... UNION ... RIGHT JOIN` on exam scripts.
- **ON vs. WHERE:** In outer joins, filtering on the preserved table in `WHERE` is safe. Filtering on the unpreserved table in `WHERE` rejects `NULL` values and turns the query into an accidental inner join.
- **Natural Join Danger:** Never use `NATURAL JOIN` blindly when tables share non-key column names (like `dept_name`). Use `JOIN ... USING` instead.
- **Keep Sample Tables Small:** In theory answers, use 2-row or 3-row tables to illustrate join types quickly.
