# T05.09: TRUNCATE vs. DELETE

> **Topic:** T05 · SQL (DDL, DML, Aggregates, Subqueries) | **Priority:** 🟢 Foundation | **Exam Frequency:** 1/7 finals (2 marks) [2023 Q.6(a)]
> **Sources:** MySQL 8.0 Reference Manual (§13.1.37, §13.2.2) · Silberschatz 7e Ch. 3 (§3.2.3, §3.9.1) · Lecture Deck 03 (Slide 54) · Fahim Notes (p. 50)

## Architectural Mechanics: DDL vs. DML

**DELETE Statement:** A DML command that removes tuples from a relation row by row. It accepts a `WHERE` clause to delete specific rows, logs individual row deletions in the transaction undo log, can be rolled back inside an active transaction, and fires row-level delete triggers.

**TRUNCATE TABLE Statement:** A DDL command that empties a table by deallocating and re-initializing its underlying data storage pages. It does not support a `WHERE` clause, runs an implicit `COMMIT` in MySQL that prevents rollback, bypasses row-level triggers, and resets the `AUTO_INCREMENT` counter to 1.

**DROP TABLE Statement:** A DDL command that removes an entire relation along with its schema definition, constraints, and data from the database catalog.

### Execution Differences
- **`DELETE FROM student WHERE dept = 'ECE';`**: The engine scans the table, acquires row-level locks, writes undo/redo log entries, and deletes matching rows individually. The `AUTO_INCREMENT` counter remains unchanged.
- **`TRUNCATE TABLE student;`**: The engine drops and recreates storage pages in bulk. Because individual rows are not scanned, row-level `BEFORE/AFTER DELETE` triggers do not fire, and execution is much faster on large tables.

## 8-Point Comparison Matrix

| Feature | `DELETE FROM` | `TRUNCATE TABLE` | `DROP TABLE` |
| :--- | :--- | :--- | :--- |
| **SQL Category** | **DML** (Data Manipulation) | **DDL** (Data Definition) | **DDL** (Data Definition) |
| **Row Filtering (`WHERE`)** | Supported (deletes matching rows) | Not supported (always empties table) | Not applicable |
| **Table Structure / Schema** | Preserved intact | Preserved intact | Completely removed |
| **Transaction Rollback** | Yes (can be rolled back) | No (implicit commit in MySQL) | No (implicit commit in MySQL) |
| **Trigger Execution** | Fires `BEFORE/AFTER DELETE` triggers | Bypasses row-level delete triggers | Bypasses delete triggers |
| **`AUTO_INCREMENT` Counter** | Retains current counter value | Resets counter back to start (1) | Destroyed with table |
| **Execution Speed** | Slower (row-by-row logging) | Very fast (page deallocation) | Instant (drops catalog entry) |
| **Disk Space Reclamation** | Space remains in table pages | Data pages returned to storage engine | All allocated space freed |

## Foreign Key Restrictions and Auto-Increment Trace

1. **Foreign Key Block on TRUNCATE:** In MySQL InnoDB, running `TRUNCATE TABLE` on a parent table referenced by a child foreign key fails with Error 1701, even if child tables are empty or use `ON DELETE CASCADE`. In contrast, `DELETE FROM` handles foreign key references smoothly.
2. **Auto-Increment Reset:**
   - Inserting 3 rows sets the next `AUTO_INCREMENT` value to 4.
   - Running `DELETE FROM orders;` followed by an insert assigns `order_id = 4`.
   - Running `TRUNCATE TABLE orders;` followed by an insert assigns `order_id = 1`.

## 🏆 Golden Questions (Past Exam Archive)

### 🎯 GQ1 · 2023 Q.6(a) · Difference Between TRUNCATE and DELETE in SQL · 02 Marks

> *Section B · CLO2 · Asked in: 2023 · L1 (asked once)*

**Question.** What is the difference between 'Truncate' and 'Delete' in SQL?

**Answer.**

Both `TRUNCATE` and `DELETE` remove rows from a relation, but they operate at different architectural levels:

| Feature | `TRUNCATE TABLE` | `DELETE FROM` |
| :--- | :--- | :--- |
| **Command Category** | **DDL** (Data Definition Language) | **DML** (Data Manipulation Language) |
| **Row Filtering (`WHERE`)** | Not supported; always empties the entire table | Supported; deletes specific filtered rows or all rows |
| **Transaction & Rollback** | Executes an implicit `COMMIT` in MySQL; cannot be rolled back | Logged row-by-row; can be rolled back inside a transaction |
| **Triggers** | Does not fire `DELETE` triggers | Fires `BEFORE DELETE` and `AFTER DELETE` triggers for each row |
| **`AUTO_INCREMENT` Counter** | Resets the auto-increment counter back to its starting value (1) | Preserves the current auto-increment counter sequence |
| **Execution Speed** | Extremely fast; deallocates data pages directly | Slower; scans rows and records individual undo/redo logs |

**Summary:** Use `DELETE` when you need selective row removal with `WHERE` or transactional safety via `ROLLBACK`. Use `TRUNCATE` when you want to empty an entire table rapidly and reset its auto-increment counter.

### 🎯 GQ2 · Exam Variant · TRUNCATE vs. DELETE vs. DROP · 03 Marks

> *Anticipated Exam Variant · Source: Silberschatz 7e Ch. 3 §3.2.3*

**Question.** Compare TRUNCATE, DELETE, and DROP commands in SQL with respect to command category, table schema, and rollback capability.

**Answer.**

1. **DELETE (DML):**
   - Category: Data Manipulation Language.
   - Table Schema: Schema, columns, and constraints remain intact.
   - Rollback: Row deletions are logged and can be undone using `ROLLBACK`.
2. **TRUNCATE (DDL):**
   - Category: Data Definition Language.
   - Table Schema: Schema, columns, and constraints remain intact.
   - Rollback: Executes an implicit commit in MySQL and cannot be rolled back.
3. **DROP (DDL):**
   - Category: Data Definition Language.
   - Table Schema: Completely destroys the schema, constraints, and data from the database catalog.
   - Rollback: Executes an implicit commit in MySQL and cannot be rolled back.

## ⚡ Exam Tips & Common Mistakes

- **Command Category:** Never classify `TRUNCATE` as DML. In standard SQL and MySQL, `TRUNCATE TABLE` is a **DDL** statement.
- **Rollback in MySQL:** Do not claim `TRUNCATE` can be rolled back in MySQL. MySQL treats `TRUNCATE` as DDL and commits immediately.
- **Tabular Format:** Presenting a comparison table with 5 to 6 key criteria secures full marks on 2-mark comparison questions.
