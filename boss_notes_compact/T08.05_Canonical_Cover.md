# T08.5: Canonical Cover of Functional Dependencies

> **Topic:** T08 · Normalization & Functional Dependencies | **Priority:** 🟢 Core | **Exam Frequency:** 1/7 finals · 8 marks (2021 Q.6(a) [3m] + 2021 Q.6(b) [5m])
> **Sources:** Silberschatz 7e Ch. 7 (§7.4.3) · Lecture Deck 06 (Slides 4, 14)

## Extraneous Attributes and Canonical Cover

Checking functional dependencies during database updates introduces runtime overhead. A **canonical cover** ($F_c$) simplifies the constraint set to its minimal equivalent form without losing any implied constraints.

**Functional Dependency:** A constraint between two sets of attributes in relation schema $R$. Let $\alpha \subseteq R$ and $\beta \subseteq R$. The dependency $\alpha \rightarrow \beta$ holds if any two tuples $t_1, t_2$ with $t_1[\alpha] = t_2[\alpha]$ also satisfy $t_1[\beta] = t_2[\beta]$.

**Extraneous Attribute:** An attribute in a functional dependency $\alpha \rightarrow \beta$ is extraneous if removing it preserves the logical closure ($F^+ = (F')^+$).
- **LHS Test ($A \in \alpha$):** $A$ is extraneous on the left if $\beta$ is a subset of $(\alpha - \{A\})^+$, computed under the current dependency set $F$.
- **RHS Test ($A \in \beta$):** $A$ is extraneous on the right if $A$ belongs to $\alpha^+$, computed under the modified set $F' = (F - \{\alpha \rightarrow \beta\}) \cup \{\alpha \rightarrow (\beta - \{A\})\}$.

**Canonical Cover ($F_c$):** A minimal set of functional dependencies logically equivalent to $F$ ($F_c^+ = F^+$). It satisfies two conditions:
1. No functional dependency in $F_c$ contains an extraneous attribute (on the LHS or RHS).
2. Each left-hand side of a functional dependency in $F_c$ is unique.

## Canonical Cover Algorithm

```text
Fc := F;
repeat
    Use the union rule to replace any dependencies in Fc 
    of the form alpha1 -> beta1 and alpha1 -> beta2 with alpha1 -> beta1 beta2;
    
    Find a functional dependency alpha -> beta in Fc with an extraneous 
    attribute either in alpha or in beta;
    
    if an extraneous attribute is found then
        delete it from alpha -> beta in Fc;
until (Fc does not change);
```

### Worked Trace (Textbook Example)

Let $R(A, B, C)$ with $F = \{A \rightarrow BC, \; B \rightarrow C, \; A \rightarrow B, \; AB \rightarrow C\}$.

1. **Apply Union Rule on identical LHS:**  
   Combine $A \rightarrow BC$ and $A \rightarrow B$ into $A \rightarrow BC$.  
   $F_c = \{A \rightarrow BC, \; B \rightarrow C, \; AB \rightarrow C\}$.
2. **Test LHS in $AB \rightarrow C$:**  
   Test attribute $A$: Compute $B^+$ under $F_c$. $B^+ = \{B, C\}$.  
   Since $C \in B^+$, attribute $A$ is extraneous on LHS.  
   Replacing $AB \rightarrow C$ with $B \rightarrow C$ leaves a duplicate rule, which is dropped.  
   $F_c = \{A \rightarrow BC, \; B \rightarrow C\}$.
3. **Test RHS in $A \rightarrow BC$:**  
   Test attribute $C$: Form $F' = \{A \rightarrow B, \; B \rightarrow C\}$.  
   Compute $A^+$ under $F'$: $A^+ = \{A, B, C\}$.  
   Since $C \in A^+$, attribute $C$ is extraneous on RHS. Drop $C$ from $A \rightarrow BC$.  
   $F_c = \{A \rightarrow B, \; B \rightarrow C\}$.
4. **Final Result:** $F_c = \{A \rightarrow B, \; B \rightarrow C\}$.

## Canonical Cover vs. Normalization

| Parameter | Normalization | Canonical Cover ($F_c$) |
| :--- | :--- | :--- |
| **Definition** | The process of decomposing relation schemas to eliminate redundancy and update/delete/insert anomalies. | A minimal, non-redundant set of functional dependencies equivalent to the original FD set ($F_c \equiv F$). |
| **Primary Goal** | Design high-integrity tables that eliminate anomalies and avoid data duplication. | Simplify the set of integrity constraints so DBMS updates can be validated with minimal overhead. |
| **Input** | A relation schema $R$ and its functional dependencies $F$. | A set of functional dependencies $F$. |
| **Output** | A collection of decomposed relations $\{R_1, R_2, \dots, R_k\}$ in a desired normal form (e.g., 3NF, BCNF). | A simplified functional dependency set $F_c$ with no extraneous attributes and unique left-hand sides. |
| **Level of Operation** | Operates on the schema design level (splitting tables and foreign keys). | Operates purely on the mathematical dependency level (simplifying FDs). |

### 🎯 GQ2 · 2021 Q.6(b) · Definition of FD and Finding Canonical Cover · 05 Marks

> *Section B · CLO1 · Asked in: 2021*

**Question.** Define Functional dependency. Consider the following functional dependency set:

  $\text{FD} = \{$  
    $A \to BC,$  
    $CD \to E,$  
    $B \to D,$  
    $E \to A$  
  $\}$

Find the canonical form of the FD set.

**Answer.**

#### 1. Definition of Functional Dependency

A **functional dependency** (FD) is a constraint between two sets of attributes in a relation schema $R$.

Let $\alpha \subseteq R$ and $\beta \subseteq R$. The functional dependency:
$$
\alpha \rightarrow \beta
$$
holds on $R$ if, in every legal relation instance $r(R)$, whenever any two tuples $t_1$ and $t_2$ have the same values for attributes in $\alpha$, they must also have the same values for attributes in $\beta$:
$$
\text{If } t_1[\alpha] = t_2[\alpha] \implies t_1[\beta] = t_2[\beta]
$$

We say $\alpha$ functionally determines $\beta$.

#### 2. Finding the Canonical Cover ($F_c$)

A canonical cover $F_c$ satisfies two conditions:
1. No functional dependency contains an extraneous attribute (on the LHS or RHS).
2. Each left-hand side of a functional dependency is unique.

**Step 1: Apply the Union Rule to combine identical LHS**  
In the given set $F = \{A \rightarrow BC, CD \rightarrow E, B \rightarrow D, E \rightarrow A\}$, the left-hand sides are $A, CD, B, E$. All left-hand sides are already unique.

**Step 2: Test for Extraneous Attributes**

1. **Check $A \rightarrow BC$:**
   - **Test attribute $B$ (on RHS):**  
     Form $F' = \{A \rightarrow C, CD \rightarrow E, B \rightarrow D, E \rightarrow A\}$.  
     Compute $A^+$ under $F'$:  
     $A^+ = \{A, C\}$.  
     $A^+$ does not contain $B$. Therefore, $B$ is **not extraneous**.
   - **Test attribute $C$ (on RHS):**  
     Form $F' = \{A \rightarrow B, CD \rightarrow E, B \rightarrow D, E \rightarrow A\}$.  
     Compute $A^+$ under $F'$:  
     $A^+ = \{A, B, D\}$ (via $A \rightarrow B$ and $B \rightarrow D$).  
     $A^+$ does not contain $C$. Therefore, $C$ is **not extraneous**.

2. **Check $CD \rightarrow E$:**
   - **Test attribute $C$ (on LHS):**  
     Check if $D \rightarrow E$ holds under $F$.  
     Compute $D^+$ under $F$: $D^+ = \{D\}$.  
     $D^+$ does not contain $E$. Therefore, $C$ is **not extraneous**.
   - **Test attribute $D$ (on LHS):**  
     Check if $C \rightarrow E$ holds under $F$.  
     Compute $C^+$ under $F$: $C^+ = \{C\}$.  
     $C^+$ does not contain $E$. Therefore, $D$ is **not extraneous**.

3. **Check $B \rightarrow D$:**  
   Both LHS and RHS have a single attribute. Neither can be removed without dropping the dependency entirely.

4. **Check $E \rightarrow A$:**  
   Both LHS and RHS have a single attribute. Neither can be removed.

**Step 3: Resulting Canonical Cover**  
Since there are no extraneous attributes, the canonical cover is:

$$
\boxed{F_c = \{A \rightarrow BC, CD \rightarrow E, B \rightarrow D, E \rightarrow A\}}
$$

*(Note: In minimal cover form with singleton right-hand sides, the equivalent set is $\{A \rightarrow B, A \rightarrow C, CD \rightarrow E, B \rightarrow D, E \rightarrow A\}$. Both representations are correct.)*

## ⚡ Exam Tips & Common Mistakes

- **RHS vs. LHS extraneous testing difference:** When testing an attribute on the LHS, use the current set $F_c$ to check whether the remaining attributes can derive the RHS. When testing an attribute on the RHS, create a modified set $F'$ without that attribute to see if the determinant can still reach it.
- **Unique LHS requirement:** Always merge dependencies with identical left-hand sides using the Union rule before testing for extraneous attributes.
- **Zero extraneous attributes outcome:** In some exam sets (like 2021 Q.6(b)), no attribute is extraneous. State every check explicitly and conclude that the canonical cover equals the original set.
