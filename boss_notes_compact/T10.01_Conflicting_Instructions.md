# T10.1: Conflicting Instructions and Conflict Serializability

> **Topic:** T10 · Serializability | **Priority:** 🟢 | **Exam Frequency:** 1/7 finals (2 marks: 2017 Q.5(b), plus part of 2021 Q.7(b))
> **Sources:** Silberschatz 7e Ch. 17 (§17.6) · Lecture Deck 07 (Slides 16–19) · Raidah Notes (p. 26)

---

## 1. What Are Conflicting Instructions?

**Conflicting Instructions:** Two instructions $I_i$ and $I_j$ from distinct transactions ($T_i \neq T_j$) conflict if they access the same data item $Q$ and at least one is a $\text{write}$ operation.

Two instructions conflict if and only if they meet all three conditions:
1. **Different Transactions:** $I_i \in T_i$ and $I_j \in T_j$ with $i \neq j$.
2. **Same Data Item:** Both instructions operate on the exact same item $Q$.
3. **At Least One Write:** At least one operation is $\text{write}(Q)$.

The table below lists all four combinations of operations on the same data item $Q$:

| Case | Instruction $I_i$ ($T_i$) | Instruction $I_j$ ($T_j$) | Conflict? | Why Order Matters |
| :---: | :---: | :---: | :---: | :--- |
| **1** | $\text{read}(Q)$ | $\text{read}(Q)$ | **No** | Neither updates $Q$. Swapping them changes nothing. |
| **2** | $\text{read}(Q)$ | $\text{write}(Q)$ | **Yes (RW)** | Swapping changes whether $T_i$ reads the old or updated value. |
| **3** | $\text{write}(Q)$ | $\text{read}(Q)$ | **Yes (WR)** | Swapping changes whether $T_j$ reads the updated or old value. |
| **4** | $\text{write}(Q)$ | $\text{write}(Q)$ | **Yes (WW)** | Swapping changes which transaction leaves the final value on disk. |

Two rules govern conflicts:
- **Operations on different data items never conflict:** If $I_i$ touches $A$ and $I_j$ touches $B$ ($A \neq B$), they never conflict, even if both are writes.
- **Never swap instructions of the same transaction:** Instructions within $T_i$ must follow program order.

---

## 2. Conflict Equivalence and Conflict Serializability

**Conflict Equivalent:** Two schedules $S$ and $S'$ on the same transactions are conflict equivalent if $S$ transforms into $S'$ by swapping non-conflicting adjacent instructions.

**Conflict Serializable:** A concurrent schedule $S$ is conflict serializable if it is conflict equivalent to some serial schedule.

Consider a 4-step schedule $S$:
$$
S:\quad T_1:\text{read}(A),\quad T_2:\text{read}(A),\quad T_1:\text{write}(B),\quad T_2:\text{write}(A)
$$

Step 2 ($T_2:\text{read}(A)$) and Step 3 ($T_1:\text{write}(B)$) access different items ($A \neq B$). Swapping them yields:
$$
S':\quad T_1:\text{read}(A),\quad T_1:\text{write}(B),\quad T_2:\text{read}(A),\quad T_2:\text{write}(A)
$$

All instructions of $T_1$ now run before $T_2$. Because valid swaps produced serial schedule $\langle T_1, T_2 \rangle$, schedule $S$ is conflict serializable.

---

## 3. Testing Conflict Serializability: Precedence Graphs

Instead of swapping by hand, the DBMS builds a directed **precedence graph** $G = (V, E)$:
- **Vertices ($V$):** One node per active transaction $T_i$.
- **Directed Edges ($E$):** A directed arrow $T_i \to T_j$ ($i \neq j$) is added whenever an operation in $T_i$ runs before a conflicting operation in $T_j$ on item $Q$:
  1. $T_i: \text{read}(Q)$ before $T_j: \text{write}(Q)$ (RW conflict).
  2. $T_i: \text{write}(Q)$ before $T_j: \text{read}(Q)$ (WR conflict).
  3. $T_i: \text{write}(Q)$ before $T_j: \text{write}(Q)$ (WW conflict).

**Conflict Serializability Theorem:** A schedule $S$ is conflict serializable if and only if its precedence graph $G$ has no directed cycles.

- If $G$ contains a directed cycle (such as $T_1 \to T_2 \to T_1$), $S$ is **not conflict serializable**.
- If $G$ is acyclic (a DAG), $S$ is **conflict serializable**. A topological sort of $G$ gives the equivalent serial execution order.

---

## 4. Conflict Serializability vs. View Serializability

$$
\text{Conflict Serializable Schedules} \subset \text{View Serializable Schedules}
$$

1. Every conflict serializable schedule is automatically view serializable.
2. A schedule can be view serializable without being conflict serializable only if it has **blind writes** (writing an item without reading it first).
3. Database engines enforce conflict serializability because cycle testing takes fast polynomial time $\mathcal{O}(V + E)$. In contrast, testing view serializability is NP-complete.

## 🏆 Golden Questions (Past Exam Archive)

### 🎯 GQ1 · 2017 Q.5(b) · 02 Marks

> *Section B · Asked in: 2017 · L1 (asked once)*

**Question (2017 Q.5(b)).** What do you know about conflict serializability?

**Answer.**

**Conflict serializability** is a correctness property of a transaction schedule. A schedule $S$ is conflict serializable if it is **conflict equivalent** to a serial schedule. That is, we can transform $S$ into a serial schedule by swapping non-conflicting adjacent instructions.

1. **Conflicting instructions:** Two instructions $I_i$ and $I_j$ of distinct transactions $T_i$ and $T_j$ conflict if they access the same data item $Q$, and at least one is a write operation:
   - $\text{read}(Q)$ and $\text{write}(Q)$ conflict.
   - $\text{write}(Q)$ and $\text{write}(Q)$ conflict.
   - Two read operations ($\text{read}(Q)$ and $\text{read}(Q)$) do not conflict.
2. **Serializability test:** A schedule is conflict serializable if and only if its **precedence graph** has no directed cycles.
3. **Execution order:** When the graph is acyclic, a topological sort gives the equivalent serial execution order.

## ⚡ Exam Tips & Common Mistakes

- **Two reads never conflict:** Writing that $\text{read}(Q)$ and $\text{read}(Q)$ conflict is a frequent error. Two reads do not alter data.
- **Check variable names first:** Operations on different data items ($A \neq B$) never conflict, even if both are writes.
- **No edges within the same transaction:** Conflicts only apply between distinct transactions ($T_i \neq T_j$). Never draw a self-loop.
- **Recipe for 2 marks:** State the definition, list the 4 read/write cases on item $Q$, and mention the acyclic precedence graph condition.
