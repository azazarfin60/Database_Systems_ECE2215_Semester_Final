## Multi-Table Schema Design Rules

When creating multiple interrelated tables from an exam specification, observe three structural rules:

1. **Create Parent Tables Before Child Tables:** A table containing a foreign key cannot reference a parent relation that does not yet exist. Always declare master relations (like `Patient`) before dependent relations (like `History` and `Report`).
2. **Spot Event-History Tables Requiring Composite Keys:** Master tables (such as `Patient`) have a single primary key (`Patient_ID`). Event-history tables (such as `History`) record multiple events per entity over time. Making `Patient_ID` the sole primary key would prevent a patient from logging more than one symptom. Declare `(Patient_ID, Symptom, Date)` as a composite primary key.
3. **Document Exam Typos and Missing Columns with Explicit Assumptions:** If an attribute is misspelled (such as `Parient_ID` in 2019 Q.5(c)) or omitted from the DDL prompt (such as `Salary` in 2023 Q.3(a)), state a one-line assumption before writing your code.

**Update Statement (`UPDATE`):** A DML command that modifies existing attribute values in matching tuples using `SET` and `WHERE`.

**Delete Statement (`DELETE`):** A DML command that removes entire rows matching a condition. Leaving out `WHERE` deletes all rows while retaining table structure.

**Alter Table Statement (`ALTER TABLE`):** A DDL command that adds, drops, or modifies columns and constraints in an existing table without deleting stored data.

## Four Maintenance Patterns

1. **Targeted Row Update (`UPDATE ... SET ... WHERE`):**
   ```sql
   UPDATE client
   SET city = 'Barishal'
   WHERE c_no = 'C0005';
   ```
2. **Conditional Row Deletion (`DELETE FROM ... WHERE`):**
   ```sql
   DELETE FROM salesman
   WHERE sal_amount = 35000;
   ```
3. **Adding a Column with Fixed Precision (`ALTER TABLE ... ADD`):**
   ```sql
   ALTER TABLE client
   ADD Telephone NUMERIC(11);
   ```
4. **Calculated Column with Output Aliasing (`AS`):**
   ```sql
   SELECT p_no, description, sell_price, sell_price * 15 AS new_price
   FROM product
   WHERE sell_price > 500;
   ```

## Correlated Subquery Mechanics

**Correlated Subquery:** An inner query that references attributes from an outer query tuple variable. The database evaluates the subquery once for each candidate row processed by the outer query.

A plain uncorrelated subquery fails when comparing an employee against the average salary of their own department:
```sql
-- WRONG: Compares every employee against the single global company average:
SELECT * FROM Employee WHERE Salary > (SELECT AVG(Salary) FROM Employee);
```

To compare against the department average, bind the inner department to the outer department using tuple aliases:
```sql
SELECT *
FROM Employee e1
WHERE e1.Salary > (
    SELECT AVG(e2.Salary)
    FROM Employee e2
    WHERE e2.Department = e1.Department
);
```

## 🏆 Golden Questions (Past Exam Archive)

### 🎯 GQ1 · 2019 Q.5(c) · Covid Registry Table Creation · 02 Marks

> *Section B · Asked in: 2019 · L1 (asked once)*

**Question.** Write down the SQL queries to create the following tables.  
`Patient (Patient_ID, Patient_name, Mobile)`  
`History (Patient_ID, Symptom, Date)`  
`Report (Parient_ID, Corona_center, Test_result)`

*(Note: Printed as "SQI." and "Parient_ID" in original question paper)*

**Answer.**

*Assumption: "Parient_ID" in the Report table is a typographical misprint for Patient_ID and serves as a foreign key referencing the Patient table.*

```sql
CREATE TABLE Patient (
    Patient_ID INT PRIMARY KEY,
    Patient_name VARCHAR(50),
    Mobile VARCHAR(15)
);

CREATE TABLE History (
    Patient_ID INT,
    Symptom VARCHAR(50),
    Date DATE,
    PRIMARY KEY (Patient_ID, Symptom, Date),
    FOREIGN KEY (Patient_ID) REFERENCES Patient(Patient_ID)
);

CREATE TABLE Report (
    Patient_ID INT PRIMARY KEY,
    Corona_center VARCHAR(50),
    Test_result VARCHAR(20),
    FOREIGN KEY (Patient_ID) REFERENCES Patient(Patient_ID)
);
```

### 🎯 GQ2 · 2021 Q.3(a) · E-Commerce Database Maintenance Drills · 08 Marks

> *Section A · CLO2 · Asked in: 2021 · L1 (asked once)*

**Question.** Consider the following E-comerce database:  
  client (<u>c_no</u>, name, city, state, baldue)  
  product (<u>p_no</u>, description, profit_percent, quantity, sell_price, cost_price)  
  salesman (<u>s_no</u>, name, city, state, sal_amount, target, sold_yearly, remarks)

Now write the appropriate MySql code to execute the following query:  
(i) Change the city of client no "C0005" to "Barishal".  
(ii) Delete all salesmen whose salaries are equal to 35000 Tk.  
(iii) Add a column called "Telephone" of datatype numeric and size = '11' to the client table.  
(iv) Find products whose selling price is more than 500. Calculate a new selling price as original price*15. Rename the new column in the output as new_price.

*(Note: "E-comerce" and "MySql" printed verbatim from original question paper)*

**Answer.**

*(i) Change city of client "C0005" to "Barishal":*

```sql
UPDATE client
SET city = 'Barishal'
WHERE c_no = 'C0005';
```

*(ii) Delete salesmen whose salary is 35000 Tk:*

```sql
DELETE FROM salesman
WHERE sal_amount = 35000;
```

*(iii) Add column "Telephone" of numeric type and size 11 to client table:*

```sql
ALTER TABLE client
ADD Telephone NUMERIC(11);
```

*(iv) Find products with sell_price > 500 and calculate new selling price:*

```sql
SELECT p_no,
       description,
       sell_price,
       sell_price * 15 AS new_price
FROM product
WHERE sell_price > 500;
```

### 🎯 GQ3 · 2023 Q.3(a) · Employee DDL, Insertion, and Correlated Subquery · 06 Marks

> *Section A · CLO2 · Asked in: 2023 · L1 (asked once)*

**Question.** Write SQL queries for the following:  
(i) Create a table "Employee" with attributes: EmpID (primary key), Name, Age and Department.  
(ii) Insert a record into this table: EmpID=1, Name='Nafisa', Age=21, department='HR'.  
(iii) Find employees whose salary is greater than the average salary of their department.

**Answer.**

*(i) Create table Employee:*

```sql
CREATE TABLE Employee (
    EmpID INT PRIMARY KEY,
    Name VARCHAR(50),
    Age INT,
    Department VARCHAR(30)
);
```

*(ii) Insert record into Employee:*

```sql
INSERT INTO Employee (EmpID, Name, Age, Department)
VALUES (1, 'Nafisa', 21, 'HR');
```

*(iii) Find employees earning more than their department's average salary:*

*Assumption: The Employee relation includes an attribute `Salary DECIMAL(10,2)`.*

```sql
SELECT *
FROM Employee e1
WHERE e1.Salary > (
    SELECT AVG(e2.Salary)
    FROM Employee e2
    WHERE e2.Department = e1.Department
);
```

## ⚡ Exam Tips & Common Mistakes

- **Table Creation Order:** Create independent tables first, followed by child relations referencing their primary keys.
- **Identify Event Log Tables:** When an entity can record multiple rows over time, use a composite primary key including entity ID and timestamp or date.
- **Missing Column Assumptions:** In 2023 Q.3(a)(iii), write a brief assumption defining `Salary` before providing the correlated query.
- **Match Attribute Names Exactly:** In 2021 Q.3(a)(ii), use `sal_amount` as defined in the prompt rather than `salary`.
- **Correlated Aliases:** Use distinct aliases (`e1`, `e2`) and equate departments (`e1.Department = e2.Department`) so averages calculate per department.
