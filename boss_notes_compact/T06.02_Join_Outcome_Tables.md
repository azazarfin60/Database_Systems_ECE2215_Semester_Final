# T06.2: Computing Join Outcome Tables in MySQL

> **Topic:** T06 · Joins & Views | **Priority:** 🟡 Medium | **Exam Frequency:** 2/7 finals · 11 marks
> **Sources:** Silberschatz 7e Ch. 4 (§4.1, pp. 125–136) · Lecture Deck 04 (Slides 5–23) · Raidah Notes (p. 18) · Fahim Notes (pp. 51–55)

## Step-by-Step Algorithm for Tracing Join Outcome Tables

**Natural Join:** A natural join ($\bowtie$) pairs rows from two relations that have equal values on all identically named attributes, returning a single copy of each shared column.

**Left Outer Join:** A left outer join ($\mathbin{⟕}$) preserves all rows from the left relation and pads missing right-relation attributes with `NULL`.

**Right Outer Join:** A right outer join ($\mathbin{⟖}$) preserves all rows from the right relation and pads missing left-relation attributes with `NULL`.

**Full Outer Join:** A full outer join ($\mathbin{⟗}$) preserves all rows from both relations and pads missing attributes on either side with `NULL`.

To solve join outcome table questions on exam scripts without making manual pairing mistakes, partition the input relations into three core blocks:

1. **Step 1: Identify the Shared Join Attribute and Target Schema**
   - Find the common attribute name (such as `t_code` or `t code`).
   - Write the output schema header, listing the common attribute only once.
2. **Step 2: Build Block A (Matched Tuples)**
   - Pair up every left row and right row that share identical join keys.
   - If one key in the right table matches two rows in the left table, write both rows.
3. **Step 3: Build Block B (Left Dangling Tuples)**
   - Find left-table rows whose join key does not exist in the right table.
   - Pad their missing right-table columns with `NULL`.
4. **Step 4: Build Block C (Right Dangling Tuples)**
   - Find right-table rows whose join key does not exist in the left table.
   - Pad their missing left-table columns with `NULL`.
5. **Step 5: Assemble the Four Join Results**
   - **(i) Natural Join:** Block A only.
   - **(ii) Left Outer Join:** Block A + Block B.
   - **(iii) Right Outer Join:** Block A + Block C.
   - **(iv) Full Outer Join:** Block A + Block B + Block C.

## MySQL Dialect Rules for Outer Joins

When writing queries alongside outcome tables, keep two MySQL rules in mind:

### 1. Column Names Containing Spaces
In RUET 2020 Q.4(c), the join key was printed as `t code`. In MySQL, any identifier with a space must be wrapped in backticks (`` `t code` ``). In 2024, it was printed as `t_code`, which requires no backticks.

### 2. Emulating FULL OUTER JOIN in MySQL
MySQL does not support the `FULL OUTER JOIN` keyword. Running it causes a syntax error. Emulate it by connecting a `LEFT JOIN` and a `RIGHT JOIN` with `UNION`:

```sql
SELECT Courses.Code, Courses.Series, Courses.t_code, Teacher.Designation
FROM Courses
LEFT JOIN Teacher ON Courses.t_code = Teacher.t_code
UNION
SELECT Courses.Code, Courses.Series, Teacher.t_code, Teacher.Designation
FROM Courses
RIGHT JOIN Teacher ON Courses.t_code = Teacher.t_code;
```

Because `UNION` removes duplicate rows, matched rows appear once, and dangling rows from both sides are preserved.

## Worked Example: Tracing Dangling Rows on Both Sides

Consider two relations where both sides contain unmatched records:

**Relation: `Student`**

| Roll | Name | advisor_id |
| :---: | :--- | :---: |
| 101 | Nabil | A1 |
| 102 | Sadia | A1 |
| 103 | Tanvir | A9 |

**Relation: `Advisor`**

| advisor_id | Room |
| :---: | :--- |
| A1 | Room-204 |
| A2 | Room-310 |

### Derivation Steps:
- **Shared Attribute:** `advisor_id`. Output schema: `(Roll, Name, advisor_id, Room)`.
- **Block A (Matched Rows):** Nabil (`101`) and Sadia (`102`) match Advisor `A1`. That gives 2 rows: `(101, Nabil, A1, Room-204)` and `(102, Sadia, A1, Room-204)`.
- **Block B (Left Dangling):** Tanvir (`103`) has `advisor_id = A9`, not in `Advisor`. Padded row: `(103, Tanvir, A9, NULL)`.
- **Block C (Right Dangling):** Advisor `A2` has no students. Padded row: `(NULL, NULL, A2, Room-310)`.

### Resulting Join Tables:
- **Natural Join (2 rows):** Block A only.
- **Left Outer Join (3 rows):** Block A + Tanvir with `Room = NULL`.
- **Right Outer Join (3 rows):** Block A + Advisor A2 with `Roll = NULL, Name = NULL`.
- **Full Outer Join (4 rows):** Block A + Tanvir (`Room = NULL`) + Advisor A2 (`Roll = NULL, Name = NULL`).

What will happen when the following actions will be performed on these two relations?  
(i) Natural Join  
(ii) Left Outer Join  
(iii) Right Outer Join  
(iv) Full Outer Join

**Answer.**

*Assumption: The attribute "t code" is the common join key between Courses and Teacher.*

The common attribute is `t code`. In SQL statements, it is written as `` `t code` ``.

#### (i) Natural Join
Matches tuples where `t code` is identical and outputs one copy of `t code`.

Relational algebra:
$$
\text{Courses} \bowtie \text{Teacher}
$$

MySQL query:
```sql
SELECT Code, Series, `t code`, Designation
FROM Courses
NATURAL JOIN Teacher;
```

**Outcome Table (4 rows):**

| Code | Series | t code | Designation |
| :--- | :--- | :--- | :--- |
| ECE 2215 | 2017 | T1 | Head |
| ECE 4127 | 2016 | T2 | Professor |
| ECE 1203 | 2019 | T3 | Lecturer |
| ECE 2219 | 2017 | T2 | Professor |

*Explanation:* Every course has a matching teacher. T4 in Teacher has no course, so it is omitted.

---

#### (ii) Left Outer Join
Preserves all rows from the left table (**Courses**). Missing right attributes get `NULL`.

Relational algebra:
$$
\text{Courses} \mathbin{⟕} \text{Teacher}
$$

MySQL query:
```sql
SELECT Courses.Code, Courses.Series, Courses.`t code`, Teacher.Designation
FROM Courses
LEFT JOIN Teacher ON Courses.`t code` = Teacher.`t code`;
```

**Outcome Table (4 rows):**

| Code | Series | t code | Designation |
| :--- | :--- | :--- | :--- |
| ECE 2215 | 2017 | T1 | Head |
| ECE 4127 | 2016 | T2 | Professor |
| ECE 1203 | 2019 | T3 | Lecturer |
| ECE 2219 | 2017 | T2 | Professor |

*Explanation:* All `t code` values in Courses (T1, T2, T3) exist in Teacher. No `NULL` padding is needed. The result matches the Natural Join.

---

#### (iii) Right Outer Join
Preserves all rows from the right table (**Teacher**). Unmatched rows get `NULL` in Courses columns.

Relational algebra:
$$
\text{Courses} \mathbin{⟖} \text{Teacher}
$$

MySQL query:
```sql
SELECT Courses.Code, Courses.Series, Teacher.`t code`, Teacher.Designation
FROM Courses
RIGHT JOIN Teacher ON Courses.`t code` = Teacher.`t code`;
```

**Outcome Table (5 rows):**

| Code | Series | t code | Designation |
| :--- | :--- | :--- | :--- |
| ECE 2215 | 2017 | T1 | Head |
| ECE 4127 | 2016 | T2 | Professor |
| ECE 2219 | 2017 | T2 | Professor |
| ECE 1203 | 2019 | T3 | Lecturer |
| `NULL` | `NULL` | T4 | Lecturer |

*Explanation:* Teacher T4 has no matching course. It appears with `NULL` for `Code` and `Series`.

---

#### (iv) Full Outer Join
Retains all rows from both tables. Missing attributes from either side are padded with `NULL`.

Relational algebra:
$$
\text{Courses} \mathbin{⟗} \text{Teacher}
$$

MySQL query:
```sql
SELECT Courses.Code, Courses.Series, Courses.`t code`, Teacher.Designation
FROM Courses
LEFT JOIN Teacher ON Courses.`t code` = Teacher.`t code`
UNION
SELECT Courses.Code, Courses.Series, Teacher.`t code`, Teacher.Designation
FROM Courses
RIGHT JOIN Teacher ON Courses.`t code` = Teacher.`t code`;
```

**Outcome Table (5 rows):**

| Code | Series | t code | Designation |
| :--- | :--- | :--- | :--- |
| ECE 2215 | 2017 | T1 | Head |
| ECE 4127 | 2016 | T2 | Professor |
| ECE 2219 | 2017 | T2 | Professor |
| ECE 1203 | 2019 | T3 | Lecturer |
| `NULL` | `NULL` | T4 | Lecturer |

*Explanation:* Combines all matching rows plus unmatched teacher T4 with `NULL` values.

Preserves all tuples from the left relation (**Courses**). Unmatched right-side fields are set to `NULL`.

Relational algebra:
$$
\text{Courses} \mathbin{⟕} \text{Teacher}
$$

SELECT Courses.Code, Courses.Series, Courses.t_code, Teacher.Designation

| Code | Series | t_code | Designation |

| E_4127 | 2021 | T2 | AP |
| E_1203 | 2022 | T3 | AP |
| E_2219 | 2021 | T3 | AP |

*Explanation:* Every course row has an assigned `t_code` present in Teacher. No `NULL` padding is needed. The outcome is identical to the Natural Join.

Preserves all tuples from the right relation (**Teacher**). Unmatched left-side fields are filled with `NULL`.

\text{Courses} \mathbin{⟖} \text{Teacher}

SELECT Courses.Code, Courses.Series, Teacher.t_code, Teacher.Designation

## ⚡ Exam Tips & Common Mistakes

- **Write Explicit NULL:** Always write uppercase `NULL` in empty table cells. Never leave cells empty or write dashes.
- **Never Duplicate the Join Column:** In Natural Join, the common attribute (`t_code` or `t code`) appears exactly once in the schema header.
- **Handle One-to-Many Matches Correctly:** Teacher T3 teaches two separate courses. T3 must appear in two distinct rows.
- **Show Queries Along with Tables:** Always write the relational algebra expression and the SQL query above each outcome table. This guarantees partial credit.
- **State MySQL Full Join Limitation:** Point out that MySQL emulates full outer join using `LEFT JOIN ... UNION ... RIGHT JOIN`.
