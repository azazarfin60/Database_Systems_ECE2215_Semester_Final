## Understanding Referential Integrity

Relational databases store related facts in separate tables. Referential integrity ensures that links across tables remain valid and consistent.

**Referential Integrity Constraint:** A referential integrity constraint requires that any value appearing in specified attributes of a referencing (child) relation must also appear in specified attributes of at least one tuple in the referenced (parent) relation.

**Foreign Key Constraint:** A foreign key constraint is a referential integrity constraint where the referenced attribute set in the parent relation is its primary key (or candidate key). For every tuple in the child table, the foreign key value must either match an existing parent primary key value or be `NULL`.

**Cascading Actions:** Cascading actions (`ON DELETE CASCADE` and `ON UPDATE CASCADE`) are automated referential rules. When a parent record is deleted or updated, the DBMS automatically deletes or updates all matching child records.

### Parent vs. Child Table Relationship

Referential integrity connects two tables:
1. **Referenced Relation (Parent Table):** Holds the master records, identified by a primary key or unique key.
2. **Referencing Relation (Child Table):** Contains a foreign key column whose values reference the parent primary key.

Every foreign key value in the child table must:
- Match an existing parent primary key, or
- Be `NULL` (if the foreign key column permits nulls).

If a child record has a foreign key value not present in the parent table, it becomes an invalid orphan record.

## How a DBMS Achieves Referential Integrity

A DBMS achieves referential integrity through three mechanisms:

1. **Schema Constraint Declaration:**  
   The database designer defines foreign keys in SQL DDL statements using the `FOREIGN KEY ... REFERENCES` clause.

2. **Active Violation Checking:**  
   The DBMS monitors `INSERT`, `UPDATE`, and `DELETE` commands to prevent orphan rows:
   - Inserting or updating a child row with a nonexistent foreign key value is rejected.
   - Deleting or updating a parent record that still has referencing child records is blocked (under `RESTRICT`).

3. **Automated Referential Actions:**  
   The designer specifies actions triggered when parent rows change:

| Action | Description | Behavior on Parent Modification |
| :--- | :--- | :--- |
| `CASCADE` | Propagates deletion or update to child rows. | Child rows are deleted or updated automatically. |
| `SET NULL` | Sets referencing foreign key to `NULL`. | Requires child foreign key to allow `NULL`. |
| `RESTRICT` | Rejects modification if child rows exist. | Immediate rejection (default in MySQL). |
| `NO ACTION` | Same as `RESTRICT` in MySQL. | Standard SQL allows deferred check. |
| `SET DEFAULT` | Sets child foreign key to default value. | Not supported by MySQL InnoDB. |

## 🏆 Golden Questions (Past Exam Archive)

### 🎯 GQ1 · 2021 Q.1(c) · Achieving Referential Integrity in MySQL · 05 Marks

> *Section A · Asked in: 2021 Q.1(c) (5 marks, CLO2) · L1*

**Question (2021 Q.1(c)).** How do we achieve referential integrity in DBMS? Provide necessary MySQL query with an appropriate example.

**Answer.**

**1. How Referential Integrity is Achieved in DBMS:**  
Referential integrity ensures that relationships between tables remain consistent. It requires that any foreign key value in a referencing table must exist as a primary key value in the referenced table, or be NULL.  
A DBMS achieves referential integrity through three mechanisms:
1. **Constraint Declaration:** The database designer defines foreign keys in the DDL schema using the `FOREIGN KEY ... REFERENCES` clause.
2. **Active Violation Checking:** The DBMS monitors `INSERT`, `UPDATE`, and `DELETE` commands. It blocks any operation that creates orphan child records.
3. **Automated Referential Actions:** The designer specifies rules for parent modifications:
   - `CASCADE`: Deleting or updating a parent row automatically deletes or updates matching child rows.
   - `SET NULL`: Sets child foreign key columns to NULL when the parent row is deleted or updated.
   - `RESTRICT` / `NO ACTION`: Default rule; rejects parent deletion or update if matching child rows exist.

**2. MySQL DDL Query Example:**

```sql
-- Parent table (Referenced relation)
CREATE TABLE Department (
    dept_name VARCHAR(20) PRIMARY KEY,
    building VARCHAR(20),
    budget DECIMAL(12, 2)
);

-- Child table (Referencing relation)
CREATE TABLE Student (
    student_id INT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    dept_name VARCHAR(20),
    FOREIGN KEY (dept_name) REFERENCES Department(dept_name)
        ON DELETE CASCADE
        ON UPDATE CASCADE
);
```

**3. Operation and Violation Demonstration:**  
Populate a valid parent department:

```sql
INSERT INTO Department VALUES ('ECE', 'Academic Building 2', 500000.00);
INSERT INTO Student VALUES (101, 'Akib', 'ECE'); -- Allowed
```

Now attempt a violating insert with a nonexistent department:

```sql
INSERT INTO Student VALUES (102, 'Shuvo', 'ME');
```

**MySQL System Response:**  
MySQL rejects the insert and raises an integrity violation error:

```text
ERROR 1452 (23000): Cannot add or update a child row: a foreign key constraint fails (`university`.`Student`, CONSTRAINT `student_ibfk_1` FOREIGN KEY (`dept_name`) REFERENCES `Department` (`dept_name`) ON DELETE CASCADE ON UPDATE CASCADE)
```

If `'ECE'` is deleted from `Department`, `ON DELETE CASCADE` automatically deletes student 101. This keeps the database consistent.

## ⚡ Exam Tips & Common Mistakes

- **Table Creation Order:** Always create parent tables before child tables. Creating a child table that references a nonexistent parent causes `ERROR 1215`.
- **Match Data Types Exactly:** The foreign key column must match the referenced primary key in data type and size (for example, `VARCHAR(20)` to `VARCHAR(20)`).
- **Quote Error 1452 in Exam Scripts:** Writing the exact MySQL error (`ERROR 1452: Cannot add or update a child row...`) proves hands-on knowledge.
- **Table Drop Order:** When dropping tables, drop child tables first, then parent tables (`DROP TABLE Student;` then `DROP TABLE Department;`).
- **`ON DELETE SET NULL` Trap:** Never use `ON DELETE SET NULL` on a column declared `NOT NULL`. The two constraints directly contradict each other.
