# T05.05b: Weighted CGPA and Extremes Without LIMIT

## Pattern 1: Weighted CGPA Calculation Across Joined Tables

**Subquery:** A `SELECT-FROM-WHERE` query nested inside an outer SQL statement. It commonly evaluates set membership (`IN`), set comparisons (`SOME`, `ALL`), existence checks (`EXISTS`), or scalar calculations.

**Scalar Subquery:** A nested query that returns exactly one row and one column. It can appear anywhere a single value is expected, such as in comparison conditions or the `SELECT` projection list.

**Set Comparison (`> ALL` and `< ALL`):** A construct where the `ALL` quantifier compares a scalar against every value returned by a subquery. For example, `x >= ALL (...)` identifies the maximum value without using `MAX()`.

An academic Cumulative Grade Point Average (CGPA) weights each course grade by its credit hours:

$$
\text{CGPA} = \frac{\sum (\text{GPA} \times \text{Credit})}{\sum \text{Credit}}
$$

In university schemas, this information is distributed across three relations:
1. `Student (St_ID, St Name)`: Stores student identity.
2. `GPA (St_ID, Sub_Code, gpa)`: Records student grade points per subject.
3. `Credit (Sub_Code, Credit)`: Defines credit weights per subject.

```sql
SELECT s.St_ID,
       s.`St Name`,
       SUM(g.gpa * c.Credit) / SUM(c.Credit) AS cgpa
FROM Student s
JOIN GPA g ON s.St_ID = g.St_ID
JOIN Credit c ON g.Sub_Code = c.Sub_Code
GROUP BY s.St_ID, s.`St Name`;
```

### Execution Steps
1. **Three-Table Join:** Join `Student` with `GPA` on `St_ID`, then join `Credit` on `Sub_Code`.
2. **Grouping:** Group by `s.St_ID` and ``s.`St Name` `` so each student forms a single summary bucket.
3. **Weighted Ratio:** `SUM(g.gpa * c.Credit)` computes total earned quality points; `SUM(c.Credit)` computes total registered credits.
4. **Identifiers with Spaces:** In MySQL, identifiers containing spaces (like `` `St Name` ``) must be enclosed in backticks.

## Pattern 2: Finding Extremes Without LIMIT

Examiners forbid `LIMIT` because it is vendor-specific non-ANSI syntax and drops tied records unpredictably.

### Method A: Absolute Extremes Using Scalar Subqueries

To return all records tied for the minimum or maximum value:

```sql
SELECT s.St_ID, s.`St Name`, g.Sub_Code, g.gpa
FROM Student s
JOIN GPA g ON s.St_ID = g.St_ID
WHERE g.gpa = (
    SELECT MIN(gpa)
    FROM GPA
);
```

The inner subquery evaluates the dynamic minimum scalar (e.g., `3.00`). The outer query retrieves all students matching that value.

### Method B: Second-Highest Value Using Nested MAX

The second-highest score is the maximum score strictly below the overall maximum score:

$$
\text{Second Highest} = \max \{ x \in S \mid x < \max(S) \}
$$

```sql
SELECT *
FROM STUDENT
WHERE CGPA = (
    SELECT MAX(CGPA)
    FROM STUDENT
    WHERE CGPA < (
        SELECT MAX(CGPA)
        FROM STUDENT
    )
);
```

- Innermost: Finds the top score (`4.00`).
- Middle: Finds the maximum score strictly less than `4.00` (`3.85`).
- Outer: Retrieves all students who achieved `3.85`.

### Method C: Correlated Subquery for N-th Highest Value

The $N$-th highest value has exactly $N - 1$ distinct values strictly above it:

```sql
-- Second-highest CGPA (N = 2, so N - 1 = 1)
SELECT *
FROM STUDENT s1
WHERE 1 = (
    SELECT COUNT(DISTINCT s2.CGPA)
    FROM STUDENT s2
    WHERE s2.CGPA > s1.CGPA
);
```

### Method D: Set Comparison Using >= ALL

A score is the absolute maximum if it is greater than or equal to all scores in the table:

```sql
SELECT *
FROM STUDENT
WHERE CGPA >= ALL (
    SELECT CGPA
    FROM STUDENT
);
```

## Pattern 3: Grouped Averages and Extremes Per Course

When computing extremes per category rather than table-wide, use `GROUP BY`:

```sql
-- Highest GPA per subject code:
SELECT Sub_Code, MAX(gpa) AS highest_gpa
FROM GPA
GROUP BY Sub_Code;

-- Average grade per course:
SELECT CID, AVG(Grade) AS avg_grade
FROM ENROLLMENT
GROUP BY CID;
```

SELECT s.St_ID, s.`St Name`, g.Sub_Code, g.gpa

    SELECT MIN(gpa)

```sql
SELECT Sub_Code,
       MAX(gpa) AS highest_gpa
FROM GPA
GROUP BY Sub_Code;
```

### 🎯 GQ2 · 2024 Q.1(c) · Average Grade Per Course · 04 Marks

> *Section A · CO2 · Asked in: 2024 · L1 (asked once)*

**Question.**  
STUDENT (SID, Name, Age, Major)  
COURSE (CID, Title, Credits)  
ENROLLMENT (SID, CID, Grade)  
Using the above schema, write a SQL query to find the average grade for each course.

**Answer.**

```sql
SELECT CID,
       AVG(Grade) AS avg_grade
FROM ENROLLMENT
GROUP BY CID;
```

*(If course title is also retrieved by joining COURSE):*

```sql
SELECT c.CID, c.Title,
       AVG(e.Grade) AS avg_grade
FROM COURSE c
JOIN ENROLLMENT e ON c.CID = e.CID
GROUP BY c.CID, c.Title;
```

### 🎯 GQ3 · CT-02 Q.01(d) · Second-Highest CGPA Without LIMIT · 03 Marks

> *CO2 · Asked in: CT-02 · L1 (asked once)*

**Question.** Given $\text{STUDENT}(\text{StudentID}, \text{Name}, \text{Department}, \text{Semester}, \text{CGPA})$, write SQL query:  
**(d)** Display the students having the second-highest CGPA without using LIMIT.

**Answer.**

```sql
SELECT *
FROM STUDENT
WHERE CGPA = (
    SELECT MAX(CGPA)
    FROM STUDENT
    WHERE CGPA < (
        SELECT MAX(CGPA)
        FROM STUDENT
    )
);
```

*Note on ties:* This query identifies the unique second-highest distinct CGPA value. If multiple students share this exact second-highest CGPA, all tied students are displayed in the result.

## ⚡ Exam Tips & Common Mistakes

- **Wrap Column Names with Spaces:** Write `` `St Name` `` inside backticks in MySQL to avoid syntax errors.
- **Never Hardcode Values:** Do not write `WHERE gpa = 3.00`. Compute minimums dynamically with `(SELECT MIN(gpa) FROM GPA)`.
- **Avoid Extraneous Joins:** In 2024 Q.1(c), joining `STUDENT` is redundant because `CID` and `Grade` are both in `ENROLLMENT`.
- **Include Non-Aggregated Columns in GROUP BY:** In CGPA queries, all projected student identifier columns must appear in `GROUP BY`.
- **Tie-Safe Extremes:** Using scalar subqueries with `MAX` or `MIN` ensures that tied students are all returned fairly.
