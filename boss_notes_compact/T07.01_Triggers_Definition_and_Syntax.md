# T07.1: SQL Triggers: Definition, Purpose, and Syntax

> **Topic:** T07 · Triggers and Stored Procedures | **Priority:** 🟡 Medium | **Exam Frequency:** 2/7 finals · 9 marks  
> **Sources:** Silberschatz 7e Ch. 5 (§5.3) · Fahim Handnote (pp. 59, 60, 62) · (No lecture slides for Unit 4 advanced SQL)

---

## Event-Condition-Action (ECA) Framework

**Trigger:** A trigger is a stored SQL block that the DBMS executes automatically when a data modification occurs on a table or view.

**Triggering:** Triggering is the automatic process where the database engine detects a table modification event (`INSERT`, `UPDATE`, or `DELETE`), evaluates the trigger condition, and executes the action statements.

**Event-Condition-Action (ECA) Model:** The three-part framework governing triggers. The event activates the trigger, the condition checks whether the action runs, and the action executes the procedural SQL statements:

1. **Event:** The database modification (`INSERT`, `UPDATE`, or `DELETE`) on a monitored table that wakes the trigger up.
2. **Condition:** An optional boolean check evaluated when the event happens. If true, the action runs. If false, the database skips the action.
3. **Action:** The procedural SQL statements that execute automatically when the condition holds.

---

## Trigger Mechanics: Timing, Events, and Granularity

When creating a trigger, define its timing, the activating event, and its execution granularity.

### 1. Trigger Timing: `BEFORE` vs `AFTER`

- **`BEFORE` Triggers:** Run before the database writes changes to disk. Use them to validate input values, set defaults, or reject invalid operations before bad data reaches the table.
- **`AFTER` Triggers:** Run after the table change succeeds. Use them to record audit logs, update summary tables, or queue follow-up tasks.

### 2. Trigger Events and Transition Variables

**Transition Variables (`OLD` and `NEW`):** Transition variables are special row references inside a `FOR EACH ROW` trigger. `OLD` holds column values before an update or delete. `NEW` holds new column values written by an insert or update.

| Trigger Event | Available Qualifiers | Reason |
| :--- | :---: | :--- |
| **`INSERT`** | `NEW` only | The row is brand new. No prior row exists, so `OLD` is undefined. |
| **`UPDATE`** | Both `OLD` and `NEW` | An existing row changes. `OLD` stores pre-update values; `NEW` stores post-update values. |
| **`DELETE`** | `OLD` only | The row is removed. No subsequent row exists, so `NEW` is undefined. |

### 3. Trigger Granularity

- **Row-Level (`FOR EACH ROW`):** Executes once for each individual row modified by the SQL statement. If an `UPDATE` modifies 20 rows, a `FOR EACH ROW` trigger runs 20 times.
- **Statement-Level:** Executes once for the entire SQL statement, regardless of the number of rows affected. (MySQL 8 supports only row-level `FOR EACH ROW` triggers).

---

## Core Purposes of Database Triggers

1. **Enforcing Complex Integrity Constraints:** Triggers enforce multi-table business rules that declarative constraints (`CHECK`, `FOREIGN KEY`) cannot express.
2. **Auditing and Security Tracking:** Triggers automatically record who changed data, when the change happened, and what values changed into dedicated audit tables.
3. **Maintaining Derived and Summary Data:** Triggers keep calculated totals synchronized across related tables, such as updating student credit totals or inventory balances.
4. **Automating Workflows and Alerts:** Triggers generate restock orders, queue notifications, or clean up dependent records when specific thresholds are crossed.

---

## When Not to Use Triggers

Triggers run silently in the background and introduce overhead if overused:

- **Cascading Loops:** A trigger updating another table can cause secondary triggers to fire. Circular chains cause infinite loops until the DBMS aborts the query.
- **Hidden Logic:** Developers running basic DML statements may not realize that side-effect updates are modifying other tables.
- **Backup and Replication Issues:** Bulk restoration or replication may unintentionally fire triggers, producing duplicate audit logs.
- **Performance Overhead:** Row-level triggers run once per affected row, slowing down bulk batch updates.

## MySQL 8 Trigger Syntax

### Statement Delimiters

In MySQL client tools, the default statement terminator is `;`. Because a trigger body contains multiple internal statements ending with `;`, redefine the delimiter using `DELIMITER //`. Return to the standard delimiter with `DELIMITER ;` after `END //`.

### Syntax Template

```sql
DELIMITER //

CREATE TRIGGER trigger_name
{ BEFORE | AFTER } { INSERT | UPDATE | DELETE }
ON table_name
FOR EACH ROW
BEGIN
    -- Declarations and trigger logic
    -- Access values via OLD.column_name and NEW.column_name
    -- Abort execution and roll back using SIGNAL:
    -- SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Custom error message';
END //

DELIMITER ;
```

- `CREATE TRIGGER trigger_name`: Sets the unique identifier for the trigger.
- `{ BEFORE | AFTER }`: Selects execution before or after table modification.
- `{ INSERT | UPDATE | DELETE }`: Specifies the activating DML event.
- `ON table_name`: Designates the target table.
- `FOR EACH ROW`: Declares a row-level trigger.
- `BEGIN ... END`: Encloses procedural statements.

## 🏆 Golden Questions (Past Exam Archive)

### 🎯 GQ1 · 2018 Q.8(a) / 2020 Q.8(a) · Definition, Purposes, and Syntax of Triggers · 05 Marks

> *Section B · Asked in: 2018 (5 marks), 2020 (4 marks) · L2 repeat merge*

**Question (2018 Q.8(a)).** What is triggering? What are the purposes of using trigger? Write the syntax for creating trigger?

**Question (2020 Q.8(a)).** What is triggering? What are the purposes of using triggering? Write the syntax for creating a trigger.

**Answer.**

#### 1. Definition of Trigger and Triggering

A **trigger** is a stored SQL block. The DBMS executes it automatically when a modification occurs on a table or view.

**Triggering** is the automatic detection of the modification event, evaluation of the trigger condition, and execution of the trigger action.

Triggers follow the **ECA (Event-Condition-Action) model**:
- **Event:** A database modification (`INSERT`, `UPDATE`, or `DELETE`) that activates the trigger.
- **Condition:** An optional boolean test checked when the event occurs.
- **Action:** The procedural SQL statements that run automatically if the condition is satisfied.

#### 2. Purposes of Using Triggers

1. **Enforcing Complex Integrity Constraints:** Triggers enforce business rules across multiple tables that standard table constraints (`CHECK`, `FOREIGN KEY`) cannot express.
2. **Auditing and Security:** Triggers automatically log sensitive operations into audit tables with user identity, timestamp, and before-and-after values.
3. **Maintaining Derived and Summary Data:** Triggers keep summary values synchronized across tables. For example, they update student total credits or warehouse stock automatically.
4. **Automating Workflows and Alerts:** Triggers generate reorders when inventory falls below minimum levels, create notifications, or clean up related dependent records.

#### 3. Syntax for Creating a Trigger (MySQL 8)

**General Template:**

```sql
DELIMITER //

CREATE TRIGGER trigger_name
{BEFORE | AFTER} {INSERT | UPDATE | DELETE}
ON table_name
FOR EACH ROW
BEGIN
    -- Trigger body statements
    -- Access row values via OLD.column_name and NEW.column_name
    -- Terminate and rollback on error using SIGNAL
END //

DELIMITER ;
```

- `BEFORE | AFTER`: Specifies whether the action executes before modifying table data or after the modification completes.
- `INSERT | UPDATE | DELETE`: Identifies the DML event that activates the trigger.
- `ON table_name`: Specifies the target table.
- `FOR EACH ROW`: Defines a row-level trigger that runs once for each affected row.
- `OLD` and `NEW`: Transition qualifiers that refer to column values before and after the change.

**Concrete Example (Enforcing non-negative stock before insert):**

```sql
DELIMITER //

CREATE TRIGGER trg_check_product_stock
BEFORE INSERT ON Products
FOR EACH ROW
BEGIN
    IF NEW.stock < 0 THEN
        SIGNAL SQLSTATE '45000'
            SET MESSAGE_TEXT = 'Error: Stock level cannot be negative';
    END IF;
END //

DELIMITER ;
```

*Variant for 2020 Q.8(a) (4 marks):* The same definition, 4 purposes, syntax template, and example answer the 4-mark question directly.

## ⚡ Exam Tips & Common Mistakes

- **Delimiter Requirement:** Always write `DELIMITER //` and `DELIMITER ;` around trigger code. Semicolons inside the `BEGIN ... END` block cause syntax errors without custom delimiters.
- **Transition Variable Rules:** Never use `OLD` in an `INSERT` trigger, and never use `NEW` in a `DELETE` trigger.
- **Timing Choice:** Use `BEFORE` when validating data or cancelling an invalid write. Use `AFTER` when recording logs or updating related tables.
- **Cancelling Transactions:** Use `SIGNAL SQLSTATE '45000'` with `SET MESSAGE_TEXT` to abort execution and return a clear error message.
