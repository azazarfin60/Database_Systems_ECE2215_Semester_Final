## Core DDL Concepts and Mechanics

**Data Definition Language (DDL):** DDL defines and alters database schemas, relation structures, and integrity constraints. Its main statements are `CREATE TABLE`, `ALTER TABLE`, and `DROP TABLE`.

**Primary Key:** A column or combination of columns that uniquely identifies every tuple in a table. Primary keys must be unique and cannot contain `NULL` values. A table has at most one primary key.

**Foreign Key:** A column or combination of columns in a child relation that references the primary key of a parent relation. It enforces referential integrity across related tables.

### 1. Common SQL Data Types in Exams

| SQL Data Type | Storage Format | Common Exam Use Case |
| :--- | :--- | :--- |
| `INT` / `INTEGER` | 4-byte signed whole number | Roll numbers, IDs, counts |
| `SMALLINT` | 2-byte signed whole number | Semesters, ages |
| `DECIMAL(p, d)` | Fixed-point decimal with $p$ digits total and $d$ decimals | GPAs (`DECIMAL(3, 2)`), credits, amounts |
| `CHAR(n)` | Fixed-length string of length $n$ | Short fixed codes (`CHAR(3)`) |
| `VARCHAR(n)` | Variable-length string up to length $n$ | Names, department titles, emails |
| `DATE` | Calendar date (`YYYY-MM-DD`) | Birth dates, test dates |

### 2. Table Creation (`CREATE TABLE`)

```sql
CREATE TABLE relation_name (
    attribute1 datatype [column_constraint],
    attribute2 datatype [column_constraint],
    ...,
    [table_level_constraints]
);
```

#### Inline vs. Composite Primary Keys
- **Single-Column Key:** Can be declared inline next to the attribute type:
  ```sql
  CREATE TABLE department (
      dept_name VARCHAR(20) PRIMARY KEY,
      building VARCHAR(30)
  );
  ```
- **Composite Primary Key:** When two or more columns are underlined in the exam schema, declare the composite key at the table level. Multiple inline `PRIMARY KEY` clauses trigger a syntax error:
  ```sql
  CREATE TABLE enrollment (
      roll INT,
      course_id VARCHAR(10),
      grade VARCHAR(2),
      PRIMARY KEY (roll, course_id)
  );
  ```

#### Foreign Keys and Referential Actions
Foreign keys link a child table to a parent table:
```sql
CREATE TABLE MARKS (
    roll INT,
    sub_code VARCHAR(20),
    gpa DECIMAL(3, 2),
    PRIMARY KEY (roll, sub_code),
    FOREIGN KEY (roll) REFERENCES INFO(roll)
        ON DELETE CASCADE
        ON UPDATE CASCADE,
    FOREIGN KEY (sub_code) REFERENCES CREDIT(sub_code)
);
```
- `ON DELETE CASCADE`: Deleting the parent tuple automatically removes all matching child tuples.
- `ON DELETE SET NULL`: Sets the foreign key column in child tuples to `NULL`.
- `ON DELETE RESTRICT` (default): Prevents deletion of the parent tuple if child records exist.

#### Column Constraints
- `NOT NULL`: Forbids missing or undefined values.
- `UNIQUE`: Guarantees distinct values across all rows.
- `DEFAULT <value>`: Sets a fallback value when an insert leaves the column blank.
- `CHECK (<condition>)`: Verifies that values satisfy a boolean predicate.

### 3. Modifying Existing Tables (`ALTER TABLE`)

Use `ALTER TABLE` to update an existing relation schema without losing stored tuples:
```sql
-- Add a new column:
ALTER TABLE student ADD session VARCHAR(10);

-- Drop a column:
ALTER TABLE student DROP COLUMN session;

-- Modify an attribute data type:
ALTER TABLE student MODIFY name VARCHAR(100) NOT NULL;

-- Rename a column (MySQL 8):
ALTER TABLE student RENAME COLUMN dept TO department;
```

### 4. Table and Row Removal: DROP vs. TRUNCATE vs. DELETE

- `DROP TABLE student;` removes the table structure, metadata, and all rows completely.
- `TRUNCATE TABLE student;` drops and recreates storage pages, instantly emptying rows and resetting the auto-increment counter while preserving the table schema (DDL).
- `DELETE FROM student;` removes tuples row by row and allows rollback inside an active transaction (DML).

## Core DML Concepts and Mechanics

**Data Manipulation Language (DML):** DML retrieves and modifies data tuples inside existing tables. Its main statements are `SELECT`, `INSERT`, `UPDATE`, and `DELETE`.

### 1. Inserting Tuples (`INSERT INTO`)
```sql
-- Explicit attribute list:
INSERT INTO student (roll, name, dept)
VALUES (1810001, 'Rahim', 'ECE');

-- Multi-row insertion:
INSERT INTO student (roll, name, dept)
VALUES
    (1810002, 'Karim', 'ECE'),
    (1810003, 'Tanvir', 'CSE');
```

### 2. Updating Tuples (`UPDATE`)
```sql
UPDATE student
SET dept = 'ECE'
WHERE roll = 1810001;
```
Always specify a `WHERE` condition to prevent updating every row in the table.

### 3. Deleting Tuples (`DELETE FROM`)
```sql
DELETE FROM student
WHERE dept = 'Civil';
```
Never write `DELETE * FROM`. SQL does not accept asterisks in `DELETE` statements.

### 4. Querying Tuples (`SELECT`)
```sql
SELECT roll, name
FROM student
WHERE dept = 'ECE';
```

## Weighted CGPA Formula Mechanics

A university Cumulative Grade Point Average (CGPA) weights each subject grade by its assigned credit hours:

$$
\text{CGPA} = \frac{\sum (\text{gpa} \times \text{credit})}{\sum \text{credit}}
$$

A simple average `AVG(gpa)` gives inaccurate results because it treats 1.50-credit labs identically to 3.00-credit theory courses.

In SQL, this calculation joins the marks table with the course credit table, groups by the student identity, and calculates the weighted quotient:
```sql
SELECT m.roll,
       SUM(m.gpa * c.credit) / SUM(c.credit) AS cgpa
FROM MARKS m
JOIN CREDIT c ON m.sub_code = c.sub_code
GROUP BY m.roll;
```

(i) Write down the SQL query to create the table MARKS.  
(ii) Write down the SQL query to find out subject code and corresponding gpa of the student whose class serial 02.  
(iii) Write the the SQL query to calculate the cgpa of each student using the formula, $cgpa = \frac{\Sigma gpa \cdot credit}{\Sigma credit}$

*(Note: In the original printed question paper, Q.4 contains only sub-question (a) with 09 marks indicated in the margin, leaving a 3-mark deficit from the standard 12 marks).*

**Answer.**

*(i) Create table MARKS:*

```sql
CREATE TABLE MARKS (
    roll INT,
    sub_code VARCHAR(20),
    gpa DECIMAL(3, 2),
    PRIMARY KEY (roll, sub_code),
    FOREIGN KEY (roll) REFERENCES INFO(roll),
    FOREIGN KEY (sub_code) REFERENCES CREDIT(sub_code)
);
```

*(ii) Subject code and GPA for student with class serial 02:*

*Assumption: In the RUET roll format (e.g., 1710002), the final two digits represent the student's class serial. Class serial 02 identifies student roll 1710002 (Oliver).*

```sql
SELECT sub_code, gpa
FROM MARKS
WHERE roll = 1710002;
```

*(Alternative dynamic filter matching the last two digits:* `WHERE roll % 100 = 2;`*)*

*(iii) Calculate CGPA of each student:*

```sql
SELECT m.roll,
       SUM(m.gpa * c.credit) / SUM(c.credit) AS cgpa
FROM MARKS m
JOIN CREDIT c ON m.sub_code = c.sub_code
GROUP BY m.roll;
```

### 🎯 GQ2 · 2018 Q.7(a) / 2024 Q.4(b) · Student Table DDL, Insert, Alter, and Selection · 04 Marks

> *Section B · Asked in: 2018, 2024 (CO2) · L2 merge*

**Question (2018 Q.7(a)).** Write down the SQL queries for following operations.  
(i) Create table for student (<u>roll</u>, Name, <u>Dept</u>)  
(ii) Insert one example entry for student table  
(iii) Modify the student table to student(<u>roll</u>, Name, dept, session)  
(iv) Show the roll and name of the students of ECE department only.

**Question (2024 Q.4(b)).** Write down the SQL queries for following operations:  
i) Create table for student (<u>roll</u>, name, dept)  
ii) Insert one example entry for student tbale  
iii) Modify the student table to student (roll, name, dept, session)  
iv) Show the roll and name of the students of ECE dept only.  
*(Note: "tbale" printed verbatim in original paper; refers to table)*

**Answer.**

*(i) Create student table:*

```sql
CREATE TABLE student (
    roll INT,
    name VARCHAR(50),
    dept VARCHAR(20),
    PRIMARY KEY (roll, dept)
);
```

*(ii) Insert one example entry:*

```sql
INSERT INTO student (roll, name, dept)
VALUES (1810001, 'Rahim', 'ECE');
```

*(iii) Modify student table to add session:*

```sql
ALTER TABLE student
ADD session VARCHAR(10);
```

*(iv) Show roll and name of students from ECE:*

```sql
SELECT roll, name
FROM student
WHERE dept = 'ECE';
```

*Variant for 2024 Q.4(b) (4 marks):* The identical queries answer parts (i) through (iv).

## ⚡ Exam Tips & Common Mistakes

- **Check Underlined Attributes:** When two attributes are underlined (like `roll` and `dept`), declare `PRIMARY KEY (roll, dept)` at table level.
- **Use ADD for New Columns:** To add a column, write `ALTER TABLE student ADD col_name datatype;`. Do not use `MODIFY` to create a new column.
- **Never Write DELETE \* FROM:** The correct syntax is `DELETE FROM table_name WHERE ...`.
- **Enclose Strings in Quotes:** Always write `'ECE'`, not `ECE`. Bare words are parsed as column identifiers.
- **Join on Sub_Code for CGPA:** Always join `MARKS` and `CREDIT` on `sub_code` before computing weighted credit products.
