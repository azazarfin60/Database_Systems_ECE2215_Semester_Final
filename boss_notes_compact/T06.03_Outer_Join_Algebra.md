## Defining Outer Joins Using Basic Relational Algebra

**Outer Join (Information Retention):** An outer join is an extended relational algebra operation that prevents loss of information during a join. It computes the standard inner join first and then adds unmatched rows from one or both relations padded with null values.

**Relational Algebra Outer Join Operators:** Relational algebra provides three outer join operators: left outer join ($\mathbin{⟕}$), right outer join ($\mathbin{⟖}$), and full outer join ($\mathbin{⟗}$). Without a condition subscript, they match naturally on shared attribute names. With a condition subscript ($\mathbin{⟕}_\theta$, $\mathbin{⟖}_\theta$, $\mathbin{⟗}_\theta$), they match rows using predicate $\theta$.

Basic relational algebra consists of six fundamental operators: selection ($\sigma$), projection ($\Pi$), Cartesian product ($\times$), set union ($\cup$), set difference ($-$), and rename ($\rho$). Outer joins are extended operations built out of these basic primitives.

Let relation $r(R)$ and relation $s(S)$ have schemas $R$ and $S$.

### 1. Natural Left Outer Join ($\mathbin{⟕}$)

A natural left outer join takes the inner join $(r \bowtie s)$ and unions it with the null-padded dangling rows of $r$:

$$
r \mathbin{⟕} s = (r \bowtie s) \cup \left( \left( r - \Pi_R(r \bowtie s) \right) \times \{(\text{null}, \dots, \text{null})\} \right)
$$

The components perform three distinct roles:
1. $(r \bowtie s)$: Computes the matched rows across both relations.
2. $(r - \Pi_R(r \bowtie s))$: Isolates dangling rows of $r$ that lack matches in $s$. The projection $\Pi_R$ is mandatory because set difference requires identical attribute schemas.
3. $\times \{(\text{null}, \dots, \text{null})\}$: Uses Cartesian product to pad each dangling row of $r$ with null values for all attributes in $S - R$.

### 2. Natural Right Outer Join ($\mathbin{⟖}$)

A natural right outer join operates symmetrically, keeping all rows of $s$ and padding dangling rows with nulls for attributes in $R - S$:

$$
r \mathbin{⟖} s = (r \bowtie s) \cup \left( \{(\text{null}, \dots, \text{null})\} \times \left( s - \Pi_S(r \bowtie s) \right) \right)
$$

### 3. Natural Full Outer Join ($\mathbin{⟗}$)

A natural full outer join combines the left outer join and right outer join:

$$
r \mathbin{⟗} s = (r \mathbin{⟕} s) \cup (r \mathbin{⟖} s)
$$

Expressed purely in fundamental operators:

$$
r \mathbin{⟗} s = (r \bowtie s) \cup \left( \left(r - \Pi_R(r \bowtie s)\right) \times \{\text{null}\} \right) \cup \left( \{\text{null}\} \times \left(s - \Pi_S(r \bowtie s)\right) \right)
$$

### 4. Conditional (Theta) Outer Joins

When relations match on an explicit condition $\theta$ rather than shared column names, replace $\bowtie$ with $\bowtie_\theta$:

$$
r \mathbin{⟕}_\theta s = (r \bowtie_\theta s) \cup \left( \left( r - \Pi_R(r \bowtie_\theta s) \right) \times \{(\text{null}, \dots, \text{null})\} \right)
$$

$$
r \mathbin{⟖}_\theta s = (r \bowtie_\theta s) \cup \left( \{(\text{null}, \dots, \text{null})\} \times \left( s - \Pi_S(r \bowtie_\theta s) \right) \right)
$$

## Algebraic Properties & Equivalence Rules

### 1. Commutativity
- **Full Outer Join is commutative** (up to column ordering):
  $$
  E_1 \mathbin{⟗} E_2 \equiv E_2 \mathbin{⟗} E_1
  $$
- **Left and Right Outer Joins are NOT commutative:**
  $$
  E_1 \mathbin{⟕} E_2 \not\equiv E_2 \mathbin{⟕} E_1
  $$
  Swapping relation order requires flipping the join operator:
  $$
  E_1 \mathbin{⟕} E_2 \equiv E_2 \mathbin{⟖} E_1
  $$

### 2. Associativity (The Non-Associativity Trap)
Standard inner joins are associative: $(A \bowtie B) \bowtie C \equiv A \bowtie (B \bowtie C)$.

In contrast, **outer joins are NOT associative**:
$$
(A \mathbin{⟕} B) \mathbin{⟕} C \not\equiv A \mathbin{⟕} (B \mathbin{⟕} C)
$$

Evaluating $(B \mathbin{⟕} C)$ first introduces nulls into attributes shared with $A$. In three-valued logic, equality checks against null evaluate to unknown, causing rows to fail subsequent matches.

### 3. Pushing Selection Predicates ($\sigma$)
- A filter $\sigma_{\theta_1}$ can be pushed inside a left outer join only if $\theta_1$ references attributes of the preserved table $E_1$:
  $$
  \sigma_{\theta_1}(E_1 \mathbin{⟕}_\theta E_2) \equiv (\sigma_{\theta_1}(E_1)) \mathbin{⟕}_\theta E_2
  $$
- Pushing a condition on the unpreserved side $E_2$ changes query semantics because it filters tuples before null-padding occurs.

### 4. Outer Join to Inner Join Conversion (Null-Rejecting Predicates)

**Null-Rejecting Predicate:** A selection predicate $\theta_1$ is null-rejecting on relation $E_2$ if it evaluates to false or unknown whenever an attribute of $E_2$ is null.

If an outer join is followed by a null-rejecting filter on the unpreserved table, all null-padded rows are discarded anyway. The query optimizer simplifies the outer join into an inner join:

$$
\sigma_{\theta_1}(E_1 \mathbin{⟕}_\theta E_2) \equiv \sigma_{\theta_1}(E_1 \bowtie_\theta E_2)
$$

## Worked Example: Tracing Full Outer Join Using Basic Operators

Let $r(A, B) = \{(10, 5), (20, 8)\}$ and $s(B, C) = \{(5, P), (9, Q)\}$.

1. **Inner Join:** Match on $B = 5$:
   $$
   r \bowtie s = \{(10, 5, P)\}
   $$
2. **Left Dangling Rows:** Project and subtract:
   $$
   r - \Pi_R(r \bowtie s) = \{(10, 5), (20, 8)\} - \{(10, 5)\} = \{(20, 8)\}
   $$
   Pad with null for attribute $C$:
   $$
   \{(20, 8)\} \times \{(\text{null})\} = \{(20, 8, \text{null})\}
   $$
3. **Right Dangling Rows:** Project and subtract:
   $$
   s - \Pi_S(r \bowtie s) = \{(5, P), (9, Q)\} - \{(5, P)\} = \{(9, Q)\}
   $$
   Pad with null for attribute $A$:
   $$
   \{(\text{null})\} \times \{(9, Q)\} = \{(\text{null}, 9, Q)\}
   $$
4. **Union:**
   $$
   r \mathbin{⟗} s = \{(10, 5, P), (20, 8, \text{null}), (\text{null}, 9, Q)\}
   $$

## 🔮 Likely Questions (High-Probability Exam Predictions)

### 🎯 LQ1 · Formal Definition of Outer Joins in Relational Algebra · 04 Marks

> *Section A/B · Likely Question · Estimated Marks: 4 Marks*

**Question.** Define Left Outer Join ($\mathbin{⟕}$), Right Outer Join ($\mathbin{⟖}$), and Full Outer Join ($\mathbin{⟗}$) using the fundamental operators of relational algebra. Show the evaluation of Left Outer Join on a sample relational instance.

**Answer.**

**1. Algebraic Formulations:**  
Let $r(R)$ and $s(S)$ be two relations. Let $\bowtie$ denote the natural inner join and let $\{(\text{null}, \dots, \text{null})\}$ represent a tuple of null values matching missing attributes.

- **Natural Left Outer Join ($\mathbin{⟕}$):**
  $$
  r \mathbin{⟕} s = (r \bowtie s) \cup \left( \left( r - \Pi_R(r \bowtie s) \right) \times \{(\text{null}, \dots, \text{null})\} \right)
  $$
- **Natural Right Outer Join ($\mathbin{⟖}$):**
  $$
  r \mathbin{⟖} s = (r \bowtie s) \cup \left( \{(\text{null}, \dots, \text{null})\} \times \left( s - \Pi_S(r \bowtie s) \right) \right)
  $$
- **Natural Full Outer Join ($\mathbin{⟗}$):**
  $$
  r \mathbin{⟗} s = (r \mathbin{⟕} s) \cup (r \mathbin{⟖} s)
  $$
  $$
  r \mathbin{⟗} s = (r \bowtie s) \cup \left( (r - \Pi_R(r \bowtie s)) \times \{\text{null}\} \right) \cup \left( \{\text{null}\} \times (s - \Pi_S(r \bowtie s)) \right)
  $$

**2. Demonstration on Sample Instance:**  
Let $r(A, B) = \{(1, a), (2, b)\}$ and $s(B, C) = \{(a, 10), (c, 30)\}$.
- Step 1: Natural join $r \bowtie s = \{(1, a, 10)\}$.
- Step 2: Matched left projection $\Pi_R(r \bowtie s) = \{(1, a)\}$.
- Step 3: Unmatched left tuples $r - \Pi_R(r \bowtie s) = \{(2, b)\}$.
- Step 4: Pad with null for attribute $C$: $\{(2, b, \text{null})\}$.
- Step 5: Union gives $r \mathbin{⟕} s = \{(1, a, 10), (2, b, \text{null})\}$.

### 🎯 LQ2 · Commutativity and Associativity of Outer Joins · 04 Marks

> *Section A/B · Likely Question · Estimated Marks: 4 Marks*

**Question.** Discuss the algebraic properties of outer joins regarding commutativity and associativity. Provide a counterexample to show whether Left Outer Join is associative.

**Answer.**

**1. Commutativity:**
- Full Outer Join is commutative: $E_1 \mathbin{⟗} E_2 \equiv E_2 \mathbin{⟗} E_1$.
- Left Outer Join is not commutative: $E_1 \mathbin{⟕} E_2 \not\equiv E_2 \mathbin{⟕} E_1$. However, $E_1 \mathbin{⟕} E_2 \equiv E_2 \mathbin{⟖} E_1$.

**2. Associativity and Counterexample:**  
Left outer join is strictly **not associative**:
$$
(r \mathbin{⟕} s) \mathbin{⟕} t \not\equiv r \mathbin{⟕} (s \mathbin{⟕} t)
$$

*Proof by Counterexample:*  
Let the relations be:
- $r(A, B) = \{(1, 1)\}$
- $s(B, C) = \{(1, 1)\}$
- $t(A, C) = \emptyset$ (empty relation with attributes $A$ and $C$)

*Evaluate Left Side: $((r \mathbin{⟕} s) \mathbin{⟕} t)$*
1. Compute $(r \mathbin{⟕} s)$: $r(1, 1)$ matches $s(1, 1)$ on $B=1$, yielding $(1, 1, 1)$.
2. Join $(1, 1, 1)$ with empty relation $t(A, C)$ using left outer join. The left tuple is preserved:
   $$
   (r \mathbin{⟕} s) \mathbin{⟕} t = \{(1, 1, 1)\}
   $$

*Evaluate Right Side: $(r \mathbin{⟕} (s \mathbin{⟕} t))$*
1. Compute $(s \mathbin{⟕} t)$: $s(1, 1)$ has no match in $t$, so missing attribute $A$ is padded with null:
   $$
   s \mathbin{⟕} t = \{(\text{null}, 1, 1)\}
   $$
2. Join $r(1, 1)$ with $\{(\text{null}, 1, 1)\}$ on shared attributes $A$ and $B$.
   - In $r$: $A = 1, B = 1$.
   - In $(s \mathbin{⟕} t)$: $A = \text{null}, B = 1$.
   - The test $1 = \text{null}$ evaluates to unknown. The match fails.
   - Preserving $r(1, 1)$ pads missing attribute $C$ with null:
   $$
   r \mathbin{⟕} (s \mathbin{⟕} t) = \{(1, 1, \text{null})\}
   $$

*Conclusion:*  
$\{(1, 1, 1)\} \neq \{(1, 1, \text{null})\}$. This proves that left outer join is not associative.

### 🎯 LQ3 · Null-Rejecting Predicates and Outer Join Optimization · 03 Marks

> *Section A/B · Likely Question · Estimated Marks: 3 Marks*

**Question.** Explain the concept of a "null-rejecting predicate" in query optimization. How can a query engine simplify an outer join into an inner join using this property?

**Answer.**

**1. Definition:**  
A predicate $\theta$ is **null-rejecting** with respect to a relation $E_2$ if $\theta$ evaluates to `false` or `unknown` whenever any attribute of $E_2$ involved in $\theta$ contains a `null` value.

**2. Mechanism:**  
Under SQL three-valued logic, comparisons with null (such as `null = 'Taylor'` or `null > 50`) evaluate to `unknown`. Selection filters keep only tuples where the predicate evaluates to `true`. Thus, any null-padded tuple generated by an outer join is discarded.

**3. Equivalence Transformation:**  
When a query applies a null-rejecting predicate $\theta_1$ on the unpreserved relation $E_2$:
$$
\sigma_{\theta_1}(E_1 \mathbin{⟕}_\theta E_2) \equiv \sigma_{\theta_1}(E_1 \bowtie_\theta E_2)
$$

**4. Example:**  
```sql
SELECT *
FROM Student
LEFT JOIN Department ON Student.Dept_ID = Department.Dept_ID
WHERE Department.Building = 'Taylor';
```
Since `Department.Building = 'Taylor'` rejects rows where `Department.Building` is `NULL`, the DBMS rewrites the query into an `INNER JOIN`.

## ⚡ Exam Tips & Common Mistakes

- **Projection is Mandatory in Set Difference:** You cannot write $r - (r \bowtie s)$ because relations must have the same schema. Always write $r - \Pi_R(r \bowtie s)$.
- **Outer Joins Are Not Associative:** Never reorder parentheses across outer joins during relational algebra derivations.
- **Relational Algebra Outer Join Symbols:**
  - Left Outer Join: $\mathbin{⟕}$
  - Right Outer Join: $\mathbin{⟖}$
  - Full Outer Join: $\mathbin{⟗}$
- **Spotting Null-Rejection:** In SQL questions, check whether a `WHERE` clause tests an attribute from the optional table. If it does, the query acts as an inner join.
