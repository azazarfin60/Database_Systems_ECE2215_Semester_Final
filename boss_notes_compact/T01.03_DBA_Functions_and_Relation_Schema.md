# T01.3: DBA Functions and Relation Schema

> **Topic:** T01 · DB Concepts & Architecture | **Priority:** 🟠 Medium | **Exam Frequency:** 3/7 finals (10 marks) · 2017 Q1c, 2020 Q1a, 2021 Q1b
> **Sources:** Silberschatz 7e Ch. 1 (§1.8.2), Ch. 2 (§2.1) · Lecture Deck 01 (Slide 10), Deck 02 (Slide 6) · Raidah Class Note p. 11 · Fahim Hand Note p. 4

## The Five Canonical Functions of the DBA

**Database Administrator (DBA):** A Database Administrator is a person or group having central control over both the enterprise data and the programs that access that data. The DBA manages schemas, storage layout, user access permissions, and system maintenance.

Following Lecture Deck 01 (Slide 10) and Silberschatz §1.8.2, the primary responsibilities of a DBA include five canonical functions:

1. **Schema Definition:**
   - The DBA creates the original database schema by executing Data Definition Language (DDL) statements.
   - This sets up tables, column data types, and integrity constraints, storing the metadata in the system catalog.

2. **Storage Structure and Access-Method Definition:**
   - The DBA defines internal storage structures, disk block layouts, and file organizations.
   - This includes creating indexes (such as B+ trees or hash indexes) to speed up queries.

3. **Schema and Physical-Organization Modification:**
   - The DBA modifies the logical schema or physical storage structures as organization needs change or performance demands dictate.
   - For example, the DBA may add new columns, partition large tables, or drop unused indexes without breaking user applications.

4. **Granting of Authorization for Data Access:**
   - The DBA acts as the security manager by granting different permissions to different user groups.
   - Using commands like `GRANT` and `REVOKE`, the DBA controls who can inspect or modify specific tables, views, columns, or rows.

5. **Routine Maintenance:**
   - The DBA carries out recurring upkeep tasks:
     - **Backups:** Performing periodic database backups to protect against media failure or disaster.
     - **Disk Space Management:** Monitoring free disk space and allocating new storage volumes before space runs out.
     - **Performance Monitoring:** Auditing slow queries and tuning database parameters to maintain responsiveness.

## Relation Schema: Concepts and Formal Notation

**Database Schema:** The overall logical design and structural blueprint of a database. It corresponds to variable type declarations in a programming language and changes infrequently.

**Relation Schema:** The logical definition of a single relation (table). It lists the relation name, its attributes (columns), and their corresponding domains (allowed data types).

**Database Instance:** The actual collection of data rows stored in the database tables at a specific point in time. It corresponds to the value of a variable at runtime and changes whenever rows are inserted, updated, or deleted.

### Formal Notation

A relation schema $R$ with $n$ attributes is written formally as:

$$
R(A_1, A_2, \dots, A_n)
$$

- $R$ is the name of the relation.
- Each $A_i$ is an attribute name.
- Each attribute $A_i$ takes values from its domain $\text{dom}(A_i)$.

### Primary Key Notation

In standard exam notation, always underline the primary key attribute (or attributes) that uniquely identify each tuple:

$$
\text{instructor}(\underline{\text{ID}}, \text{name}, \text{dept\_name}, \text{salary})
$$

$$
\text{student}(\underline{\text{roll\_no}}, \text{name}, \text{dept}, \text{cgpa})
$$

Here, $\underline{\text{ID}}$ and $\underline{\text{roll\_no}}$ uniquely identify individual records.

### Schema vs. Instance

| Concept | Programming Language Analogy | Database Meaning | Mutability |
| :--- | :--- | :--- | :--- |
| **Relation Schema** | Type declaration (`type instructor = record ...`) | Structural definition of table name, attributes, and types | Fixed during design; rarely changes |
| **Relation Instance** | Runtime variable value (`instructor1 = {"101", ...}`) | Set of actual rows (tuples) in the table right now | Changes with every `INSERT`, `UPDATE`, or `DELETE` |

## 🏆 Golden Questions (Past Exam Archive)

### 🎯 GQ1 · 2020 Q.1(a) · 05 Marks

> *Section A · Asked in: 2020, 2021 (CLO1), 2017 · L2 merge*

**Question (2020 Q.1(a)).** What are the five main functions of a database administrator? What is relation schema?

**Question (2021 Q.1(b)).** What are the five main functions of a database administrator?

**Question (2017 Q.1(c)).** What are the main functions of a database administrator? Point out the name only.

**Answer.**

**Five Main Functions of a Database Administrator (DBA):**
1. **Schema definition:** The DBA creates the original database schema by executing DDL statements.
2. **Storage structure and access-method definition:** The DBA defines internal storage structures, indexing methods, and file organizations to optimize data access.
3. **Schema and physical-organization modification:** The DBA modifies database schemas and physical storage layouts to improve performance or adapt to changing business requirements.
4. **Granting of authorization for data access:** The DBA assigns access rights and user roles to regulate who can inspect or modify specific data items.
5. **Routine maintenance:** The DBA performs recurring operational tasks. These include periodically backing up the database, monitoring running jobs, and ensuring sufficient free disk space.

**Relation Schema:**  
A **relation schema** is the formal logical definition or blueprint of a relation (table). It specifies the name of the relation along with its set of attributes (columns) and their corresponding domains (data types).

- Format: $R(A_1, A_2, \dots, A_n)$
- Example: $\text{instructor}(\underline{\text{ID}}, \text{name}, \text{dept\_name}, \text{salary})$, where $\underline{\text{ID}}$ serves as the primary key.

*Variant for 2021 Q.1(b) (3 marks):* State and explain the five DBA functions above; omit the relation schema.  
*Variant for 2017 Q.1(c) (2 marks):* List only the names: (1) Schema definition, (2) Storage structure and access-method definition, (3) Schema and physical-organization modification, (4) Granting of authorization for data access, (5) Routine maintenance.

## ⚡ Exam Tips & Common Mistakes

- **Stick to the five canonical slide headings:** Grade schemes match the five headings from Lecture Deck 01, Slide 10 directly. Do not invent informal duties like "helps end users" or "writes application code".
- **Respect the "name only" constraint:** In 2017 Q.1(c), the prompt asked for "the name only" for 2 marks. Listing the five numbered titles secures full marks without wasting time on prose.
- **Always underline the primary key:** When providing a relation schema example, write $R(\underline{A_1}, A_2, \dots, A_n)$ with the key underlined.
